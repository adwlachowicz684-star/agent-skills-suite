## 四步结构：通用判据

> ⭐ **这是判断"能不能做成技能"的最实用判据**：

```
① 收集信息
② ⭐ 判断条件
③ 执行操作
④ 生成结果
```

```
□ ⭐ 尤其是那些"依赖资深员工经验、难以标准化交接"的任务
□ ⭐ 定制技能能快速把隐性知识显性化
```

> 呼应 `writing-org-context.md`：
> **个人经验 → 组织可复用的生产力资产**。

## 电商与零售

**典型场景**（大促赠品计算）：

```
痛点  活动规则复杂、库存校验、赠品匹配逻辑交织
      客服/运营难以快速判断

技能做法
□ ⭐ 把活动规则、库存校验、赠品匹配逻辑打包
□ ⭐ 运营只需输入订单号
□ ⭐ Agent 自动判断赠品合规性并生成处理建议
□ 用自然语言 + 结构化标记告诉 agent 该任务的全部边界和逻辑
```

## 什么最值得做

> ⭐ **优先级排序**（按 ROI）：

```
1. ⭐ 依赖资深员工经验、难以标准化交接的
   ——离职就失传的东西

2. ⭐ 规则严密、高频重复、不允许出错的
   ——报销审核、发票校验

3. 跨系统数据整合的
   ——人肉拼装成本高

4. 输出结构固定、需要品牌一致的
```

**技能的三种组成部分**（企业定制的典型形态）：

```
□ 自然语言 + 结构化标记   告诉 agent 全部边界与逻辑
□ ⭐ 可执行脚本           封装 API 调用、数据处理、文件操作
   例：一个 Python 脚本完成 Excel 数据比对、生成差异报告
   ⭐ agent 通过技能知道何时调用它
□ ⭐ 模板与参考文件        文案模板、邮件格式、品牌规范、样例报告
   ——确保输出符合企业标准
```

> ⭐ 这正好对应 `skill-crafting` 的 `skill-structuring` 的 `directory-contract.md` 的三个子目录：
> 指令在 SKILL.md、确定性逻辑在 scripts/、模板在 assets/。

## 自查

```
□ 是否用"四步结构"判断过流程是否适合？
□ ⭐ 是否优先选择了"依赖资深经验、难交接"的任务？
□ 电商场景是否把规则/库存/匹配打包（只需输订单号）？
□ ⭐ 财务类是否明确"规则严密且不允许出错"？
□ 模型是否被限制为"组织数字"而非"生成数字"？
□ HR 类是否结合了公司政策与历史数据？
□ ⭐ HR 类是否守住了合规边界（不做录用决策）？
□ 供应链的合同比对是否输出差异清单 + 风险等级？
□ ⭐ 跨系统调用是否走脚本（而非模型声称）？
□ 输出是否用模板保证一致性？
□ 是否用齐了 SKILL.md / scripts/ / assets/ 三层？
□ 是否说明了"agent 何时调用脚本"？
□ 是否把隐性知识显性化了（这是核心目标）？
```
