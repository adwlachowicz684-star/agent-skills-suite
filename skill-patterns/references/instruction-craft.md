## 1. ⭐ 读者是模型，不是人

> ⭐ **新手最常见的写法，是把正文写成一篇"产品介绍"——
> "本技能旨在帮助用户高效地……"。这是浪费：
> ⭐ 模型不需要被"介绍"，它需要被指挥。**

**第二个思维转变**：

> ⭐ **所有"什么时候用"的信息都放进 description，别放正文。
> ⭐ 正文是给"已经决定用它"的模型看的操作手册。**

## 2. 祈使句，不是愿望句

```
❌ "希望能全面分析一下竞品的情况"
✅ "搜索目标竞品的产品、定价、用户评价，
    按功能/价格/口碑/策略四个维度归类，逐项标注优劣势"
```

> ⭐ **愿望句让 AI 自由发挥，结果随机。
> 祈使句锁定动作和产出，执行确定性高。**

**重要步骤补一句原因**：

```
"各维度用表格而非段落呈现——表格的对比结构让差异一目了然"
```

> ⭐ **补了原因，AI 理解"为什么"之后执行会更稳。**

## 3. ⭐ 把输出格式钉死，并配示例

```
## 输出格式
严格按以下 13 列输出，一列不缺、顺序不乱:
| 用例编号 | 用例等级 | 标题 | 前置条件 | 步骤描述 | 预期结果 | ... |

**示例:**
| ZC-001 | P0 | 正常注册成功 | 邮箱未注册 | 1.打开注册页 2.输入合法信息 3.提交 | 注册成功,跳转登录页 |
```

> ⭐ **给一个填好的示例，胜过十句"请注意格式"。**

## 4. 给流程，不给愿望

```
❌ "请全面地分析"
✅ "对照维度清单逐项过一遍，每个维度都判断是否适用"
```

正文应该长这样（可直接抄的骨架）：

```markdown
当你收到用户请求时，如果用户没有特别说明，按以下步骤处理:
1. 将输入数据按类型分组，类型以数据第一列的值为准。
2. 对每组计算总数、平均值和变化率。
3. 将结果写入 Markdown 表格，表头包括:类型、总数、平均值、变化率。
4. ⭐ 如果第 2 步计算失败，跳过该组并在报告末尾标注"计算失败",
   不要中断整个流程。
```

> ⭐ 四个关键点：**祈使句 · 编号步骤 · 明确的输入处理逻辑 · 失败兜底**。
>
> ⭐ **尤其是"如果失败怎么做"这种兜底指令，
> 能大幅减少模型卡在中间不干活的情况。**

**长度**：

```
⭐ 能用 5 步说清楚的事，不要写成 10 步
⭐ 正文越长，留给实际任务的窗口越小
```

## 5. 结尾放质量自查清单

```markdown
## 质量自查
- [ ] 输出字段齐全、顺序正确、无缺列
- [ ] ⭐ 每条预期结果都可验证，没有"显示正常"这类没法断言的写法
- [ ] 编号连续不重复
- [ ] 边界与异常场景都覆盖了，不是一水儿的正向流程
```

> ⭐ 让模型产出后对着 checklist 自检一遍，
> **能显著减少低级遗漏**。

> ⭐ 注意第 2 条：**"显示正常"这类没法断言的写法**——
> 这跟 `golden-rules-failure-modes.md` 的
> "把每个形容词换成一条规格"是同一条原则。

## 6. ⭐ 讲"为什么"，而不是堆 MUST

> ⭐ **这是官方指南里最值得认同的一条：
> 模型对"解释了原因的要求"执行得更好、更会举一反三。**

```
❌ "禁止臆造需求"
✅ "PRD 没写的一律进疑问清单，绝不自己编个验收标准当既定事实
    ——⭐ 这是 AI 产出最容易翻车的地方"
```

> ⭐ **说清后果，比命令本身更有约束力。**

这与《skill-crafting》`guidance-forms.md` 的
"反模式必须带 Why + Instead"完全吻合——
**只写"不要 X"是禁令，加上"因为 Y、改成 Z"才变成配方**。

## 7. 示例给三种

> ⭐ **3–5 组输入输出对照，必须覆盖三类场景：**

| 场景 | 教会 AI 什么 | 例子 |
|---|---|---|
| **常规** | 标准操作长什么样 | 3 个竞品信息齐全 → 输出完整对比报告 |
| **特殊** | ⭐ 非典型输入也能兜住 | 只给 1 个竞品 → 输出单品深度分析，而非强行对比 |
| **异常** | ⭐ 遇到不对的输入别硬来 | 用户要求分析自家产品 → 提示这是自查而非竞品分析 |

写法：**每组写清"用户输入了什么 → 技能应该输出什么"**。

> ⭐ **一句话顶十句解释。**

**技巧**：

```
⭐ 示例里的输入风格尽量贴近用户真实说话方式
——因为模型是通过语义相似性来匹配技能的
```

## 两条可视化法则

```
① 碰到"看情况处理" → ⭐ 用决策表格
   | 竞品数量 | 分析策略 |
   | 1 个     | 做深度单品分析 |
   | 2–5 个   | 维度对比 + 关键发现 |

② 碰到多步流程 → ⭐ 画 ASCII 图
   确认竞品名单 → 搜索信息 → 信息充足? → 是 → 维度对比 → 输出报告
                                       → 否 → 提示用户补充
```

> ⭐ **视觉化表达：歧义少、密度高，后期维护也省力。**

## 速查

```
□ ⭐ "何时用"在 description，不在正文
□ 祈使句，不是愿望句
□ 重要步骤补一句"为什么"
□ ⭐ 输出格式钉死 + 一个填好的示例
□ ⭐ 每步有失败兜底
□ 5 步能说清就不写 10 步
□ 结尾有质量自查清单（可断言，不是"显示正常"）
□ ⭐ 讲为什么，而不是堆 MUST
□ ⭐ 示例覆盖常规/特殊/异常三类
□ 输入风格贴近真实说话方式
□ "看情况" → 决策表；多步骤 → ASCII 图
```

**一句话**：

> ⭐ **模型不需要被介绍，它需要被指挥。**
