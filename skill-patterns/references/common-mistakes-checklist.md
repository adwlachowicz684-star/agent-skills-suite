## 1. ⭐ 描述层（最常见、最隐形）

> ⭐ **这是技能失败最常见的单一原因。**

| 错误 | 表现 | 修法 |
|---|---|---|
| **写成产品介绍** | "资深架构师视角，覆盖高可用、可扩展性、成本优化三大维度" | ⭐ 对人是有效营销，⭐ **对路由器是低信息量噪声** |
| ⭐ **缺负边界** | 几乎每份都写了"什么时候用我"，极少写"什么时候别用我" | ⭐ 缺了负边界，相邻技能互相抢单 |
| **向量空间太远** | 用户不会说"请以资深架构师视角"，会说"这方案能扛住双十一吗" | ⭐ 用用户的原话 |
| **比名字还宽** | 造成路由冲突 | 与 name 精确对齐 |

**那个"两个技能谁该接"的问题很典型**：

```
一个"数据分析"和一个"财报解读"摆在同一目录
用户问"帮我看下这家公司季度收入的变化"——谁该接？
```

> ⭐ 这就是 `description-by-collision-risk.md` 的混淆伙伴审计要解决的问题。

## 2. 正文层

| 错误 | 修法 |
|---|---|
| **背景历史 / 版本历史 / changelog** | ⭐ 移出去——正文是给 agent 的操作行为，不是团队面散文 |
| **README 式上手引导** | 同上 |
| ⭐ **只有价值观没有可执行行为** | ⭐ 写会改变 agent 行为的指令 |
| ⭐ **"确保质量""全面分析"** | ⭐ 无具体判据 = 对模型等于没有约束 |
| 含糊动词（"应该""考虑""大概"） | 用祈使句："读""写""计算" |

**"写给 agent，不是写给人类"** 是这一层的总纲：

```
⭐ 检查 SKILL.md 要看操作行为，不是团队面散文
```

## 3. ⭐ 结构层

| 错误 | 表现 |
|---|---|
| ⭐ **六千字全量注入** | ⭐ 每轮对话先交一笔固定税 |
| ⭐ **改完就发，没有回归** | ⭐ 动一句提示词，可能让三个原本能过的场景悄悄挂掉 |
| 参考文件嵌套引用 | 模型会改用 `head -100` 预览，信息不完整 |
| 未被引用的资源 | 是噪音，稀释检索 |
| 脚本假设了不存在的运行时 | ⭐ 在 API 沙箱里没有网络，脚本就死 |

## 4. 输出层

```
❌ "输出一份摘要" —— 没有声明形状，每次运行长得都不一样
✅ 模板钉在 assets/，带显式占位符
```

> ⭐ 没有声明形状的输出，**下游无法解析、无法跨运行做趋势对比**。

其他两条：

```
· 畸形输入要"清晰错误 + 恢复路径"——⭐ 静默崩溃是 ship-blocker
· 明确"本技能不做什么"——防止在相邻提示上过触发
```

## 5. ⭐ 维护层

| 错误 | 后果 |
|---|---|
| ⭐ **不标日期** | ⭐ "亚马逊规则一个季度一变，不标日期的技能三个月后就是坑" |
| 没有 Owner | 出问题时没人能解释它为什么仍处于启用状态 |
| 没有版本记录 + 评测证据 + 停止开关 | ⭐ "自我改进"更像不可控覆盖 |
| ⭐ 指向已移动/已重命名的文件 | ⭐ 要么修，要么退役 |

## 三层评估视角的收口

| 层 | 关键指标 | 做法 |
|---|---|---|
| L1 触发 | 召回 / 精确 / 误触发 | ⭐ 30–50 正样本 + 30–50 负样本（⭐ **负样本比正样本值钱**） |
| L2 执行 | 确定性断言 → Rubric → 稳定性 | ⭐ 同一用例跑 5 次全过 |
| ⭐ L3 成本 | 常驻 token / 总 token / P50·P95 耗时 / 工具调用次数 | ⭐ **质量分的提升 ÷ 增加的 token** |

> ⭐ **L3 那个比值最该算**：
> 一个技能把 rubric 均分从 6.2 拉到 7.0，代价是 token 翻三倍，
> **这笔账多半不划算**；同样的涨幅只多花 15% 上下文，那就该留。

**建议下限**（工程实践值）：

```
50    触发用例下限
5     ⭐ 同一用例重复次数（pass^5）
10%   ⭐ 人工复核抽样比例
```

## 速查

```
描述层：
□ ⭐ 写成产品介绍 = 对路由器是噪声
□ ⭐ 缺负边界 → 相邻技能抢单
□ 用用户的原话，不是你的术语
□ 不比 name 更宽

正文层：
□ ⭐ 无背景历史/changelog/README 式引导
□ ⭐ 价值观 → 换成可执行行为
□ ⭐ "确保质量" = 废话，给判据
□ 祈使句，不用"应该/考虑"

结构层：
□ 不全量注入（每轮固定税）
□ ⭐ 改完就发没有回归 = 三个场景悄悄挂掉
□ 不嵌套引用；未引用资源是噪音

输出层：
□ 声明形状；模板钉 assets/
□ 畸形输入要给恢复路径

维护层：
□ ⭐ 标日期
□ 有 Owner / 版本 / 评测证据 / 停止开关
□ ⭐ 不留指向死路径的技能

三层评估：
□ L1 触发（负样本更值钱）
□ L2 执行（pass^5）
□ ⭐ L3 成本（质量提升 ÷ 增加 token）
□ 50 用例 / 5 次 / 10% 人工复核
```

**一句话**：

> ⭐ **负样本比正样本值钱——正样本证明它能用，
> 负样本证明它不会在别人该上场的时候抢戏。**
