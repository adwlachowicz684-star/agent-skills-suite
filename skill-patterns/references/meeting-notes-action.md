## 抽取什么

四类结构化输出：

```
□ 决策记录
□ ⭐ 行动项（带负责人 + 截止日 + ⭐ 置信度）
□ 开放问题
□ 可分发的摘要邮件
```

> ⭐ **置信度是这套设计的灵魂**——见下。

## 信号模式表

| 信号 | 例子 | 抽取 |
|---|---|---|
| will | "Sarah will send the report" | 行动项，负责人 Sarah |
| @提及 + 承诺 | "@tom can you review?" | 行动项，负责人 tom（疑问形式） |
| by / due | "by Friday"、"due 2026-08-20" | 截止日 |
| `Action items:` 段 | 该段下列出的全部 | 全部 |
| 复选框 | "- [ ] call vendor" | 行动项，未分配 |
| assign(ed)? to | "assigned to Priya" | 负责人 |
| decided / agreed / going with | 同上 | ⭐ 决策 |
| approved / rejected | 同上 | ⭐ 决策 |
| TBD / question / ? | 同上 | 开放问题 |

**日期解析**：

```
□ ⭐ 自然语言日期（"by Friday"、"next Tuesday"、月末、两周内）
□ ⭐ 相对会议日期解析——不是相对今天
```

## 歧义怎么处理

> ⭐ **这是"确定性抽取"最该学的一节。**

```
"we should probably..."   → ⭐ 低置信度（标记待复核）
祈使句但无负责人          → ⭐ 负责人 = Unassigned
```

**规则是：宁可标记不确定，也不要猜一个填进去。**

```
❌ 把"我们应该大概要做 X"当成确定的行动项
✅ 抽出来，但标 low-confidence，让人复核
```

呼应 `metrics.md`（**`skill-evaluating`**）与
`grounding-verification.md`（**`skill-crafting`**）：
**不确定就是不确定**——
把推断当成事实输出，是垂直行业技能最常见的失败模式。

## 跨会议结转

```bash
python3 scripts/meeting_extractor.py notes.txt \
  --meeting-date 2026-08-19 \
  --previous lastweek.json \
  --minutes minutes.md
```

```
□ ⭐ 与上次会议的 JSON 对比
□ 未完成项结转，带"年龄"与"陈旧警告"
□ ⭐ 输出按负责人的任务清单
```

> ⭐ **"带年龄的陈旧警告"是个很好的设计**——
> 一个挂了三次会议还没做的行动项，
> 要么该删，要么该升级，不该继续无声结转。

## 五个常见坑

**① 把抽取结果当真相**

```
□ 引擎是确定性的，不是读心术
□ ⭐ 发邮件出去之前先看置信度标记
```

**② 没有 `--meeting-date` 的相对日期**

```
□ "By Friday" 不知道是哪个周五就没有意义
□ ⭐ 不传会议日期，日期会按今天的上下文解析（并被标记）
```

**③ 多人重叠的聊天转写**

```
□ 时间戳行会被剥离
□ ⭐ 说话人前缀（Name:）自动成为负责人候选
```

**④ ⭐ 把完整纪要发给所有人**

```
□ 邮件草稿含按负责人分节的内容
□ ⭐ 给高管的版本要裁剪
```

**⑤ 用它做它不做的事**

见下节。

## 边界：不做什么

> ⭐ **显式排除清单**（呼应 `code-simplifier.md` 的"何时不该简化"）：

```
❌ 逐字转写（需要先用转写工具）
❌ ⭐ 日历排程
❌ ⭐ 项目管理同步（Jira/Linear 有各自的技能）
   ——⭐ 本技能产出的是那些工具消费的结构化中间物
```

> 最后一句值得单独记：
> **本技能产出的是"结构化中间物"，不是终点**。
> 这定义了它在更大流程中的角色——
> 呼应 `market-research-skills.md`（**（领域实例库·已归档）**）
> 评价标准第 6 条：**在更大流程中有清晰角色**。

## 命令示例

```bash
# 基础抽取
python3 scripts/meeting_extractor.py notes.txt --meeting-date 2026-08-12

# 完整输出：JSON + Markdown 纪要 + 邮件草稿
python3 scripts/meeting_extractor.py notes.txt \
  --meeting-date 2026-08-12 --title "Product sync" \
  --json out.json --minutes minutes.md --email email.md
```

**接受的笔记格式**：

```
□ 自由文本
□ ⭐ 聊天式行（"10:42 Sarah: I'll send the deck"）
□ 复选框列表
□ "Action items:" 段落
□ ⭐ 以上常常混在一起
```

> ⭐ 最后一条很关键：真实笔记**从来不是单一格式**，
> 技能必须说明它能处理混合输入。

## 可迁移的四条做法

**① 确定性抽取进脚本，润色交模型**

```
□ 模式匹配、日期解析、去重 → scripts/
□ 语义判断、语气调整       → 模型
```

**② 每个抽取项带置信度**

```
□ 高置信度直接用
□ ⭐ 低置信度标记待复核——不猜
```

**③ 相对时间必须有个锚点参数**

```
□ "by Friday" 需要 --meeting-date
□ ⭐ 缺锚点时要标记，而不是按今天算
```

**④ 明确"产出的是中间物"**

```
□ 定义技能在流程中的位置
□ ⭐ 列出它不做什么（转写、排程、PM 同步）
```
