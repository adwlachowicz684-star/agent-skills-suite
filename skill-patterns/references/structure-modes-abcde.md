## 1. 模式 A：极简指导型

```
my-skill/
└── SKILL.md        # 设计原则、思维框架、方法论
```

**适用**：简单工具的用法、原则性指导。

**⭐ 推荐行数：50–200 行**

真实案例：`explaining-code` 只有 **96 字**。

---

## 2. 模式 B：示例模板型

```
my-skill/
├── SKILL.md            # 导航 + 选择逻辑
└── examples/  (或 templates/)
    ├── template-a.md
    ├── template-b.md
    └── template-c.md
```

**适用**：多种模板选择（不同类型的邮件/报告）、知识点众多且相对独立的主题。

**⭐ 推荐行数：30–100 行，⭐ 核心作用是「导航」**

> ⭐ 注意行数比模式 A 还少——
> **因为内容都进了模板文件，SKILL.md 只负责"选哪个"**。

---

## 3. 模式 C：工具脚本型

```
my-skill/
├── SKILL.md
└── scripts/
```

**适用**：代码执行、确定性操作。

> ⭐ 对应 《skill-scripting》`scripts-as-production.md`：
> **脚本执行不进上下文，只输出进**——这是省 token 的关键。

---

## 4. 模式 D：知识库型

```
my-skill/
├── SKILL.md
├── scripts/
├── references/
└── assets/
```

**适用**：技术框架知识库。

> ⭐ 与 `five-design-patterns.md` 的 Tool Wrapper 对应：
> **检测到关键词才加载 references/ 里的领域文档。**

---

## 5. 模式 E：完整工作流型

```
my-skill/
├── SKILL.md
├── scripts/
├── references/
└── assets/
```

**适用**：完整解决方案、多阶段流程。

> 目录结构与 D 相同，**差别在 SKILL.md 的内容**——
> E 有明确的阶段划分与验证点。

---

## 6. 速查表

| 模式 | 目录 | ⭐ 推荐行数 | 适用 |
|---|---|---|---|
| **A 极简指导** | 只有 SKILL.md | **50–200** | 原则、方法论、简单工具 |
| **B 示例模板** | SKILL.md + examples/ | **30–100** | ⭐ 多模板选择、导航为主 |
| **C 工具脚本** | SKILL.md + scripts/ | — | 确定性操作、代码执行 |
| **D 知识库** | 全目录 | — | 框架知识、按需加载 |
| **E 完整工作流** | 全目录 | — | 多阶段 + 验证点 |

**按字数的另一套口径**（可作交叉参考）：

```
超简洁型  ~96 字        explaining-code
简洁型    250–1000 字    internal-comms (211 字)
标准型    1000–2000 字   article-translator (1053 字)
详细型    2000–5000 字   skill-creator (1660 字)
⭐ 超过 5000 字 → 详细内容进 references/，代码进 scripts/
```

## 7. ⭐ 与五种设计模式的区分

这两套容易混，其实维度不同：

| | 五种结构模式 A–E | 五种设计模式 |
|---|---|---|
| **问的问题** | ⭐ **文件怎么组织** | ⭐ **内部逻辑怎么设计** |
| 例子 | B：模板放 examples/，SKILL.md 做导航 | Generator：用模板强制输出结构 |
| 关系 | 骨架 | ⭐ 骨架之上的行为 |

> ⭐ 两者是**正交**的：
> 一个 Generator 模式既可以用模式 B 的目录（模板放 examples/），
> 也可以用模式 E（还有脚本和参考文档）。

## 速查

```
□ 只有原则 → A（50–200 行）
□ 多模板选择 → B（⭐ 30–100 行，SKILL.md 只导航）
□ 确定性操作 → C（脚本）
□ 框架知识 → D（references 按需）
□ 多阶段+验证点 → E
□ ⭐ >5000 字 → 拆
□ 结构模式（文件怎么放）≠ 设计模式（逻辑怎么走）
