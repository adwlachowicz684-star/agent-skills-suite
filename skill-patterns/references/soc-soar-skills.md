## 核心原则：先富集后行动

> ⭐ **enrich before acting, gate the blast radius,
> keep everything reversible**

```
1. 先富集——多源情报算出聚合风险分与置信度
2. 再行动——按显式、有序的规则决策
3. ⭐ 门控爆炸半径
4. ⭐ 一切可回滚
```

## 四步流程

**① 定义触发**

```
□ 哪个检测/告警启动这个 playbook
□ 关联的指标（indicators）
```

**② 富集**

```bash
python scripts/enrich_ioc.py --ioc 192.168.1.100 \
  --sources vt,abuseipdb,otx
```

```
□ 查多个威胁情报源（VirusTotal、AbuseIPDB、OTX、Group-IB）
□ ⭐ 算出聚合风险分 + 置信度
```

> ⭐ **多源聚合是防误判的关键**——
> 单一情报源的误报率足以造成生产中断。

**③ 决策**

> ⭐ **应用显式、有序的规则。**

```
恶意 + 高置信度  → 阻断
可疑             → ⭐ 升级为工单（人工看）
良性             → 作为误报关闭
```

> ⭐ **"可疑 → 工单"这一档是整个设计的核心**：
> 它承认了不确定性的存在，
> 而不是把中间地带硬推向某一侧。
>
> 呼应 `meeting-notes-action.md`（**（领域实例库·已归档）**）的
> **低置信度标记待复核**——同一条原则。

**④ 响应**

```bash
# ⭐ 默认 dry-run
python scripts/respond_block.py --ip 192.168.1.100 \
  --device paloalto --action block

# 真正提交需要显式标志
python scripts/respond_block.py --ip 192.168.1.100 \
  --device paloalto --action block --commit
```

**三个必须有的性质**：

```
□ ⭐ 默认 dry-run
□ ⭐ 临时阻断带 TTL / 过期时间
□ ⭐ 生成一个回滚动作
```

## 四层护栏

```
1. ⭐ never-block allowlist（永不阻断白名单）
2. ⭐ max-actions 熔断器（最大动作数）
3. ⭐ 生产环境的批准门
4. ⭐ 完整审计日志
```

> ⭐ **"熔断器"这层很值得注意**——
> 它防的是"规则本身正确但触发了异常大量的动作"，
> 这类失控不是单条规则能拦住的。
>
> 呼应 `error-handling.md`（**`skill-crafting`**）的熔断三态机，
> 与 `agent-incident-response.md`（**`skill-governance`**）的
> **"先暂停外部动作"**。

## 产出与测试计划

**产出**：厂商中立的 `playbook-template.yml`

```
trigger → enrich → decision → actions → guardrails → rollback
```

> ⭐ **厂商中立很重要**——
> 呼应 `protocol-layering.md`（**`skill-orchestration`**）的
> 可移植性思路，以及安全库用 Sigma 作为检测规则单一来源的做法：
> **避免锁定，保持一份检测逻辑**。

**测试计划**：

> ⭐ **提供 dry-run 演练，展示将会发出的确切 API 调用，
> 让上线前能充分评审。**

## 授权与证据完整性

```
□ ⭐ 明确只用于授权防御——你自己拥有或受聘保护的系统
□ ⭐ 保持证据完整性：始终在日志副本上工作
□ ⭐ 关键警告：阻断生产流量的自动化会造成中断
    ——在翻转 --commit 标志前充分评审
```

呼应 `security-domains.md`（**（领域实例库·已归档）**）：
**授权边界必须显式**。

## 一个值得抄的设计选择

> ⭐ **`stdlib-only`（只用标准库）**。

**为什么**：

```
□ 技能保持轻量
□ ⭐ 能部署在隔离网 / 受限环境——那里没法 pip install
```

呼应 `air-gapped.md`（**`skill-distribution`**）：
**每个外部依赖必须在传输时捆绑，运行时不 npm install**。

> 这是一个很好的例子说明
> **"无依赖"不只是洁癖，是部署环境的硬要求**。

## 技能链的分工

```
日志分析 → 检测规则生成 → ⭐ SOAR playbook → IR 报告
                              ↑                  ↑
                    值得自动响应的交过来      动作回流更新事件记录
```

> ⭐ **"值得自动响应的才交给 SOAR"**——
> 上游已经做了一轮筛选。
> 呼应 `security-pipeline.md`（**`skill-orchestration`**）的
> **可利用性验证独立成步**。
