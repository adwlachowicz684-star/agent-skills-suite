## 1. 三级预算

| 级别 | 内容 | 成本 | 何时加载 |
|---|---|---|---|
| L1 元数据 | name + description | **~100 tokens** | ⭐ 始终（启动时） |
| L2 正文 | SKILL.md body | **<500 行 / ~5,000 tokens** | 触发时 |
| L3 资源 | references / scripts / assets | 5,000+ | 按需 |

**字段级预算**（更细的口径）：

```
name          5–15 tokens
description   50–200 tokens     ⭐ 触发主机制
license       5–20 tokens
metadata      可变
```

> ⭐ **"challenge principle"**（挑战原则）：
> **正文里每一段都要证明自己配得上 token 成本。**
> 如果内容没有提供 agent 所缺的信息，就该移到 references/ 或删掉。
>
> 这与《skill-refining》`pruning.md` 的 no-op 测试完全同源。

## 2. ⭐ 激活不是一次性开销

> ⭐ **激活不是任务结束后就消失的一次性成本。
> 一旦技能被激活，它的指令会留在对话里，
> ⭐ 并在本次会话剩余时间里持续消耗上下文。**

官方口径很精确：

```
渲染后的 SKILL.md 作为一条消息进入对话，
⭐ 并在会话剩余时间里一直留在那里。
⭐ 文件不会在后续轮次被重新读取。
```

三个后果：

```
① ⭐ 每一行都是重复成本——臃肿的正文在第 20 轮还在计费，
   不只是触发它的那一轮
② ⭐ 要写"常驻指令"，而不是"一次性步骤"——
   agent 整个会话都看到同一份文本
③ ⭐ 压缩可能驱逐你的技能（见下节）
```

> ⭐ 第 ② 条很少有人意识到：
> 如果你写"第一步做 X"，agent 在会话后期**仍然看着这句话**——
> 它不知道那是"已经做过的一次性步骤"。
> 所以**步骤措辞要能承受被反复看到**。

---

## 3. ⭐ 压缩会驱逐技能

> ⭐ 当会话变长触发压缩时，
> 系统会**重新挂载每个技能最近一次的调用**，
> 保留**每个技能的前 5,000 tokens**，
> ⭐ **总预算 25,000 tokens，最近的优先**。
>
> ⭐ **调用了很多技能的话，最早的那几个会被整个丢掉。**

> ⭐ 这解释了一个常被误读的症状：
> **技能"中途失效"时，指令不一定消失了——
> 可能模型只是改用了另一种方法。**
>
> 应对：**强化技能指令，或在压缩后重新调用它。**

这与 `budget-truncation.md` 的"压缩后每个技能只留前 5,000 tokens"完全吻合，
而且给出了更强的结论：**不只是留前 5000，还可能在有多个技能时被整个丢掉**。

## 4. ⭐ 算术：96% 的节省从哪来

设 N = 技能数，T(desc) = 单条描述成本，T(full) = 单个正文成本，k = 任务真正打开的技能数。

```
全量预加载：  C(static)      = N × T(full)
渐进式加载：  C(progressive) = N × T(desc) + k × T(full)
```

代入规范自己的预算（T(desc)=100，T(full)=5,000），50 个技能其中 1 个被激活：

```
C(static)      = 50 × 5,000        = 250,000 tokens
C(progressive) = 50 × 100 + 5,000  =  10,000 tokens

ρ = 1 − 10,000/250,000 = ⭐ 96%
```

> ⭐ **同样的 50 项能力、同样的任务，省 96%。**

公式也标出了它在哪里失效：**k 变大时优势缩小**——
如果一次任务打开 10 个技能，渐进式的收益就没这么夸张了。

## 5. 实证分布

```
40,000+ 个已发布技能的分析：
  中位数            ~1,400 tokens
  ⭐ 90% 在 4,000 以下
```

对照：

```
5 个技能全量加载    → 每次会话开始就 12,500 tokens
同样 5 个渐进式加载 → ⭐ 约 300 tokens，直到真的需要某个
```

**微技能 vs 单体**（证据相当干净）：

```
SkillsBench（2026，11 个领域 86 个任务）：
  ⭐ 2–3 个模块的聚焦技能 > 单个综合大文件
  ⭐ 精选技能平均通过率 +16.2 个百分点
     医疗与制造 > 40 点
     通用软件工程 ~4.5 点
```

> ⭐ 最后一行最重要：
> **技能在你"做事有自己的一套"的地方帮助最大——
> 也就是说，帮助在你的判断力所在之处。**

## 速查

| 项 | 数字 |
|---|---|
| L1 描述 | ~100 tokens/技能 |
| ⭐ L2 正文硬上限 | 500 行 / 5,000 tokens |
| ⭐ 压缩后保底 | 每技能前 5,000，总 25,000，最近优先 |
| 实证中位数 | ~1,400 tokens |
| 渐进式收益 | ⭐ 96%（50 技能、激活 1 个） |

```
□ 正文每一行是否配得上 token 成本（challenge principle）
□ ⭐ 步骤措辞能否承受"被反复看到"
□ ⭐ 是否知道压缩会驱逐旧技能
□ ⭐ 拆分沿工作的接缝，不是按角色
□ ⭐ 别过度拆——近似重复的描述会让选择变混乱
```

**一句话**：

> ⭐ **从提示词工程 → 上下文工程 → harness 工程。**
