## 1. 六层

一套完整的技能正文，从目标到兜底共六层：

| 层 | 回答什么 |
|---|---|
| ① 目标 | ⭐ 要达成什么 |
| ② 输入 | 拿什么做 |
| ③ 流程 | 怎么做 |
| ④ 输出格式 | 产出什么形状 |
| ⑤ 自检标准 | ⭐ 到了怎么确认 |
| ⑥ FAQ | ⭐ 走偏了怎么回正 |

> ⭐ **六层到位，AI 就知道
> 目标在哪、怎么去、到了怎么确认、走偏了怎么回正。**

## 2. ⭐ 第六层最常被漏

```
Q: 用户提到的竞品搜不到信息?
A: ⭐ 如实告知信息不足，建议用户提供补充资料或更换分析对象。
```

> ⭐ 注意这个答案的形态：
> **不是"跳过"，不是"编一个"，而是"如实告知 + 给替代路径"**。

这正是 `research-skills.md` 那条硬护栏的实例——
**不准编造**，且要说清哪些没验证。

**FAQ 层应该写什么**：

```
① 输入缺失/无效怎么办
② 外部依赖不可用怎么办
③ 结果不确定时如何表述
④ ⭐ 用户的要求超出技能边界时怎么办
```

## 3. ⭐ 判断标准是否基于事实

**自检标准这一层的两个判据**：

```
① ⭐ 是否基于事实而非主观判断?
② ⭐ 行动建议是否可执行?
```

对应到 `golden-rules-failure-modes.md`：

```
❌ "代码干净"、"输出看起来不错"      → 主观，无法判定失败
✅ "输出字段齐全、无缺列"、"无 console 错误" → 事实，可判定
```

以及 `instruction-craft.md` 里那条很实用的例子：

> ❌ "显示正常" —— **这类没法断言的写法要禁止**

## 4. 与骨架六小节的对应

六层（本篇）与六小节（`skeleton-template.md`）是同一件事的两种切法：

| 六层 | 六小节 |
|---|---|
| ① 目标 | （隐含在何时用里） |
| ② 输入 | Required inputs |
| ③ 流程 | Step-by-step procedures |
| ④ 输出格式 | Expected outputs |
| ⑤ 自检标准 | Definition of done |
| ⑥ FAQ | ⭐ Failure handling（部分） |

> ⭐ 差异在于：**六小节把"何时不用"和"失败处理"显式列为独立小节**，
> 而六层把"走偏了怎么回正"独立成 FAQ 层。
>
> **两者互补，可以合并着用**：
> 用六小节做骨架，用 FAQ 层补异常预案。
