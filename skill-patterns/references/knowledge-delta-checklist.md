## 1. ⭐ 元问题

> ⭐ **评估任何技能时，回到这个根本问题：
> "这个领域的专家看到这个技能，会说
> '是的，它抓住了我花好几年才学会的东西' 吗？"**

这一句是整套评估的锚点。

---

## 2. ⭐ 知识增量（最重要的一节）

```
[ ] ⭐ 没有对基础概念的 "What is X" 解释
[ ] ⭐ 没有对标准操作的分步教程
[ ] ⭐ 有针对非显然选择的决策树
[ ] ⭐ 有只有专家才知道的权衡
[ ] ⭐ 有来自真实经验的边界情况
```

> ⭐ 前两条是**排除项**——
> 解释"什么是 X"和教标准操作，模型本来就会，**写了就是浪费 token**。
>
> 后三条是**必含项**——它们才是技能存在的理由。

> 这与 `pruning.md` 的 no-op 测试互为表里：
> **能通过的都该删，删了会改变行为的才该留。**

---

## 3. 思维模式 + 流程

```
[ ] 传递思维模式（如何思考这类问题）
[ ] 有 "Before doing X, ask yourself..." 框架
[ ] 包含模型不会知道的领域专属流程
[ ] ⭐ 区分"有价值的流程"和"通用流程"
```

> 最后一条最关键：**通用流程（先读代码再改）不值得写**，
> 模型默认就会做。

---

## 4. 反模式

```
[ ] 有明确的 NEVER 清单
[ ] ⭐ 反模式是具体的，不是含糊的
[ ] ⭐ 包含 WHY（非显而易见的理由）
```

---

## 5. 规格（description 是核心）

```
[ ] 合法 YAML frontmatter
[ ] name: 小写、≤64 字符
[ ] description 回答：它做什么（WHAT）
[ ] description 回答：何时使用（WHEN）
[ ] ⭐ description 含触发关键词
[ ] ⭐ description 具体到让 agent 知道何时用
```

---

## 6. 结构

```
[ ] SKILL.md < 500 行（⭐ 理想 <300）
[ ] 重内容在 references/
[ ] ⭐ 加载触发嵌在工作流里
[ ] ⭐ 有 "Do NOT Load" 防止过度加载
```

---

## 7. 自由度

```
[ ] ⭐ 创意任务 → 高自由度（给原则）
[ ] ⭐ 脆弱操作 → 低自由度（精确脚本、无参数）
```

---

## 8. 可用性

```
[ ] 多路径场景有决策树
[ ] 有可运行的代码示例
[ ] 有错误处理与回退
[ ] 覆盖了边界情况
```

---

## 用法

这份清单可以直接当**评审 rubric** 用。
两类用法：

```
① 写完自查     —— 逐条打勾，前两大节优先
② 评审他人技能 —— ⭐ 前两大节任一条不满足，直接退回
```

> ⭐ 优先级：**知识增量 > 思维模式 > 反模式 > 规格 > 结构 > 自由度 > 可用性**
> 一个结构完美但没有知识增量的技能，等于零。
