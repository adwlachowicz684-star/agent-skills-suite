## 1. ⭐ 四种类型，四种测法

| 类型 | 测试方法 | 验证什么 |
|---|---|---|
| **Technique**（TDD、调试） | ⭐ 应用到问题 X 和**不寻常的问题 Y** | 产出正确步骤；**能正确适配** |
| **Pattern**（设计模式） | ⭐ 展示代码 X（匹配）和代码 Y（near-miss） | ⭐ 正确识别；**正确拒绝** |
| **Reference**（API 文档、清单） | 问 "X 的规则是什么" 和 "边界情况 Z 呢" | 找到正确答案；**处理知识缺口** |
| **Discipline**（安全审查） | ⭐ 先审正确代码，然后**在时间压力下再审一次** | ⭐ 干净代码能过；**压力下仍执行所有规则** |

> ⭐ 两个最值得抄的设计：
>
> **① Pattern 类必须测 near-miss**——
> 只测"该识别的能识别"不够，还要测"不该识别的会被拒绝"。
>
> **② Discipline 类要加时间压力**——
> 因为这类技能的失败模式恰恰是**赶工时跳过规则**。

## 2. 令牌效率目标（按类型）

| 症状 | 修法 |
|---|---|
| 散文写结构化信息 | ⭐ 改用表格 |
| 解释性段落 | ⭐ 改用简短祈使句 |
| 参考资料在正文 | 移到独立文件（按需加载） |
| 重复内容 | ⭐ 只说一次 |
| 代码示例 | ⭐ 只在模式非显然时才给 |

## 3. 十一条验证清单

```
1  frontmatter 有 name 和 description
2  ⭐ description 以 "Use when" 开头
3  概览是 2–3 句
4  ⭐ 阶段编号，且带 STOP 标记
5  ⭐ 有决策表（不是散文）
6  有反模式表
7  ⭐ 有反理性化守卫
8  有集成点表
9  有具体示例
10 ⭐ 声明了技能类型（RIGID / FLEXIBLE）
11 总行数 < 500
```

> 第 10 条很有意思：**声明技能自己是刚性还是柔性**——
> 这决定了模型该严格照做还是可以变通。

## 4. 按类型的行数目标

| 技能类型 | 目标行数 | 策略 |
|---|---|---|
| 上手型工作流 | < 100 行 | 最少步骤 |
| ⭐ 高频加载的技能 | < 200 行 | ⭐ 表格代替散文 |
| 综合参考型 | < 400 行 | 按阶段拆分 |
| **绝对上限** | **500 行** | 超出的一律移到独立文件 |

## 速查

| 类型 | 关键测试 |
|---|---|
| Technique | ⭐ 不寻常的问题也要对 |
| Pattern | ⭐ near-miss 必须被拒绝 |
| Reference | 边界情况 + 知识缺口 |
| ⭐ Discipline | ⭐ 时间压力下仍守规则 |

| 行 | 目标 |
|---|---|
| 上手工作流 | <100 |
| 高频加载 | <200 |
| 综合参考 | <400 |
| ⭐ 硬上限 | 500 |

**技能类型声明**：RIGID（严格照做）/ FLEXIBLE（可变通）——
**必须在技能里写明**，否则模型不知道该多严格。
