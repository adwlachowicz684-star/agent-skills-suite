## 1. ⭐⭐⭐⭐⭐ 一个真实形态

```
skill-A：输出不超过 30 行
skill-B：摘要控制在 30 行以内
skill-C：每段 ≤ 5 行，总计 ≤ 30 行
```

某天 A 的 30 被改成 25（有充分理由）。B 和 C 仍是 30。

```
交接时：A 说"合规"，B 说"超了"
```

> ⭐⭐⭐⭐⭐ **每个技能单独跑都是对的——没有一个会报错。**

---

## 2. ⭐⭐⭐⭐⭐ 为什么它不报错

三个环节全部沉默：

```
① 修改时：改 A 的人不知道 B、C 里也有这个数
② 运行时：每个技能只按自己那份执行，内部完全自洽
③ 冲突时：⭐⭐⭐⭐⭐ 冲突发生在两个技能之间，
          而没有任何环节会把两份技能放在一起读
```

> ⭐⭐⭐⭐⭐ 这是"静默失败"里最容易被漏的一种，
> 因为它连"局部成功"都不是——**每个局部都完全成功**。

---

## 3. ⭐⭐⭐⭐⭐ 与"沉积"的关系：检测手段失效

| | 沉积 | 本份 |
|---|---|---|
| 位置 | ⭐⭐⭐ 同一文件内 | ⭐⭐⭐⭐⭐ 跨文件 |
| 形态 | 新旧内容互相矛盾 | 同一个值的多个副本不一致 |
| 检测 | ⭐⭐⭐⭐ 把所有提到同一件事的地方放在一起看 | ⭐⭐⭐⭐⭐ 这个手段失效 |

失效的两个原因：

```
① ⭐⭐⭐⭐⭐ grep 数值会命中大量无关内容（"30 行"也可能是别的意思）
② ⭐⭐⭐⭐⭐ 两份文件永远不会被同一次阅读覆盖——
   渐进式披露决定了模型一次只加载一份技能
```

> ⭐⭐⭐⭐⭐ **所以它不是"没检查"，是"结构上无法被检查"。**
> 唯一的出路是改成"一处定义、多处引用"，让检查有地方可查。

---

## 4. ⭐⭐⭐⭐⭐ 判定：什么该外置

一句话：

> ⭐⭐⭐⭐⭐ **这个数字/规则，会在两个以上技能里出现吗？会 → 它是共享约定，不该内联。**

反过来说：只在一个技能里用的数字，外置反而增加跳转成本（且违背"技能自包含"）。

```
✅ 外置：跨技能一致才有意义的（合规阈值、格式、枚举）
❌ 不外置：只在本文上下文中成立的（这个接口的 30s 超时）
```

---

## 5. ⭐⭐⭐⭐⭐ 三类该外置的东西

```
① ⭐⭐⭐⭐⭐ 阈值与上限 —— 行数、超时、重试次数、并发数、置信度档位
② ⭐⭐⭐⭐⭐ 分类体系 —— 严重程度三档、状态枚举、错误码
③ ⭐⭐⭐⭐ 命名与格式 —— 日期格式、ID 前缀、状态字段名、产物目录名
```

第二类最容易被忽略，也最致命：

```
A 技能输出 {"severity": "high"}
B 技能期望 {"severity": "P0"}
```

> ⭐⭐⭐⭐⭐ 两边都在用一个叫 severity 的字段，
> 值域不同，而⭐⭐⭐⭐ 交接时不会报错——它是合法 JSON、合法字符串。

---

## 6. ⭐⭐⭐⭐⭐ 修法：canonical + 引用（且引用要带当前值）

```
❌ "长度限制见 conventions.md"
✅ "输出 ≤ 30 行（以 skill-output/references/output-length-budget.md 为准）"
```

> ⭐⭐⭐⭐⭐ **引用时必须把当前值也写出来。**
> 理由不是"方便"，是加载机制：

```
⭐⭐⭐⭐ 渐进式披露意味着被引用那份文档不一定已加载
→ 只给链接 = 触发时这个值不存在
→ ⭐⭐⭐⭐⭐ 等于把"值"换成了"一次可能不发生的跳转"
```

这与 `skill-content/references/external-links-in-skills.md` 的"链接 + 摘要"是同一条原则：
摘要（这里是当前值）在本地，链接只用于追溯。

---

## 7. ⭐⭐⭐⭐⭐ 校验：把规则编码成脚本

```python
CANON = {"max_output_lines": 30, "retry_max": 3, "severity_levels": ["high","mid","low"]}
# grep 所有技能中这些值的出现处，与 CANON 比对，不等则 CI 失败
```

最低成本版本（一行就能用）：

```bash
grep -rn "30 行\|≤ 30\|不超过 30" skill-*/references/*.md | wc -l
```

> ⭐⭐⭐⭐⭐ **出现次数 > 1 就该人工确认。**
> 又一次把书面规则编码成校验器——
> 与"含糊词 grep 阈值设为 0"、"名字含 deploy 强制 disable-model-invocation"同手法。

---

## 8. ⭐⭐⭐⭐ 例外：Gotchas 里的数字不外置

```
"这个接口在月结期间静默返回上个月数据（超时 30s）"
```

> ⭐⭐⭐⭐⭐ 这类数字是**不可推理的个案**，它的价值恰恰在于和具体上下文绑在一起。
> 外置后读的人只看到"30s"，看不到"月结期间"——
> ⭐⭐⭐⭐ 于是它退化成一个无出处数字（违反 `skill-precision/references/unjustified-numbers.md`）。

判据：**这个数字脱离本段还有意义吗？** 没有 → 不外置。

## 9. ⭐⭐⭐⭐ 自检

| 问 | 动作 |
|---|---|
| ⭐⭐⭐⭐⭐ 这个数字在几个技能里出现？ | >1 → 立 canonical |
| ⭐⭐⭐⭐⭐ 引用处有没有写出当前值？ | 只写链接 → 补上值 |
| ⭐⭐⭐⭐ 分类体系在几个技能里各定义了一次？ | >1 → 合并 |
| ⭐⭐⭐⭐ 有没有一行脚本能断言一致性？ | 没有 → 写进 CI |
| ⭐⭐⭐ 这个数字脱离本段还有意义吗？ | 没有 → 不外置（Gotchas 类） |

## 速查

```
□ ⭐⭐⭐⭐⭐ 每个技能单独跑都对 → 冲突只在技能之间，且没有任何环节会同时读两份
□ ⭐⭐⭐⭐⭐ 渐进式披露决定了跨文件不一致"结构上无法被检查"
□ ⭐⭐⭐⭐⭐ 判据：会在两个以上技能里出现吗？会 → 共享约定，不该内联
□ ⭐⭐⭐⭐⭐ 三类该外置：阈值上限 / 分类体系 / 命名格式
□ ⭐⭐⭐⭐⭐ 引用必须带当前值：跳转是下一层，触发时不一定已加载
□ ⭐⭐⭐⭐⭐ severity 值域不一致是合法 JSON 的静默失败
□ ⭐⭐⭐⭐⭐ grep 出现次数 > 1 就该确认；把一致性写进 CI
□ ⭐⭐⭐⭐ 例外：Gotchas 里的数字不外置（脱离上下文就变成无出处数字）
□ ⭐⭐⭐⭐ 关系：unjustified-numbers 要求"每个数字有出处"；
           本份要求"同一个数字只有一个出处"
```

**一句话**：

> ⭐⭐⭐⭐⭐ **同一个阈值复制到三个技能里，改了其中一个，另外两个不会报错——因为每个技能单独跑都完全自洽，冲突只发生在技能之间，而渐进式披露决定了没有任何环节会同时读两份。修法不是"记得同步"，是立一个 canonical 并让其余处引用：引用时必须把当前值也写出来，因为被引用那份文档在触发时不一定已加载，只给链接等于把值换成了一次可能不发生的跳转。**
