## 硬数字

多个来源口径略有出入，共识区间很清楚：

| 文件 | 理想 | 可接受 | 硬上限 |
|---|---|---|---|
| **`SKILL.md`** | **100–150 行** | 60–300 行 | **500 行** |
| `references/*.md` | 100–300 行 | — | 300 行（另一口径 500） |
| `examples/*` | — | — | 200 行 |
| `scripts/*` | — | — | 200 行 |

**可执行规则**：

```
理想 100–150 行
可接受 60–300 行
硬上限 500 行 —— 到了就拆分
```

**低于下限也不行**：太短则缺乏模型保持一致所需的**具体性**。

## 为什么 500 行是上限

不是拍脑袋，是物理边界：

```
技能正文重新注入时：每技能上限 5,000 tokens，总 25,000
上限按字符算：chars / 4
→ 5,000 × 4 = 20,000 字符阈值
→ 每行约 40 字符 → 500 行 ≈ 20,000 字符
```

> 超过就**截断**，而**截断保头不保尾**——所以承重指令必须放顶部。

## 该放哪里

| 内容类型 | 去向 |
|---|---|
| 触发条件、何时用 | **留在 SKILL.md** |
| 快速参考、关键命令 | **留在 SKILL.md** |
| 2–3 个核心示例 | **留在 SKILL.md** |
| 长篇解释 | → `references/` |
| API 文档 | → `references/` |
| 历史背景 | → `references/` |
| 大段代码 | → `scripts/` |
| 10+ 个示例 | → `references/examples.md` |

> **原则：SKILL.md 是目录和入口，不是全部内容。**

## 三条结构纪律

**① 一层引用深度**

> 所有引用文件**最好直接由 SKILL.md 链接**，保持一层深度，
> **避免链式引用（A → B → C）**，防止模型只读到部分内容。

**② 长文件加目录**

> **超过 100 行**的参考文件，顶部加目录（Table of Contents），
> 帮助模型快速了解结构。

**③ 别塞大二进制**

> 一个技能文件夹里带个 2 MB 二进制，那是个**没人会装的技能**——
> clone 慢，而且**信任信号是错的**。

## 运行时真相

**压缩不是恢复，是部分重建**。长会话里：

| 内容 | 压缩后 |
|---|---|
| 项目根 CLAUDE.md | ✅ 从磁盘重新注入 |
| 带 `paths:` 的规则 | ❌ **丢失**，直到再读到匹配文件 |
| 嵌套 CLAUDE.md | ❌ **丢失** |
| **技能清单** | ❌ **不重新注入**——只有真正调用过的存活 |
| 已调用技能正文 | ⚠️ 重新注入，按上述上限，最旧的先丢 |

**四个落地结论**：

1. **截断保头不保尾** → 承重指令放顶部
2. **按字符算不按 token 算** → 用 `wc -m` 量，阈值 19,900 字符
3. **拥有目录的技能才可恢复** → 单文件命令被截断后没有任何位置信息
4. 上下文用到 **20–40%** 时质量就开始打折 → "压缩后依然差"是因为**压缩前就退化完了**

## 与数据分离

> **技能定义怎么做（how），数据文件定义做什么（what）。**

```
milestone-manager/
├── SKILL.md              ← 操作逻辑（稳定，跨项目复用）
└── data/
    └── ms-config.json    ← 项目参数（随项目变）
```

**好处**：换项目只换数据文件，技能逻辑原样搬走。

> **技能里不该出现"8 周""7/19""5 人"这种具体数字——它们都是参数。**

## 自查

```
□ SKILL.md 是否在 500 行以内？（wc -l）
□ 是否在 100–150 行的理想区间？
□ 是否有超过 300 行的 references 文件？
□ 是否有超过 100 行但没加目录的 reference？
□ 是否存在 A → B → C 的链式引用？
□ 文件夹里有没有大二进制？
□ 长解释、API 文档、历史背景是否都移走了？
□ 确定性逻辑是否都在 scripts/ 里？
□ 是否有写死的、本该是参数的具体值？
```
