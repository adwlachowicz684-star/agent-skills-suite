## 翻译什么、不翻译什么

| 元素 | 处理 | 原因 |
|---|---|---|
| `name` | ❌ **不翻译** | 它是标识符 |
| `description` | ✅ **翻译** | 它是路由依据——见下 |
| 正文指令 | ✅ 翻译 | 给人读 |
| 文件路径（`scripts/`、`references/`） | ❌ 不翻译 | 会被解析 |
| 命令名（`/skill-i18n`、`git push`） | ❌ 不翻译 | 会被解析 |
| 技术标识符（变量名、JSON 键） | ❌ 不翻译 | 会被解析 |
| URL 与链接 | ❌ 不翻译 | 会被解析 |
| 代码块 | ⚠️ **谨慎** | 见下 |

> ⭐ **最关键的一条**：
> **`description` 必须翻译**——
> 因为匹配是拿它和**用户请求的表述**比的。
> 你在英文 description 里写满英文触发词，
> 中文用户用中文提问时**根本匹配不上**。

## frontmatter 怎么处理

```yaml
---
name: port-allocator        # ← 保持不变（标识符）
description: 翻译这个        # ← 翻译成目标语言
---
```

> ⚠️ **一个真实陷阱**：
> 翻译 `description` 时不要逐字硬译，
> 要**按目标语言里用户实际会怎么说**来重写触发词。
> 这呼应 《skill-description》的 `frontmatter.md` 里的铁律——
> **匹配发生在传入请求的表述上，不是你的内部命名上**。

## 风格适配

不同语言的视觉风格惯例不同：

| 语言 | Emoji 使用 | 示例 |
|---|---|---|
| 中文 (zh-CN) | **常见** | ✅ 正确 / ❌ 错误 |
| 日语 (ja) | **极少** | 正しい / 間違い |
| 韩语 (ko) | 中等 | ✅ 올바름 / ❌ 잘못됨 |
| 西语 (es) | 极少 | Correcto / Incorrecto |

**敬语层级**：

```
日语  礼貌体（です/ます）
中文  标准书面语
韩语  礼貌体（합니다/습니다）
西语  正式 usted 形式
```

**自然翻译**：

```
□ 按目标语言调整句子结构，不要保留源语言的句法
□ 使用恰当的正式程度
□ 适当本地化示例（人名、地名、货币、日期格式）
□ 如果项目里已有翻译惯例，遵循它
```

## 增量更新与安全

```
□ ⚠️ 绝不覆盖源 SKILL.md
□ 只在源文件比译文新时才翻译（增量更新）
□ 检测到已有译文时给出选项：
   覆盖全部 / 跳过已有 / 逐个选择
□ 每个技能可以有自己的语言配置
□ 首次翻译需要用户选择语言
□ 支持命令行 flag，便于其他技能调用
```

**生成的文件命名**：

```
SKILL.zh-CN.md（简体中文）
SKILL.ja.md（日本語）
```

> ⚠️ 注意：这些是**译文**，不是技能本体。
> **只有 `SKILL.md` 会被识别为技能入口**——
> 译文文件不会被加载（呼应 `skill-crafting` 的 `skill-structuring` 的 `directory-contract.md`）。

## 给非中文读者的三条

> 如果你在把**中文技能**翻译成英文，或反之，注意这三点：

**① 中文触发词比英文精确**

```
"写 commit" 在中文里没有歧义。
这让中文 description 的路由更锐利。
```

**② 但中文日常表达更丰富**

> ⭐ **这是中文场景最大的劣势**：
> 同一件事至少有五种说法。

```
铁律：把所有你和同事会说的说法都写进 description。
漏掉一个常用说法，用户就觉得"技能不灵"。
```

**③ 客套表达等于没有约束**

```
❌ "尽量遵守" "酌情处理" "应该会"
✅ "必须" "禁止" "不得"

中文里的"尽量""酌情"对模型等于没有约束
——它不会因此更努力，只会因此有借口。
```

## 自查

```
□ name 是否保持了原样（未翻译）？
□ description 是否翻译了，且按目标语言的用户表述重写了触发词？
□ 路径、命令名、技术标识符、URL 是否都没动？
□ 代码块是否保持了可运行（未破坏语法/编码）？
□ emoji 与敬语是否符合目标语言惯例？
□ 是否遵循了项目已有的翻译惯例？
□ 增量更新逻辑是否基于"源文件比译文新"？
□ 是否保证了绝不覆盖源 SKILL.md？
□ 中文译文是否把常见说法都覆盖进了 description？
□ 是否清除了"尽量/酌情"这类无约束力的客套表达？
```
