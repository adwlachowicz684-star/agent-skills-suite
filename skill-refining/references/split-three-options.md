## 1. 拆分信号

```
· SKILL.md 超过 500 行
· ⭐ 功能模块明显各管各的
· 正文超过 1,000 行 → 必须拆
```

**拆的原则**：

> ⭐ **干活的各自为战，主技能只排流程。**

---

## 2. ⭐ 三种拆法

**方案一：按子主题拆**

```
react-hooks/               →  react-state-hooks/
  SKILL.md（太大）              SKILL.md（useState, useReducer）
                              react-effect-hooks/
                                SKILL.md（useEffect, useLayoutEffect）
                              react-custom-hooks/
                                SKILL.md（创建自定义 hook）
```

**方案二：按层级拆**

```
django/                    →  django-basics/
  SKILL.md（太综合）            SKILL.md（上手）
                              django-advanced/
                                SKILL.md（高级模式）
```

**方案三：抽参考资料（最常用）**

```
api-guide/                 →  api-guide/
  SKILL.md（巨大）              SKILL.md（简明概览）
                              reference.md（详细 API 文档）
                              examples.md（代码示例）
```

> ⭐ 方案三最省事，因为它不增加技能数量，
> 只是把 L2 的内容移到 L3——**不引入新的路由决策**。

---

## 3. ⭐ 别过度拆

> ⭐ **不要过度拆分，因为近乎重复的描述会让选择变混乱。**
>
> ⭐ **沿着工作的接缝拆。一个流程或知识领域一个技能。**

理由与 `library-size-effect.md` 一致——
**拆得越细，描述越相近，遮蔽越严重**。

**另一条实证**：

```
SkillsBench（2026，11 领域 86 任务）：
  ⭐ 2–3 个模块的聚焦技能 > 单个综合大文件
```

> ⭐ 也就是说：**拆是对的，但拆成 2–3 个模块就够了，
> 不要拆成 20 个。**

---

## 4. ⭐ 一个看起来像技能问题、其实不是的情况

> ⭐ **如果你是因为"两个角色需要它的不同两半"而想拆文件，
> ⭐ 那工作本身已经是分开的了，是这个文件在假装它是一体的。**
>
> **给每个角色各自的技能，
> 让共享的工艺放在"圈层"级别，两边都能取用。**

判据很实用：

```
拆的动机是"内容太多"  → 拆文件（方案三）
拆的动机是"两个角色各用一半" → ⭐ 拆成两个角色的技能 + 共享层
```

> ⭐ 这与 `gamedev-skill-routing.md` 的三维正交设计同源——
> **引擎技能 / 学科技能 / 类型技能**，共享原语放在能被两边取用的层。

---

## 拆后必做的三件事

```
① ⭐ 更新交叉引用（双向）
② ⭐ 更新注册表计数
③ ⭐ git diff 确认没有意外删除原内容
```

> ⭐ 第 ③ 条最容易被漏——
> 拆的时候手快删多了，等发现时已经提交。

## 速查

```
拆分信号：
□ >500 行
□ 功能模块各管各
□ >1000 行必须拆

三种拆法：
□ 按子主题（横向）
□ 按层级（basics / advanced）
□ ⭐ 抽参考资料（最省事，不增路由决策）

约束：
□ ⭐ 别过度拆——近似描述导致选择混乱
□ ⭐ 拆成 2–3 个模块就够
□ ⭐ "两个角色各用一半" → 拆成角色技能 + 共享层（不是拆文件）

拆后：
□ 双向交叉引用
□ 更新注册表计数
□ ⭐ git diff 确认无意外删除
```

**一句话**：

> ⭐ **沿着工作的接缝拆，不要沿着目录的方便拆。**
