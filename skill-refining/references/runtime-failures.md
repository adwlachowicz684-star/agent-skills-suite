# 三类运行时故障：慢、无限循环、上下文溢出

> 技能写得对，但跑起来出问题——这三类占了绝大多数。
> 每类的**根因都不在技能内容本身**。

## 故障一：响应慢

**三个根因**：

```
1. 技能正文过大——每次调用都要全量处理
2. 技能串联了太多顺序的工具调用
3. 技能加载了耗时的外部数据
```

**对应修法**：

```
1. ⭐ 拆分成聚焦的子技能
2. 减少每轮加载的上下文量
3. 在技能逻辑允许的地方改用并行工具调用
```

> 呼应 `context-budget.md`（**`skill-refining`**）与
> `performance.md`（**`skill-selection`**）。

## 故障二：无限循环

> ⭐ **这是逻辑错误，不是性能问题**：
> 技能让 agent 重试直到成功，但**没设最大重试次数或兜底退出条件**。

agent 会无限重试，消耗 token 且产出不了任何有用结果。

```markdown
# ❌
重试该操作直到成功。

# ✅
最多重试 3 次；仍失败则把错误返回给用户，
并附上已尝试的命令与原始输出。
```

**规则**：

```
□ ⭐ 任何重试/循环/批量都必须声明终止条件与上限
□ 循环要有兜底退出路径（失败后做什么，不是一直试）
□ 见过跑满 200 次烧光 token 的生产事故
```

## 故障三：上下文溢出

**症状**：处理大量文件或长对话时表现退化——
丢掉早期指令、丢失任务状态，或直接报 context overflow。

**四种预防策略**（按有效性排序）：

```
1. ⭐ 保持技能正文精简
   ——技能文件每个字节从第一个 token 起就计入上下文预算

2. ⭐ 用渐进式披露
   ——顶部简略，详细部分只在需要时加载

3. ⭐ 激进地做摘要
   ——长工具输出回灌上下文前先压缩
   实测：10,000 token 的数据库查询结果通常能压成 200 token 的相关数据

4. ⭐ 状态外置
   ——中间结果写到文件或数据库，按路径引用
   不要把全部任务状态留在对话里
```

第 3 条的数字值得记住：**10,000 → 200，压缩比 50:1**。
长工具输出不摘要就直接回灌，是上下文最快见底的方式。

**还有一个经验值**：

```
同时启用的技能过多时（经验上 20–50 个）要做分组与裁剪
```

呼应 `scale-effects.md`（**`skill-governance`**）——
1,236 个技能实测吃掉 36.6% 上下文。

## 第四类：输出与状态

**输出格式坏掉**：

```
症状：技能要求特定输出结构，但没给足够明确的指令
修法：指定确切格式（JSON schema / Markdown 表格 / 纯文本）
     ⭐ 而不是含糊描述
     冲突时加硬规则：
     "始终返回符合此 schema 的 JSON 对象。JSON 块外不要加任何散文。"
```

**会话间状态丢失**：

> ⭐ **这不是 bug，是设计如此**——
> Claude 不在会话间持久保存内存状态。

需要状态（任务列表、用户偏好、累积数据）就必须**外置**：

```
□ 本地文件
□ 数据库
□ 持久 MCP memory server
```

技能在每次会话开始/结束时读写这个外部存储。

## 排查顺序

```
1. 慢        → 拆子技能 · 减少每轮上下文 · 并行化
2. 无限循环   → 加最大次数 + 兜底退出
3. 上下文溢出 → 精简正文 · 渐进式披露 · 摘要 · 状态外置
4. 输出格式坏 → 给确切 schema + 硬规则
5. 状态丢失   → 外置存储（不是 bug）
```

## 自查

- [ ] 正文超过 150 行了吗？（→ 慢）
- [ ] 有顺序工具调用可以并行吗？（→ 慢）
- [ ] 每个重试都有最大次数和兜底路径吗？（→ 无限循环）
- [ ] 长工具输出回灌前做了摘要吗？（→ 溢出）
- [ ] 任务状态有没有外置？（→ 溢出 + 状态丢失）
- [ ] 输出格式给了确切 schema 还是散文描述？（→ 输出坏）
- [ ] 同时启用的技能超过 20 个了吗？（→ 分组裁剪）
