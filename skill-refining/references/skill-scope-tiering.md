## 1. ⭐ 核心原则

> ⭐⭐ **"不盲目删除，只调整作用域"**——
> 避免误删关键能力后返工。

这个原则很值得记住，因为它跟常见的"清理"直觉相反：
**多数人的第一反应是删掉不用的，而这里的做法是改变它何时生效。**

理由很实在：删错了要返工，而改作用域是可逆的。

---

## 2. 四类分级与生效策略

按**使用频率与重要性**将技能分四类：

| 级别 | 生效范围 | 说明 |
|---|---|---|
| ⭐ 高频核心 | 全局常驻 | 服务日常高频任务 |
| 中频项目类 | ⭐ 仅在对应项目生效 | 不占全局上下文 |
| ⭐ 低频长期未用 | ⭐ 转为"触发空壳" | 几乎不占启动 token |
| 特殊关键 | 特殊处理 | — |

> ⭐ 中频那类的处理最容易被忽略：
> **项目级技能不该占全局上下文**——这是个纯粹的浪费，且没人注意到。

---

## 3. ⭐⭐ 触发空壳

> ⭐ **低频技能不直接删除，而是转为"触发空壳"状态：**
> 仅保留
> ```
> 2–5 个自然语言触发词
> 能力摘要
> ⭐ 恢复路径
> ```
> **几乎不占用启动 Token。**

```
⭐ 转为触发模式后，单个技能可减少约 89% 的启动上下文开销
```

> ⭐⭐ **"恢复路径"这一条是这类设计的关键**：
> 空壳不是墓碑，它必须告诉你**怎么把它变回完整形态**。
>
> 没有恢复路径的空壳 = 变相删除，只是没人承认。

**底层机制**：基于技能的两阶段加载

```
启动时仅加载简介（占启动上下文）
命中调用才读取完整文档
```

**配套工具**：本地可视化控制台（Skill Scope Console）

```
按来源、用途、使用频率多维度筛选
⭐ 直观展示每个技能的三项数据：
   全局占用 Token · 归档后占用 Token · 调用后占用 Token
方便手动调整策略
```

> ⭐ "三项数据并列展示"这个设计很好——
> **让你一眼看见"降级能省多少、调用时又要花多少"**，
> 而不是只看一个静态数字。

## 4. 治理结果

```
318 个唯一技能 ⭐ 全部保留，无一个被直接删除
仅调整生效范围：
   核心全局   29 个
   保守全局   118 个
   项目级     14 个
   ⭐ 触发级   157 个   ← 最多的一类
   特殊关键   24 个
```

**成效**：

```
功能完整度不变
大幅削减无效上下文占用 + 降低 token 成本
⭐⭐ "减少了信息噪音，模型决策效率反而得到提升"
```

> ⭐ 最后那条又一次印证 `skill-reducer-study.md` 的"少即是多"：
> **削减噪音不只省钱，还让模型决策更准。**

## 5. ⭐ 一条行业佐证

```
⭐ Claude 团队已主动删减 80% 的系统提示语
   新一代模型智能度足够，⭐ 堆砌规则反而会拖累表现
```

> ⭐ 这条把上面的实践上升到行业趋势：
> **模型越强，堆规则的边际收益越低、边际危害越高。**

## 速查

```
□ ⭐⭐ 原则："不盲目删除，只调整作用域"——删错要返工，改作用域可逆
□ 分级：高频全局 / 中频项目级 / ⭐ 低频触发空壳 / 特殊关键
□ ⭐ 中频项目类不该占全局上下文（常被忽略的纯浪费）

⭐⭐ 触发空壳：
□ 只留 2–5 个触发词 + 能力摘要 + ⭐ 恢复路径
□ ⭐ 单技能减少约 89% 启动上下文
□ ⭐⭐ 没有恢复路径的空壳 = 变相删除
□ 基于两阶段加载：启动只加载简介，命中才读全文

□ 控制台展示三项数据：全局占用 / 归档后占用 / 调用后占用
□ 318 个技能全部保留，157 个转触发级
□ ⭐ 减少噪音 → 模型决策效率反而提升
□ ⭐ 行业佐证：Claude 团队删减 80% 系统提示语
```
