## 1. ⭐⭐ 少即是多

> ⭐⭐ **论文发现了一个反直觉现象：
> 压缩后的技能不仅 token 更少，⭐ 功能质量反而提升了 2.8%。**

**原因**：

```
⭐ 移除非必要内容减少了上下文窗口中的"干扰"（distraction），
   让 agent 更专注于核心指令。
```

> ⭐⭐ 这给"瘦身"提供了全新的理由——**以前瘦身是为了省钱，
> 现在有了第二个理由：⭐ 瘦身本身能提升质量。**

这与 `skillsbench-vs-realworld.md` 的两条数据互相印证：

```
· "全面"型详尽文档 −2.9pp（有害），"详细"型 +18.8pp
· 无关技能会主动伤害弱模型（消耗 token 去遵循无用指令）
```

三条来自不同来源的证据，指向同一个结论：**多余的内容是负资产，不只是浪费。**

## 2. 阶段 1：路由描述压缩

**方法（值得抄的是它的验证回路）**：

```
① 收集能触发原始技能的查询集合
② 用压缩后的描述测试
③ ⭐ 若存在触发失败，则从已删除的子句中"贪婪地恢复"
   最能提升触发率的那一条
④ 直到所有查询均能正确触发
```

> ⭐ 第 ③ 步是这个方法最妙的地方：
> **不是压缩完就结束，而是用查询集做回归，按贡献度逐条回补。**
>
> 这跟 `assert-on-environment.md` 的"同步校验断言本身"一样——
> **对优化动作本身做验证**。

## 3. ⭐ 阶段 2：主体重构（渐进式披露）

把单体架构技能自动转成分层架构：**核心内容常驻，补充内容按需加载**。

**① 分类驱动的内容拆分**

对技能主体做段落级自动标注，分成五类：

```
核心规则  → ⭐ 保留在常驻核心模块
背景     → 转为按需加载模块
示例     → 转为按需加载模块
模板     → 转为按需加载模块
冗余     → ⭐ 直接删除
```

**② 不同分类做定制化压缩**

```
核心规则   语义合并与精简
示例/模板  ⭐ 按概念去重，仅保留代表性内容
背景      精准摘要
⭐ 外部引用文件与主体之间的跨文件去重
⭐ 为保留的引用添加"触发条件、主题关键词"等路由元数据
```

> ⭐ 最后一条特别有价值：**给 reference 文件加路由元数据**。
> 这与 `references-vs-assets.md` / `reference-file-practices.md` 的分层思路一致，
> 但更进了一步——**不只说"按需读"，还为每个文件写明"什么时候读它"**。

## 4. ⭐ 双机制验证与回滚

**忠实性验证**：

```
校验压缩后内容是否完整保留了原技能的所有核心操作概念
⭐ 失败则回滚对应内容类型
```

**任务化功能评估**：

```
为每个技能生成 5 类测试任务
⭐ 双机制验证：代码执行断言 + LLM 评审
⭐ 对于失败任务，自动识别并将必要的非核心内容"提升"为常驻核心
⭐ 最多 2 轮迭代，确保功能不退化
```

> ⭐ "将非核心内容提升为核心"这一步是关键：
> **说明压缩不是单向的**——它承认"我可能压错了"，并有一条回补路径。

这与阶段 1 的"贪婪回补"是同一种思路：**优化动作必须配回滚回路**。

## 5. 压缩率数字

```
路由描述：平均 48% 压缩率
         ⭐ 已有完整描述的技能压缩率达 56.5%

技能主体：平均 39% 压缩率，单技能平均节省约 1000 token
         SkillsBench 基准上主体压缩率 75%
         ⭐ 野生技能核心主体平均压缩率 77.5%
         ⭐⭐ 超大技能（>10K token）核心主体压缩率可达 95.8%
```

**端到端**：

```
600 个技能中实现 86% 通过率（⭐ 压缩提高了性能）
迁移到四个家族的五个模型上，平均保留率 0.965
独立 agent 框架上保留率 0.944
```

> ⭐⭐ **"超大技能压缩率 95.8%"这个数字要单独记住**：
> 说明**越臃肿的技能，冗余占比越高**——
> 一个 10K token 的技能里有 9.5K 是可以拿掉的。
>
> 这也解释了为什么"长度依赖模式"明显：**越长的技能越值得压。**

## 速查

```
⭐⭐ 核心发现：
□ ⭐ 压缩后功能质量⭐ 反升 2.8%（不只是省钱）
□ ⭐ 原因：减少"干扰"，让 agent 更专注核心指令
□ 与 "全面型文档 −2.9pp"、"无关技能伤害弱模型" 同源

阶段 1 描述压缩：
□ 收集触发查询集 → 压缩 → ⭐ 按贡献度贪婪回补 → 全部通过
□ ⭐ 对优化动作本身做验证

阶段 2 主体重构：
□ 段落分五类：核心规则/背景/示例/模板/冗余
□ ⭐ 冗余直接删；其余转按需加载
□ 示例模板⭐ 按概念去重；背景做摘要
□ ⭐ 跨文件去重 + ⭐ 为引用文件加路由元数据

验证：
□ 忠实性验证（核心概念是否全保留）→ 失败回滚
□ ⭐ 双机制：代码断言 + LLM 评审
□ ⭐ 失败任务 → 把必要内容"提升"回核心，最多 2 轮

压缩率：
□ 描述 48%（已有完整描述的 56.5%）
□ 主体 39%，单技能省约 1000 token
□ ⭐ 野生技能 77.5%；⭐⭐ >10K token 的技能达 95.8%
□ 600 技能 86% 通过率；跨五模型保留率 0.965
```

**一句话**：

> ⭐⭐ **一个 10K token 的技能里，有 9.5K 是可以拿掉的——
> 而拿掉之后它不只是更便宜，还更好用（+2.8%）。**
