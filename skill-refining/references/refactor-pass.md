## 先分清"表现"与"行为"

这是重构的核心纪律：

```
表现（可以改）
  · 措辞、语气、冗余
  · 结构、顺序（为了清晰）
  · ⭐ 把内容移到 references/

行为（不能改）
  · ⭐ 工作流步骤的集合
  · ⭐ 任何显式的 must / do not / never
  · frontmatter 的 allowed-tools
  · 必需的产物路径、命名约定、输出格式
  · ⭐ description 的触发范围
  · 记录边界情况的示例
```

> ⭐ **拿不准是表现还是行为时，先问用户。**

一条特别容易踩的：**description 可以 sharpen 措辞，
但绝不能收窄或放宽匹配范围**。
改了触发范围等于改变了"这个技能什么时候用"——
那是行为，不是表现。

## 六步流程

```
① 盘点    Inventory
② 通读    Read in full
③ 诊断    Diagnose
④ 计划    Diff plan
⑤ 应用    Apply
⑥ 验证    Verify + Report
```

## 每步的产出

**① 盘点**

```
git status --porcelain
编辑/写入历史
列出候选文件及其行数
过滤：只看作用域内的 .md / .tmpl / .prompt
```

产出：**候选文件清单 + 行数**

**② 通读**

```
⭐ 完整读每个文件（不要只看 diff）
记下 frontmatter 的用途与结构划分
```

产出：**每个文件的结构笔记**

> ⭐ "完整读"不能省——
> 只看 diff 会错过"新内容和旧有的某段重复了"这类问题。

**③ 诊断**

```
对着坏味道清单走一遍（见 skill-smells.md）
标记命中项
```

**④ ⭐ Diff plan（这一步不要动手改）**

```
对每个文件，列出启发式违规：
  格式：启发式 → 位置 → 建议改动
  ⭐ 一条 bullet 一个违规

不要写重写版本
⭐ 给用户看 diff 计划，问是否有条目跨越行为线
等待批准
```

> ⭐ **"先出计划再动手"是这一步的全部意义**——
> 让你和用户有机会在改动发生前判断"这是不是行为改动"。

**⑤ 应用**

```
⭐ 用 Edit 逐处修改，不用 Write 整体重写
```

**⑥ 验证与报告**（见下）

## 为什么用 Edit 不用 Write

> ⭐ **最小 diff 可审查；整体重写会藏住回归。**

理由很实际：

```
Write 整体重写
  → reviewer 看到的是一份新文件
  → ⭐ 无法回答"和之前有什么不同"

Edit 逐处修改
  → 每处改动都是可理解的
  → ⭐ 不小心删掉一行会立刻被看到
```

## 验证行为未变

改完后**重新通读每个文件**，逐项确认：

```
[ ] ⭐ 工作流步骤 —— 没删、没增、没合并
     （可以重命名或重排以求清晰）
[ ] ⭐ 规则 —— must / do not / never 一条没丢
[ ] allowed-tools —— 与之前一致
[ ] 产物路径、命名、输出格式 —— 与之前一致
[ ] ⭐ 触发条件 —— 读起来依然匹配同样范围的请求
[ ] 边界示例 —— 都还在
```

> ⭐ **`触发条件必须"读起来"一致**，不只是"字段还在"。
> 你可以 sharpen 措辞让它更好触发，
> 但不能让它开始匹配以前不匹配的请求（反之亦然）。

## 报告要说什么

```
每个文件：
  · 改动前 → 改动后 行数
  · ⭐ 关键收益（不只是"更短了"）

行为保留声明：
  · 工作流步骤、规则、allowed-tools、触发条件均未变

⭐ 哪些文件没动，以及为什么
```

最后一条值得强调：

> ⭐ **沉默的不作为容易被误认为遗漏。**
> 明确说"这个文件已经够紧了，所以没动"
> 或"改它会跨越行为线，所以没动"，
> 是把决策权交回给用户。

## 一个配套的长期建议

重构之后立刻做两件事：

```
① ⭐ 建 eval 集（如果之前没有）
   ——把这次重构确认的行为锁下来

② 记下重构的理由
   ——否则半年后有人会再重构一遍，
     并且很可能改回原样
```

> 第 ② 条不是形式主义：
> **没有记录理由的重构，会变成来回摆动。**

## 什么时候不该重构

```
❌ 技能还在频繁变化中     ——先稳定，再重构
❌ ⭐ 没有 eval 兜底      ——你无法确认行为没变
❌ 只是"看起来不够新"     ——不是重构理由
```

第二条最关键：**没有 eval 的重构是在赌**——
你靠通读来确认行为未变，而通读会漏。
