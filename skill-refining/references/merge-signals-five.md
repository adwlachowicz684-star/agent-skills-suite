## 1. ⭐⭐⭐⭐⭐ 单向棘轮

拆分的理由我们收集了很多，而且都很具体：

```
重启测试 · 双向无知 · 独立业务动作 · 权限集合不同 ·
description 里"或"出现两次 · SKILL.md 超 500 行
```

> ⭐⭐⭐⭐⭐ **而合并的理由，一条也没被系统地写过。**
> 结果就是一个单向棘轮：**任何系统只有拆分判据时，
> 它会持续拆分，因为拆分永远有理由，而合并永远没有理由。**

真实的症状：

```
"我们有 47 个技能，每次都要先跑 A 再跑 B 再跑 C"
→ 问：为什么不合成一个？
→ 答：⭐ 没人能说出该合的理由，因为没人写过"什么时候该合"
```

## 2. ⭐⭐⭐⭐ 五个合并信号

| # | 信号 | ⭐ 强度 |
|---|---|---|
| 1 | ⭐⭐⭐⭐⭐ **永远一起被调用**（A 出现的地方 100% 有 B） | 最强 |
| 2 | ⭐⭐⭐⭐ 拆开后**中间产物没有任何其他消费者** | 强 |
| 3 | ⭐⭐⭐⭐ **顺序耦合**（B 必须在 A 之后，且反向无意义） | 强 |
| 4 | ⭐⭐⭐ 单独调用任一者**得不到有意义结果** | 中 |
| 5 | ⭐⭐⭐ 两个技能的**失败模式互相纠缠** | 中 |

> ⭐⭐⭐⭐ 第 2 条是重启测试的镜像：
> 重启测试问"失败了人类从哪里重启"；
> **这条问"中间产物有没有被别人用过"——没有，那次拆分就是人为的断点。**

第 5 条值得展开：拆分的一个理由是"失败模式是笛卡尔积"，
但 ⭐ **如果拆开后两个技能的失败模式仍然纠缠**（A 出错导致 B 必然出错），
那拆分只是把复杂度搬了个家，还多付一次加载。

## 3. ⭐⭐⭐⭐⭐ 最强的信号：顺序耦合

```
A → B 永远这个顺序，且 B 单独跑无意义
```

> ⭐⭐⭐⭐⭐ **这不是"两个技能"，这是一个技能被拆成了两半。**

三个判据确认它：

| 问 | 是 → 该合 |
|---|---|
| B 单独运行，输出有意义吗？ | 无意义 |
| A 结束后，你会拿 A 的输出做别的事吗？ | 从不 |
| 有没有人只调用 B？ | 没有 |

三个全是"是/没有" → **合并**。

> ⭐⭐⭐⭐ 这条和第 2 条其实是一件事的两种问法：
> **中间产物无人消费** ⟺ **顺序耦合**。
> 用哪个问都行，看哪个在你脑子里更容易回答。

## 4. ⭐⭐⭐⭐ 合并与拆分的判据不是对称的

很容易以为"拆分的反面就是合并"。不是：

| | 拆分判据 | ⭐ 合并判据 |
|---|---|---|
| 依据 | ⭐ 设计期的性质（职责、权限、认知动作） | ⭐⭐ **运行期的行为**（一起被调用、中间产物无消费者） |
| 何时能用 | 写之前就能判 | ⭐⭐⭐ 必须跑了才知道 |

> ⭐⭐⭐⭐⭐ **这个不对称很重要**：
> 拆分可以提前设计，⭐⭐ **合并只能事后观察。**
> 所以正确的顺序是：**先按设计判据拆，再用运行数据回头合。**
> 反过来（先合一坨再想怎么拆）会失败，因为你没有运行数据。

也解释了一个现象：**为什么刚建好的技能库不该急着合并**——
那时还没有数据，"永远一起被调用"还看不出来。

## 5. ⭐⭐⭐ 三种合并方式

按强度从弱到强：

**① ⭐ 编排层合并**（不改技能）

```
写一个调用 A 再调用 B 的编排，两个技能文件不动
```

> ⭐ 成本最低、可回退。⭐ **先试这个。**

**② ⭐⭐ 主技能 + 子步骤**

```
A 成为主技能，B 变成 A 的一个 reference 或步骤
```

**③ ⭐⭐⭐ 完全合并成一个技能**

```
只有一个 SKILL.md，原来的边界消失
```

> ⭐⭐⭐ **不要直接跳到第 ③ 种。**
> ① 能解决"永远一起用"的问题，且保留了将来再拆的可能；
> ③ 是不可逆的（合并后再拆，你丢失了原来的边界依据）。

这个顺序和 `orchestrator-timing.md` 完全一致：
**手动搬运超过三次才写编排器**——编排本身就是一种轻合并。

## 6. ⭐⭐⭐⭐ 合并的代价必须先算

合并不是免费的，三条代价：

| 代价 | 说明 |
|---|---|
| ⭐⭐⭐ 正文变长 | 每次触发都加载全部，即使只用一半 |
| ⭐⭐⭐ 触发面变宽 | ⭐ 原 A 的触发词和原 B 的触发词进了同一个 description |
| ⭐⭐⭐⭐ 权限变大 | ⭐⭐⭐⭐ 最贵的一条 |

> ⭐⭐⭐⭐ **第三条是硬约束**：
> 如果两个技能的**权限集合不同**（一个只读、一个要写），
> ⭐⭐⭐⭐⭐ **不要合并**——
> 合并后低权限场景被迫获得高权限，这是纯粹的安全损失，
> 没有任何便利值得换。

这条正好是我们第四个拆分判据的镜像：
**权限集合不同就该拆** ⟹ **权限集合不同就不能合**。
⭐ 它是五个合并信号里唯一的**否决项**——
其余四条都成立也不能合。
