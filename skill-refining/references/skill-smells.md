## 结构类

```
① name 与目录名不一致          ⭐ 静默不加载
② 文件名不是恰好 SKILL.md      ⭐ 静默不加载
③ frontmatter 的 --- 没顶格     解析失败
④ description 为空              从不触发
⑤ ⭐ 正文超过 500 行            触发即整篇加载
⑥ ⭐ references 互相链接         模型会部分读取，漏内容
⑦ 引用文件不存在                加载后中途断
```

> 前四条是"技能从不生效"的绝大多数原因
> （见 `reload-debug.md`：~80% 在文件层）。

## 触发类

```
⑧  description 只有一句"做什么"
    ⭐ 缺"什么时候用"——无法路由

⑨  description 用了第一人称
    "I can help you..."  ⭐ 能用，但触发正确率下降

⑩  用内部术语而不是用户词汇
    "工单" vs 用户说的"问题单"

⑪  测试措辞就是 description 的原词
    ⭐ 测的是字符串匹配，不是路由

⑫  与另一个技能触发词高度重叠
    ⭐ 遮蔽的来源

⑬  没有任何否定触发
    ⭐ 过触发的直接原因
```

## 正文类

```
⑭  出现 "确保质量" / "注意性能" / "适当处理"
    ⭐ 对模型等于没有约束

⑮  步骤里出现"视情况而定"
    ⭐ 条件不可执行

⑯  规则埋在末尾的 Notes 章节
    ⭐ 会被漏掉——移到它所约束的步骤旁

⑰  失败模式只写了 happy path
    ⭐ 生产里一定会断

⑱  有禁令但没给替代方案
    ⭐ 模型不知道该做什么（见 guidance-forms.md）

⑲  重教模型已知的内容
    "什么是 git" / Python 语法教程
```

## 资源类

```
⑳  目录里有 README.md / CHANGELOG.md
    ⭐ 技能是给 agent 用的

㉑  脚本里硬编码绝对路径
    换机器就断

㉒  脚本里有交互式 input()
    ⭐ 非交互环境会挂死

㉓  脚本有文件操作但无异常处理
    错误会意外上抛

㉔  打包进了库代码
    应该走 npm/pip

㉕  含时效信息（"截至 2024 Q4"）
    ⭐ 会腐烂
```

## 生命周期类

```
㉖  反模式数量为 0
    ⭐ "危险"信号——说明没遇到过真实失败

㉗  没有 eavl 集
    ⭐ 无法证明它有用，也无法防止回归

㉘  零调用但已上线很久
    ⭐ 先查是不是压根没加载成功

㉙  没有被任何 references 引用的 assets
    ⭐ 未被引用的资源是噪音

㉚  一个技能覆盖多个不相邻领域
    该拆
```

## 怎么用这份清单

**作为 PR 评审的门禁**——逐条打勾，任一条命中就打回。

**作为清库的排序依据**——命中最多的先处理。

**作为自查表**——写完新技能后过一遍。

⚠️ 三条使用注意：

```
① ⭐ 这些是信号，不是判决书
   有些命中是合理的（如第 ⑳ 条在需要给人看的分发包里）

② ⭐ 用脚本能自动查的，不要靠人
   ①–⑦、㉑–㉓、㉙ 都可机械检测
   （见 skill-authoring 的 validate_skill.py）

③ 触发类（⑧–⑬）只能靠 eval 发现
   ⭐ 不能靠读代码判断
```

最后一条最重要：
**这份清单能覆盖的大多是机械问题；
真正决定技能好坏的触发与输出质量，只能靠实测。**

## 一条元观察

> 注意这些坏味道里，
> **"静默失败"类的（①②⑧⑨）代价最高**——
> 它们不报错，只是不工作，
> 让人把时间花在错误的排查方向上。

所以排查顺序永远是：**先跑验证器，再谈其他。**
