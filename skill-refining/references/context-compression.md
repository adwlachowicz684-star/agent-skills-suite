## 干预的优先级

成本从低到高，效果从大到小：

```
① ⭐ 工具设计（最便宜、最有效）
② 工具输出截断
③ 输入淘汰
④ LLM 摘要（最贵，兜底）
```

**第 ① 条被严重低估**：
quiet 模式、截断输出、只返回可操作字段——
这些能让有效上下文寿命延长 **3–4 倍**，
而且**不需要任何压缩基础设施**。

> ⭐ 换个角度说：**上下文不够，往往是你的工具太吵。**

## 三层级联

```
Layer 1  工具输出截断
         ——不需要 LLM 调用，处理掉大部分压力

Layer 2  输入淘汰（eviction）
         ——同样不需要 LLM 调用

Layer 3  LLM 摘要
         ⭐ ——昂贵的兜底，不是默认手段
```

判断标准很简单：**前两层能不能扛住？**
扛得住就别碰第三层。第三层不仅贵，还会**丢信息**。

## 压缩的两个研究结论

**ACON（ICML 2026）**

```
在自然语言空间做压缩，不需要微调
根据失败分析迭代优化压缩准则
→ 峰值 token 减少 26–54%
```

一个反直觉的发现：

> ⭐ **小模型在 ACON 压缩后性能提升 46%**
> ——因为被删掉的历史本身就是干扰源。

而且压缩器可以被蒸馏进更小的模型，**保留 95% 精度**，
运行时开销显著降低。

**MemAgent**

```
有效上下文 3.5M tokens
性能衰减 < 5%
```

这说明"上下文长度"不是硬天花板，
**是可以靠压缩能力换的**。

## 预算目标

```
⭐ 目标占用率 30–40%
```

留出来的空间是给**响应生成**和**意料之外的工具输出**的。

配套的一条纪律：

> **监控每次请求的 token 用量，而不只是整个会话的。**
> 会话级平均会把"某一次请求已经爆了"这件事平滑掉。

## 结构化摘要该有哪些字段

压缩时不要用自由散文，用**显式字段**：

```
session intent   会话意图
progress         进展到哪
artifacts        产出了什么
next steps       下一步
```

⚠️ 并且：**产物清单（artifact manifest）要与摘要分开维护**。
混在一起的话，摘要一压缩，你就不知道自己已经做过什么了。

## 记忆要分层

四种记忆**不能用同一套存储与检索机制**：

| 层 | 内容 | 特点 |
|---|---|---|
| 工作记忆 | 上下文窗口 | 快、小、易失 |
| 情景记忆 | 近期会话 | 按时间检索 |
| 语义记忆 | 事实 | 按相关性检索 |
| **程序性记忆** | **模式、套路** | ⭐ **这正是技能所处的位置** |

> 这个分类解释了为什么"把所有东西塞进 CLAUDE.md"必然失败——
> 那是拿工作记忆的机制去装语义记忆和程序性记忆的内容。

## 注入前先验证

> ⭐ **上下文投毒（幻觉内容或过期内容）修起来比防起来难得多。**

所以**所有上下文注入都要过两道闸**：

```
相关性检查
新鲜度检查
```

这条对技能同样适用——
一段过时的 SKILL.md 被注入后，模型会**把它当真**，
而不是"记得它可能过期了"。

## 与技能的关系

把这套套到技能上，得到三条：

```
1. 技能变"重"了，先看是不是 scripts/ 该抽走的没抽走
   ——工具输出截断 = 脚本只回摘要（Layer 1，最便宜）

2. 长会话里技能失效，先查压缩边界
   ——参见 `skill-crafting` 的 `runtime-truth.md`

3. ⭐ 别急着给技能加"自我摘要"能力
   ——先确认前两层已经用满
```

**门控工具暴露**也是同一思路的延伸：
只暴露当前任务阶段相关的工具，既省 token 又提高准确率。
