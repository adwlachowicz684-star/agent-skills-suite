# 自定义指令 / 技能 / MCP：三种机制各自解决什么

> ⭐ **MCP 增加的是"能做什么"（API 与操作）；
> 技能提供的是"怎么用它们"（程序性知识）。**

## 一句话区分

```
自定义指令  几乎对所有任务都为真的规则（常开）
技能        条件匹配时加载的程序性知识 + 资源
MCP         外部 API 与操作能力
```

## 对照表

| | 自定义指令（CLAUDE.md/AGENTS.md） | 技能 | MCP |
|---|---|---|---|
| 加载时机 | ⭐ **每轮全文** | 条件匹配时 | 工具名常驻，schema 延迟 |
| 适合内容 | 命名约定、lint 策略 | 发布流程、事故分诊 | 数据库访问、Slack 集成 |
| 判据 | ⭐ **每轮都为真** | **当做 X 时** | **需要外部能力** |
| 成本 | 常驻 | L1 常驻 + L2/L3 按需 | 工具名常驻 |

## 各自该装什么

**自定义指令**

```
✅ 命名约定
✅ lint 策略
✅ ⭐ 几乎每次任务都适用的规则
❌ 只在特定任务用到的流程（→ 技能）
```

判据很直接：**这条规则每一轮都为真吗？**
是 → 自定义指令；否 → 别放这儿。

**技能**

```
✅ 条件匹配时加载的程序性知识 + 资源
✅ 发布流程、事故分诊、特定领域的 SOP
❌ ⭐ 只是改语气或格式的东西（→ 用户偏好或系统提示）
```

**MCP**

```
✅ 外部 API 与操作
✅ 数据库访问、第三方服务集成
❌ 纯知识（→ 技能或 RAG）
```

## 两条容易搞混的边界

**① 风格型变体不是技能**

> ⭐ **一个只改变语气或格式的技能，
> 属于用户偏好或系统提示，不属于技能。**

判据：它是否包含**程序性知识**（做事的步骤与方法）？
只有"用更正式的语气" → 不是技能。

**② 技能不授予工具访问权**

```
技能可以写"用 BigQuery:bigquery_schema 查表结构"
但如果那个 MCP server 没连上，技能也变不出这个能力
```

> ⭐ **够不着系统的时候，你要的是 MCP server，不是更好的技能。**

反过来也成立：**有了 MCP 不知道该看什么，需要的是技能。**

## 支持情况

主流工具对技能的支持（2025-12 起）：

```
GitHub Copilot   支持（编码 agent、CLI、VS Code agent 模式）
VS Code          稳定（1.109+；需开启 chat.useAgentSkills）
OpenAI Codex     支持（v0.76.0+）
Cursor           支持（列于 agentskills.io）
Claude Code      支持（技能的发源地，.claude/skills）
```

目录位置：

```
.github/skills/<skill-name>/SKILL.md   ← 推荐（Copilot / VS Code）
.claude/skills/                        ← 仍在支持
```

⭐ **GitHub Copilot 会自动识别 `.claude/skills/`**，
所以已有的 Claude Code 技能可以原样使用。

## 一个组合实例

场景：每次发布要生成 release notes。

```
自定义指令  "提交信息用 Conventional Commits"        ← 每轮为真
技能        "发布流程：从 git log 生成 release notes，
             按 feat/fix/breaking 分组，含迁移说明"  ← 做这件事时
MCP         "GitHub:list_pull_requests"              ← 拿得到数据
```

三者各司其职，**缺任何一个都不完整**：

```
只有 MCP    → 能访问 GitHub，但不知道该看什么
只有技能    → 知道流程，但拿不到 PR 数据
只有指令    → 提交规范了，但没人生成 notes
```

## 一个选型决策顺序

```
第 1 问  需要外部能力/数据吗？
         是 → MCP（再问：知道怎么用吗？不知道 → 加技能）

第 2 问  这条规则每轮都为真吗？
         是 → 自定义指令
         否 → 继续

第 3 问  是程序性知识（how-to）吗？
         是 → 技能
         否 → 再问是事实性知识吗？是 → RAG（见 skill-vs-rag.md）

第 4 问  只是风格/语气？
         是 → ⭐ 用户偏好，不是技能
```

## 一条成本提示

> 装 10 个 MCP（每个 10 个工具）= 常驻约 **100 个工具描述**
> 装 50 个技能 = 常驻约 **5,000 tokens**

两者都会占用常驻预算，
但**MCP 的常驻成本通常被严重低估**。

所以"能用技能解决就别上 MCP"不只是简洁问题，
在工具数量多的时候**直接影响准确率**
（工具数 >10 准确率开始下降，>20 边际收益急剧递减）。
