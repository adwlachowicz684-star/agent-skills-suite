## 先纠正一个误解

> ⭐ **"MCP 还是技能"在系统层面是伪二选一。**

Anthropic 官方的原话是：他们"探索技能如何**补充** MCP server，
教会 agent 涉及外部工具和软件的更复杂工作流"。

**最常见的正确形态**：

```
薄 server 提供访问 + 技能提供工作流
```

具体例子：

```
MCP server 暴露 create_issue / search_issues / update_issue
   → agent 能调用，但不知道你们的分诊规则、标签方案、升级阶梯

技能 "triage-incoming-bugs" 编码的正是这些
   → 它调用 server 的工具作为自己的手

⭐ server 是肌肉，技能是训练。谁也替代不了谁。
```

呼应 `protocol-layering.md` 那句更底层的表述：
**MCP 假设"工具是你的"；A2A 假设"agent 是别人的"**。

## 五问决策法

按顺序问，任一问命中就倾向 server：

```
1️⃣ 需要连到一个真实的外部系统吗？
   （数据库、API、文件系统、工单系统）
   → 是：MCP server

2️⃣ 需要认证或按用户授权范围吗？
   ⭐ MCP 有内建授权模型：OAuth、增量 scope 同意、远程端点
   ⭐ 技能完全没有 auth 概念
   → 需要人授权访问自己的账号：server

3️⃣ 这个能力主要是流程和判断吗？
   "我们团队怎么写事故复盘""发版的步骤""报告的行文风格"
   → ⭐ 是知识，不是连接：技能

4️⃣ 有多少参考材料跟着走，多久需要一次？
   ⭐ 渐进式披露让技能特别适合"大但偶尔用"的上下文：
      长 API 参考、查找表、模板库、校验脚本
   ⭐ 不用时上下文成本为零
   → 塞进常连的 server 意味着每请求都付费

5️⃣ 还有谁要消费它，更新怎么发？
   server = 一次部署，集中版本化，客户端重连即生效
   技能 = 一个文件夹，可移植可版本控制，但 ⭐ 你发的是副本而非更新活端点
   → 十个团队要同一个活能力：server 集中化
   → 十个团队要同一份操作手册：技能好传播，但同步由你负责
```

> ⭐ **如果前四问都没有强制你选 server，默认选技能。**
> 它更轻、上下文更便宜、可移植。

## 功能对照表

| 维度 | MCP | 技能（SKILL.md） |
|---|---|---|
| 主要用途 | 工具/数据集成 | 可复用指令集 |
| 格式 | JSON-RPC over stdio/HTTP | Markdown + YAML frontmatter |
| 运行时 | ⭐ 长驻 server 进程 | ⭐ 静态文本，加载进上下文 |
| 版本化 | server 控制 | frontmatter 里的 SemVer |
| 可从 registry 安装 | 是（npm、Smithery） | 是（skills-hub 等） |
| 能力类型 | 工具、资源、提示 | ⭐ **仅指令** |
| 开放标准 | 是（Anthropic） | 是（社区驱动） |
| 采纳面 | Claude、Cursor、Cline、Windsurf… | Claude、Cursor、Codex、Windsurf… |

> ⭐ 表里最关键的一行是**运行时**：
> server 是活的进程，技能是死的文本。
> 这决定了它们各自擅长什么——也决定了**技能无法授予工具访问权**
> （呼应 `claude-md-vs-skill.md`，**`skill-crafting`**）。

## 什么时候两个都要

**判定信号**：

```
□ 需要碰外部系统（→ server）
□ 且有一套"怎么用"的领域知识（→ 技能）
□ 且这套知识会变（→ 技能比改 server 代码便宜）
```

**一个反直觉但重要的推论**：

> ⭐ **MCP server 趋向商品化**——第十五个 Postgres MCP 的增量很小；
> **技能才是差异化的地方**——
> 两个技能用同样的 MCP，可以编码完全不同的专业知识。

呼应 `mcp-composition.md`（**`skill-orchestration`**）的三层栈：

```
能力层（MCP）→ 指令层（技能）→ 编排层（agent）
```

## 一句话总结

```
需要 AI 去做某件外部的事（查库、打 API、扫 Notion）→ MCP
需要 AI 稳定地按某个流程做事                      → 技能
两者都要                                          → 薄 server + 技能
```

> ⭐ **技能能调用 MCP 工具**——技能是指令，可以引用通过 MCP 暴露的任何工具。
> 一个"部署"技能可以在步骤里调用 Vercel、AWS 或你自建的 MCP server。
