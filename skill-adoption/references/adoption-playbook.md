# 团队推广：为什么推广会卡住

> ⭐ **最反直觉的一条**：
> **推广卡住，是因为第一次独奏通常令人失望。**
> 工程师把 agent 用在手上最棘手的任务上——那个自己都解决不了的——
> 得到平庸结果，于是断定"这工具还不行"。
> **他们选了最糟糕的第一个任务。**

## 两个卡点

**卡点 1：第一次独奏选错了任务**

```
❌ 工程师把 agent 用在
   模糊的、重度依赖判断的、没有任何护栏的任务上

✅ ⭐ agent 擅长的是：
   ⭐ 范围明确、机械化、高上下文的工作

→ 所以入门任务必须专门挑选"agent 能做好"的那些
```

**卡点 2：肌肉记忆问题**

```
□ ⭐ 资深工程师有几十年"手工做"的条件反射
□ ⭐ 伸手找 agent 是一个新反射，
   在工期压力下要与快速舒适的老反射竞争
□ ⭐ 没有刻意练习和可见的同伴行为，
   新反射永远形不成，人们会安静地退回旧方式
```

> ⭐ 这两个卡点都不是"工具不好"的问题——
> 呼应 `team-adoption.md` 的"信任缺口的负面对称性"。

## 前三十天：结构化，非可选

> ⭐ **把上手当作一件严肃的工具来对待**：

**给每位工程师一组精选的入门任务**（专门挑 agent 擅长的）：

```
□ 为一个测试不足的模块补测试
□ 升级一个依赖
□ 写一个迁移脚本
□ ⭐ 为已有服务起草文档
```

```
□ ⭐ 这些能产出早期胜利，而胜利才是建立信念的东西
□ ⭐ 第一周在真实任务上赢一次，胜过十场演示
```

**配套"开箱即用的团队配置"**（而不是让新人从空白开始）：

```
□ ⭐ 连好你们的问题跟踪器与 CI 的 MCP servers
□ ⭐ 一组编码了团队约定的技能
   你们怎么写测试 · 怎么组织迁移 · 提交信息格式
□ ⭐ 自动跑 linter 与测试的 hooks
□ ⭐ 当工具已经知道你们的风格，
   新用户就不必通过挫折去发现它
```

**流程图**：

```
新人上手 → 精选入门任务（agent 友好）
        → 共享技能与 MCP 配置预装
        → 是否取得早期胜利？
           否 → 与推广冠军结对 → 回到入门任务
           是 → 工程师添加自己的模式
              → 回传给团队技能库
              → 在评审中被强化
```

## 让习惯固化下来的规范

> ⭐ **习惯在社交强化中形成**——
> 把推广嵌进既有仪式，而不是另造新仪式：

**① 在代码评审里常态化一行说明**

```
□ 说明这个改动是怎么产出的
□ ⭐ 目的不是监督，而是让"agent 辅助的工作"可见且平常
```

**② 资深工程师公开分享会话与提示词**

```
□ ⭐ 这传递的信号是：这就是我们这里做真实工作的方式，
   不是 junior 走的捷径
```

**③ 建立"把技能贡献回去"的规范**

```
□ 有人摸索出处理你们那种数据库迁移的好模式
  → ⭐ 就该变成全队继承的共享技能
□ ⭐ 这把推广从个人努力变成复利的团队资产
□ ⭐ 也给了工程师投入的理由：他们的好点子会传播
```

**④ ⭐ 同等重要：明确"评审严格度不下降"**

```
□ agent 产出的 diff 与人工产出的一样受审视
□ ⭐ 早先就把这点讲明，能防止文化漂移
  ——人们因为"是 AI 做的"就橡皮图章，质量就是这样悄悄腐蚀的
```

## 推广冠军的角色

```
□ ⭐ 每次成功的落地都有一两个真正兴奋且擅长的人
□ ⭐ 早识别他们，并给明确的时间去支持团队
   办公时间 · 结对 · 一个能丢卡住的会话并得到解卡的频道
□ ⭐ 冠军比强制令更能转化怀疑者，
   因为他们回答了怀疑者真正在问的问题：
   ⭐ "让我看看它在我这类问题上能不能跑通"
```

**⚠️ 避免相反的错误：按指标强制使用**

```
□ ⭐ 告诉人们每周必须用 X 次 → 产出的是刷数据，不是推广
□ ⭐ 让工具在它擅长的那类工作上明显是更省力的路径，
   把胜利晒出来，⭐ 让"拉"胜过"推"
□ ⭐ 使用率最高且最持久的团队，几乎没有是靠配额做到的
```

## 诚实地度量

```
□ ⭐ 追踪深度，不只是广度
□ ⭐ 日活是弱信号——真正重要的是：
   agentic 工作是否出现在有意义的任务上
   使用它的人是否报告真的省了时间
□ ⭐ 轻量脉冲调查："这周 agent 帮你省时间了吗？省在什么上？"
```

> ⭐ 呼应 `team-adoption.md` 的监控指标与
> `skill-evaluating` 的 `metrics.md`：
> **使用率不等于价值**。

## 自查

```
□ 是否为新人准备了"agent 擅长"的入门任务？
□ ⭐ 是否知道"选错第一个任务"是推广卡住的头号原因？
□ 是否意识到肌肉记忆问题（新反射 vs 老反射）？
□ ⭐ 是否提供了开箱即用的团队配置（MCP + 技能 + hooks）？
□ 入门任务是否含"补测试/升依赖/写迁移/起草文档"？
□ ⭐ 是否强调"第一周真实任务赢一次 > 十场演示"？
□ 是否有"没赢就与冠军结对"的兜底路径？
□ ⭐ 评审里是否有"一行说明"（让 agent 工作可见）？
□ 是否鼓励资深者公开分享会话？
□ ⭐ 是否有"把技能贡献回团队"的规范？
□ ⭐ 是否明确了"评审严格度不下降"？
□ ⭐ 是否有推广冠军，且给了明确时间？
□ 是否避免了"按指标强制使用"？
□ ⭐ 度量是否看深度（有意义任务 + 主观省时）而非日活？
□ 是否做了轻量脉冲调查？
□ 是否强调"拉 > 推"？
```
