## 子代理不能再生子代理

```
⭐ Subagents cannot spawn other subagents.
```

如果你的工作流需要**嵌套委派**，只有两条路：

```
① 用技能（在主会话上下文里跑）
② 从主会话链式调用子代理（一个接一个，不是嵌套）
```

> ⭐ 注意"链式"和"嵌套"的区别：
> 链式 = 主会话 A → 子代理 B（返回）→ 主会话 A → 子代理 C
> 嵌套 = 子代理 B 内部再开一个子代理 ← **不支持**

这个限制直接影响编排设计：**需要多层分解的任务，
要么在技能里用流程步骤表达，要么在主会话里手动串。**

## 恢复：不是重新调用

每次调用子代理都是**全新实例 + 全新上下文**。
要接着上次干，得**恢复**而不是重新调用。

```
恢复后的子代理保留完整会话历史
——包括之前所有的工具调用、结果和推理
——它从上次停下的地方精确继续
```

机制上：子代理完成时，主会话拿到它的 **agent ID**；
用 `SendMessage` 以该 ID 为 `to` 发起恢复。

⚠️ 前置条件：`SendMessage` 只在开启 agent teams 时可用
（`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`）。

一个很实用的行为：

> **已停止的子代理收到 SendMessage 会自动在后台恢复**，
> 不需要新的 Agent 调用。

transcript 文件位置：`~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`

## transcript 独立于主会话

三个关键性质：

```
① 主会话压缩时，子代理 transcript 不受影响
   ——它们存在独立文件里

② transcript 在会话内持久
   ⭐ 重启客户端后，恢复同一 session 仍能接着用

③ 自动清理基于 cleanupPeriodDays（默认 30 天）
```

①②③ 合起来意味着：**子代理的产出比主对话更耐久**。
长任务里，把关键结论放进子代理 transcript 反而更安全。

另外，子代理**支持自动压缩**，逻辑与主会话相同。

## 启动上下文里有什么

非 fork 子代理的初始上下文：

```
✅ 自己的 system prompt + 环境信息（不是完整的 Claude Code system prompt）
✅ 委派任务消息
✅ ⭐ CLAUDE.md 与记忆层级（~/.claude/CLAUDE.md、项目规则、
   CLAUDE.local.md、受管策略文件）
✅ git status 快照（会话开始时取的）
✅ ⭐ skills 字段里点名的技能——加载完整内容
```

例外：

```
⚠️ Explore 与 Plan 是唯一跳过 CLAUDE.md 与 git status 的
⚠️ 内置 agent 不预加载技能
⚠️ 没有 frontmatter 字段或 per-agent 设置能改这个行为
```

**fork** 是唯一例外——它**继承父对话**而不是全新开始。

一个重要的推论：

> 主会话读取 Explore / Plan 的结果时**带着完整 CLAUDE.md 上下文**，
> 所以**大多数规则不需要传给子代理本身**。
> 如果某条规则必须生效（如"忽略 vendor/ 目录"），
> ⭐ **在委派时把它写进 prompt**。

## 上下文成本与替代方案

```
⭐ 跑很多个子代理、每个都返回详细结果，会消耗大量上下文。
```

三种情况的取舍：

| 情况 | 建议 |
|---|---|
| 需要持续并行 | ⭐ **agent teams**（每个 worker 有独立上下文） |
| 超过上下文窗口 | 同上 |
| 只是想问个快速问题 | `/btw`——看得见完整上下文、无工具访问、**答案不进历史** |

`/btw` 那条特别值得记：**答案被丢弃而不是加入历史**。
想"问一下但不污染上下文"时用它，比开子代理轻得多。

## 选主会话还是子代理

**用主会话**：

```
□ 任务需要频繁来回 / 迭代打磨
□ 多个阶段共享大量上下文（规划 → 实现 → 测试）
□ 快速、定点的小改动
□ ⭐ 延迟敏感（子代理要从零收集上下文，慢）
```

**用子代理**：

```
□ 产出冗长但主上下文不需要
□ ⭐ 想强制特定的工具限制或权限
□ 工作自包含，能返回摘要
```

**改用技能**：

```
□ ⭐ 想要可复用的提示词或工作流
□ ⭐ 并且希望它在主会话上下文里跑，而不是隔离的子代理上下文
```

> 最后这一组是选型的核心：
> **要隔离 → 子代理；要复用 + 留在主上下文 → 技能。**
