## 1. 覆盖率 100% 的错觉

```
技能清单：
  fetch       owner: 张三   ✅
  analyze     owner: 李四   ✅
  report      owner: 王五   ✅
  ─────────────────────────
  覆盖率：100%
```

一条端到端流程跑挂了。三份 owner 都在，⭐⭐⭐⭐⭐ **而没有人负责"这条链能跑通"**。

> ⭐⭐⭐⭐⭐ **Owner 是按技能登记的，故障是按链发生的。**
> 这是两个不同的维度，而治理表只有前者。

对比一下单技能的情况：技能没 owner → 清单里那一格是空的 → 一眼可见。
链没 owner → 清单里没有"链"这一行 → ⭐⭐⭐⭐⭐ **它不表现为缺失，它根本不出现**。

---

## 2. 三个具体后果

| 后果 | 表现 |
|---|---|
| ⭐⭐⭐⭐⭐ 没人收到告警 | 报警按技能发，链级失败落在"没有失败"的那一环之外 |
| ⭐⭐⭐⭐⭐ 没人做端到端测试 | 每个技能各有测试集，没有一个测试跑完整条链 |
| ⭐⭐⭐⭐ 没人决定保留还是拆散 | "这条链还有用吗"这个问题没有提问的人 |

第二条最贵，也是唯一会被误当成"已解决"的：

```
fetch 测试通过 ✅
analyze 测试通过 ✅
report 测试通过 ✅
→ 看起来端到端被覆盖了
```

> ⭐⭐⭐⭐⭐ **覆盖率是"每个环节被覆盖"，不是"环节之间被覆盖"**——
> 而链上失败几乎全部发生在环节之间（传丢、传错、陈旧、partial）。

这与 `skill-evaluating` 里"正例只能证明能做到"是同构的：
组件级全绿，组合级从未被验证。

## 3. 为什么没人认领

不是推诿，是结构上没有信息：

```
张三（fetch）：我的技能返回了 200，产物写了
李四（analyze）：我收到的数据是空的，我报了"缺输入"
王五（report）：我没被调用
```

> ⭐⭐⭐⭐⭐ **三个人说的都是事实，而这三个事实合起来不包含"链失败了"这个结论。**

每个人只看得到自己那一环的输入和输出，
⭐⭐⭐⭐⭐ 而链的失败恰恰是"每一环都自洽、合起来不自洽"——
参见 `skill-chain-failure/references/chain-failure-shapes.md`。

所以"指定一个 owner"这件事的价值不在追责，在于⭐⭐⭐⭐⭐ **制造一个能同时看到三环输出的位置**。
没有这个位置，就没有人具备判断"链挂了"所需的全部信息。

## 4. 编排器是唯一的天然载体

链的 owner 挂在哪？三个选项：

| 挂在哪 | 问题 |
|---|---|
| 挂在每个技能上 | ⭐⭐⭐⭐⭐ 三个 owner = 没有 owner |
| 挂在文档/wiki | ⭐⭐⭐⭐⭐ 出事时没人会先去翻它 |
| ⭐⭐⭐⭐⭐ 挂在编排器技能上 | 编排器自己也需要 owner（递归一层，但只递归一层） |

> ⭐⭐⭐⭐⭐ **编排器是一个技能，所以它天然有 owner 字段、有 changelog、能被 grep 到。**
> 这是它比"文档里写一句"强的地方——不是内容更好，是**它在系统里**。

递归那一层也好办：编排器的 owner 就是链的 owner。
⭐⭐⭐⭐ 于是链级责任最终落在一个人身上，而不是三个人共享。

顺带一条：没有编排器的链（靠模型自己串）怎么办？
→ ⭐⭐⭐⭐⭐ **那就没有载体，此时链级 owner 只能登记在"最下游那个技能"上**，
因为它至少能看到"上游没给我东西"。这不如编排器，但比没有强。

## 5. 三条最低要求

```
① ⭐⭐⭐⭐⭐ 链有 owner（字段，不是口头约定）
② ⭐⭐⭐⭐⭐ 链有一条端到端冒烟用例（真的从 A 跑到 C）
③ ⭐⭐⭐⭐ 链有自己的 changelog（环上任一环变更都记一条）
```

第②条只要一个用例：⭐⭐⭐⭐⭐ **一条能跑通的输入，从第一环跑到最后一环，断言最终产物存在且非空**。
它测的不是正确性，是"这条链还连着"——而这一件事从来没人测过。

第③条是三个里最容易省的，也是最容易被打脸的：

```
改了 analyze 的输出字段 → analyze 的 changelog 有一条
                       → ⭐⭐⭐⭐⭐ 链的 changelog 一条都没有
                       → 半年后没人知道这条链什么时候变过
```

> ⭐⭐⭐⭐⭐ **变更记录按技能组织，而故障按链发生**——
> 与第 1 节是同一个结构错配的两种表现。

成本一句话说清：⭐⭐⭐⭐⭐ **三条加起来不到十行，而它是唯一能让"端到端"这件事有人负责的机制。**

## 6. 自检

| 检查 | 不通过的信号 |
|---|---|
| ⭐⭐⭐⭐⭐ 技能清单里有"链"这一行吗？ | 没有，只有技能 |
| ⭐⭐⭐⭐⭐ 端到端有没有一条真的从 A 跑到 C 的用例？ | 只有各环的单元测试 |
| ⭐⭐⭐⭐⭐ 上一次链级失败，谁收到的告警？ | 没人 / 三个 owner 都收到但都不认为归自己 |
| ⭐⭐⭐⭐ 编排器有 owner 吗？ | 它是"公共的" |
| ⭐⭐⭐⭐ 环上任一环变更，链级 changelog 有记录吗？ | 只在技能自己的 changelog 里 |
| ⭐⭐⭐⭐⭐ 能不能在 30 秒内说出这条链归谁？ | ⭐⭐⭐⭐ 要问三个人才知道 |
