## 6. ⭐⭐⭐⭐ PreToolUse 不只阻断，还能改写

```
⭐⭐⭐⭐⭐ 传统理解：PreToolUse 要么放行、要么阻断（二选一）

⭐⭐⭐⭐⭐ 实际能力：通过顶层 hookSpecificOutput 对象，PreToolUse 还读取
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ permissionDecision
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ permissionDecisionReason
   ⭐⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ modifyInput     ← ⭐⭐⭐⭐⭐ ⭐⭐⭐ **可以⭐ 就地改写⭐ 工具输入，
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不是⭐ 一味阻断**
```

> ⭐⭐⭐⭐⭐ 这⭐ 是⭐ 一个⭐ 我们⭐ 此前⭐ 完全没有⭐ 覆盖的⭐ 第三选项：
> ```
> ① 放行          ② 阻断          ③ ⭐⭐⭐⭐⭐ 改写后放行
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 第 ③ 项的⭐ 价值⭐ 很大：⭐⭐⭐⭐⭐ ⭐⭐⭐ 很多⭐ 情况下⭐ 你⭐ 不是⭐ 想⭐ 禁止
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 这个动作，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而是⭐ 想⭐ 让⭐ 它⭐ 用⭐ 正确的⭐ 参数⭐ 发生
> （⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 例：⭐ 把⭐ 目标路径⭐ 收进⭐ 允许目录、⭐⭐⭐⭐⭐ ⭐⭐⭐ 给命令⭐ 补上⭐ 缺失的 flag）。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **只挡不改，⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型⭐ 只能⭐ 重新猜一次——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而⭐ 那⭐ 正是⭐ 第 5 节⭐ "九次重试"⭐ 的⭐ 另一个⭐ 成因。**

## 7. ⭐⭐⭐⭐ PostToolUse 无法阻断，但能纠偏

> ⭐⭐⭐⭐⭐ **"⭐ 因为⭐ 工具⭐ 已经⭐ 跑完了，⭐⭐⭐⭐ ⭐⭐⭐ 你的 hook ⭐ 无法⭐ 阻断它，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 但⭐ 它可以：⭐⭐⭐⭐⭐ ⭐⭐⭐ 格式化、⭐⭐⭐⭐ ⭐⭐⭐ lint、
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 跑⭐ 变更模块的⭐ 单元测试，⭐⭐⭐⭐⭐ ⭐⭐⭐ 然后⭐ 把发现⭐ 通过
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ stdout ⭐ 追加进⭐ 模型的⭐ 下一轮。"**

```
典型用法：Edit/Write 之后自动 ruff format / prettier --write / gofmt
          + ⭐⭐⭐⭐⭐ 只跑变更模块的测试（不是全量）
          + ⭐⭐⭐⭐⭐ ⭐⭐⭐ 把 lint 结果 stdout 注入下一轮
```

> ⭐⭐⭐⭐⭐ 这条⭐ 是⭐ "⭐⭐⭐⭐⭐ **反馈环：做 → 检查 → 修**"⭐ 的⭐ 一次⭐ 系统级实现——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而且⭐ 它⭐ 把⭐ 我们⭐ 反复强调的⭐ 那条
> "⭐ 反复被违反的⭐ 书面规则⭐ 应编码成⭐ 校验器"⭐ 落到了⭐ 最自然的⭐ 位置：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ **工具⭐ 刚跑完，⭐⭐⭐⭐⭐ ⭐⭐⭐ 检查与修正⭐ 立刻自动发生，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 不需要⭐ 模型⭐ 记得⭐ 去做。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 另外⭐ "⭐ 只跑⭐ 变更模块的⭐ 测试"⭐ 这条⭐ 也值得⭐ 抄——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 它⭐ 与⭐ `unity-refactor-skill.md` 那句
> "⭐ 重构技能⭐ 默认范围⭐ 该是⭐ 最近改动"⭐ 是⭐ 同一个⭐ 判断（⭐ 范围 = 变更集）。

## 8. ⭐⭐⭐⭐⭐ 压缩后重注入上下文

```json
{ "hooks": { "SessionStart": [ { "matcher": "compact",
    "hooks": [ { "type": "command",
      "command": "echo 'Reminder: use Bun, not npm. Run bun test before committing. Current sprint: auth refactor.'" } ] } ] } }
```

> ⭐⭐⭐⭐⭐ **"⭐ 上下文窗口⭐ 满了⭐ 就压缩，⭐⭐⭐⭐ ⭐⭐⭐ 压缩⭐ 会丢掉⭐ 重要细节。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 用⭐ 带 `compact` matcher 的⭐ SessionStart hook，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 在⭐ 每一次压缩之后⭐ 重新注入⭐ 关键上下文。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **你的命令⭐ 写到 stdout 的⭐ 任何文本，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 都会被⭐ 加进 Claude 的上下文。**"**

> ⭐⭐⭐⭐⭐⭐ **这条⭐ 直接⭐ 补上了⭐ 我们⭐ 一个⭐ 长期⭐ 悬空的⭐ 问题。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 我们⭐ 此前⭐ 记录过⭐ 两个⭐ 事实：
> ```
> ① ⭐⭐⭐⭐⭐ 压缩只保留开头 5000（three-stages-discovery-activation-execution）
> ② ⭐⭐⭐⭐⭐ 技能一旦激活就留在对话里，压缩可能把它挤出去（context-budget-math）
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 但⭐ 我们⭐ 没有⭐ 记录过⭐ **怎么办**。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这条 hook ⭐ 正是⭐ 答案：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ **压缩是一个⭐ 可订阅的⭐ 事件，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 你可以⭐ 在它⭐ 之后⭐ 把关键约束⭐ 重新写回去。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 这⭐ 比⭐ "把关键指令⭐ 放开头"⭐ 更可靠——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 后者⭐ 是⭐ 被动⭐ 顺应⭐ 截断，⭐⭐⭐⭐⭐ ⭐⭐⭐ 前者⭐ 是⭐ 主动⭐ 重注入。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 一条⭐ 分寸⭐ 也很值得⭐ 照抄：
> ⭐⭐⭐⭐ **"⭐ 如果⭐ 是⭐ 每会话都需要的⭐ 上下文注入，⭐⭐⭐⭐⭐ ⭐⭐⭐ 考虑用 CLAUDE.md ⭐ 而不是 hook。"**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与⭐ 我们⭐ 已有的⭐ 五问决策流程
> （"⭐⭐⭐ Q3 每会话都需要的规则 → CLAUDE.md"）⭐ 完全一致。

## 9. ⭐⭐⭐⭐ 子代理里也会跑

> ⭐⭐⭐⭐ **"⭐ 来自⭐ settings 文件、⭐ 托管策略、⭐ 插件的 hooks，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 在⭐ 子代理内部⭐ 同样运行。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 当⭐ 子代理⭐ 调用工具时，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ PreToolUse / PostToolUse ⭐ 会⭐ 触发
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 与主会话中⭐ 相同的⭐ 已配置 hooks，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 且⭐ 输入⭐ 携带 `agent_id` 与 `agent_type`
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 以标识⭐ 该子代理。"**

```
⭐⭐⭐⭐⭐ 推论一：⭐⭐⭐⭐⭐ ⭐⭐⭐ 想在子代理里也生效的护栏 → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 必须放在
              ⭐ settings / managed / plugin 来源，⭐⭐⭐⭐⭐ ⭐⭐⭐ 不能只放 user/local
⭐⭐⭐⭐⭐ 推论二：⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 输入带 agent_id/agent_type → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 可以
              ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **按子代理类型差异化**（比"一刀切"精细得多）
```

> ⭐⭐⭐⭐⭐ 推论一⭐ 与⭐ 我们⭐ 已有的⭐ `skill-vs-subagent-decide.md` 那条
> "⭐⭐⭐⭐⭐ **不显式挂技能，⭐⭐⭐⭐⭐ ⭐⭐⭐ 你的子代理就是在裸奔**"⭐ 是⭐ 同一族——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 只不过⭐ 那里⭐ 说的是⭐ 技能，⭐⭐⭐⭐⭐ ⭐⭐⭐ 这里⭐ 说的是⭐ 护栏：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ **隔离不豁免约束，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但前提是⭐ 约束⭐ 来自⭐ 正确的层。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 企业侧⭐ 还有⭐ 一条⭐ 硬开关：
> ⭐⭐⭐⭐ **`allowManagedHooksOnly`：⭐⭐⭐⭐⭐ ⭐⭐⭐ user / project / local / plugin
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 的 hooks ⭐ 全部被禁，⭐⭐⭐⭐⭐ ⭐⭐⭐ 只留⭐ 托管 hook。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 是⭐ "⭐⭐⭐⭐⭐ **作用域即信任边界**"⭐ 的⭐ 一次⭐ 强制实现。

## 10. ⭐⭐⭐ 与技能的最终分工

```
⭐⭐⭐⭐⭐ 技能 = ⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型"需要知道"的（按需加载的知识与流程）
⭐⭐⭐⭐⭐ Hook = ⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型"不可被信任去遵守"的（每次都发生、确定性）
```

> ⭐⭐⭐⭐⭐ 这⭐ 已是⭐ 我们⭐ 记录的⭐ 关于⭐ 这条⭐ 分工的⭐ 第五个⭐ 独立来源，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 这份⭐ 补上了⭐ 前四次⭐ 都没有的⭐ 三样东西：
> ```
> ① ⭐⭐⭐⭐⭐ 完整的机制（12 事件 + ⭐⭐⭐⭐⭐ ⭐⭐⭐ 三档退出码 + ⭐⭐⭐⭐⭐ ⭐⭐⭐ 三层配置）
> ② ⭐⭐⭐⭐⭐ 第三种动作：⭐⭐⭐⭐⭐ ⭐⭐⭐ 改写（modifyInput），不止放行/阻断
> ③ ⭐⭐⭐⭐⭐⭐ 恢复手段：⭐⭐⭐⭐⭐ ⭐⭐⭐ compact matcher 重注入——⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 压缩⭐ 不再是⭐ 不可挽回的
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 配套⭐ 两条⭐ 运行细节：
> ⭐⭐⭐ **事件触发时，⭐⭐⭐⭐ ⭐⭐⭐ 所有匹配的 hooks 并行运行；
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 完全相同的 hook 命令会自动去重。**

## 速查

```
□ ⭐⭐⭐⭐⭐ 三层：hook event（生命周期点）· matcher group（过滤器）· hook handler（实际执行）
   ⭐⭐⭐⭐ ⭐⭐⭐ 可选 if 条件：⭐⭐⭐⭐⭐ ⭐⭐⭐ 廉价匹配先做，不匹配就不 spawn 进程（省开销）
□ ⭐⭐⭐⭐⭐ 12 事件：SessionStart · UserPromptSubmit · PreToolUse(阻断) · PermissionRequest(阻断)
   PostToolUse(不阻断) · PostToolUseFailure · Notification · SubagentStart/Stop · Stop · PreCompact · SessionEnd
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ Stop/SubagentStop 可返回 additionalContext 续接本轮（不算错误）
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 输入含 background_tasks/session_crons → ⭐⭐⭐⭐⭐ ⭐⭐⭐ Hook 能看见还有什么在排队再决定该不该停
□ ⭐⭐⭐⭐⭐ 退出码三档：0=放行（UserPromptSubmit/SessionStart 的 stdout 进上下文）
   2=硬阻断（stderr 作为原因反馈给 Claude）· 其他非0=错误（模型看到失败，stderr 只写日志不给 Claude）
□ ⭐⭐⭐⭐⭐ 沉默 ≠ 批准："Hook 没反对"不等于"Hook 同意了"——exit 0 无输出只是把决策交还权限流程
□ ⭐⭐⭐⭐⭐ 阻断消息必须可行动：⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 写明下一步该做什么，而不只是哪里错了
   ⭐⭐⭐⭐⭐⭐ 实测代价：⭐⭐⭐⭐⭐ ⭐⭐⭐ Claude 把同一条被阻断命令试了九次，因为拒绝消息没给替代方案
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ （"禁令要带替代方案"第五次独立出现，且这次有可观测代价）
□ ⭐⭐⭐⭐ PreToolUse 第三选项：⭐⭐⭐⭐⭐ ⭐⭐⭐ modifyInput 就地改写工具输入（而非只放行/阻断）
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 只挡不改 → 模型只能重新猜 → 正是"九次重试"的另一成因
□ ⭐⭐⭐⭐ PostToolUse 不能阻断但能纠偏：⭐ 格式化/lint/跑变更模块测试 → stdout 注入下一轮
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这是"做→检查→修"反馈环的系统级实现，且模型不需要记得去做
□ ⭐⭐⭐⭐⭐ 压缩后重注入：SessionStart + matcher "compact" → stdout 任何文本进上下文
   ⭐⭐⭐⭐⭐⭐ ⭐⭐⭐ 这补上了"压缩会驱逐技能"长期悬空的怎么办——比"放开头"更可靠（主动 vs 被动）
   ⭐⭐⭐⭐ ⭐⭐⭐ 分寸：每会话都需要的注入用 CLAUDE.md 而非 hook
□ ⭐⭐⭐⭐ 子代理内也跑（settings/managed/plugin 来源），输入带 agent_id/agent_type 可差异化
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 企业可用 allowManagedHooksOnly 禁掉 user/project/local/plugin
□ ⭐⭐⭐⭐⭐ 分工：技能=模型需要知道的；Hook=模型不可被信任去遵守的
   ⭐⭐⭐⭐ ⭐⭐⭐ 匹配时并行运行；相同命令自动去重
```

**一句话**：

> ⭐⭐⭐⭐ **Hook 用 exit 0 / 2 / 其他三档与模型通信，且"沉默不等于批准"——而阻断消息必须写明下一步该做什么，否则模型会把同一条被拒绝的命令试九次；此外 PreToolUse 还能用 `modifyInput` 就地改写工具输入，而 `compact` matcher 的 SessionStart hook 则补上了"压缩会驱逐技能"长期悬空的解法：压缩是可订阅事件，之后可以把关键约束重新写回上下文。**

---

## 速查

```
□ ⭐⭐⭐⭐ PreToolUse 第三选项：modifyInput 就地改写工具输入（而非只放行/阻断）
   ⭐⭐⭐⭐⭐ 只挡不改 → 模型只能重新猜 → 正是"九次重试"的另一成因
□ ⭐⭐⭐⭐ PostToolUse 不能阻断但能纠偏：格式化/lint/跑变更模块测试 → stdout 注入下一轮
   ⭐⭐⭐⭐⭐ 这是"做→检查→修"反馈环的系统级实现，模型不需要记得去做
□ ⭐⭐⭐⭐⭐ 压缩后重注入：SessionStart + matcher "compact" → stdout 任何文本进上下文
   ⭐⭐⭐⭐⭐⭐ 补上了"压缩会驱逐技能"长期悬空的怎么办——比"放开头"更可靠（主动 vs 被动）
   ⭐⭐⭐⭐ 分寸：每会话都需要的注入用 CLAUDE.md 而非 hook
□ ⭐⭐⭐⭐ 子代理内也跑（settings/managed/plugin 来源），输入带 agent_id/agent_type 可差异化
   ⭐⭐⭐⭐⭐ 企业可用 allowManagedHooksOnly 禁掉 user/project/local/plugin
□ ⭐⭐⭐⭐⭐ 分工：技能=模型需要知道的；Hook=模型不可被信任去遵守的
   ⭐⭐⭐⭐ 匹配时并行运行；相同命令自动去重
```
