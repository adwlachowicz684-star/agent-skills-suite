## 清单该记什么

```
□ 名称与版本
□ ⭐ 来源（内部/第三方/个人）与 provenance
□ ⭐ 作用域（企业/项目/个人）
□ ⭐ 权限（allowed-tools、能碰什么）
□ 负责人
□ ⭐ 最近调用时间与频率
□ 上次审计日期与结论
□ 许可证
```

> ⭐ **`provenance`（来源可追溯）这一项最重要**——
> 出事时你要能回答"这个技能从哪来"。

呼应 `packaging.md`（**`skill-refining`**）与
`security-review.md`（**`skill-governance`**）。

## 三类技能的状态

```
ACTIVE      在用，有负责人，最近审计过
DEPRECATED  已标记废弃，仍在迁移期
QUARANTINE  ⭐ 发现可疑，已停用待查
```

> ⭐ **QUARANTINE 是个值得单独设的状态**：
> 出事时你要能**立刻停掉**一个技能，
> 而不是先走完废弃流程。

呼应 `lifecycle.md`（**`skill-governance`**）的五阶段：
`DRAFT → ACTIVE → MATURE → DEPRECATED → ARCHIVED`。

## 留存与删除

**两个方向的要求常常冲突**：

```
合规要求：日志留存 ≥6 个月（见 compliance-audit.md）
隐私要求：个人数据应及时删除
```

**处理原则**：

```
□ ⭐ 区分"内容"与"元数据"
   元数据（谁、何时、用了哪个技能、花了多少 token）→ 留存
   内容（prompt 原文、工具载荷、用户数据）→ ⭐ 短留存或去标识化

□ ⭐ 留存期要写死，不能"默认永久"
```

呼应 `telemetry-schema.md` 的"什么不该记"与
`pii-data-handling.md` 的去标识化层次。

**删除要真的删**：

```
□ 从清单移除 ≠ 从磁盘删除
□ ⭐ 归档（ARCHIVED）要移出自动加载路径
   ——否则它还在付目录税
```

呼应 `lifecycle.md`：**归档而非删除**，
但要确保归档的东西不再被加载。

## 定期审计

**四个触发点**：

```
1. ⭐ 定期（季度）：全量过一遍
2. ⭐ 版本变更时：每个版本独立重新审计
3. ⭐ 事故后：复盘时检查相关技能
4. ⭐ 依赖变更时：上游 MCP/脚本变了
```

**审计动作**：

```
□ 从未被调用的 → 考虑移除（用 /skill-doctor）
□ 负责人空缺的 → 指派或废弃
□ ⭐ 版本过旧的 → 检查上游是否还在维护
□ 权限过宽的 → 收紧
```

呼应 `library-ops.md`（**`skill-distribution`**）的
五维健康诊断——**基于规则的，几乎零 LLM token**。

## 一条容易被忽略的关系

> ⭐ **技能清单本身也是攻击面。**

```
□ 一个能写清单的 agent，就能往里加自己的技能
□ ⭐ 清单的写权限要独立管控
□ ⭐ 清单变更要留审计日志
```

呼应 `untrusted-repo-content.md`（**`skill-selection`**）的思路：
**任何自动读取的来源都是数据，不是指令**——
清单读取要校验签名或哈希。

呼应 `release-versioning.md` 的
**用内容寻址（tree SHA）而非只看版本号**。
