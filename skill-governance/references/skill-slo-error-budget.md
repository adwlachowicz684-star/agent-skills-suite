## 1. ⭐⭐⭐⭐⭐ 缺口：有指标，没有执法

我们已经有了一整套指标：体检四指标、九维 rubric、灰度期的版本级拆分、
delta 判读表。缺的是最后一步：

```
观测到了 → 然后呢？
```

现状通常是：

| 情况 | 实际发生 |
|---|---|
| 通过率掉了 5 个点 | 记下来，继续发布 |
| 触发率只有 40% | 记下来，继续发布 |
| 返工率逐月上升 | 记下来，继续发布 |

> ⭐⭐⭐ **指标没有后果，就等于没有指标。**
> 它变成了"我们知道自己在变差"的记录，而不是阻止变差的机制。

SLO + 错误预算补的就是这个：**把"变差"变成一个有明确后果的状态**。

## 2. ⭐⭐⭐⭐ 三条 SLI 与它们的口径

只留三条——**超过三条的 SLO 没人守得住**：

| SLI | 定义 | ⭐ 口径要点 |
|---|---|---|
| **触发准确率** | 该触发时触发 /（该触发 + 不该触发） | ⭐ 分母必须含误触发，否则 100% 无意义 |
| **输出合格率** | 输出通过验收 / 总输出 | ⭐ 验收要可判定（见《skill-content》的 `skill-content/references/validation-escalation.md`） |
| **净增益** | 新增通过 − 回归数 | ⭐⭐⭐ 只报毛通过率会掩盖"换血"（59% 抵消的来源） |

三条的分工很清楚：

```
触发准确率  → 入口
输出合格率  → 出口
⭐ 净增益    → ⭐⭐⭐ 你到底是在变好还是在换血
```

> ⭐⭐⭐ **第三条最不可省**。前两条都涨、净增益为负，
> 说明你把一个技能改成了另一个技能，而不是改好了它。

**口径统一的三条硬要求**（否则数字无法跨版本比较）：

1. ⭐ 同一份 eval 集，不得中途换题
2. ⭐ 每条用例跑 ≥3 次取平均（单次会把偶然当能力）
3. ⭐ 模型版本要 pin——**换模型的数字不能和前一个模型比**

## 3. ⭐⭐⭐⭐⭐ 错误预算

```
错误预算 = 1 − SLO
```

例：输出合格率 SLO 定 90%，那 30 天窗口内的预算就是 **10% 的失败配额**。

```
窗口 30 天 · 1000 次调用 · 允许 100 次不合格
已用 87 次 → 剩 13 → ⭐ 本周期还能发版吗？
```

> ⭐⭐⭐ **预算的价值不在算出来，在它把两个部门的分歧变成一道算术题。**
> "要不要发这个改动"从争论变成了"还剩多少预算"。

三个设定要点：

| 项 | 建议 | 理由 |
|---|---|---|
| 窗口 | 30 天 | 太短噪音大，太长失去约束力 |
| SLO 起点 | ⭐ **先定得宽松，跑两个月再收紧** | ⭐ 一开始定 95% 会导致要么天天超预算、要么没人当真 |
| 计分范围 | ⭐ 只计入"技能实际被调用"的场景 | 未触发不算失败，否则误触发与漏触发会互相污染 |

## 4. ⭐⭐⭐ 预算耗尽后的三种状态

不要只有"停"和"不停"两档——那会让人绕过它：

| 状态 | 触发 | ⭐ 后果 |
|---|---|---|
| 🟢 正常 | 预算 > 50% | 正常发布 |
| 🟡 收紧 | 20% < 预算 ≤ 50% | ⭐ **只放行修复类改动**，新特性排队 |
| 🔴 冻结 | 预算 ≤ 20% | ⭐⭐ **停止一切非回滚类改动**，全力修质量 |

> ⭐⭐⭐ **关键是 🟡 这一档**。只有 🔴 的话，团队会在"还差一点就冻结"时
> 抢着把改动塞进去——那正是最危险的时候。

🔴 状态的退出条件也要先写死，否则冻结会变成无限期：

```
连续 7 天合格率回到 SLO 以上 → 解除
或 回滚到上一个达标版本 → 立即解除
```

## 5. ⭐⭐⭐ 谁来执行

| 角色 | 职责 |
|---|---|
| ⭐ 技能 Owner | 看自己的预算，决定发不发 |
| 平台/CI | ⭐⭐ 自动计算并在 PR 上标注"当前预算"，不达标直接阻断 |
| 团队 | ⭐ 只在 🟡/🔴 切换时介入 |

> ⭐⭐⭐ **预算必须显示在 PR 上**，不能只在 dashboard 里。
> 人只有在做决定的那一刻看到数字，数字才有用——
> 这与"把 P0/P1 后果写进门禁"是同一条原则。

## 6. ⭐⭐ 常见误用与仲裁

**误用一：把 SLO 当 KPI 考核个人**

```
❌ 用它给工程师排名
✅ 它是服务的健康度，不是人的绩效
```

理由很实际：**一旦变成考核，数字就会被优化**——
最简单的优化方式是偷偷放宽验收条件。

**误用二：所有技能都上 SLO**

```
⭐ 只给"进了生产、有人依赖"的技能上
   个人随手写的、只自己用的 → 不需要
```

这与 `skill-boundaries/references/worth-skillifying.md` 的可授权维度一致：**影响面决定治理强度**。

**误用三：与"质量分"混为一谈**

| | 九维 rubric | ⭐ SLO |
|---|---|---|
| 对象 | 技能本身写得好不好 | ⭐ 它在生产里表现好不好 |
| 时点 | 发布前一次性 | ⭐ 持续 |
| 用途 | 打分、找短板 | ⭐⭐ **执法：能不能发版** |

一句话：**rubric 是体检报告，SLO 是准驾证。**
