## 1. ⭐ 为什么必须有运维机制

```
传统系统自动化、接口功能：⭐ 上线稳定 = 永久稳定
技能：⭐ ⭐ 上线稳定 ≠ 永久稳定
```

> ⭐ 差别在于**技能的行为依赖于一个会变的模型**。
> 传统功能靠开发交付；**AI 能力靠运维交付。**

配套一句：**严禁"一次性写完永久不动"，采用轻量化迭代机制。**

## 2. 四段式运维体系

### ① 日常监控：线上稳定性巡检

```
周期：⭐ 每周例行
抽检样本：⭐ 本周真实线上调用记录 10–20 条

⭐ 四大检查项：
   1. 格式稳定性 —— 模板是否错乱、缺字段、缺模块
   2. ⭐ 内容准确性 —— 是否新增幻觉、编造信息
   3. 边界适配性 —— 新业务场景是否适配失效
   4. 语气规范 —— 是否出现口语化、多余解释

产出：《技能每周稳定性巡检报告》
```

> ⭐ 第 2 项单独列出很重要：**幻觉是会随模型更新新产生的**，
> 不是写完时没有就永远没有。

### ② 问题收集：建立技能问题工单池

**可收集的问题类型**：

```
输出格式不稳定 · 偶尔漏信息缺内容 · 出现编造错误结论 ·
新场景不兼容 · 输出太啰嗦或太简单 · ⭐ 模型波动导致效果下滑
```

**管理规则三条**：

```
· ⭐ 所有问题必须留存原始输入 + 原始输出
· ⭐ 每条问题归类：格式 / 幻觉 / 边界 / 风格
· ⭐ 纳入迭代版本排期，不堆积、不遗漏
```

> ⭐ 第一条是硬要求：**没有原始输入输出的工单无法复现，等于没记。**

### ③ 版本迭代：小步快跑

```
⭐ 节奏：
   小问题     → 周迭代
   中问题     → 双周迭代
   重大适配   → 专项迭代

迭代内容范围：
   强化防幻觉约束 · 锁死不稳定输出格式 · 新增边界场景兼容规则 ·
   优化话术精简冗余 · 补充缺失业务判断逻辑 · ⭐ 适配模型新版本波动
```

> ⭐ 最后一项是技能特有的：**模型换代时技能要跟着调**，
> 这是传统功能不存在的运维项。

### ④ 回归验收：迭代后必须全量回归

> ⭐ **每次更新必须做回归，否则越迭代越崩。**

```
四条通过标准：
   1. ⭐ 历史旧样本全部可用（不退化）
   2. 本次优化问题彻底解决
   3. 无新增副作用、无新增错乱
   4. 边界 case 稳定性提升

通过 → 更新版本号 + 留存迭代记录
```

## 3. ⭐ 三类问题的标准化迭代方案

| 问题 | ⭐ 迭代方案 | 具体动作 |
|---|---|---|
| **格式不稳定** | ⭐ 强制模板锁死 | 增强指令"严格遵循模板输出，禁止增减模块、禁止调整结构"；固定表格渲染规则；禁止随机开场白/结束语 |
| **幻觉编造** | ⭐ 强化溯源约束 | 新增"无依据不输出，不确定标注待确认"；新增"所有结论必须基于原文内容"；清理 AI 主观推测 |
| **场景不兼容** | ⭐ 补充边界规则 | 新增异常输入识别；新增场景匹配判断；新增专属兜底话术 |

> ⭐ 这张表的价值在于：**问题类型 → 方案类型是一一映射的**，
> 不用每次重新想怎么修。

**版本留存内容**（每次迭代必须存档，六项）：

```
1. 原版本完整 Prompt
2. 修改点明细
3. 解决的问题
4. 新增约束规则
5. ⭐ 回归测试样本
6. 上线时间、迭代人

⭐ 价值：可追溯、可回滚、可复盘、可团队传承
```

## 4. ⭐ S/A/B 分级

> 按重要性区分运维投入，**资源精准倾斜，不浪费运维人力**。

| 级别 | 定义 | 巡检 | 响应 |
|---|---|---|---|
| **S 级** | ⭐ 高频、全员使用、业务依赖强 | ⭐ 每周 | ⭐ 问题 24 小时响应，迭代优先级最高，样本库持续扩充 |
| **A 级** | 部门级常用 | 双周 | 问题按需迭代 |
| **B 级** | 个人辅助、低频场景 | 按需 | ⭐ 问题积累到一定量级统一优化 |

> ⭐ 分级的关键收益是**允许 B 级暂时不修**——
> 不分级的话，要么全修（浪费），要么全不修（出事）。

## 5. ⭐ 五条运维红线

```
1. ⭐ 禁止无记录随意修改技能
2. ⭐ 禁止不做回归直接上线
3. ⭐ 禁止积累大量 Bug 长期不迭代
4. ⭐ 禁止一个技能无限叠加复杂逻辑（复杂场景必须拆分子技能）
5. ⭐ 禁止模型变差不做人工干预、放任输出降级
```

> ⭐ 第 4 条与 `granularity-atomic-workflow.md` 的拆分信号呼应；
> ⭐ 第 5 条是技能特有的红线——**模型波动不是"环境抖动，等它自己好"，
> 而是要人去改技能适配。**

## 速查

```
□ ⭐ 上线稳定 ≠ 永久稳定（技能依赖会变的模型）
□ 严禁一次性写完永久不动

四段式：
□ 监控：每周抽检 10–20 条，四检查项（格式/⭐幻觉/边界/语气）
□ 收集：⭐ 必须留存原始输入+输出，四分类（格式/幻觉/边界/风格）
□ 迭代：小问题周 / 中问题双周 / 重大专项
□ ⭐ 回归：四条标准，不做回归禁止上线

三类问题映射：
□ 格式不稳定 → 模板锁死
□ 幻觉编造   → 溯源约束
□ 场景不兼容 → 补充边界规则

版本留存六项：
□ 原 Prompt / 修改点 / 解决的问题 / 新增规则 / ⭐回归样本 / 时间与迭代人

分级：
□ S 级每周巡检 + 24h 响应
□ A 级双周
□ B 级积累到量级再统一优化

五红线：
□ ⭐ 无记录修改 / 不回归上线 / 长期不迭代
□ ⭐ 无限叠加复杂逻辑（要拆子技能）
□ ⭐ 模型变差放任降级
```

**一句话**：

> ⭐ **传统功能靠开发交付，AI 能力靠运维交付。**
