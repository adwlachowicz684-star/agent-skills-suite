## 1. ⭐⭐⭐⭐⭐ 分类判据：看到什么 / 知道什么 / 世界变成什么

```
① ⭐⭐⭐ 产物型  —— 用户要"看到什么"：报告、清单、代码、摘要、图表
② ⭐⭐⭐⭐⭐ 判定型 —— 用户要"知道什么"：是否合规、属于哪类、风险等级、能不能合并
③ ⭐⭐⭐⭐ 变更型  —— 用户要"世界变成什么"：创建工单、发邮件、改配置、合并 PR
```

> ⭐⭐⭐⭐⭐ **一个技能常常同时是两类，而正文只按其中一类写契约——
> 这就是"输出看起来完整但没用"的高发区。**

判定方法：看用户拿到输出后做的第一个动作是什么。

```
读它        → 产物型
照它做决定  → 判定型           ← ⭐⭐⭐⭐⭐ 这一类最容易被当成产物型来写
什么都不用做 → 变更型
```

---

## 2. ⭐⭐⭐⭐⭐ 三类产出的默认失败各不相同

| | 默认失败 | 为什么没人报 |
|---|---|---|
| 产物型 | ⭐⭐⭐⭐⭐ 停在任意位置（缺分母） | 输出读起来完整，只是少了几条——而没人知道少了 |
| ⭐⭐⭐⭐⭐ 判定型 | ⭐⭐⭐⭐⭐ 硬猜（缺弃权项） | 有结论、有依据格式、看起来专业 |
| 变更型 | ⭐⭐⭐⭐ 局部成功 | 返回的 JSON 是 ok，只是世界没变成那样 |

三行的共同点：

> ⭐⭐⭐⭐⭐ **每一类的失败在"输出文本"这一层都是绿的。**
> 所以只断言输出文本，三类全都测不出来。

## 3. ⭐⭐⭐⭐⭐ 产物型：缺分母就停在任意位置

契约三件套（详见 `skill-output/references/enumeration-and-completeness.md`）：

```
分母（一共应该有多少）· 每单元产出上限 · "全部处理完"的可判定信号
```

> ⭐⭐⭐⭐⭐ 少了分母，它停在哪里取决于⭐⭐⭐ **它恰好看到了多少**，
> 而不是实际有多少——于是同一个技能两次运行产出数量不同，且都不报错。

---

## 4. ⭐⭐⭐⭐⭐ 判定型：最容易拿高分却没用

### 4.1 先验分布陷阱

```
测试集里 90% 的样本是"合规"
→ 一个永远回答"合规"的技能 = 90 分
```

> ⭐⭐⭐⭐⭐ **这是判定型技能独有的失效方式**：
> 产物型抄不出来（要生成内容），变更型抄不出来（要真的改），
> ⭐⭐⭐⭐⭐ **只有判定型可以靠"总是猜同一个答案"拿到很高的分。**

修法两条：

```
① ⭐⭐⭐⭐⭐ 报各类别单独统计，不报总准确率
② ⭐⭐⭐⭐⭐ 测试集的类别分布要刻意均衡，甚至反真实分布
```

第二条反直觉但必要：

> ⭐⭐⭐⭐⭐ 它测的是"能不能分辨"，不是"猜得准不准"。
> 按真实分布做测试集，等于奖励那个"猜多数类"的技能。

### 4.2 必须有弃权项

```
类别集合 = {高, 中, 低}          ← 封闭集合
⭐⭐⭐⭐⭐ 缺的那一类："无法判定"
```

> ⭐⭐⭐⭐⭐ **不属于任何一类时，模型会选最接近的一类——
> 而判定技能的全部价值恰恰在于它敢说"无法判定"。**

这与 `skill-precision/references/enumeration-closed-vs-open.md` 完全同源：
列表外的输入被默认归类，且静默。

### 4.3 依据字段不可省

```
❌ {"risk": "high"}
✅ {"risk": "high", "basis": "第 3 条（涉及生产写操作）", "confidence": "中"}
```

`basis` 的两个作用（见 `skill-examples/references/decision-rationale-output.md`）：

```
① ⭐⭐⭐⭐ 排错时不需要重跑
② ⭐⭐⭐⭐⭐ 可被统计：某条规则被频繁引用却常判错 → 它该进 Gotchas
```

## 5. ⭐⭐⭐⭐⭐ 变更型：断言的对象是世界，不是输出

```
❌ 断言输出包含 "已创建工单 PROJ-123"
✅ 断言工单系统里存在 PROJ-123，且字段与请求一致
```

> ⭐⭐⭐⭐⭐ **"输出说成功了"和"世界真的变了"之间没有任何机制保证一致。**
> 这与 `skill-recovery/references/execution-error-protocol.md` 同源——
> 那份是技能返回了错误而模型把它改写成成功；
> ⭐⭐⭐⭐ 这份是技能返回了成功，而世界没变。

契约要点：

```
① ⭐⭐⭐⭐⭐ 变更前后的值（diff 可见）
② ⭐⭐⭐⭐⭐ 可逆性 / 补偿动作（见 skill-recovery 的 reversibility-and-undo）
③ ⭐⭐⭐⭐⭐ 幂等键（重跑不产生第二个对象）
④ ⭐⭐⭐⭐ 写入后回读校验（不是"发出请求"就算完成）
```

---

## 6. ⭐⭐⭐⭐⭐ 混合型：判定错了会被变更固化

```
判定为高风险 → 自动创建工单 / 自动拒绝 PR / 自动回滚
```

> ⭐⭐⭐⭐⭐ **判定的错误会被变更固化：判定错了，工单已经在那儿了。**
> 产物型判错了只是输出不对，改一版就行；
> ⭐⭐⭐⭐⭐ 变更型判错了，后果已经进入世界，且可能已经被人看到。

所以判定与变更之间必须有：

```
① ⭐⭐⭐⭐⭐ 阈值（什么等级才触发变更，而不是一有判定就触发）
② ⭐⭐⭐⭐⭐ 人工确认点（见 skill-execution 的 human-checkpoint-design）
③ ⭐⭐⭐⭐ 记录判定的 basis，供事后复核
```

> ⭐⭐⭐⭐ 判据：**如果这个判定错了，撤销的成本是多少？**
> 成本高 → 中间必须站一个人。

## 7. ⭐⭐⭐⭐ 一栏对照表

| | 产物型 | 判定型 | 变更型 |
|---|---|---|---|
| 用户要 | 看到什么 | 知道什么 | 世界变成什么 |
| 契约要点 | 分母 + 单元上限 + 完成信号 | ⭐⭐⭐⭐⭐ 封闭类别 + 弃权项 + basis | 前后值 + 可逆/补偿 + 幂等键 |
| 默认失败 | 停在任意位置 | ⭐⭐⭐⭐⭐ 硬猜 | 局部成功 |
| eval | 结构 + 要素比对（快照三选二） | ⭐⭐⭐⭐⭐ 金标准 + 类别均衡测试集 + 各类别分别统计 | ⭐⭐⭐⭐⭐ 断言世界状态，不断言输出 |
| 成本风险 | 长度膨胀 | ⭐⭐⭐⭐ 高分假象 | ⭐⭐⭐⭐⭐ 不可撤销 |

## 8. ⭐⭐⭐⭐ 自检

| 问 | 不通过时 |
|---|---|
| 用户拿到输出后做的第一个动作是"读/决定/什么都不做"中的哪一个 | 说不清 → 契约按错了类型写 |
| ⭐⭐⭐⭐⭐ 能不能回答"一共处理了多少个" | 不能 → 产物型的分母缺失 |
| ⭐⭐⭐⭐⭐ 类别集合里有没有"无法判定" | 没有 → 判定型会硬猜 |
| ⭐⭐⭐⭐⭐ 测试集里多数类占比是否 > 70% | 是 → 分数虚高 |
| ⭐⭐⭐⭐⭐ eval 断言的是输出文本还是世界状态 | 变更型断言文本 → 测不出局部成功 |
| ⭐⭐⭐⭐ 判定与变更之间有没有阈值和确认点 | 没有 → 判定错误被固化 |

## 速查

```
□ ⭐⭐⭐⭐⭐ 判据：用户要"看到什么 / 知道什么 / 世界变成什么"
□ ⭐⭐⭐⭐⭐ 三类失败在输出文本层都是绿的 → 只断言文本，三类全测不出
□ ⭐⭐⭐⭐⭐ 判定型独有陷阱：测试集不均衡 → 永远猜多数类就能拿 90 分
□ ⭐⭐⭐⭐⭐ 判定型必须有"无法判定"这一项，否则列表外输入被默认归类
□ ⭐⭐⭐⭐⭐ 变更型必须断言世界状态（回读），不是断言输出
□ ⭐⭐⭐⭐⭐ 判定→变更的链上必须有阈值 + 人工确认点：判定错了会被固化
□ ⭐⭐⭐⭐ 产物型的分母：能不能回答"一共处理了多少个"
□ ⭐⭐⭐⭐ basis 字段可统计 → 常被引用的规则若常错，它该进 Gotchas
```

**一句话**：

> ⭐⭐⭐⭐⭐ **先分清用户要的是"看到什么、知道什么、还是世界变成什么"——三类产出的失败在输出文本层全都是绿的，所以只断言文本就三类都测不出：产物型缺分母会停在任意位置，判定型在没有弃权项时会硬猜、且在不均衡测试集上靠"永远猜多数类"就能拿 90 分，变更型则可能返回了 ok 而世界根本没变。**
