> 这份讲⭐⭐⭐⭐⭐ **污染不止发生在第二次调用——它发生在后续整个对话里，包括不再调用技能的时候**，
> 因为输出已经进入了上下文，而模型无法区分"这是我生成的"和"这是用户提供的"。

## 1. ⭐⭐⭐⭐⭐ 模型读上下文时不区分"谁写的"

对话历史里有两种文本：

```
用户说的：  "我们只统计付费用户"
模型说的：  "上月留存率 41%"
```

> ⭐⭐⭐⭐⭐ **对模型而言这两句在结构上是同一类东西——都是上下文里的既有文本。**
> 没有标签、没有来源字段、没有置信度。它读到"41%"，就和读到"只统计付费用户"一样，当作给定条件。

于是第一轮里那个带猜测的数字，在第二轮变成了一条**无需再验证的前提**。
而且它比用户输入更"好用"——⭐⭐⭐⭐ 因为它更具体、更像结论、且格式规范。

## 2. 自我确认闭环

```
轮 1：技能输出"留存率 41%"（其中含一次未声明的口径选择）
轮 2：用户问"留存率为什么低" → 模型以 41% 为前提展开分析
轮 3：用户问"改善建议"     → 结论建立在轮 1、轮 2 之上
```

> ⭐⭐⭐⭐⭐ **每一轮都在确认前一轮，而确认的依据是前一轮的输出本身——没有任何一轮回到数据源。**

闭环的三个特征，全部指向"难发现"：

```
① ⭐⭐⭐⭐⭐ 它不产生矛盾（后一轮与前一轮一致，所以自检永远通过）
② ⭐⭐⭐⭐⭐ 它越往后越具体（细节增加 → 看起来越可信）
③ ⭐⭐⭐⭐ 用户的追问在强化它（追问 = 接受了这个前提）
```

第③条最值得记：**用户越认真地追问，这个错误被加固得越牢**——
因为每一轮追问都在增加"围绕这个数字建立的推理"，而推翻它的成本随之上升。

## 3. ⭐⭐⭐⭐⭐ 纠正在结构上更贵

纠正需要用户说出一句几乎没人会说的话：

```
"你上一轮那个数字是编的"   ← 用户不知道
"请重新验证上上轮的结论"   ← 用户不知道需要
```

> ⭐⭐⭐⭐⭐ **用户看到的是一份自洽的分析，他没有任何线索知道该怀疑哪一步。**
> 而怀疑的线索恰恰在技能那一侧（哪一步是推断、哪一步没取到数），不在输出里。

于是常见结局是：错误结论被带进下一份产出，而那份产出看起来更完整、更正式。

## 4. ⭐⭐⭐⭐⭐ 最危险的一类：不可追溯的结论

| 输出中的信息 | 后续轮能验证吗 |
|---|---|
| ⭐⭐⭐⭐ 带取数口径与时间窗 | 能（照着再算一遍） |
| ⭐⭐⭐ 带来源路径 | 能（打开看） |
| ⭐⭐⭐⭐⭐ 只有一个数字或一句判断 | ⭐⭐⭐⭐⭐ **不能——没有任何可复核的东西** |

> ⭐⭐⭐⭐⭐ **不可追溯的结论一旦进入上下文，就永久获得了事实的地位**，
> 因为后续没有任何办法把它和真的事实区分开。

这正是"输出要写依据"的第二重理由：

```
第一重：评审时看得懂（当时的人能判断）
⭐⭐⭐⭐⭐ 第二重：后续轮能复核（后来的人/后来的轮次能验证）
```

> ⭐⭐⭐⭐⭐ 而第一重往往被当成全部理由——于是很多输出写了"因为"，
> 但写的是⭐ 解释（"因为它更合理"）而不是⭐⭐⭐⭐⭐ 依据（"按规则 3b，A=3 人日"）。
> 解释不可复核，依据可复核。

## 5. 三条修法

**① 输出自带可复核信息**（成本最低，收益最直接）

```
统计区间：2026-09-22 ~ 2026-09-29
口径：仅付费用户，去重按 user_id
来源：warehouse.orders（路径/hash）
```

约 30–50 token，换来的是⭐⭐⭐⭐⭐ **后续任何一轮都能重新验证，而不必继承**。

**② 置信度分档，不用百分数**

```
实测 / 推断 / 未获取
```

> ⭐⭐⭐⭐⭐ 分档的意义是把"这条能不能当事实用"变成后续轮可以判断的东西。
> 而"置信度 0.73"是假精度——它看起来更精确，但没人知道 0.73 是怎么来的。

**③ ⭐⭐⭐⭐⭐ 技能不得假设上下文里的既有结论是真的**

正文要写明这一条，否则模型默认继承：

```
需要用到上下文中已存在的数字/结论时：
  ⭐⭐⭐⭐⭐ 若它带有可追溯来源 → 沿用
  ⭐⭐⭐⭐⭐ 若没有 → 重新计算，不得引用
```

> ⭐⭐⭐⭐⭐ 这条是三修法里唯一能真正切断闭环的——
> 前两条是让验证"成为可能"，这一条是让验证"必须发生"。

## 6. ⭐⭐⭐⭐ 与"写了依据的输出排错时不需重跑"的关系

两条规则指向同一个机制，但作用方向相反：

```
写依据 → ⭐⭐⭐⭐ 出错点直接可见（排错不需重跑）
不写依据 → ⭐⭐⭐⭐⭐ 输出进入上下文后变成不可复核的事实（错误被继承）
```

> ⭐⭐⭐⭐⭐ 合起来看：**写依据不是"输出更好看"的改进，是把输出从"不可证伪"变成"可证伪"。**

顺带解释了一个常见现象：⭐⭐⭐⭐ 为什么"看起来专业的输出"反而更容易带偏后续——
越专业就越少被怀疑，而它是否可复核与是否专业**完全无关**。

## 7. 检查清单

- [ ] ⭐⭐⭐⭐⭐ 输出首部带可复核信息（口径 / 时间窗 / 来源路径）
- [ ] ⭐⭐⭐⭐⭐ 每个关键结论标注"实测 / 推断 / 未获取"三档，不用百分数
- [ ] ⭐⭐⭐⭐⭐ 正文写明：上下文里没有可追溯来源的既有结论，重新计算，不得引用
- [ ] ⭐⭐⭐⭐ 输出的"因为"必须是依据（指向输入与规则），不是解释
- [ ] ⭐⭐⭐⭐ 派生数字标明算法，便于后续轮复算
- [ ] ⭐⭐⭐ 用户追问时，技能应能指出结论依赖的是哪一轮的哪个前提
