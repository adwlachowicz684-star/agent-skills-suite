## 1. ⭐⭐⭐ 5832 次对照实验的核心数字

```
⭐ 给 Agent 添加 Skill 平均仅提升少量任务通过率
⭐⭐ 但约 ⭐⭐⭐ 59% 的新增能力收益会被原有能力的损耗抵消
⭐⭐ 实际应用中 ⭐ 不加载 Skill 反而效果更稳定
```

**原始计数**：

```
5832 次对照实验
  技能新增  553 次成功
  同时带来  324 次失败
  ⭐⭐ 新增失败抵消了 59% 的毛收益
```

> ⭐⭐⭐ **"没有一套 Skill 能做到只加能力不伤原有能力。"**

## 2. ⭐⭐⭐ 为什么平均通过率会骗人

> ⭐⭐ **传统评测仅统计平均通过率，
> ⭐⭐⭐ 无法区分"能力净增长"与"能力换血"。**

```
相同的平均提升，两种完全不同的实质：

A：扩大了能力边界（原来不会做的现在会了，原来会的还会）
   → ⭐ 净增长

B：新增了能力，⭐ 同时破坏了大量原有能力
   → ⭐⭐ 换血

⭐⭐ 两者平均分可能一样，⭐⭐⭐ 可靠性差异极大
```

**这意味着一个具体的测量要求**：

```
❌ 只记 avg pass_rate
✅ ⭐⭐⭐ 必须分别记：
   · ⭐ 基线通过 → 新版本失败  （⭐⭐ 回归 / 能力损耗）
   · ⭐ 基线失败 → 新版本通过  （新增能力）
   → ⭐⭐ 净增益 = 新增 − 回归
```

> ⭐⭐⭐ 这个"净增益"口径是本份最重要的可操作结论。
> 它与 `skill-lift-eval.md` 的 NVIDIA 数据不冲突而是⭐ 互补：
> **NVIDIA 测的是各维度提升（毛），这份测的是扣掉损耗后的净。**
> 一个技能可以同时"+41 正确性"和"损耗 59%"——
> ⭐ 因为正确性提升可能集中在新增场景，而损耗发生在原有场景。

## 3. ⭐⭐ 没有一套技能能做到只加不伤

> ⭐⭐ 这是一条**全称否定**，而且是基于 5832 次实验的。
> 它意味着⭐ **"找一个零副作用的技能"不是目标**——不存在。

**正确的目标应该是**：

```
⭐ 让净增益为正，并且知道副作用落在哪里
```

**推论**（对库规模问题）：

```
⭐ 既然每加一个技能都有损耗，
⭐⭐ 那么"装得越多越好"不仅错，而且是⭐ 系统性变差
```

> ⭐⭐⭐ 这为 `library-size-effect.md` 的"遮蔽"提供了一个⭐ 不同的机制解释：
> 那份归因于"技能之间抢触发"，
> 这份提出了第二条路径——⭐ **即使没触发，常驻的描述也在改变行为**。

## 4. ⭐⭐⭐ 常驻描述会潜移默化改变行为

> ⭐⭐ **多数 Agent 框架会将 Skill 描述⭐ 常驻上下文、仅触发后加载正文。**
> ⭐⭐⭐ **即使未调用 Skill 正文，⭐ 描述中的概念也会渗入 Agent 判断。**

两个具体后果：

```
① ⭐ 引发输入锚定偏移（anchoring shift）
② ⭐⭐ 验证环节被挤占
```

> ⭐⭐⭐ 第 ② 条特别值得注意，因为它解释了一类"说不清哪里不对"的退化：
> **你装的技能越多，agent 用于自检的余量越少——
> 而没有任何日志会记录这件事。**
>
> ⭐⭐ 这与 `skillsbench-vs-realworld.md` 那条
> "弱模型有技能反而更差（无关技能消耗 token 去加载无用指令）"、
> `skill-reducer-study.md` 的"压缩后质量反升 2.8%（减少干扰）"
> 是⭐⭐⭐ 第三个独立来源的同一结论：
> **占用上下文的东西，即使正确，也有成本。**

**顺带一个诚实的自我观察**（原文作者）：

```
"除了那些有着我鲜明个人特色需求的 skill，
 ⭐ 不加载 skill 纯模型输出的效果也没想象中差。"
```

> ⭐⭐⭐ 这句和 `skillsbench-vs-realworld.md` 的结论完全对上了：
> **通用软件工程类场景技能收益只有 ~4.5pp**，
> 而⭐ 收益大的正是"有自己的一套做法"的地方。
> 两个独立来源指向同一条：
> **技能的价值在⭐ 个人/团队独特方法论，不在通用知识。**

## 5. ⭐⭐ 这条发现怎么改变你的做法

**测量上**：

```
□ ⭐⭐⭐ 分别统计"新增通过"与"新增失败"，报⭐ 净增益
□ ⭐⭐ 对每个技能单独测，⭐ 而不是只测整个库
   （否则一个高收益技能会掩盖三个负收益技能）
□ ⭐⭐ 对照组必须"完全不加载"，
   而不是"加载另一个技能"（后者测的是 A vs B，不是有 vs 无）
```

**库管理上**：

```
□ ⭐ 装技能要有⭐ 准入门槛，不是越多越好
□ ⭐⭐ 定期做"减法测试"：
   逐个禁用，看净增益是不是反而变好
   ⭐⭐ 这是唯一能发现"这个技能其实在拖后腿"的方法
□ ⭐⭐⭐ 优先保留⭐ 有鲜明独特方法论的技能；
   ⭐ 通用知识类技能是损耗的主要来源
```

> ⭐⭐⭐ 最后这条是整套收藏里对"哪些技能该留"给出的⭐ 最明确的答案。
> 它与 `worth-skillifying.md` 的五维矩阵、
> `skill-scope-tiering.md` 的"触发空壳"是同一条线的三个落点。

**一处诚实的边界**：

```
⚠️ 这份来源未公开实验的具体技能集与任务集构成。
   59% 这个数字应视为⭐ 一个强烈的警示信号，
   而不是可外推到你环境的精确常数。
   ⭐⭐ 用法：用它来⭐ 质疑"我只看了平均通过率"这件事，
       而不是用来预测你会损失多少。
```


**一句话**：

> ⭐⭐⭐ **平均通过率分不清"能力净增长"和"能力换血"——
> 必须分别统计新增通过和回归（基线通过却新版失败），

> 而没有一套技能能做到只加能力不伤原有能力。**
