## 从快到慢的四级排查

| 步骤 | 耗时 | 做什么 |
|---|---|---|
| **1. 重载** | **2 秒** | 执行 `/reload-skills`（或对应客户端的重载命令），重新扫描目录 |
| **2. 验证** | **10 秒** | 直接问它："你那个 XXX 技能现在的流程是什么？" |
| **3. 开新会话** | **10 秒** | `/new` 或 `/reset`——新会话从头读取所有技能文件 |
| **4. 查格式** | — | 用查看命令检查，加载失败会提示格式错误 |

> **第 1 步能解决 90% 的案例；到第 3 步 99% 都能解决。**

**终极手段**：如果你手动改了很多次、前后逻辑已经乱了——
**"把这个技能删了，按我说的重新创一个。"**
让 agent 从零重建，反而比反复 patch 省心得多。

## 第 0 步：先确认真的重载了

> ⚠️ **重启客户端往往没用。**
> 技能系统有自己的缓存与注册表——**你重启 100 次，技能还是旧的**。

**按客户端分**：

```
□ 有 /reload-skills 或 /reload 的 → 先执行它（不重启、不新会话）
□ 重启才生效的 → 确认 name / description 改动（这两个是启动时读的）
□ 有自动热重载的 → 确认开关开着（如 skills.load.watch = true）
```

> **一个关键区分**：
> **纯技能正文改动**通常热重载即可；
> **涉及工具策略变更或 System Prompt 注入逻辑调整的**，
> **必须在全新会话里重建上下文**才体现。

**热重载失效时先查这三个高频原因**：

```
□ 目录放错了（不在被监听的技能目录下）
□ 文件后缀/文件名不对
□ 权限问题（当前用户无读写权限 → chmod -R 755）
```

## 热重载机制

**自动热重载**（部分实现默认开启）：

- 检测到 SKILL.md 变更 → **约 250ms 内**自动重新加载
- 依赖**文件系统事件监听**，无需人工干预
- 前提：监听开关为 `true`、文件时间戳确实更新了

**手动强制重载**：

```bash
openclaw skills reload        # 例：立即刷新全部已加载技能
# 输出：Reloaded 17 skills from ./skills and ~/.openclaw/skills
```

> 该命令**不重启网关进程**，不影响正在运行的会话。

**文件监听缓存问题**（偶发）：

```bash
rm -rf ~/.cache/skill-watch    # 删缓存
<重启网关>
```

## 手动验证闭环

> 当自动机制都不生效时，逐级手工验证：

```
1. 确认文件位置与权限
   ls -la <skills 目录>/      # 权限 644，扩展名正确

2. 手动导入测试（最关键的一步）
   在 REPL 里 require 那个文件，看是否抛 SyntaxError

3. 检查编译产物
   .ts 源文件是否有对应 .js 产物，或自动编译是否开启

4. 验证函数签名
   node -e "const s=require('./x.js'); console.log(typeof s.default)"
   → 必须输出 function

5. 强制重载并看日志
   openclaw skill reload <name>
   → 观察日志里是否出现 "Reloaded skill <name>"
```

> **第 2 步最关键**——它能区分"文件有问题"和"加载器有问题"。

## 验证：别信"应该生效了"

> ⭐ **改完之后马上问一句：
> "你那个 XXX 技能现在的流程是什么样的？"**

如果它说的跟你的改动**对得上**，说明加载成功了。

> 这一步正好呼应 `skill-evaluating` 里主张的：
> **每条结论都要有证据，禁止"应该""看起来"。**
> 加载成功也一样——**要让它复述出来给你看**。

## 两个技能矛盾时听谁的

> 这是高手才会碰到的问题。

**一般规则**（呼应 `discovery.md`）：

```
项目级 > 全局级
嵌套最近的 > 上层的
```

**一个值得注意的新行为**：部分实现在**同名冲突**时，
会把嵌套的那个暴露成 `<外层名>:<内层名>`——**两个都保留、都可用**，
而不是一个覆盖掉另一个。

> 所以当你发现"改了没生效"，先确认：
> **是不是有一个同名但位置更靠前的技能在遮蔽它？**

## 自查

```
□ 是否先执行了重载命令（而非重启客户端）？
□ 是否让 agent 复述了一遍技能内容来验证？
□ 是否试过开新会话（工具策略类改动必须）？
□ 目录是否在被监听的路径下？
□ 文件权限与后缀是否正确？
□ 是否有同名技能在更高优先级位置遮蔽它？
□ 是否查了日志里的 "Reloaded skill <name>"？
□ 反复 patch 无效时，是否考虑过删了重建？
```
