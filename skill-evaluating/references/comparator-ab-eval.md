## 1. ⭐ comparator agents：盲评

官方 skill-creator 新增了 comparator agents 做 A/B 比较：

```
两个技能版本，或技能 vs 无技能
⭐ 评委在不知道哪个是哪个的情况下评判输出
```

> ⭐⭐ **盲评是这个机制的关键**——
> 不盲的话，评委知道自己看过哪个版本、或者知道"哪个是新的"，
> 就会产生系统性偏差。这与 `judge-design.md` 的"换一个全新实例来审"同源。

**为什么必须并行独立跑**：

```
顺序跑 eval 有两个问题：
  ① 慢
  ② ⭐ 累积的上下文会在测试之间渗透（bleed）

⭐ 解法：每个 eval 起一个独立 agent
  ——干净上下文、各自的 token 与计时指标
  ——⭐ 更快，且无交叉污染
```

> ⭐ 第 ② 条解释了"为什么测试结果会莫名其妙地漂移"：
> 不是技能变了，是**上一轮的上下文渗到了这一轮**。

## 2. ⭐ benchmark mode

```
⭐ 用你的 evals 跑一套标准化评估
```

**三个用途**：

```
① ⭐ 模型更新之后跑一次
② 迭代技能的过程中跑
③ 作为回归基线
```

**追踪三个指标**：

```
⭐ eval 通过率 · 耗时 · token 用量
```

> ⭐ 官方明确：**你的 evals 和结果留在你手里**——
> 可以本地存、接 dashboard、或接入 CI。
> 这保证了评测不被平台锁定。

## 3. ⭐ 三种对照对象

```
① 技能 v1 vs 技能 v2      —— 改了有没有变好
② 有技能 vs 无技能        —— ⭐ 这个技能到底有没有用
③ 技能 A vs 技能 B        —— 两个实现选哪个
```

> ⭐ 第 ② 种最容易被跳过，但它才是"这个技能该不该存在"的证据。
> 许多技能从未做过这个对照，于是**没人知道它是不是只是让输出变长了**。

## 4. ⭐⭐ 统计纪律：五条不能犯的错

**① 偷看（peeking）**

```
⭐ 在达到样本量之前查看结果
⭐ 会把假阳性率从 5% 抬到 26%+
```

**② 提前停止**

```
⭐ "达到显著" ≠ "达到所需样本量"
⭐ 测试必须跑满计划的样本量
```

**③ 事后定义成功标准（HARKing）**

```
⭐ 看到初步结果之后再定义成功标准 = HARKing
   （Hypothesising After Results are Known）
⭐ ⭐ 这会直接让实验失效
```

> ⭐ 这条与 `trace-debugging.md` 的"先写恢复契约再注入故障"是同一条：
> **标准必须在看到数据之前写下。**

**④ 把统计显著当成实际显著**

```
⭐ p < 0.05 但提升只有 0.1%
   ——结果是真的，但可能不值得上线
```

> ⭐ **统计显著回答"是不是真的"，实际显著回答"值不值得"。**
> 两者必须分开评估。

**⑤ 多指标 / 重复测试**

```
⭐ 不要用多个主指标——需要多重假设校正，且让上线决策变得含糊
⭐ 同一人群反复跑同一实验要做事后校正
```

**样本量公式**（需要时可用）：

```
每组所需样本 = 16 × p × (1-p) / MDE²

p   = 基线转化率（小数）
MDE = 最小可检测效应（小数）
```

**最短运行时长**：

```
⭐ 至少 2 个完整业务周（覆盖星期效应）
⭐ 即使提前达到了样本量也要跑满
```

## 5. 决策框架

| 结果 | 建议 |
|---|---|
| 显著正向提升，护栏指标无虞 | **上线**，推到 100% |
| ⭐ 显著正向提升，但护栏指标有恶化 | **先调查**，理解权衡再上线 |
| 不显著，但趋势为正 | 延长测试（需要更多数据或更大效应） |
| 不显著且持平 | 停止测试 |
| 显著负向 | 不上线，回退并分析原因 |

**上线前必须核对的三件事**（来自结果解读阶段）：

```
□ 测试是否跑满了计划时长（没跑满要标出来——偷看问题）
□ ⭐ 是否发生了样本比例失衡（SRM）
□ 是否有新奇效应/季节因素等混淆
```

## 速查

```
□ ⭐ comparator 必须盲评（评委不知道哪个是哪个）
□ ⭐ 并行独立 agent 跑，避免上下文渗透
□ ⭐ benchmark 追踪三指标：通过率 / 耗时 / token
□ ⭐ 模型更新后要重跑一次
□ ⭐ 三种对照：v1 vs v2 / 有 vs 无 / A vs B
□ ⭐⭐ "有 vs 无"最常被跳过，但它是"该不该存在"的证据

统计纪律：
□ ⭐ 不偷看（假阳性 5% → 26%+）
□ ⭐ 不提前停（显著 ≠ 样本够）
□ ⭐ 成功标准先写（事后定义 = HARKing，实验作废）
□ ⭐ 统计显著 ≠ 实际显著
□ ⭐ 单一主指标，多指标要校正
□ ⭐ 至少跑满 2 个完整业务周
□ ⭐ 解读时核对：跑满时长 / SRM / 混淆因素

决策：
□ 显著+护栏好 → 上线
□ ⭐ 显著+护栏差 → 先调查
□ 不显著+趋势正 → 延长
□ 不显著+持平 → 停止
□ 显著负 → 回退分析
```

**一句话**：

> ⭐ **"达到显著"不等于"达到样本量"，
> 而"看到结果后再定标准"会让整个实验作废。**
