## 1. ⭐⭐⭐ 优先级铁律

**症状**：技能成功调用，但输出不按规则来、时好时坏、逻辑跑偏。

```
⭐⭐⭐ 临时 Prompt > 技能内置规则 > 全局 Rule
```

> ⭐⭐⭐ **大部分输出异常，都是⭐ 高优先级规则覆盖了技能逻辑。**
>
> 这条很关键，因为它把排查方向从"我的技能写错了"
> 转向了"**有什么东西盖过了我的技能**"——
> 这两者的修法完全不同。

---

## 2. 冲突一：全局 Rule 覆盖技能

```
场景：技能要求输出 JSON，实际一直输出 Markdown
原因：⭐ 全局 rules.md 统一规定输出格式，优先级更高
```

**修法**：

```
⭐ 在技能开头明确声明：
   "本技能输出规则优先，覆盖全局规则"
```

> ⭐ 这条修法看起来"粗暴"，但它是必要的——
> **技能是被复用到你没预想的上下文里的**，
> 全局规则的作者并不知道你的技能需要例外。
>
> ⭐ 更稳的做法是同时说明"为什么"（呼应 `write-reasons-not-rules.md`）：
> "本技能下游解析器只接受 JSON，故输出规则优先于全局格式约定。"

## 3. ⭐⭐ 冲突二：用户临时 Prompt 覆盖技能

```
场景：完整的技能流程被用户一句"简单说说"直接简化作废
```

**修法**：

```
⭐ 增加容错规则：
   "⭐ 即使用户要求简化，⭐ 必须保留核心步骤，
    ⭐ 不得省略关键内容"
```

> ⭐⭐ 这条非常实用，因为它处理的是**一个几乎必然发生的情况**：
> 用户会用"简短点""不用那么详细"来压缩输出，
> 而技能里那些"关键步骤"恰恰会被一起压掉。
>
> ⭐ 写法要点：**不能只写"不能简化"，要写明"哪些不可省略"**
> ——又一次印证"禁令必须带替代/保留清单"。

---

## 4. ⭐ 冲突三：多技能边界重叠

```
场景：同时开启"代码审查"和"Bug 修复"技能
     ⭐ AI 无法选择，⭐ 干脆全部不用
```

**修法**：

```
⭐ 每个技能明确职责边界：
   代码审查：只查问题、给建议，⭐ 不修改代码
   Bug 修复：定位问题、⭐ 直接输出修正代码
```

> ⭐⭐ 注意"干脆全部不用"这个结果——
> 这与 `library-size-effect.md` 的"遮蔽"、
> `namespace-collision.md` 的"互相稀释触发概率"是同一个现象：
> **重叠的代价不是"选错"，是"一个都不选"**。

---

## 5. ⭐⭐ 用非作者的措辞测试

> ⭐⭐ **不要用你写 description 时的那句话去测试。**

```
⭐ 用⭐ 同一个任务的 10 种不同说法来测
⭐ 更好：⭐ 请一位从没读过你 description 的同事描述他想要什么，
        ⭐ 用他的原话
```

> ⭐⭐⭐ **"手动测试用的是你自己的措辞——
> 也就是你写 description 时用的措辞。当然会匹配。"**
>
> 这与 `troubleshooting-manual.md` 里那条
> "没有反馈闭环是元问题中的元问题"完全一致，
> 但这里给了⭐ 可执行的解法（找同事要原话）。

**覆盖率目标**：

> ⭐ **让 description 能匹配 80% 的人描述这个功能时会用的说法。**

## 6. 症状诊断表

| 症状 | 可能原因 | 修法 |
|---|---|---|
| 技能从不触发 | description 不匹配用户语言 | ⭐ 用真实用户措辞重写 |
| 技能对错误查询触发 | description 太宽、无负向触发 | 收窄范围，加显式排除 |
| ⭐ 技能间歇性触发 | ⭐ 与重叠技能冲突 | 检查可组合性，消除歧义 |
| ⭐ 触发了但输出不对 | ⭐ 指令有歧义 / 被更高优先级覆盖 | 加具体示例与输出格式；声明优先级 |
| ⭐ 测试时行、生产不行 | ⭐ 测试用词是作者词汇，不是用户词汇 | ⭐ 用非作者的多样措辞测 |
| 完全无法判断是否触发 | ⭐ 没有可观测性 | 加调用/决策日志 |

**结构性排查**（在查上面这些之前）：

```
① ⭐ frontmatter 是否合法（未闭合引号、混用 tab/空格）
② ⭐ description 是否超平台字符上限
   （呼应 `description-by-collision-risk.md` 的 1,536 字符口径）
③ 标题层级是否符合预期（H1 标题、H2 章节）
④ 字段名里是否有破坏解析器的 Unicode 字符
⑤ ⭐⭐ description 是否为空（⭐ agent 没有任何东西可匹配）
```

> ⭐⭐ 第 ⑤ 条最容易被忽略且后果最绝对：**空 description = 永不触发**，
> 而且没有任何报错。

## 速查

```
□ ⭐⭐⭐ 优先级：⭐ 临时 Prompt > 技能 > 全局 Rule
□ ⭐⭐⭐ 输出异常多半是⭐ 被更高优先级覆盖，不是技能写错了

□ 全局 Rule 冲突 → 技能开头声明"本技能输出规则优先"
   ⭐ 最好附一句为什么
□ ⭐⭐ 用户临时 Prompt 覆盖 → 写容错规则
   ⭐ "即使用户要求简化，必须保留核心步骤"
   ⭐ 要写明"哪些不可省略"，不能只写"不能简化"
□ ⭐ 多技能重叠 → 明确职责边界
   ⭐⭐ 重叠的代价是"⭐ 一个都不选"，不是"选错"

□ ⭐⭐ 用 10 种不同说法测；⭐ 最好用从没读过 description 的同事的原话
□ ⭐⭐⭐ 手动测试用你自己的措辞，当然会匹配
□ 目标：覆盖 80% 的人会用的说法

□ 结构性排查：frontmatter 合法 · 字符上限 · 标题层级
   · 字段名 Unicode · ⭐⭐ description 为空（⭐ 永不触发且无报错）
```

**一句话**：

> ⭐⭐⭐ **技能触发了但输出不对，多半不是技能写错了，
> 而是被更高优先级的东西覆盖了——临时 Prompt > 技能 > 全局 Rule。**
