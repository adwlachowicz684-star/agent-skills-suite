## 三类故障

| 类型 | 表现 | 通常原因 |
|---|---|---|
| **欠触发** | 该触发时没触发 | description 太窄、缺字面触发词 |
| **过触发** | 不该触发时触发 | description 太宽、缺 Do NOT |
| **冲突** | 两个技能抢同一个请求 | 边界重叠、关键词共享 |

## 诊断与修法

### 欠触发

```yaml
# ❌
description: 处理代码迁移

# ✅ 补：做什么 + 从哪到哪 + 触发场景
description: >
  将项目中旧版 HTTP 客户端迁移到新版统一请求库。
  适用于 Go 项目使用 old-http-client 需要替换为 unified-httpclient 的场景。
  包含 import 路径替换、请求参数适配和错误处理改造。
```

### 过触发

加 **"NOT for X → 用 Y 代替"**：

```yaml
Do NOT use for 代码评审、PR 描述——这类需求请用 code-review 技能。
```

> **排除项和触发词同等重要。** 这是最强的一条路由提示，
> 一条同时治欠触发和过触发。

### 冲突

常见情形：`dev-assistant` 这种大而全的技能会和专门技能打架。

**解法**：把大而全的技能**拆小**，或在其 description 里显式让路。

## 测试集设计

**约 20 条查询，分两类**：

### 正例（should-trigger，8–10 条）

设计技巧——四个维度都要变：

| 维度 | 变化 |
|---|---|
| **语气** | 正式 / 随意口语 / 带错别字 / 缩写混用 |
| **显式程度** | 从"分析这个 CSV"到"老板要我从这个数据文件做个图表" |
| **详细程度** | 从短提示到含文件路径、列名、背景故事的长消息 |
| **复杂度** | 单步任务和多步工作流都覆盖 |

> **最有价值的正例是关联不明显的查询**——那才真正考验 description 措辞。

### 负例（should-not-trigger，8–10 条）

核心是找**近失样本**：共享关键词或概念，但实际需求完全不同。

| 技能 | 近失样本 | 为什么不触发 |
|---|---|---|
| CSV 分析 | "更新 Excel 预算里的公式" | 需要 Excel 编辑，不是 CSV 处理 |
| CSV 分析 | "写个脚本把 CSV 传到 Postgres" | 需要数据库 ETL，不是分析 |
| 生成 commit | "帮我 review 这段代码的 commit" | 是代码评审，不是生成提交信息 |

**增加真实性**：加文件路径（`~/Downloads/report_final_v2.xlsx`）、
个人背景（"我经理让我……"）、具体细节（列名、公司名）、随意语言和错别字。

## 触发率怎么算

> **模型行为是非确定性的**——同样的输入不一定返回同样结果。

**每条查询跑至少 3 次**，算触发率：

```
正例触发率 > 0.5   （3 次中至少 2 次）
负例触发率 < 0.5
```

**判读**：

- 正例 3 次只触发 1 次 → description 对该场景**覆盖不够**
- 负例 3 次触发 2 次 → description **范围过宽**，需收紧

**防过拟合**：用 **60/40 分割**——训练集上找缺口并优化，
留出验证集上确认改进能泛化到新提示。

## 技能偷窃

> 一个技能"偷走"了本该属于另一个技能的调用。

**检测法**：

```
1. 单独启用每个技能，各测一遍  → 记录基线
2. 同时启用所有技能，再测一遍
3. 谁停了 → 谁被偷了
```

## evals.json 结构

```json
{
  "skill_name": "my-skill",
  "evals": [
    {
      "id": 1,
      "prompt": "帮我分析这个 CSV 的销售趋势",
      "should_trigger": true,
      "expected_output": "含趋势摘要与至少一个图表的分析报告"
    },
    {
      "id": 2,
      "prompt": "把这个 CSV 导入 Postgres",
      "should_trigger": false,
      "expected_output": null
    }
  ]
}
```

**配套做法**：

- **硬检查交给代码**（断言、正则、退出码）
- **软判断交给评审者**（rubric，如"是否指出了风险"）
- **共存测试**：单独跑得好，不代表在 20 个技能里还能被选中

## 一条经验

> **拿不准时，往窄了写。**
> 欠触发可以修（补触发词），过触发会侵蚀信任（用户会关掉整个技能）。
