# 先手动跑一遍：eval 的素材从哪来

> ⭐ **你不知道它在哪里失败，就不知道 eval 该测什么。**
> 所以第一步不是写 eval，是**手动跑**。

## 第一步：不开技能，跑代表性任务

官方循环的第一步：

```
⭐ 先不开技能，在代表性任务上跑，记录具体失败
```

为什么必须先做：**你猜的失败点通常不是真实的失败点**。

```
你以为它会卡在"不知道用什么工具"
实际它卡在"读错了文件路径"
```

这一步的产出不是分数，是**一份具体的失败清单**。

## 第二次：开了技能，记下每处手动修正

```
codex exec --full-auto '用 $setup-demo-app 技能在这个目录创建项目'
```

> 这第一次上手跑，**目的不是验证正确性，是发现边界情况**。

关键纪律：

> ⭐ **你在这里做的每一个手动修正，都是一个未来的 eval 候选**——
> 补一个漏掉的 npm install、修正 Tailwind 配置、
> 收紧触发描述……

理由：**你不得不手动修的地方，正是技能没覆盖到的地方。**
把它变成 eval，就是把"这次的正确行为"锁定下来，
防止以后回归。

## 然后才建 eval

```
② 至少建三个针对这些缺口的 eval 场景
③ 测量基线
④ ⭐ 写能通过的最小指令集
⑤ 迭代
```

第 ④ 条的"最小"很重要——
**先写刚好能通过的最小指令，而不是一开始就写完整版**。
完整版会掩盖"哪条指令真正起作用"。

## 用 --json 做确定性判分

```
⭐ 跑 agent 时开 --json
   stdout 变成 JSONL 结构化事件流
   → 可以写确定性检查
```

能判什么：

```
□ 有没有跑 npm install？
□ 有没有创建 package.json？
□ ⭐ 有没有按预期顺序调用命令？
```

> ⭐ **这些检查故意做得很轻**——
> 它们提供快速、可解释的信号，
> 是加任何模型评分之前该有的第一层。

## 一个最小 harness

```js
// evals/run-evals.mjs
function runAgent(prompt, outJsonlPath) {
  const res = spawnSync("codex",
    ["exec", "--json",      // ⭐ 必需：输出结构化事件
            "--full-auto",  // 允许文件系统改动
            prompt],
    { encoding: "utf8" });
  mkdirSync(path.dirname(outJsonlPath), { recursive: true });
  writeFileSync(outJsonlPath, res.stdout, "utf8");
  return { exitCode: res.status ?? -1 };
}
// 对每个 prompt：跑 → 存 JSONL → 解析 → 跑确定性检查
```

一个"足够好"的实现就长这样。
**不需要框架，不需要数据库**。

## 让 CSV 长成活的记录

```
id,should_trigger,prompt
test-01,true,"用 $setup-demo-app 技能创建名为 devday-demo 的项目"
test-02,true,"搭一个最小的 React + Tailwind demo 做 UI 实验"
test-03,true,"做一个展示 Responses API 的小 demo"
test-04,false,"给现有的 React 应用加 Tailwind"
```

四条各测一件事：

| 用例 | 测什么 |
|---|---|
| test-01 **显式** | 点名能调起；改动名字/描述/指令不会破坏直接调用 |
| test-02 **隐式** | ⭐ 不点名时，description 够不够强 |
| test-03 **情境** | ⭐ 加了领域噪声还能不能触发 |
| test-04 **负向** | ⭐ 会不会过于急切地触发 |

> 10–20 行就足够发现回归。

然后：

> ⭐ **每次发现一个漏触发、或输出偏离预期，就加一行。**
> **这份小 CSV 会慢慢长成"这个技能必须持续做对的事"的活记录。**

## 一条关于规模的建议

```
□ ⭐ 单个技能：10–20 条 prompt 就够
□ 不需要大型 benchmark 才能拿到价值
□ ⭐ 从小 CSV 起步，随真实失败增长
```

反面：一开始就建 200 条用例的团队，
通常在维护到第 30 条时就放弃了。

**小而活 > 大而僵。**

## 与四层金字塔的关系

这套方法对应金字塔的第 2–3 层
（触发 eval / 行为 eval），
而它**依赖第 1 层先过**：

```
第 1 层（结构 lint）没过 → ⭐ 不要往下走
  文件都加载不了，跑什么都是测旧版本
```
