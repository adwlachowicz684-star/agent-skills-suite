> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 第一反应⭐ 就是'我正文写得太少了'，

## 2. ⭐⭐⭐⭐⭐ 五步排错顺序

```
① ⭐⭐⭐⭐⭐ 压根没触发        → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 改名称与 description
② ⭐⭐⭐⭐⭐ 触发了但漏步骤     → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 改正文与文件导航
③ ⭐⭐⭐⭐⭐ 读到了规则还做错   → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 补真实示例，⭐⭐⭐⭐ ⭐⭐⭐ 或把确定规则交给脚本
④ ⭐⭐⭐⭐⭐ 工具失败          → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 查连接、参数、凭证、权限
⑤ ⭐⭐⭐⭐⭐ 多个 Skill 抢任务 → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 收窄描述，或重新分组
```

> ⭐⭐⭐⭐⭐ 这个⭐ 顺序⭐ 的⭐ 价值⭐ 在于⭐ 它⭐ 是⭐ **收敛的**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 每一步⭐ 先排除⭐ 一个⭐ 层，⭐⭐⭐⭐⭐ ⭐⭐⭐ 且⭐ 顺序⭐ 按⭐ "⭐ 最常见 → ⭐ 最罕见"
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 排列，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不是⭐ 按⭐ "⭐ 最容易改 → ⭐ 最难改"。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 第 ③ 步⭐ 那句⭐ 尤其⭐ 值得⭐ 记，⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 它⭐ 给了
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 两个⭐ 不同⭐ 的⭐ 药方，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 且⭐ 有⭐ 先后：
> ```
> ⭐⭐⭐⭐⭐ 先：⭐⭐⭐⭐⭐ ⭐⭐⭐ 补真实示例（模型理解偏了 —— 是"没学会"）
> ⭐⭐⭐⭐⭐ 后：⭐⭐⭐⭐⭐ ⭐⭐⭐ 把确定规则交给脚本（模型学会了但做不到 —— 是"不该它做"）
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与⭐ 我们⭐ 已有的⭐ 一条⭐ 精确对应：
> ⭐⭐⭐⭐⭐ **"⭐ 反复被违反的⭐ 书面规则⭐ 应编码成⭐ 校验器"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而⭐ 这里⭐ 补上了⭐ 前置判断：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **先确认⭐ 它⭐ 是⭐ "不懂"⭐ 还是⭐ "做不到"。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 不懂 → ⭐ 给示例；⭐⭐⭐⭐⭐ ⭐⭐⭐ 做不到 → ⭐ 给脚本。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 把⭐ 脚本⭐ 用在⭐ "不懂"⭐ 的情况上，⭐⭐⭐⭐⭐ ⭐⭐⭐ 就是
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 我们⭐ 记过的⭐ "⭐ 伪技能陷阱"⭐ 的一个⭐ 变体。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 第 ⑤ 步⭐ 的⭐ "⭐ 重新分组"⭐ 也⭐ 值得⭐ 注意——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 它⭐ 与 `collision-arbitration.md` 的
> "⭐ 首选⭐ exclusive_group（⭐ 声明期预防）"⭐ 一致：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **抢任务⭐ 的⭐ 根治⭐ 是⭐ 改⭐ 分组，⭐⭐⭐⭐⭐ ⭐⭐⭐ 不是⭐ 加⭐ 仲裁。**

## 3. ⭐⭐⭐⭐⭐ 五类测试用例

```
① ⭐⭐⭐⭐⭐ 该触发的正常请求
② ⭐⭐⭐⭐⭐ 不该触发的相似请求

> ⭐⭐⭐⭐⭐ 第 ⑤ 类⭐ 是⭐ 本轮⭐ 最该⭐ 补的⭐ 一档——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 我们⭐ 此前⭐ 记的⭐ 评测⭐ 维度⭐ 有⭐ 触发 / 执行 / 失败路径 / 回归，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ **没有⭐ 一类⭐ 是⭐ 专门测⭐ "在别的技能也在场时，⭐⭐⭐⭐⭐ ⭐⭐⭐ 它还选得对吗"。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 这⭐ 恰恰⭐ 是⭐ 规模化⭐ 之后⭐ 的⭐ 主要⭐ 失效⭐ 模式
> （⭐⭐⭐⭐⭐ ⭐⭐⭐ 我们⭐ 记过：⭐⭐⭐⭐⭐ ⭐⭐⭐ **>10 个技能，⭐⭐⭐⭐⭐ ⭐⭐⭐ 误触发⭐ 就从边缘情况
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 变成⭐ 主要维护负担**）。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 第 ④ 类⭐ 也⭐ 值得⭐ 强调：
> ⭐⭐⭐⭐⭐ **"⭐ 失败路径⭐ 最容易漏，⭐⭐⭐⭐⭐ ⭐⭐⭐ 却⭐ 恰恰是⭐ 线上⭐ 最常出现"**
> （`eval-set-two-dimensions.md`）——⭐⭐⭐⭐⭐ ⭐⭐⭐ 两个来源⭐ 同一结论。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 五类⭐ 合起来⭐ 看，⭐⭐⭐⭐⭐ ⭐⭐⭐ 还⭐ 可以发现
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 一个⭐ 结构：⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ **①⑤ 测"选得对不对"，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ ②③④ 测"干得对不对"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 前者⭐ 是⭐ 入口，⭐⭐⭐⭐⭐ ⭐⭐⭐ 后者⭐ 是⭐ 出口，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 正好⭐ 对应⭐ 我们⭐ 那条

## 4. ⭐⭐⭐⭐⭐ 负例要"够近"

> ⭐⭐⭐⭐⭐ **"⭐ 负例⭐ 别写 ⭐ '今天天气怎么样' ⭐ 这种没用的。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 写 ⭐ '修改 Jira 状态'、⭐ '给客户发进度'、⭐ '写项目复盘'
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 才有价值——⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **它们⭐ 和目标⭐ 够近，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 能⭐ 真测出⭐ 边界⭐ 写没写清。**"**

```
❌ "今天天气怎么样"（离得太远，⭐⭐⭐⭐⭐ ⭐⭐⭐ 任何技能都不会误触发，⭐⭐⭐⭐⭐ ⭐⭐⭐ 测了等于没测）
✅ "修改 Jira 状态" / "给客户发进度" / "写项目复盘"（⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 相邻领域）
```

> ⭐⭐⭐⭐⭐⭐ **这是⭐ "负例⭐ 要⭐ 近命中"⭐ 这条⭐ 结论的⭐ 第三次⭐ 独立出现**
> （⭐⭐⭐⭐⭐ ⭐⭐⭐ 前两次：⭐⭐⭐⭐⭐ ⭐⭐⭐ `description-tuning-official-loop.md` 的
> "⭐ 别用明显无关的"，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 与 `localization-zh-adaptation.md` 的
> "⭐⭐⭐⭐⭐ ⭐⭐⭐ 容易误触发的⭐ 相邻反例"）。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 三个来源⭐ 给出⭐ 的⭐ 理由⭐ 也⭐ 完全一致：
> ⭐⭐⭐⭐⭐ **⭐ 远的⭐ 负例⭐ 不会误触发，⭐⭐⭐⭐⭐ ⭐⭐⭐ 所以⭐ 它⭐ 永远⭐ 通过，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ 是⭐ 一条⭐ 恒过的⭐ 断言——⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 恒过的断言
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 比⭐ 没有断言⭐ 更危险。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 三处⭐ 结论⭐ 在此⭐ 完全⭐ 合流。

## 速查

```
□ ⭐⭐⭐⭐⭐ 大部分问题不在正文里，而在触发与连接这两头
   ⭐⭐⭐⭐⭐⭐ "一看到不对就疯狂补字，越补越乱"——错误排错是主动把技能改差（补字=增加干扰）
□ ⭐⭐⭐⭐⭐ 五步顺序（按最常见→最罕见）：① 没触发→改名称与 description
   ② 触发漏步骤→改正文与文件导航  ③ 读到规则还做错→补真实示例 / 或把确定规则交给脚本
   ④ 工具失败→查连接·参数·凭证·权限  ⑤ 多个 Skill 抢任务→收窄描述或重新分组
   ⭐⭐⭐⭐⭐ ③的先后：先确认是"不懂"(给示例) 还是"做不到"(给脚本)；⑤的根治是改分组不是加仲裁
□ ⭐⭐⭐⭐⭐ 五类测试用例：该触发的正常 · 不该触发的相似 · 说法模糊的边界
   ⭐⭐⭐⭐⭐ 缺输入或工具挂掉 · ⭐⭐⭐⭐⭐⭐ 跟别的 Skill 并存时还选不选得对（新增的一档）
   ⭐⭐⭐⭐⭐ ①⑤ 测入口（选得对不对），②③④ 测出口（干得对不对）
□ ⭐⭐⭐⭐⭐ 负例要"够近"：❌"今天天气怎么样" ✅"修改 Jira 状态"/"给客户发进度"/"写项目复盘"
   ⭐⭐⭐⭐⭐⭐ "负例要近命中"第三次独立出现——远的负例恒过，恒过的断言比没有断言更危险
```
