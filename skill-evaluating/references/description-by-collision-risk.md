## 1. 五段式 description

| 段 | 作用 | 例子 |
|---|---|---|
| **WHAT** | 做什么 | "从试验文档提取不良事件" |
| **WHEN** | ⭐ 含真实用户请求、输入类型、工作流上下文 | "当用户要求'AE 提取'、'安全表'、'CTCAE 分级'" |
| **HOW** | ⭐ 说明预期产物 | "产出结构化表：每个 AE 映射到 MedDRA 术语、CTCAE 等级…" |
| ⭐ **NOT** | ⭐ **点名最容易混淆的伙伴** | "不适用于会议摘要的 AE；用 scrape-ae-from-congress-abstracts" |
| **ALSO** | ⭐ 加用户可能用但不点名方法的说法 | "也触发于非正式请求，如'一期看到了哪些毒性？'" |

> ⭐ **NOT 段必须"点名替代方案"，不能只说"不要找我"**——
> 这与 `activation-rate.md`、`namespace-collision.md` 完全一致。

## 2. ⭐ 按碰撞风险定长度

```
碰撞风险低    40–60 词    WHAT + WHEN + HOW
碰撞风险中    60–90 词    + NOT
碰撞风险高    90–120 词   ⭐ 完整 WHAT/WHEN/HOW/NOT/ALSO

⭐ 避免超过 ~150 词——详细流程放正文
```

> ⭐ 这个设计的价值：**长度不是凭感觉，而是由"邻居有多挤"决定的**。
> 你不用纠结"写多长"，先做混淆伙伴审计，风险等级自然给出目标长度。

## 3. ⭐ 混淆伙伴审计

定稿前，拿你的 description 跟邻居比，逐条问：

```
① 另一个技能共享 ≥2 个关键词？          → ⭐ 加 NOT 重定向
② 另一个技能用同样的数据模态？          → ⭐ 明确写出你的模态
③ 另一个技能回答相似的领域问题？        → ⭐ 把输出格式写明确
④ 用户有理由把它们搞混吗？              → ⭐ 把区分性短语加进 ALSO
⑤ ⭐ 两个技能是否对同一输入调同一工具？  → ⭐ 考虑合并
```

**评审时维护一张短审计表**：

| 技能 | 关键词 | ⭐ 区分点 |
|---|---|---|
| `scrape-ae-from-congress-abstracts` | 不良事件、提取 | ⭐ 来源是会议摘要，不是试验文档 |
| `extract-ae-from-drug-labels-articles-faers` | 不良事件、安全 | ⭐ 来源是药品说明书、出版物或 FAERS |

> ⭐ 这张表的价值：
> **它把"两个技能看起来很像"变成"两行的区分点"**——
> 而区分点正是要写进 NOT 段的东西。

## 4. ⭐ 八条反模式

| 反模式 | 后果 | 修法 |
|---|---|---|
| 太通用 | 匹配太多技能 | ⭐ 点明来源、模态、输出 |
| 太窄 | 漏掉有效的用户措辞 | 加同义词与非正式触发 |
| ⭐ 比名字还宽 | ⭐ 造成路由冲突 | ⭐ 与 name 的精确范围对齐 |
| ⭐ 没有反触发词 | ⭐ 在邻居面前失效 | 加 NOT 重定向 |
| 太长 | 难用于选择 | 细节移进正文 |
| 实现细节太多 | 与路由无关 | ⭐ 改为描述输入与输出 |
| "helps with X" 式 | 缺任务或上下文线索 | 补 WHAT + WHEN |
| 多个技能共享宽泛动词 | 互相抢单 | 收紧 |

## 5. 集合级审计

> 单个技能写对了没用——**要看整个集合**。

**四类典型重叠**（来自实际审计）：

```
· 平台技能 vs 领域技能重叠
· 认证入口技能 vs 平台专属认证技能重叠
· web / 小程序 / nodejs 数据库技能重叠
· ⭐ "设计/规格/评审"类技能都声称拥有宽泛的规划或评估动词
```

**如果两个技能共享相同的可能提示，要给出处置结论**：

```
· 收紧其中一个的 description
· 加不适用情形
· 把共享细节移进 reference
· ⭐ 合并
· ⭐ 按平台或模式拆分
```

**六种重叠标记**：

```
acceptable overlap · mild redundancy · trigger conflict
merge candidate · split candidate
```

**路由测试集**（每个可能过宽/过窄的技能）：

```
≥3 条 应该触发
≥3 条 不应该触发
1 条 最近邻对比
⭐ 集合审计要包含跨技能提示，如"该触发 auth-tool 还是 auth-web？"
```

## 速查

```
□ 五段式：WHAT / WHEN / HOW / ⭐NOT / ALSO
□ ⭐ 长度由碰撞风险定（40–60 / 60–90 / 90–120 词）
□ ⭐ 混淆伙伴审计五问
□ ⭐ 两技能对同一输入调同一工具 → 合并
□ description 范围不超过 name
□ ⭐ NOT 段要点名替代方案
□ ⭐ 集合级审计 + 六种重叠标记
□ 每个技能 3 正 + 3 负 + 1 最近邻
```

**一句话**：

> ⭐ **不要问"我的 description 写得好不好"，
> 要问"它跟邻居比，区分点说清楚了吗"。**
