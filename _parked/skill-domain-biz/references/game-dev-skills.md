# 游戏开发类技能

> ⭐ **为什么游戏开发特别受益**：
> 天然多角色（程序、关卡、美术方向、音频、QA），
> 纯靠一个通用对话模型**容易把关卡、手感、资源规范搅在同一上下文里**。
> 技能/多 agent 包把角色拆开，用交接剧本串起来。

## 两类：工作室编排 vs 引擎规范

**① 工作室编排（多 Skill + 多角色）**

```
形态  数十个角色 agent、数十条工作流技能
      按真实工作室层级交接：概念 → 资源 → 关卡装配 → 试玩反馈

价值
□ ⭐ 上下文隔离——关卡设计师不必吞下整仓渲染细节
□ ⭐ 交接可重复——同一套评审清单可在多个项目复用
□ 可演示——适合原型周、Game Jam、垂直切片

⚠️ 风险
□ ⭐ 角色越多，编排与权限越像小型工作流引擎
□ 必须明确"谁能改盘、谁只能提议"
   ⭐ 否则会变成多 agent 同时改同一场景文件
```

**② 引擎专用类**

| 方向 | 解决什么 | 典型约束 |
|---|---|---|
| **Godot** | GDScript 2.0、静态类型、节点树与官方风格 | 触发词含 Godot / GDScript / 场景树 |
| **Unity / 跨引擎** | 脚手架目录、程序集、资源命名、基础场景骨架 | 减少"AI 乱建文件夹" |
| ⭐ **关卡/手感评审** | 节奏、可读性、难度曲线清单 | ⭐ 输出评审表**而非直接改关卡** |

```
□ ⭐ 引擎技能属于"强偏好 + 中等能力增益"
   ——模型会写脚本，但"必须静态类型、禁止隐式变体、
     信号怎么挂"要写进技能
   ⭐ 否则产出像教程残片
```

> ⭐ 呼应 `skill-authoring` 的 `skill-types.md` 的 Gotchas：
> **框架专属的硬性约定（静态类型、信号挂法）正是最容易漏的部分**。

## 引擎专用类

**该编码进技能的引擎约定**：

```
□ ⭐ 目录与资源命名（res:// 、Assets/ 约定）
□ ⭐ 静态类型要求（禁止隐式变体）
□ 节点树结构与场景骨架
□ 信号怎么挂
□ 程序集划分
```

> ⭐ **"资源路径写死"是很好的一条**：
> 技能内规定 `res://` / `Assets/` 约定，
> **避免模型发明平行目录**。

## 四条使用建议

```
1. ⭐ 先引擎、后工作室
   单人原型先装 Godot/Unity 技能
   团队 Jam 再上 Studios 编排

2. ⭐ 资源路径写死
   技能内规定 res:// / Assets/ 约定，避免模型发明平行目录

3. ⭐ 美术与程序分权
   生成贴图/音频若走外部工具，用"能力增益"技能 + 脚本
   ⭐ 不要让模型"假装已导出资源"

4. ⭐ 试玩反馈闭环
   留一条"试玩笔记 → 缺陷清单 → 仅改逻辑"的技能
   ⭐ 防止每轮重写整关
```

> ⭐ **第 4 条特别值得学**——
> "仅改逻辑"这个约束防止了大规模重写，
> 呼应 `skill-domain-eng` 的 `legacy-modernization.md` 的增量（而非 big bang）原则，
> 也呼应 `skill-crafting` 的 `grounding-verification.md` 的证据驱动。

**第 3 条**也呼应 `skill-crafting` 的 `grounding-verification.md` 的核心命题：
**模型声称"已生成资源"≠ 资源真的存在**。

## 权限问题

> ⭐ **多角色编排的硬约束**：

```
□ 必须明确"谁能改盘、谁只能提议"
□ ⭐ 否则多 agent 会同时改同一场景文件
□ 提议型角色应只输出建议，由执行型角色统一落地
```

> 呼应 `skill-orchestration` 的 `multi-agent-review.md` 的汇总规则与
> `skill-crafting` 的 `grounding-verification.md` 的执行契约：
> **分工之后必须有明确的汇总与写入归属**。

## 自查

```
□ 是否区分了"工作室编排"与"引擎规范"两类？
□ ⭐ 是否实现了上下文隔离（关卡设计师不必吞渲染细节）？
□ ⭐ 是否明确了"谁能改盘、谁只能提议"？
□ 是否警告"多 agent 同时改同一文件"的风险？
□ ⭐ 引擎约定是否写死（静态类型、信号挂法、目录命名）？
□ ⭐ 资源路径是否固定（避免模型发明平行目录）？
□ ⭐ 是否禁止模型"假装已导出资源"？
□ 是否有"试玩笔记 → 缺陷清单 → 仅改逻辑"的闭环？
□ ⭐ 是否防止了每轮重写整关？
□ 评审类技能是否输出评审表而非直接改？
□ 是否有可复用的交接清单（跨项目）？
□ 是否建议"先引擎后工作室"的落地顺序？
□ 外部工具生成资源是否走脚本（而非模型声称）？
```
