# 财务/会计类技能

> ⭐ **首要原则（这类场景的硬约束）**：
> **财务数据不应离开你的基础设施**——自托管时，
> 供应商访问不到你的 QuickBooks 凭据、银行流水或交易历史。

## 最有价值的两类技能

**QuickBooks 技能**：

```
□ 读取损益表、资产负债表、交易流水
□ 推送日记账分录与支出记录
□ 通过 API 支持 Online 与 Desktop 版
```

**Xero 技能**：

```
□ 提取发票、账单、银行交易、联系人
□ 创建发票草稿并标记付款
```

> ⭐ **这两类都是"能力增益"**（呼应 `skill-authoring` 的 `skill-types.md`）：
> 模型原本够不着这些系统——**技能 + MCP/API 才让它能真正读取与写入**。
> 单纯写流程没有用，必须配上连接层。

## 月度结账报告工作流

> ⭐ **这是"技能 + 定时"替代手工周期的典型**：

**传统流程**（2–3 小时，每周/每月重复）：

```
从 QuickBooks 导出 → 粘贴到 Excel → 计算差异
→ 格式化表格 → 发送给利益相关者
```

**自动化后**：

```
每月 1 号早上 6 点
  ↓
从 QuickBooks 提取上个月的损益表
  ↓
将每个行项目与 Google Sheets 中的预算比对
  ↓
⭐ 计算差异（绝对值和百分比）
⭐ 标记任何超过 10% 的项目
```

> ⭐ **两个可抄的设计细节**：
> 1. **阈值是可配置的谓词**（超过 10%）——
>    呼应 `skill-crafting` 的 `guidance-forms.md` 的 `if <可观察谓词> then`
> 2. **预算与账目分离**——
>    账目来自系统，预算来自表格，**技能负责比对**，
>    呼应 `skill-distribution` 的 `team-workflow.md` 的"指令与数据分离"

> 呼应 `skill-orchestration` 的 `automation.md` 的定时技能：
> **周期性报告是最适合"技能 + 定时"的场景**——
> 结构固定、频率固定、数据源固定。

## 自托管的风险清单

> ⭐ **数据不出网不等于没有风险**：

```
□ ⭐ 保持服务器补丁更新
□ ⭐ 在环境变量中保护 API 凭据
□ ⭐ 确保只有授权用户才能向 agent 发布命令
□ 凭据轮换
□ ⭐ 审计日志
□ 访问控制模式
```

> ⭐ 呼应 `skill-governance` 的 `security-review.md` 与 `compliance-audit.md`：
> **"谁做了什么"必须可追溯**——财务场景尤其如此。

## 这类技能的设计要点

```
1. ⭐ 写操作必须显式确认
   推送日记账分录、创建发票——都不能静默执行

2. ⭐ 凭证类操作要有幂等键
   重复推送一笔分录是不可接受的
   ——呼应 api-design-skills.md 的幂等策略

3. ⭐ 数字必须来自系统，不能由模型推算
   ⭐ agent 不得"估算"余额或差异
   ——呼应 grounding-verification.md 的证据先于声明

4. ⭐ 差异阈值可配置，且标明百分比与绝对值两者
   只给百分比会掩盖小基数上的大幅波动

5. ⭐ 报告要含数据来源与提取时间
   否则无法判断数字的新鲜度
   ——呼应 data-engineering-skills.md 的新鲜度 SLA
```

> ⭐ **第 3 条是财务类最重要的红线**：
> 模型可以**组织与呈现**数字，但**不能生成**数字。

## 自查

```
□ 是否明确了"数据不出基础设施"的前提？
□ ⭐ 读取与写入是否区分（写入需显式确认）？
□ ⭐ 写操作是否有幂等键（防重复分录）？
□ ⭐ 是否禁止模型推算/估算财务数字？
□ ⭐ 差异是否同时给出绝对值与百分比？
□ 阈值是否可配置（而非写死 10%）？
□ 预算与账目是否分离（指令与数据分离）？
□ ⭐ 报告是否含数据来源与提取时间（新鲜度）？
□ 是否有定时触发机制？
□ ⭐ 是否有审计日志（谁做了什么）？
□ 凭据是否走环境变量（不硬编码）？
□ 是否只有授权用户能向 agent 发布命令？
□ 是否覆盖了 Online 与 Desktop 两个版本（如适用）？
□ 是否说明了自托管的操作安全风险（补丁、轮换、访问控制）？
```
