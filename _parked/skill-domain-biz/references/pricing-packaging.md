# 定价与包装

> 定价是高一致性要求的场景：
> 技能的价值在于**口径一致**，不是算出"正确价格"。

## 三个层次

```
1. ⭐ 价值指标（value metric）
   按什么收费：席位？用量？结果？
   ⭐ 这是最重要的一层——选错了后面全错

2. 包装（packaging）
   分几档、每档含什么

3. 价格点（price point）
   每档具体多少钱
```

> ⭐ **多数人直接从第 3 层开始**——
> 而真正决定成败的是第 1 层。

## 定价依据的选择

| 依据 | 适合 | ⭐ 风险 |
|---|---|---|
| 按席位 | 协作型、人均价值明确 | ⭐ 客户会少买席位、共享账号 |
| 按用量 | 用量与客户获得的价值同步增长 | ⭐ 客户会抑制用量——与你想要的正相反 |
| 按结果 | 价值极易衡量（如代收、风控） | ⭐ 归因难、收入波动大 |
| 按功能分档 | 价值随功能跃迁 | ⭐ 客户为不需要的功能付费，或卡在档位边界 |
| 混合 | 多数成熟 SaaS | ⭐ 复杂度高，客户难以预测账单 |

**选择判据**：

> ⭐ **价值指标应与"客户获得的价值"同步增长。**
> 若不同步，客户增长时你的收入不涨，或客户被惩罚。

## 包装的三条规则

**① 档位数 3–4 个**

```
□ ⭐ 少于 3 个：没有升级路径
□ ⭐ 多于 4 个：客户决策成本过高
```

**② 每档要有明确的目标客户画像**

```
❌ "基础版 / 专业版 / 企业版"
✅ ⭐ "独立开发者 / 小团队（2–10 人）/ 部门（10–100 人）/ 企业"
```

> ⭐ 用客户能自我识别的标签，
> 而不是抽象的能力等级。

**③ ⭐ 升级触发点要具体**

```
□ 什么情况下客户该升档——写清触发条件
□ 例："超过 5 个项目"或"需要 SSO"
□ ⭐ 不要让客户自己猜
```

呼应 `customer-success-playbook.md`（**`skill-domain-biz`**）的
扩展信号判定——同一条"可判定"纪律。

## 红线

```
□ ⭐ 模型可以组织数字，不能生成数字
   ——所有价格必须来自定价表，不由模型推算

□ ⭐ 不向客户承诺折扣、退款或未来价格
   ——这些必须人工复核

□ ⭐ 公开价格与合同价格要区分来源
   ——混用会造成对外承诺错误

□ ⭐ 价格变更要有生效日期与过渡规则
```

呼应 `vertical-compliance.md`（**`skill-domain-biz`**）与
`customer-support-skills.md` 的同一组红线。

## 自查

- [ ] 先定了价值指标，再谈价格点吗？
- [ ] 价值指标与客户获得的价值同步增长吗？
- [ ] 每种定价依据的风险都知道吗？
- [ ] 档位在 3–4 个吗？
- [ ] 每档用客户能自我识别的标签吗？
- [ ] 升级触发点是具体条件吗？
- [ ] 所有价格都来自定价表而非推算吗？
- [ ] 折扣/退款有没有转人工？
