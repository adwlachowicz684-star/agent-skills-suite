# OKR 与目标管理类技能

> 一个"看起来很适合做成技能、其实很容易做坏"的领域。
> ⭐ 关键在**区分可判定的部分和需要人判断的部分**。

## 哪些部分适合自动化

```
✅ 结构完整性检查（有没有 KR、有没有负责人、有没有截止日）
✅ ⭐ KR 的可判定性审查（这条能被测出来吗）
✅ 一致性检查（KR 是否支撑 O、跨团队是否冲突）
✅ 格式与术语统一
```

## 哪些必须留给人

```
❌ ⭐ 目标本身的价值判断（这个 O 值不值得做）
❌ ⭐ 打分（0–1 分是多少）
❌ 跨部门优先级排序
❌ ⭐ 承诺资源
```

> 这几条的共同点：**它们需要组织上下文和责任归属**，
> 模型不具备，也不该替人承担。

## KR 的可判定性检查

这是最有价值、也最可自动化的部分。

> ⭐ **一条 KR 如果无法被测量，它就不是 KR。**

检查表：

```
□ ⭐ 有数字吗（或明确的二元状态）？
□ 有明确的当前值吗？
□ 有目标值吗？
□ ⭐ 有明确的测量方式吗（从哪个系统取数）？
□ 有截止日吗？
□ ⭐ 这个数字的变化能归因到团队行动吗？
```

最后一条最常被漏：

```
❌ "用户满意度提升到 4.5"
   ⭐ 满意度受很多因素影响，无法归因

✅ "结账流程的 P95 从 820ms 降到 400ms"
   可测量、可归因
```

**反面示例对照**：

| ❌ 不可判定 | ✅ 可判定 |
|---|---|
| "改善用户体验" | "结账步骤从 5 步减到 3 步" |
| "提升品牌知名度" | "品牌词搜索量增长 30%" |
| "加强数据安全" | "完成 3 个高危项的修复并通过渗透测试" |
| "提高团队效率" | "PR 首次评审中位数从 1.9h 降到 30min" |

> ⭐ 自动化最有价值的动作就是：
> **把左列的 KR 标出来，要求改成右列的形式。**

## 一个常见失败：把 OKR 写成任务清单

```
❌ O: 完成支付重构
   KR1: 设计新架构
   KR2: 实现代码
   KR3: 上线

⭐ 这是任务清单，不是 OKR
   ——KR 是"完成重构"，那 O 是什么？
```

> ⭐ **KR 描述的是"衡量成功的指标"，不是"要做的事"。**

判据：**这条 KR 能取值 0–1 之间的任意小数吗？**
能 → 是 KR；只能是"做了/没做" → 它是任务。

自动化检查：

```
□ KR 里是否含"完成""实现""上线"这类完成态动词？
   ⭐ 有 → 大概率是任务，不是 KR
```

## 输出格式

```
## Objective
[一句话目标，不含数字]

## Key Results
KR1: [指标] 从 [当前值] 到 [目标值]
     测量方式：[从哪个系统取数]
     截止：[日期]
     负责人：[人]

## 一致性检查
□ ⭐ 每条 KR 都直接支撑 O？
□ 完成全部 KR 是否意味着 O 达成？（⭐ 常见漏洞）
□ 与其他团队的 KR 有冲突吗？

## 需要人确认的部分
□ 这个 O 的优先级
□ 资源承诺
□ ⭐ 打分口径
```

> ⭐ "完成全部 KR 是否意味着 O 达成" 这个检查很关键——
> 经常出现"三条 KR 全绿，但目标没达成"的情况。

## 自查

```
[ ] ⭐ 每条 KR 都有数字或明确二元状态？
[ ] 每条 KR 都有测量方式？
[ ] ⭐ 每条 KR 的变化能归因到团队行动？
[ ] KR 里没有"完成/实现/上线"这类完成态动词？
[ ] ⭐ 检查了"全部 KR 完成 ⇒ O 达成"？
[ ] ⭐ 打分和资源承诺明确交给人了？
[ ] 输出区分了"可自动判断"与"需人确认"？
```

## 一条提醒

> ⭐ **这类技能的价值在"逼你把话说清楚"，
> 不在"帮你写一份 OKR"。**

模型最适合做的是**审查和提问**：
"这条 KR 怎么测量？"、"全部 KR 达成等于 O 达成吗？"

> 它不该做的是替你决定"这个目标值不值得追"。

## 延伸：所有"目标/计划类"技能通用

这套适用于 OKR、季度计划、项目章程、目标分解：

```
可自动化：结构、可判定性、一致性、格式
必须留人：价值判断、优先级、资源、评分
```

**区分这两者，是这类技能做得好不好的唯一分水岭。**
