# 招聘/HR 类技能

> ⚠️ **这类技能必须带合规边界**——
> 招聘决策属于高风险场景（见 `skill-governance` 的 `compliance-audit.md`），
> **技能可以辅助筛选，但不能做录用决策**。

## 四大能力

| 能力 | 做什么 | 用途 |
|---|---|---|
| **简历解析** | ⭐ 自动提取教育背景、工作经历、项目经验、核心技能等非结构化信息，转为结构化字段 | 提升初筛效率，替代人工逐字阅读 |
| **JD 匹配** | 基于岗位 JD 的关键词与任职要求，与简历做语义相似度计算，⭐ **输出匹配度评分 + 缺口项** | 辅助筛选，快速定位高匹配候选人 |
| **面试辅助** | 按岗位要求生成结构化面试题，汇总候选人优劣势与风险点 | 提高面试质量，支撑决策 |
| **招聘沟通** | 生成邀约、跟进、录用等全流程沟通文本 | 提升协同效率，减少沟通成本 |

> ⭐ 传统招聘流程中**简历筛选、JD 匹配、面试题生成**
> 是耗时最长、重复性最高的三个环节——正是技能的主场。

---

## 技术实现逻辑

**简历解析**：

```
NER 命名实体识别 + 大模型语义解析
预设"教育/经历/技能"等字段的提取规则
⭐ 输出 JSON 格式结构化结果
```

**JD 匹配**：

```
词嵌入 → JD 与简历各自转成向量 → 余弦相似度
⭐ 结合权重分配（如核心技能 30%、工作经验 25%）
→ 综合评分
```

**面试辅助**：

```
基于 JD 任职要求生成"专业能力、项目经验、沟通协作"
等维度的结构化面试题
结合简历信息归纳核心优劣势与潜在风险
```

**招聘沟通**：

```
预设沟通场景的话术模板
结合候选人信息（岗位、工作年限）动态生成
⭐ 适配企业话术规范
```

## 必须守住的边界

> ⭐ **四条硬约束**（缺任何一条都不该上线）：

```
1. ⭐ 技能不得做录用决策
   ——输出的是"辅助信息"，决定权在人
   （呼应 compliance-audit.md：招聘评估属高风险场景）

2. ⭐ 匹配评分必须可解释
   ——给出"匹配度 + ⭐ 缺口项"
   ⭐ 只给一个分数是不可接受的（黑箱评分无法申诉）

3. ⭐ 不得使用受保护特征
   性别、年龄、民族、婚育状况等不得进入匹配计算

4. ⭐ 简历数据属个人信息
   ——留存期限、访问权限、删除机制必须明确
   （呼应 compliance-audit.md 的删除权与
     legal-contract-skills.md 的零幻觉策略）
```

> ⭐ **第 2 条尤其重要**：
> "输出匹配度评分 + 缺口项"这个设计不只是好用，
> **它是合规要求**——候选人有权知道为什么被筛掉。

## 这类技能的设计要点

```
□ ⭐ 结构化输出用 JSON schema 固定
   ——呼应 output-contract.md 的 Schema-First

□ ⭐ 权重可配置
   核心技能 30%、工作经验 25%……
   ⭐ 权重本身就是组织口径，应放在数据文件里
   ——呼应 team-workflow.md 的指令与数据分离

□ ⭐ 话术模板独立维护
   ——放 templates/ 或 references/，品牌与法务可独立更新

□ ⭐ 风险点要显式列出
   面试辅助输出的不只是"优势"，还要有"潜在风险"

□ ⭐ 沟通文本需人工过目再发送
   ——尤其录用/拒绝类消息
```

## 自查

```
□ 是否四大能力齐全（解析/匹配/面试/沟通）？
□ ⭐ 是否明确"技能不做录用决策"？
□ ⭐ 匹配评分是否可解释（带缺口项）？
□ ⭐ 是否排除了受保护特征？
□ ⭐ 简历数据是否有留存期限与删除机制？
□ 输出是否有 JSON schema？
□ ⭐ 权重是否可配置（且放在数据文件里）？
□ 话术模板是否独立维护？
□ 面试辅助是否同时输出优劣势与风险点？
□ ⭐ 沟通文本（尤其录用/拒绝）是否需人工过目？
□ 是否说明了技术实现（NER + 向量相似度）？
□ 是否定义了结构化字段集（教育/经历/技能）？
□ 是否避免了只给一个黑箱分数？
□ 是否有审计日志（谁查看了谁的简历）？
```
