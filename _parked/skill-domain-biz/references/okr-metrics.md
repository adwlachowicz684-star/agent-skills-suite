## 1. ⭐ 关键原则：指标必须与业务 KPI 挂钩

> ⭐ **不要追踪"回答长度"这种代理指标——追踪业务真正关心的。**

例：客服场景应追踪**首次解决率（FCR）**，而不是回答长度。

```
❌ 代理指标：输出字数、响应时长、调用次数
✅ 业务指标：FCR、转化率、缺陷逃逸率、人工复核通过率
```

这条对技能评估同样成立——
`metrics.md` 里反复强调的"边际效应"，本质就是要求挂到真实业务结果。

## 2. 场景 → 权重 → 关键指标

不同业务场景，维度权重完全不同。不要一套指标走天下：

| 业务场景 | 核心维度与权重 | 关键指标示例 | ⭐ 避坑重点 |
|---|---|---|---|
| **智能客服** | 语言理解 40% + 安全伦理 30% | 意图识别 F1 ≥ 0.85 | ⭐ **长尾 query 覆盖（方言/错别字）** |
| **数据分析 Agent** | 工具调用 50% + 推理规划 30% | SQL 生成正确率 ≥ 90% | ⭐ 边界条件（空值/超大结果集） |
| **办公助手** | 推理规划 40% + 工具调用 30% | 多步任务完成率 ≥ 80% | ⭐ API 限流/超时异常处理 |

> ⭐ **最后一列"避坑重点"是这套表里最有价值的**——
> 它标出每个场景最容易在上线后才暴露的失败点。
>
> 客服的长尾（方言、错别字）在测试集里几乎不出现，
> 但线上占比不低；数据分析的空值/超大结果集同理。

## 3. 三维评估框架

| 维度 | 关键指标 |
|---|---|
| 语言理解 | 意图识别 F1、上下文连贯性 |
| 工具调用 | API 调用成功率、参数解析准确率 |
| 推理规划 | 任务完成率、多步逻辑一致性 |
| 安全伦理 | 有害内容拦截率、隐私泄露检测 |

> 加权时按第 2 节的业务场景表分配，不要平均。

---

## 4. 避坑重点

**测试集要覆盖长尾**：

```
客服    方言、错别字、口语化表达
数据分析 空值、超大结果集、边界日期
办公    限流、超时、并发
```

> ⭐ **测试集里没有的，上线后一定会出现。**

**人工评估聚焦高价值场景**：

```
自动化覆盖 80% 常规场景
人工聚焦 20% 高价值场景
```

一个实测有效的做法：

> ⭐ **先用自动化筛掉错误率 > 15% 的版本，再对剩余版本做人工深度评估
> ——成本降低 60%+。**

人工评估的质量保障：

```
双盲（评估员不知道模型版本）
Krippendorff's Alpha > 0.7（需 ≥3 名评估员）
⭐ 提供正/反例说明（避免主观偏差）
```

## 速查

| 场景 | 主要权重 | 盯什么 |
|---|---|---|
| 客服 | 语言理解 + 安全 | ⭐ 长尾 query、FCR |
| 数据分析 | 工具调用 | ⭐ 空值/超大结果集、SQL 正确率 |
| 办公助手 | 推理规划 | ⭐ 限流/超时、多步完成率 |

| 通用 | |
|---|---|
| 指标选择 | ⭐ 挂业务 KPI，不用代理指标 |
| 自动化 vs 人工 | 80/20，先自动筛再人工深评 |
| 人工信度 | 双盲 + Alpha > 0.7 + ≥3 人 |
