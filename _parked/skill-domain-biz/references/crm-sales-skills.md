## 为什么 CRM 适合做成技能

对照 `pm-skills.md` 的通用判据：

```
□ ⭐ 一致性是否比创造性重要？→ 是（CRM 字段必须一致）
□ ⭐ 强依赖组织内部语境？  → 是（你们的阶段定义、评分口径）
□ 是否符合"收集信息 → 判断条件 → 执行操作 → 生成结果"四步？→ 是
□ 是否依赖资深员工经验、难以标准化交接？→ 是
```

四项全中——这是技能化的高价值目标。

## 十类工作流

```
 1. 活动自动记录
    邮件、会议、通话、笔记 → 落到正确的联系人/客户/商机

 2. 联系人与客户富集
    职位、公司规模、行业、域名、社交链接、地区

 3. 线索捕获与资格判定
    网页表单、 inbound 邮件、聊天；去重、打分、路由

 4. 管道卫生
    阶段更新、停滞商机提醒、缺失字段检查、成交日期提醒

 5. ⭐ 去重与合并建议
    重复的线索/联系人/客户，⭐ 带置信度评分

 6. 跟进序列
    根据对话意图创建任务、提醒和外联草稿

 7. 会议准备简报
    客户摘要、最近互动、未结工单、续约日期、干系人

 8. 商机摘要与交接
    销售→客户成功的交接说明：实施要求、风险、成功标准

 9. 分群与名单构建
    用于营销活动、续约、增购、流失风险的动态人群

10. 报表支持
    清洗字段、打结果标签、标准化原因、提升预测准确度
```

## 需要接的系统

```
CRM 平台       Salesforce / HubSpot / Dynamics 365 / Zoho
邮箱与日历     Google Workspace / Microsoft 365
通话与会议     Zoom / Google Meet / Teams（含转写）
客户沟通       Intercom / Zendesk / Help Scout
营销自动化     Marketo / Mailchimp / HubSpot Marketing
产品用量分析    Amplitude / Mixpanel / Pendo（流失信号）
计费与订阅     Stripe / Chargebee（续约日期、付款风险）
数据与治理     数仓/BI、客户主数据、审计日志、访问控制
富集来源       企业数据库与公开公司信息（在允许范围内）
```

> ⭐ **产品用量与计费这两类经常被漏**——
> 但它们恰恰是流失风险最强的信号源。

## 人工把关怎么设计

> ⭐ **目标不是"减少人工"，是"把人的脑力用在只有人能判断的地方"。**

```
自动化能做的：
  □ 抓取信号
  □ 结构化
  □ 按规则打分
  □ 生成草稿

必须留给人：
  □ ⭐ 承诺退款、赔偿、折扣
  □ ⭐ 敏感客户关系的措辞
  □ ⭐ 低置信度的合并建议
  □ ⭐ 超过阈值的异常
```

**升级规则必须可判定**：

```
❌ "有疑问时交给人工"
✅ "置信度 <0.8 的合并建议不自动执行，进人工队列"
✅ "涉及金额 >X 的折扣请求一律人工复核"
```

呼应 `customer-support-skills.md` 那条红线：
**复杂投诉先整理事实，再交人；不自动回复**。

## 线索评分的边界

从 CRM 笔记识别"温线索"并推荐下一步动作，典型流程：

```
1. CRM 笔记接入（记录、邮件、通话记录）
2. 路由到 HubSpot / Airtable / Sheets / Zapier
3. ⭐ 温线索判定逻辑：风险评分 · 互动趋势 · 客户信号 · 下一步动作
4. AI 处理
5. ⭐ 销售复核：置信度检查、写回 CRM 备注
6. 跟踪：风险看板、CRM 任务、团队提醒
```

**三条必须写进技能的约束**：

```
□ ⭐ 匹配评分必须可解释——给"匹配度 + 缺口项"
   只给一个黑箱分数无法申诉
□ ⭐ 领域专属评分口径要写清（产品线、合同、续约窗口）
   通用模板覆盖不到
□ ⭐ 合规与数据治理的护栏要写进 prompt
   （隐私、访问控制）
```

**工具选型的诚实对比**（值得抄这种写法）：

| 维度 | 现成自动化 | 定制 GenAI | 人工复核 |
|---|---|---|---|
| 见效速度 | 快 | 中（要开发测试） | 取决于流程 |
| 对决策的控制 | 配置驱动 | 提示驱动 | 显式人工监督 |
| 成本 | 低-中（持续） | 较高（前期） | 运营成本 |
| 一致性 | 高（重复流程） | 随模型质量变化 | 关键步骤最可靠 |
| 可审计性 | 日志可追溯 | ⭐ 提示与输出需要治理 | 完整人工轨迹 |

> ⭐ **最后一行最关键**：定制 GenAI 的**可审计性最弱**——
> 这正是必须留人工复核与日志的原因。

## 数据质量的坑

```
症状：CRM 笔记字段不统一，自动解读被误导
     ⭐ 不一致的笔记会误导 AI

修法：
□ 定义字段标准（线索温度、下一步动作）
□ ⭐ 不要把过期价格表混进知识库
   ——会生成"看似专业但实际错误"的回复
□ 隐私与访问控制在各系统间要一致
```

呼应 `customer-support-skills.md`：
**知识库字段至少含：问题类型 · 适用产品 · 规则原文 · 生效时间**。

## 输出要拆成多块

```
❌ 一整段"给客户的回复"
✅ 拆开：
   · 面向客户的回复
   · 内部动作（要更新哪些字段）
   · ⭐ 风险提示（哪些不能自动说）
   · 复盘字段（供下次改进）
```
