## 为什么单纯的讲义没用

```
❌ 把员工手册塞进技能
   ——模型读了它，但没有人因此学会任何东西
```

> ⭐ **技能的作用是改变 agent 的行为，
> 不是存储文档。**
> 文档该进 RAG（见 `skill-vs-rag.md`）。

判据：**这段内容会改变 agent 下一步做什么吗？**
不会 → 它不是技能内容。

## 该自动化什么

```
✅ ⭐ 生成练习与检验（考题、场景模拟）
✅ 把制度转成可判定的检查清单
✅ ⭐ 一致性检查（课程是否覆盖了所有必学项）
✅ 个性化路径（根据岗位/已有基础）
✅ 常见问题的标准答复（带引用来源）
```

## 不该自动化什么

```
❌ ⭐ 判定"这个人合不合格"
❌ 绩效相关结论
❌ ⭐ 涉及个人的评价或比较
❌ 法律/合规的最终口径
```

> 这些需要责任归属与申诉渠道——
> 和 `customer-support-skills.md` 里
> "匹配评分必须可解释"是同一条原则。

## 三类有效形态

**① 制度 → 可判定检查清单**

```
❌ "要遵守数据安全规范"
✅ 上岗前检查清单：
   □ 已签署保密协议
   □ 已完成数据安全培训并通过测验
   □ 已开通最小权限账号（非管理员）
   □ ⭐ 已确认知道数据分级标准在哪里查
```

> ⭐ 最后一条最值得学：
> **不是"知道标准"，而是"知道去哪里查标准"**——
> 后者可验证，且不会过期。

**② 场景模拟**

```
给定场景：客户要求把数据导出到个人邮箱
让学员判断该怎么做，并说明依据
⭐ 评分点：
   · 识别出这是数据外发请求
   · 引用了正确的条款
   · 知道要上报而不是自行决定
```

> ⭐ 场景模拟比选择题有效得多，
> 因为它测的是**判断过程**，不是记忆。

**③ 覆盖面检查**

```
□ 每个必学项都有对应的练习？
□ ⭐ 每个练习都有明确的通过标准？
□ 有没有必学项没有任何检验手段？
□ 高频错误场景被覆盖了吗？
```

最后一条呼应 `anti-pattern-section.md`：
**高频错误必须来自真实经历**——
从过去的入职问题、事故复盘里提取。

## 输出格式

```
## 学习路径
按岗位与基础分组，每步注明：
  · 学什么
  · ⭐ 怎么检验（可判定）
  · 预计时长

## 检验
□ [可判定的通过条件]

## ⭐ 需人确认的部分
□ 是否合格
□ 例外情况
□ 记录归档
```

> ⭐ **"需人确认的部分"这一节不能省**——
> 它明确了模型的边界。

## 一条通用原则

把这套推广到所有"培训/考核/认证"类场景：

```
可自动化：生成练习、一致性检查、路径推荐、标准答复
必须留人：合格判定、评价、例外处理
```

## 自查

```
[ ] ⭐ 内容会改变 agent 的行为吗（不是纯文档）？
[ ] 制度被转成了可判定的检查清单？
[ ] ⭐ 有场景模拟（不只是选择题）？
[ ] 每个必学项都有检验手段？
[ ] ⭐ 高频错误来自真实经历？
[ ] 合格判定明确交给人了？
[ ] ⭐ 引用了制度来源（可追溯）？
[ ] 输出区分了"自动"与"需人确认"？
```

## 一个警告

> ⚠️ **这类技能容易包含会过期的内容。**

制度、流程、联系人、系统名称都会变。

```
□ ⭐ 标注制度版本与生效日期
□ ⭐ 不写死具体人名/系统名，写"去哪里查"
□ 定期复查（见 lifecycle.md）
```

第二条特别实用：
**"找 X 同学开通权限" 半年后必然失效；
"在内部服务目录里申请权限" 不会。**
