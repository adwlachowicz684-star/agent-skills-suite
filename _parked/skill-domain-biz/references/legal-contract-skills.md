> ⭐ **元原则（最值钱的一条）**：

## 为什么拆成多个 Agent

> 一个成熟实现把合同审查拆成五个专职 Agent，
> ⭐ **每个输出到独立文件**，而不是在大段正文里混着点评：

| Agent | 职责 | 输出 |
|---|---|---|
| **Planner** | 定义任务边界与审查口径 | `00-brief.md` |
| **Clause** | 把合同拆成"可审查单元" | `01-document-map.md` · `02-clause-register.md` |
| **Law** | ⭐ 核对"依据"而非凭经验下结论 | `03-authority-log.md` |
| **Risk** | 用风险分类法分级、合并重复 | `04-risk-register.md` |
| **Report** | 把结论变成业务能直接用的交付物 | 审查意见书 |

**Planner 至少要确认六件事**（这一步常被跳过）：

```
□ 合同类型
□ 审查目标（合规/商业/采购/销售/交付/数据/IP/用工/签署把关）
□ ⭐ 交易角色——我方 / 对方 / 中立
□ 是否有我方模板、公司政策、审批矩阵、红线
□ 是否要求出修改建议、替代条款、签署结论
□ 时效要求与版本信息
```

> ⭐ **"交易角色"这一项最容易漏**——
> 同一份合同，代表甲方还是乙方看，结论完全相反。

**Clause Agent 的关键动作**：

```
□ 建立条款目录与 clause id
□ ⭐ 无编号的合同切成 C1、C2、C3 形式
□ 识别关键定义、权利义务、金额、期限、触发条件、例外、责任分配
□ ⭐ 标记缺失条款、冲突条款、模糊表述和空白变量
```

## 三层扫描 × 四步动作

> ⭐ **这个结构直接来自几十年合同实务沉淀的方法论**：

```
宏观层   交易结构 · 主体 · 程序
中观层   形式 · 框架 · 配套
微观层   条款 · 语言 · 细节
```

**四步动作**：

```
① 前置澄清   立场 / 目的 / 截止
② 分层扫描   宏观 → 中观 → 微观
③ 条款落地   改什么 / 怎么改
④ 交付跟进   报告 / 复核
```

**每个风险点的九列字段**（这是可直接抄的输出契约）：

```
名称 · 等级 · 后果 · 措辞 · 依据 · …
⭐ 每个风险点 → P0/P1/P2 分级 → 谈判优先级
```

**合同类型路由**（12 类固定覆盖，不另开目录）：

```
01 买卖   02 租赁   03 服务   04 知识产权   05 担保   06 借贷/赠与
07 互联网协议  08 婚姻家事  09 劳动用工  10 房地产  11 建设工程  12 公司投资

⭐ 为什么不扩到 13、14 类？
   当前痛点是覆盖深度不均，不是类别数量不足。
   新增优先在现有类别内做深。
   未单列的细分类型通过路由清单归入既有类别。
```

> ⭐ **这条设计决策值得单独学**——
> 它主动拒绝了"看起来更全面"的扩张。

## 风险分级与依据日志

**分级标准**（示例，按你的法域替换）：

```
高   违约责任无封顶 · 无解除权 · 知识产权强制归对方
     · 无保密 · 付款条件严重失衡 · 争议解决约定到对方所在地
中   付款账期偏长 · 履约范围模糊 · 争议解决条款薄弱
     · ⭐ 违约金过高有被法院调减的风险
低   格式问题 · 非标但可接受的条款
```

**Law Agent 的核心要求**——⭐ **核对依据，而不是凭经验下结论**：

```
每条依据必须写清：
□ 来源级别
□ 标题
□ ⭐ 发布日期 / 生效日期
□ ⭐ 与你的审查结论的关系（而不只是"相关"）
```

```
□ 区分三类：违法/违规风险 · 违反公司制度或审批要求 · 市场惯例偏离
□ 检索并记录法律法规、监管规则、司法解释、用户提供的公司制度
□ ⭐ 一条铁律：如果检索说"未提及"，标记为"未验证——需人工复核"
   绝不允许补全
```

> ⭐ 呼应 `skill-domain-eng` 的 `research-skills.md` 的"禁止编造引用"与
> `skill-crafting` 的 `grounding-verification.md` 的"证据先于声明"。
> **法律场景把这条从"好习惯"升级为"执业风险"。**

## 谈判 Playbook 的输出格式

> ⭐ **对每个被标记的条款，输出四项**——这是可直接用的交付物：

```
① 当前措辞     ⭐ 原文引用（逐字，便于正确 redline）
② 风险说明     结合适用法律与相关解释
③ 建议替代措辞  ⭐ 给出可直接替换的文本
④ 退一步底线    fallback——谈不下来时退到哪
```

**最终风险摘要**：

```
□ 总体风险等级（可签 / 修改后可签 / 不建议签）
□ ⭐ 签前必谈条款
□ 锦上添花条款
□ 后续动作建议
```

**必备条款清单**（按法域替换）：

```
当事人信息 · 标的 · 数量 · 质量 · 价款或报酬
· 履行期限和方式 · 违约责任 · 争议解决方法
```

## 克制：什么时候该收手

> ⭐ **这一节是全文最值得记住的部分。**

**一条强约束**：

```
□ 合同最终由人签、推进、执行——⭐ 人才是验收节点
□ Agent 的目标是把人的脑力消耗压到最低
□ ⭐ 不是源源不断地产出
```

**零幻觉策略**：

```
□ 检索说"未提及" → 标记"未验证——需人工复核"
□ ⭐ 宁可少说一条，不可编造一条
□ 每条结论都能追溯到具体条款与依据
```

**一条很实际的防呆规则**：

```
□ ⭐ "已配置但未在本环境确认，也要先问"
  ——避免把别人或老环境的身份误用到你的正式交付
```

**为什么法律场景特别需要技能而非提示词**：

```
□ 法律工作的评判标准是⭐ 可追溯性，不是流畅度
□ 一次编造的引用、漏掉的赔偿例外、虚构的法规
  → 就是执业过失与审计风险
□ ⭐ 技能是受治理的、可重复的，产出能让合伙人签字
  ——裸提示词做不到
```

**另一个值得记的数据**：

```
法律从业者平均每年花 200+ 小时在可自动化的重复工作上
——约每人每年四周
```

## 自查

```
□ 是否拆成了专职 Agent（Planner/Clause/Law/Risk/Report）？
□ Planner 是否确认了"交易角色（我方/对方/中立）"？
□ Clause 是否给每条条款编了 id（无编号合同切成 C1/C2/C3）？
□ ⭐ Law Agent 是否要求写清依据的发布/生效日期与关系？
□ 是否区分了违法违规 / 违反公司制度 / 惯例偏离？
□ ⭐ 是否有"未提及即标记需人工复核"的零幻觉策略？
□ 是否用了三层扫描 × 四步动作？
□ 是否有固定的合同类型路由（且主动拒绝无限扩张）？
□ 风险是否有 P0/P1/P2 分级？
□ 谈判 Playbook 是否有四项（原文/说明/替代/底线）？
□ ⭐ 是否有克制原则（人是验收节点，不源源不断产出）？
□ 是否有防呆规则（已配置未确认也要先问）？
□ 是否标明了法域并说明需按实际法域替换？
□ 是否声明"技能不替代执业判断"？
```
