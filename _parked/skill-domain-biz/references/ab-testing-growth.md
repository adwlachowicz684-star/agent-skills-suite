## 结果怎么解读

| 结果 | 结论 |
|---|---|
| 显著胜出 | 实施变体 |
| 显著落败 | 保留对照组，**搞清为什么** |
| 无显著差异 | 需要更多流量，或更大胆的测试 |
| 信号混杂 | 深挖，可能要分群看 |

> ⭐ **"显著落败"也要记为什么**——
> 负面结果的信息量常常高于正面结果。
>
> 呼应 `security-pipeline.md`（**`skill-orchestration`**）：
> **正负样本都回流**，只记成功的会让判断越来越偏。

## ICE 优先级

```
Impact     这个改动如果奏效，影响多大？
Confidence ⭐ 我们有多大把握它会奏效？（⭐ 基于数据，不是直觉）
Ease       多快多便宜能上线并测出来？

ICE = (Impact + Confidence + Ease) / 3
```

**用法**：

```
□ 跑 ICE 最高的实验
□ ⭐ 每月重新评分——上下文会变
```

> ⭐ **"每月重评"这条最容易被省**。
> 三个月前的低优先级假设，随着产品变化可能变成最高。

## 实验手册：把赢家变成模式

> ⭐ **测试赢了不要只实施它——把模式记下来。**

每份记录要含：

```
## [实验名]
日期
假设
样本量（每组 n）
结果：胜/负/无结论 —— 主指标变化 X%（95% CI: [范围], p=[值]）
⭐ 护栏指标：有哪些，各自结果如何
⭐ 分群差异：按设备/分群/队列的显著差异
为什么成立/不成立：分析
⭐ 模式：可复用的洞察
   例："定价 CTA 附近的社会认同能提升套餐选择"
⭐ 适用到：其他可能有效的页面/流程
状态：已实施 / 搁置 / 需跟进测试
```

**三条重点字段**：

```
□ ⭐ 护栏指标——没记护栏的赢家可能是假赢家
   （转化率涨了但退款也涨了）
□ ⭐ 分群差异——整体无差异时常藏着某个分群的强信号
□ ⭐ 模式与适用到——这是从"一次测试"变成"资产"的关键
```

> 呼应 `methodology-skills.md` 的"把成熟方法论编码成技能"：
> **模式（pattern）比结果（result）更值得沉淀。**

## 运营节奏

```
每周（30 分钟）
  □ 检查运行中的实验有没有技术问题
  □ ⭐ 检查护栏指标
  □ ⭐ 不要提前宣布赢家——但如果护栏显著为负，就停

双周
  □ 结束已完成的实验
  □ 分析结果、更新手册、从 backlog 启动下一个

每月（1 小时）
  □ 复盘实验速度、胜率、累计提升
  □ 补充假设 backlog
  □ 用 ICE 重新排序

每季度
  □ ⭐ 审计手册：哪些模式已被广泛应用？
     哪些获胜模式还没规模化？
     漏斗哪些区域测试不足？
```

> ⭐ **"不要提前宣布赢家"是统计纪律的核心**——
> 呼应 `test-pyramid.md`（**`skill-evaluating`**）：
> **跑一次不算证据**，要跑够样本。

## 常见错误

**设计阶段**：

```
❌ 改动太小（检测不出来）
❌ 一次测太多东西（无法归因）
❌ 没有清晰假设
```

**执行阶段**：

```
❌ 提前停止
❌ ⭐ 测试中途改东西
❌ 不检查实现是否正确（变体真的生效了吗）
```

**分析阶段**：

```
❌ ⭐ 忽略置信区间
❌ ⭐ 挑分群（cherry-picking segments）
❌ 过度解读无结论的结果
```

> 中间那组"执行阶段"的三条，
> 呼应 `error-handling.md`（**`skill-crafting`**）的思路：
> **失败要能归因到具体阶段**，混着看就不知道改哪里。

## 实验速度的健康指标

| 指标 | 目标 |
|---|---|
| 每月启动实验数 | ⭐ **4–8**（多数团队） |
| 胜率 | ⭐ **20–30%**（成熟项目的常见值） |
| 平均测试时长 | 2–4 周 |
| backlog 深度 | 20+ 条假设在队列里 |
| 累计提升 | 所有赢家的复利收益 |

**两个数字要反着读**：

```
□ ⭐ 胜率持续高于 30% → 可能假设太保守
   你在测那些"本来就知道会赢"的东西
□ 胜率过低 → 假设质量差，或改动太小检测不出
```

> ⭐ 这是个很好的例子说明**指标要配解读规则**：
> 单给"胜率 20–30%"会被误读成"越高越好"。

呼应 `finance-accounting-skills.md` 与 `pm-skills.md` 的同一条：
**指标定义必须含计算逻辑 + 边界条件 + 常见误读**。

## 相关技能的分工

```
cro           → 基于 CRO 原则生成测试点子
analytics     → 设置测试的度量
copywriting   → 撰写变体文案
本篇           → ⭐ 实验的设计、解读与持续运营
```

> ⭐ **这种"相关技能"清单值得抄进每个领域技能的末尾**——
> 它让 agent 知道边界在哪、什么时候该交给别的技能。
>
> 呼应 `skill-composition-patterns.md`（**`skill-orchestration`**）的
> 重叠处理：**限定作用域最优雅，让冲突根本不发生**。
