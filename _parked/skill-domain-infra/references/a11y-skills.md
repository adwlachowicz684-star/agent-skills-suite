# 无障碍类技能

> ⭐ **一句定位**：
> **你的 agent 能做出漂亮的 UI。这个技能让它们对所有人可用。**
>
> **无障碍是一项公民权利，不是一个功能。**

## 为什么这类技能特别适合封装

```
□ 规则是明确的、可检查的（对比度 4.5:1，不是"看起来清楚"）
□ ⭐ 模型"知道"无障碍，但默认不会主动遵守
□ 后果是法律性的（ADA、Section 508）
□ ⭐ 事后补救成本远高于一开始就做对
```

> ⭐ **一句很传神的话**：
> **你没法把巧克力豆塞进已经烤好的玛芬里。**
> 无障碍属于设计、架构与开发阶段——不是事后外挂。

**适用时机**（写进 description 的触发词）：

```
□ 构建 UI 组件（按钮、表单、模态框、菜单）
□ 页面布局与内容结构
□ 添加图片、媒体、交互元素
□ 审计已有代码
□ 修复无障碍缺陷
□ ⭐ 编写应当验证无障碍的测试
```

## 三层规则：预防 / 识别 / 修复

> ⭐ **这个三层结构是这类技能的骨架，值得直接搬。**

### 预防（构建时）

```
ALWAYS  正文对比度至少 4.5:1（大文本 3:1）
ALWAYS  ⭐ 用语义 HTML 元素，而不是自定义 div
ALWAYS  所有表单输入都有显式、可见的标签
ALWAYS  所有交互元素键盘可达
ALWAYS  有可见的焦点指示器
ALWAYS  正确的标题层级（不跳级）
ALWAYS  有意义的图片都有 alt 文本
ALWAYS  ⭐ 动作用 button，导航用 link
PREFER  语义 HTML 优先于 ARIA（ARIA 是补充，不是替代）
```

### 识别（发现问题时）

```
ALWAYS  用自动化工具（axe、WAVE）
ALWAYS  ⭐ 只用键盘导航测一遍
ALWAYS  ⭐ 用屏幕阅读器测一遍（NVDA、VoiceOver）
REMEMBER ⭐ 自动化工具只能抓到 30–57% 的无障碍问题
```

### 修复（改的时候）

```
NEVER  ⭐ 只用颜色传达信息
NEVER  用 placeholder 文本代替标签
NEVER  空的链接或按钮
NEVER  通用文本（"点击这里"）
NEVER  ⭐ 键盘陷阱
NEVER  移除焦点指示器（* { outline: none }）
```

## POUR 框架

> 所有无障碍工作映射到四条原则（WCAG 分类）：

```
Perceivable   可感知——用户能感知内容吗？
              文本替代、对比度、可适配布局
Operable      可操作——用户能操作界面吗？
              键盘、时间、癫痫安全、导航
Understandable 可理解——用户能理解内容与 UI 吗？
              可读、可预测、输入辅助
Robust        健壮——能和辅助技术配合吗？
              解析、名称/角色/值、状态消息
```

**语义 HTML 优先**：

```
□ ⭐ 第一条 ARIA 规则：不要用 ARIA
□ 每页一个 h1，不跳级
⭐ 标题层级是给屏幕阅读器的导航大纲——
   绝不为"字号"选标题层级（那是 CSS 的活）
□ 地标元素（header/nav/main/footer 等）包住页面内容
   屏幕阅读器用户在地标之间跳转导航
□ 按行为选元素，不按外观：
   button = 动作 / a（必须有 href）= 导航
   ⭐ 绝不用 div 干这两件事
```

**按钮 vs 链接**：

```
导航  → <a>（href 必需）
动作  → <button>
⭐ 绝不使用没有 href 的 <a>
⭐ 绝不为了这两件事用 <div>
```

## Gotchas：模型最常犯的错

> ⭐ **这类"Claude 最常犯的错"清单，是整份技能里最高信号的部分**
> ——呼应 `skill-authoring` 的 `skill-types.md` 对 Gotchas 的定位。

```
❌ 在 <div> 上加 role="button"
✅ 直接用 <button>——它免费提供可聚焦性、Enter/Space、role

❌ 在原生 HTML 够用时加 ARIA
✅ ⭐ 第一条 ARIA 规则：原生元素能用就别用 ARIA

❌ 用 opacity: 0 隐藏内容
✅ ⭐ 元素仍留在 tab 顺序和无障碍树里
   用 display: none 或 hidden 属性

❌ 关闭时忘了归还焦点
✅ ⭐ 模态/菜单/弹窗关闭时，焦点必须回到触发元素

❌ 缺少 Escape 支持
✅ ⭐ 每个浮层都必须能用 Escape 关闭——不是可选项

❌ 模态背景不用 inert
✅ ⭐ 用 inert 属性，而不是手动给每个元素加
   aria-hidden + tabindex="-1"
```

**键盘模式**（必备清单）：

```
Tab / Shift+Tab   在交互元素间移动
Enter / Space     激活按钮与链接
方向键            在复合组件内导航（tabs、菜单、日期选择器）
Escape            关闭模态、菜单、弹窗
```

```
□ ⭐ 焦点指示器必须可见
□ 绝不用 * { outline: none }
□ 用 :focus-visible 做仅键盘的轮廓
```

**其他该编码进去的细节**：

```
□ 尊重 prefers-reduced-motion（动画安全）
□ 响应式缩放
□ ⭐ 焦点管理：焦点陷阱、roving tabindex、焦点恢复、skip link
□ 表单输入用 aria-describedby 关联描述
□ 不用颜色单独传达信息
```

## 自动化只能抓 30–57%

> ⭐ **这是整份技能里最重要的一个数字**——
> 它决定了"跑一遍 axe 就算完"是错的。

| 方法 | 能抓到什么 |
|---|---|
| **自动化测试** | ~30–57%（对比度、标签、ARIA） |
| **键盘测试** | 所有交互必须能在无鼠标下完成 |
| **屏幕阅读器测试** | 内容被朗读出来时必须讲得通 |

> ⭐ 呼应 `skill-crafting` 的 `grounding-verification.md`：
> **跑过工具 ≠ 验证过**。
> 技能里必须写明"自动化之外还要做什么"。
