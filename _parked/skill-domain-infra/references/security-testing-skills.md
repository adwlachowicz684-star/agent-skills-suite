## 安全测试金字塔

```
单元测试        测安全函数（加密、校验）
SAST           开发期静态分析
SCA            依赖与组件漏洞扫描
DAST           运行中的动态测试
IAST           SAST + DAST 结合
渗透测试        专家手工测试
红队演练        对抗性模拟
```

**四类对比**（写进技能让 agent 会选）：

| 类型 | 特点 |
|---|---|
| **SAST** | 不执行分析源码 · 早发现 · **覆盖全** · ⭐ **误报率高** |
| **DAST** | 测运行中的应用 · 发现运行时与配置问题 · 语言无关 · **需要已部署环境** |
| **SCA** | 依赖漏洞 · 许可合规 · 可自动修复 |
| **手工** | 渗透测试 · 业务逻辑校验 · 复杂攻击场景 |

## 五阶段工作流

**阶段 1 规划**：定义安全需求与威胁模型 · 选工具与技术 · 建立基线 · 设严重度阈值与验收标准

**阶段 2 自动化测试**：
```
□ SAST 集成进 IDE 与 CI/CD
□ SCA 配置依赖扫描
□ DAST 对已部署环境定时扫描
□ 容器扫描镜像（Trivy 等）
```

**阶段 3 手工测试**：
```
□ 认证与授权测试
□ 业务逻辑漏洞评估
□ API 安全测试（OWASP API Top 10）
□ 渗透测试与利用
```

**阶段 4 分析与修复**：
```
□ 按严重度与可利用性分诊
□ 消除误报
□ ⭐ 基于风险排序修复
□ 跟踪漏洞直至解决
□ ⭐ 用回归测试验证修复
```

**阶段 5 持续监控**：新漏洞监控 · 代码变更后重扫 · 定期渗透 · 更新基线

## 六个常见错误

> ⭐ **这是整份技能里最该直接抄的部分**：

| ❌ 错 | ✅ 对 |
|---|---|
| 只用 SAST 或只用 DAST | ⭐ **分层组合多种测试类型** |
| 不经复核就忽略或压制发现 | ⭐ **有系统分诊流程，安全团队验证** |
| 只在发布前做安全测试 | ⭐ **贯穿开发全过程的持续测试** |
| 只测主应用代码 | ⭐ **要包含依赖、API、基础设施与第三方集成** |
| 所有发现同等对待 | ⭐ **风险排序（严重度 × 可利用性 × 业务影响）** |
| DAST 扫描不做认证 | ⭐ **配置认证扫描，才能测到受保护功能** |

> ⭐ 倒数第二条最容易被忽略——
> 未认证的 DAST 只扫到了登录页，等于没扫。

## 优先级排序

```
⭐ 风险 = 严重度 × 可利用性 × 业务影响
```

**漏洞优先级可借助的公开信号**：

```
CVSS   通用漏洞评分
⭐ EPSS  被实际利用的概率
⭐ CISA KEV  已知被利用漏洞目录
```

> ⭐ **CVSS 高不等于紧急**——
> 结合 EPSS 与 KEV 才能判断"现在要不要修"。
> 这是把"严重度"从主观形容词变成可查数据的关键。

## 工具分层与红线

> ⭐ **按域分层，每个工具对应明确用途**：

| 域 | 工具举例 | 用途 |
|---|---|---|
| 容器 | Grype、Trivy | CVE 检测，按 CVSS/EPSS/KEV 排序 |
| Dockerfile | Hadolint | 安全 lint 与最佳实践 |
| IaC | Checkov | 750+ 内置策略 |
| 密钥 | Gitleaks | 硬编码密钥检测 |
| SAST | Horusec | 18+ 语言，20+ 工具 |
| SBOM | Syft | 软件物料清单 |
| 策略即代码 | OPA | 合规校验 |
| 威胁建模 | pytm | STRIDE 分析 |
| 检测规则 | Sigma | 通用 SIEM 规则格式 |
| 取证 | osquery、Velociraptor | 端点分析 |

**引用的标准框架**（写进技能作依据）：

```
OWASP · CWE · MITRE ATT&CK · NIST · SOC2 · PCI-DSS · GDPR
```

**红线**（必须写进技能）：

> ⚠️ **只应在授权范围内使用。**
> 渗透、漏洞利用、凭据破解类工具**不得用于未授权目标**。
> 技能应显式要求：确认授权范围后再执行，并对结果脱敏。

> 呼应 `skill-governance` 的 `compliance-audit.md` 与 `security-review.md`：
> **安全技能本身必须有边界声明**，否则会被用于越界用途。

```
□ ⭐ 是否显式声明了授权红线？

□ 是否有误报的系统化分诊流程（而非直接压制）？
□ 是否要求持续监控（新漏洞、变更后重扫）？
```
