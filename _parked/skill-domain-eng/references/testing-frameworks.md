## 框架选型表

| 场景 | 框架 | 技能要点 |
|---|---|---|
| 前端单元 | Vitest / Jest | mocking、覆盖率、快照的取舍 |
| 前端 E2E | ⭐ Playwright / Cypress | **locator 策略与断言写法** |
| Python 单元/集成 | pytest | fixture 作用域、参数化 |
| Python Web | pytest-django / FastAPI TestClient | 客户端与 DB 事务 |
| Java 集成 | ⭐ @SpringBootTest + Testcontainers | 容器生命周期、上下文缓存 |
| Python 集成 | testcontainers-python | 同上 |
| 异步任务 | ⭐ Celery 测试 | eager mode 的陷阱 |
| 契约测试 | ⭐ Pact | consumer/provider 双向验证 |
| 消息测试 | Kafka / RabbitMQ / 多 broker | ⭐ 幂等与重试语义 |
| 测试数据 | factory_boy | ⭐ 不要在上生产的数据上测 |
| 变异测试 | mutation testing | 验证测试真的能抓到错 |

> ⭐ **"变异测试"值得单独提**：
> 它回答的问题是"这份测试真的有效吗"——
> 呼应 `test-pyramid.md`（**`skill-evaluating`**）里
> "写了测试不等于测试有效"（红绿循环：回滚修复后**必须失败**）。

## 契约测试

**解决什么**：前后端各自测试都过，联调就炸。

```
consumer 端测试 → 生成契约文件
provider 端验证 → 拿契约跑自己的实现
⭐ 双向都要跑，只跑一端等于没做
```

**红线**：

```
□ ⭐ 契约文件要版本化并随服务一起走
□ ⭐ provider 验证必须进 CI（否则契约会腐烂）
□ ⭐ 不要用真实 PII 写契约样例
```

## 集成测试与 Testcontainers

**核心难题**：测试需要真实依赖（Postgres、Kafka、Redis）。

```
□ 用 Testcontainers 起真实容器，不用内存替代品
□ ⭐ 容器复用策略决定测试时长
     ——每个测试起一个 Postgres 会很慢
□ ⭐ 失败时保留容器日志，否则无从排查
```

**Java 特有**：

```
@SpringBootTest 会缓存应用上下文
⭐ 不同的 @MockBean 组合会导致上下文重启
   ——测试变慢的元凶，技能里要写清楚
```

**Python 特有**：

```
□ FastAPI TestClient 的 dependency_overrides 要在每个测试后清理
□ ⭐ 否则测试间会互相污染
```

## 属性测试

> ⭐ **适用于"穷举边界不现实"的场景。**

**适用场景**：

```
□ 序列化/反序列化
□ 数据转换
□ 有数学性质的算法
□ API 契约
□ ⭐ 状态机
```

**写法要点**：

```
❌ 描述具体的输入输出对
✅ ⭐ 描述不变式（invariants）
```

例：

```
❌ assert reverse([1,2,3]) == [3,2,1]
✅ 对任意列表 xs：reverse(reverse(xs)) == xs
   ——这一条能覆盖你没想到的所有情况
```

> 呼应 `skill-anatomy.md`（**`skill-authoring`**）的"程序优于声明"：
> **描述性质而非实例**——同一条原则在测试里的应用。

## 冒烟测试

**定位**：实现完成后的即时验证，活的 HTTP 测试。

```
□ ⭐ 不是替代测试套件，是"刚写完能不能跑起来"的快速确认
□ 失败后能编排修复循环
□ ⭐ 要覆盖真实启动路径，不是 mock 出来的
```

## 各类测试的红线

**通用**：

```
□ ⭐ 修 bug 之前先加回归测试
□ ⭐ 覆盖率按代码类别分层，不搞一刀切
     关键路径 100% / 业务逻辑 ≥85% / 简单 getter 可跳过
□ ⭐ 不用 sleep 等待——用显式等待条件
□ 不测实现细节（否则重构就红）
```

**E2E 特有**：

```
□ ⭐ 优先用面向用户的 locator（角色、文本），不用 CSS 选择器
□ ⭐ 不用快照测试作为主要手段
□ ⭐ 测试之间要完全隔离（每个用例独立的数据与登录态）
```

**契约特有**：

```
□ 双向验证
□ 契约进 CI
□ 不用真实 PII
```

**消息/异步特有**：

```
□ ⭐ 验证幂等——重复消费不能产生副作用
□ ⭐ 验证重试语义——失败后重试的行为符合预期
□ ⭐ 不要用真实 broker 做单元测试（慢且不稳定）
```

**变异测试特有**：

```
□ ⭐ 变异得分低说明测试"看起来在测"但抓不住错
□ ⭐ 只对关键路径跑（全量跑太慢）
```

## 覆盖率报告的正确写法

```
❌ "你现在 72% 覆盖率"
✅ ⭐ "这 8 个函数零测试，这 3 个分支从未被执行"
```

> 前者是一个无法行动的数字；
> 后者是一份待办清单。
>
> 呼应 `pm-skills.md`（**`skill-domain-biz`**）的同一条原则：
> **给出可行动的清单，而不是抽象的度量。**
