## 1. ⭐⭐ 前提：脚本以你的权限运行

> ⭐⭐ **技能里的脚本和你 `npm install` 的包拥有同样的访问权限——
> 只是⭐ 它以你的权限运行，并且⭐ 能看到你的对话上下文。**

还有一条执行顺序上的事实：

> ⭐ **hooks 里的 shell 指令在模型对输出进行推理⭐ 之前就执行了。**

> ⭐ 所以"我在技能里写了不要删文件"这句话，
> 在脚本已经跑完之后才被读到——**它拦不住任何事**。

## 2. 边界一：路径

**规则**：

```
✅ 只写技能目录内（用 ${CLAUDE_SKILL_DIR}）
✅ 写用户显式指定的工作区路径
❌ 写 /etc/、~/.bashrc、~/.profile
❌ 创建指向技能目录外的 symlink
```

**扫描方式**（来自 15 向量审计）：

```
🟡 HIGH  写到技能目录外、/etc/、~/.bashrc、~/.profile、创建 symlink
🔴 CRITICAL  指向系统目录的 symlink
```

> ⭐ 一个具体的好习惯：**脚本开头就把"允许写的根目录"定义成一个常量，
> 所有写操作都过一次校验**。这比在 SKILL.md 里写"不要写到别处"有效得多——
> 因为它是代码，不依赖模型遵守（呼应 `determinism-boundary.md`）。

## 3. 边界二：凭据

**绝对不要**：

```
❌ 硬编码 API key（sk- / pk_ / AKIA / ghp_ / glpat-）
❌ 连接串写进文件（postgres:// / mongodb+srv:// / redis://）
❌ 私钥（-----BEGIN）
❌ ⭐ 环境变量带实际赋值（KEY=actual_value）——看着像配置，其实是泄露
```

**应该**：

```
✅ ⭐⭐ 走环境变量传递，绝不写进文件
✅ 从用户已配置的凭据源读取（~/.aws 之类）时，⭐ 要在 SKILL.md 里声明
✅ 需要用户配置时，用技能里的 config.json + 首次运行询问
   （见《skill-crafting》的 `official-lessons.md` 的初始化流程）
```

> ⭐⭐ **"KEY=actual_value"这一条最阴**：
> 它看起来只是"默认配置"，实际上就是把密钥交出去了。
> 判据很简单：**等号右边如果是真值而不是占位符，就是泄露。**

## 4. 边界三：网络

**CRITICAL 级模式**：

```
🔴 requests.post() / urllib.request / socket.connect() / httpx / aiohttp
🔴 curl / wget / nc / netcat / /dev/tcp
🔴 ⭐ DNS 隧道
```

> ⭐⭐ 但要区分两件事：**"有网络调用"不等于"恶意"**——
> 数据获取类技能（连接内部数据库、看板、监控）本来就要联网。
>
> ⭐ 判据是：**⭐ 联网目标与技能声明的用途是否一致**。
> 一个"格式化 Markdown"的技能在往外 POST，那才可疑。

**扫描时的三个问题**：

```
① 它访问哪些文件？是否越出技能目录？
② 它发网络请求吗？⭐ 到哪些域名？⭐ 带什么数据？
③ 它读环境变量吗？读哪些？⭐ 拿来做什么？
```

## 5. ⭐ 声明 vs 执行

这是本份最重要的一条，也是整套安全讨论的收敛点：

```
技能里声明 allowed-tools   = ⭐ 意图
权限规则 / MCP server 侧限制 = ⭐⭐ 强制执行
```

三处独立来源给出同一结论：

```
· ⭐ 权限规则优先级高于 frontmatter 声明
· ⭐ Cursor 不解析 allowed-tools，技能会在没有工具限制的情况下运行
· ⭐⭐ 真正的边界在 MCP server 侧的 --read-only，不在技能声明里
```

> ⭐⭐ **所以：技能里的安全声明是给模型看的说明，不是给系统看的锁。**
> 需要真边界，就必须在执行侧配（permission 规则 / MCP server 参数 / 沙箱）。

## 6. ⭐ 最小权限的实际写法

```
❌ Bash                          ← 能干任何事
✅ Bash(git:*)                   ← 只有 git
✅ Bash(python:scripts/*)        ← 只能用仓库里的脚本
✅ Read, Grep                    ← 只读

⭐ 能用具体工具就别用 bash
   "git" 而不是 bash -c "git log"
```

**bash + curl 是经典危险组合**：

```
🚩 既能执行命令，又能外传数据
   = 数据窃取 / 反向 shell / 恶意投递的组合
```

**分寸**（一段很好的 Q&A）：

```
Q：只有 git 权限的技能还危险吗？
A：⭐ 是的，只是程度低——能克隆恶意仓库、能通过外部提交外传数据，
   但⭐ 不能直接执行任意代码。
```

> ⭐⭐ **最小权限不是零风险，是降低上限。**
> 这句话很重要，因为它避免了两种极端：
> "声明了就安全"（错）和"既然不安全就别用"（也错）。
