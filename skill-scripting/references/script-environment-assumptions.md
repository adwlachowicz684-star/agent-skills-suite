## 1. ⭐⭐⭐⭐⭐ 五个默认假设

| 假设 | 默认值（脚本作者心里的） | 实际 |
|---|---|---|
| ⭐⭐⭐⭐⭐ cwd | 项目根目录 | 取决于谁调用了它 |
| 命令存在 | `python3` / `node` / `jq` 都有 | 可能没有，可能是另一个版本 |
| 编码 | UTF-8 | Windows 上可能是 GBK |
| 时区 / locale | 本地时区、中文排序 | CI 上是 UTC、C locale |
| 环境变量 | `.env` 里有值 | 全新克隆里是空的 |

> ⭐⭐⭐⭐⭐ **它们不是"依赖"，所以没人声明。**
> 依赖是"要装什么"，而环境假设是"跑在哪"——
> 后者没有对应的字段，于是只能写进正文，**而正文是触发之后才加载的**。

## 2. 假设一：cwd（最贵的那个）

```python
open("config/settings.json")     # ⭐⭐⭐⭐⭐ 相对于什么？
```

三种调用来源，cwd 都不一样：

| 来源 | cwd |
|---|---|
| 用户手动跑 | 用户当前所在目录 |
| ⭐⭐⭐⭐ 模型自动调用 | 会话的工作目录（不一定是你以为的那个） |
| ⭐⭐⭐⭐⭐ 被另一个技能调用（fork） | 可能完全不同 |

后果分两种，第二种更贵：

```
① 文件不存在        → 报错（可见，会去修）
② ⭐⭐⭐⭐⭐ 文件存在但是另一个  → 不报错，处理了错误的文件
```

> ⭐⭐⭐⭐⭐ **第二种之所以更贵，是因为"存在"这个检查通过了。**
> 脚本读到了一个配置、解析成功、输出正常——只是它是别的项目里的那个。

修法（SKILL.md 的 Critical Rules 里已有，这里补上理由）：

```python
HERE = Path(__file__).resolve().parent          # 脚本自身所在目录
SKILL_DIR = Path(os.environ["CLAUDE_SKILL_DIR"])  # 技能安装目录
```

> ⭐⭐⭐⭐ 两者用途不同：**技能自带的资源用 `${CLAUDE_SKILL_DIR}`**，
> 因为技能可能被装到任何位置；
> **脚本旁边的静态文件用 `__file__`**，因为它们跟着脚本走。

而作用于项目文件时的唯一正确写法是**要求显式传入绝对路径**，不猜。

## 3. 假设二：命令与版本存在

```python
subprocess.run(["node", "build.js"])   # 没装 node → FileNotFoundError
subprocess.run(["python", "-c", ...])  # macOS 上 python 可能指向 2.7
```

两类失败，第二类更危险：

| | 症状 |
|---|---|
| 命令不存在 | 报错（可见） |
| ⭐⭐⭐⭐ 版本不对 | 脚本能跑，行为不同（语法、默认参数、时区处理都可能变） |

> ⭐⭐⭐⭐ **版本不匹配是唯一一种"同一个命令、两种正确行为"的情况。**

最小可行的声明方式不是写文档，是**在脚本里检查并说清**：

```python
import sys
if sys.version_info < (3, 9):
    print("需要 Python >= 3.9（当前 {}.{}）；"
          "本脚本使用了 dict 合并运算符".format(*sys.version_info[:2]),
          file=sys.stderr)
    sys.exit(30)
```

> ⭐⭐⭐⭐ 关键不只是"报错"，而是**说明为什么需要这个版本**——
> 否则模型只会看到"版本不对"，不会知道能不能降级处理。

## 4. 假设三：编码

```python
open(path).read()          # ⭐⭐⭐⭐ 用平台默认编码
```

| 平台 | 默认 |
|---|---|
| Linux / macOS | UTF-8 |
| ⭐⭐⭐⭐ Windows（中文环境） | 可能是 GBK |

两类症状：

```
UnicodeDecodeError          → 报错（可见）
⭐⭐⭐⭐⭐ 读出来是乱码但不报错  → 后续所有处理基于错误文本
```

> ⭐⭐⭐⭐⭐ 第二类在中文技能库里尤其常见：
> 读 GBK 文件用 UTF-8 解析，某些字节序列恰好能解码成合法字符，
> **于是内容错了，而没有任何环节认为出错了**。

修法一行：`open(path, encoding="utf-8")`——
**显式写出编码不是风格问题，是声明"这个脚本假定输入是 UTF-8"**，
于是输入不是 UTF-8 时会明确失败，而不是静默产出错内容。

## 5. 假设四：时区与 locale

```python
datetime.now()                     # 本地时区
sorted(names)                      # 按 locale 的排序规则
f"{value:,.2f}"                    # 千分位与小数点随 locale 变
```

> ⭐⭐⭐⭐⭐ **这三项在作者的机器上永远正确，而它们不在任何依赖清单里。**

时区尤其隐蔽，因为它产生的是"差几小时"的错误：

```
本地 CST 统计"今天" → 2026-10-02 00:00 ~ 23:59
CI 上 UTC       → 同一段代码统计的是不同的 8 小时
```

> ⭐⭐⭐⭐ 输出完整、数字真实、时段偏移，且不产生任何异常信号。
> （与之同源的时间窗口问题见
> 《skill-input》的 `skill-input/references/relative-time-resolution.md`。）

两条规则：

```
① 存储与计算一律用 UTC，只在展示层转本地
② ⭐⭐⭐⭐⭐ 把时区写进输出：{"tz": "Asia/Shanghai", "window": [...]}
```

第二条才是关键——它不能防止算错，但能让错变成可见。

## 6. 假设五：环境变量与本地配置

```python
token = os.environ["API_TOKEN"]      # KeyError（可见）
token = os.getenv("API_TOKEN", "")   # ⭐⭐⭐⭐⭐ 空串（不可见）
```

> ⭐⭐⭐⭐⭐ **`getenv` 带默认值这个写法，把"没配置"变成了一个合法的配置值。**

后果链条：

```
token = "" → 请求发出 → 401 → 脚本重试 → 仍 401 → 最后返回"部分成功"
```

而如果不重试直接报告 401，问题会在第一次就暴露。
（重试在权限类错误上的无效性见
《skill-input》的 `skill-input/references/tool-argument-construction.md`。）

规则：**凭据缺失是非 0 退出，不是降级**。

## 7. ⭐⭐⭐⭐ 为什么没人声明

三个原因，第三个最根本：

| | 说明 |
|---|---|
| 没有字段 | frontmatter 里没有 `environment` 这一项 |
| ⭐⭐⭐⭐ 无法验证 | 作者只有一台机器，他无法知道自己做了什么假设 |
| ⭐⭐⭐⭐⭐ 假设是隐性的 | ⭐⭐⭐⭐⭐ **你不知道自己不知道的东西** |

> ⭐⭐⭐⭐⭐ 第二条是关键：**环境假设的定义就是"你没意识到的那部分环境"。**
> 所以它不是"忘了写"，是**结构上写不出来**——
> 你只能声明你已经想到的依赖，而假设恰恰是没想到的那部分。

这解释了为什么"换个环境测一遍"有效而"仔细回想一遍"无效：
前者不需要你知道自己假设了什么。

## 8. ⭐⭐⭐⭐⭐ 修法：探测，不假设

这是库里反复出现的同一手法的第六个场景
（前五个：版本探测、环境探测、schema 探测、规模探测、字段探测）：

```
❌ 声明"数据长什么样 / 环境是什么样"   → 会过期
✅ 写"怎么查出它长什么样"              → 不会过期
```

脚本层的具体形式：

```python
# ❌ 假设目录结构
files = glob.glob("src/**/*.ts")

# ✅ 探测后告知
found = glob.glob("**/*.ts", recursive=True)
if not found:
    print("⚠ 未找到 .ts 文件。探测结果："
          f"根目录={os.getcwd()}，顶层={os.listdir('.')[:20]}", file=sys.stderr)
    sys.exit(20)
```

> ⭐⭐⭐⭐⭐ **探测失败的报错里必须带上探测到的东西。**
> 只说"没找到"时，模型只能猜原因；
> 把"我看到了什么"一起输出，模型就能判断是路径错了还是真的没有。

三种"不能探测、必须假设"的例外：

```
① 编码（探测不可靠，必须显式声明）
② 时区（探测结果是"当前"，而你需要的是"应该用哪个"）
③ ⭐⭐⭐⭐⭐ 安全相关的边界（探测意味着"不存在时不禁止"，错了就是放行）
```

> ⭐⭐⭐⭐⭐ 第三条与 `reusability-over-specification.md` 的例外条款完全一致：
> **Gotchas、项目约定、安全红线这三样不能探测。**

## 9. 自检

| 检查 | 做法 |
|---|---|
| ⭐⭐⭐⭐⭐ 全新克隆 | 新目录 clone 一份，直接跑脚本（最常见的一次性发现 2–3 条） |
| ⭐⭐⭐⭐⭐ 换 cwd | `cd /tmp && python /abs/path/script.py`，看是否还能找到文件 |
| ⭐⭐⭐⭐ 无本地配置 | 临时 `mv .env .env.bak` 再跑 |
| ⭐⭐⭐⭐ 显式编码 | `grep -n "open(" scripts/*.py`，有没有不带 `encoding=` 的 |
| ⭐⭐⭐ 时区 | `TZ=UTC` 跑一次，对比输出 |
| ⭐⭐⭐ 版本 | 在最低支持版本上跑一次 |

> ⭐⭐⭐⭐⭐ 最高性价比的一条：**换 cwd 跑一次。**
> 零成本、30 秒，而它能同时暴露路径假设、相对路径、以及
> "存在但是另一个文件"这一类最贵的静默失败。
