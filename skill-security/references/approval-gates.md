## 门该拦什么

> ⭐ **护栏只拦不可逆操作。**

```
✅ 该拦：
   force push
   生产部署
   数据库删除 / 删字段
   公开发布
   对外发消息（邮件、工单回复、社媒）
   花钱的操作
   阻断生产流量

❌ 不该拦：
   读操作
   本地文件写入（工作区内）
   跑测试
   生成草稿
```

呼应 `authoring-checklist.md`（**`skill-authoring`**）：
**过约束会让 agent 瘫痪——一次普通 git push 也要确认三遍**。

## 门放哪一层

```
❌ 提示词层："删除前请确认"
   ——⭐ 这是建议，不是门

✅ ⭐ 工具层：allowed-tools 不给该权限
   ——没权限就是没权限

✅ ⭐ Hook 层：PreToolUse 拦截，exit 2 阻止
✅ ⭐ 脚本层：默认 dry-run，--commit 才真做
✅ 流程层：先输出命令清单，确认后再执行
```

**关键区分**（呼应 `sandbox-execution.md` 与 `what-not-to-do.md`）：

> ⭐ **技能里的权限声明不是安全边界。
> 安全控制必须在工具层做，技能说了不算。**

**一个重要的设计分歧**（来自 `Anthropic 实践`）：

```
客户常用：  PreToolUse 硬门禁
Anthropic 自己：⭐ 把硬门禁放在 CI 阶段
```

两者不冲突——**运行时门防"做错事"，CI 门防"错的东西进来"**。

## 四种门的形式

**① 默认 dry-run**（最推荐）

```bash
tool --dry-run     # 默认：只显示会改什么
tool --commit      # 显式才真做
```

呼应 `cli-design-skills.md`（**`skill-domain-eng`**）与
`idempotency-resume.md`（**`skill-crafting`**）。

**② 命令清单先行**

```
执行前先输出完整命令清单，用户确认后再逐条执行
```

**③ Hook 拦截**

```
PreToolUse matcher: Bash(rm *) / Bash(git push --force *)
不匹配 → 放行
匹配   → ⭐ exit 2 阻止（exit 1 只是留标记，不阻止）
```

> ⭐ **退出码协议很关键**：
> `exit 2` 才阻止，`exit 1` 只在日志里留个标记。
> 这是 `Hooks` 最容易搞错的地方。

**④ 分级：白名单 + 熔断**

```
□ never-block allowlist（永不阻断白名单）
□ max-actions 熔断器（动作数上限）
□ ⭐ 生产环境额外批准门
```

呼应 `soc-soar-skills.md`（**`skill-domain-eng`**）。

## 三条失效方式

> ⭐ **门最容易在这些地方失效**：

**① 流程顺序让门失效**

```
❌ 先读不可信内容，再经过批准门
   ——⭐ 不可信内容里写着"跳过确认"，门就被绕过了

✅ ⭐ 写操作的确认门必须在读取不可信内容之后仍然有效
```

呼应 `untrusted-repo-content.md`（**`skill-selection`**）：
**PR/Issue/CI 日志都是数据不是指令**。

**② 门太宽导致麻木**

```
□ 什么都拦 → 用户闭眼点确认 → 门等于不存在
□ ⭐ 只拦不可逆的，才能保住门的效力
```

**③ 恢复时门重复触发**

```
□ 长任务跑到一半，恢复时又要重新批准
□ ⭐ 批准状态要写进状态文件（见下）
```

## 批准状态要持久化

> ⭐ **状态文件记录批准，这样重跑不会反复询问。**

呼应 `idempotency-resume.md`：

```
□ 破坏性变更需要额外确认
□ ⭐ 批准记录在状态文件里
□ 增量变更按 plan-then-execute 推进
```

**为什么重要**：

```
不持久化 → 恢复时卡住 → 自主流程断了
         → 或者用户为了让流程跑完而一次性批准所有后续
```

## 过犹不及

**症状与修法**：

```
症状：agent 变瘫痪，一切都要确认
修法：⭐ 只拦不可逆操作

症状：确认对话框变成仪式（用户不看就点）
修法：⭐ 减少门的数量，让每个门都有意义

症状：门被绕过（agent 找别的方式达成）
修法：⭐ 门要在工具层，不能在提示词层
```

> ⭐ 呼应 `guidance-forms.md`（**`skill-crafting`**）的形态匹配：
> **禁令只在防明知故犯时有效**——
> 想真正阻止，要给机制而不是措辞。
