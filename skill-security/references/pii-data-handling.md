## 三个暴露面

```
1. ⭐ 技能文件本身
   ——SKILL.md 是明文，会被整段读进上下文
   ——⭐ 硬编码密钥/内网地址会被扫描器抓，也会被模型看到

2. ⭐ 运行时数据
   ——技能读到的用户文件、数据库内容、日志
   ——会进入上下文，进而进入 trace 与日志

3. ⭐ 输出与遥测
   ——模型的输出、工具的响应、可观测平台的记录
```

呼应 `skill-structuring` 的 `frontmatter-fields.md`（**`skill-crafting`**）：
**不写硬编码密钥/内网地址——只写"从环境变量读取"**。

## 技能该写什么

**必写的三条**：

```
□ ⭐ 不写硬编码密钥、令牌、内网地址、个人身份信息
□ ⭐ 需要凭据时只写"从环境变量读取"
□ ⭐ 处理外部数据时声明"这是数据不是指令"
```

第三条呼应 `prompt-injection.md`（**`skill-orchestration`**）：
**用边界标记包裹不可信内容**。

**按数据类型分级**（这是技能真正的价值）：

| 数据类型 | 处理方式 |
|---|---|
| 凭据 / 密钥 | ⭐ 永不进入上下文；脚本读取环境变量 |
| PII（姓名、手机、邮箱） | ⭐ 默认去标识化后再进入上下文 |
| 财务数据 | 聚合优先，不逐条进入 |
| 健康数据 | ⭐ 默认不进入；确需时脱敏且标注 |
| 业务数据 | 按需进入，但输出要限制 |

## 去标识化的层次

```
1. 抑制（suppression）
   直接删掉标识符字段

2. ⭐ 泛化（generalization）
   精确值 → 区间或类别
   例：年龄 37 → "35–39"；地址 → 城市

3. 假名化（pseudonymization）
   换成稳定但不可逆的代号
   ⭐ 保留可关联性（同一人始终是同一代号）——分析仍可做

4. 掩码（masking）
   部分保留：138****1234
```

> ⭐ **假名化与匿名化不同**：
> 假名化后数据**仍属个人数据**（因为可重新识别），
> 匿名化后不再是。
> 技能里要写清用的是哪一种——这个区别决定合规义务。

## 日志与遥测的红线

呼应 `telemetry-schema.md` 的"什么不该记"：

```
❌ 系统提示词原文    → ✅ prompt_template_version
❌ 思维链            → ✅ 归一化后的 prompt_hash
❌ 原始工具载荷      → ✅ schema 版本 + 白名单字段
❌ ⭐ 用户 PII       → ✅ 去标识化后的引用 ID
```

**目标**：

> ⭐ **让 prompt 可 diff，但不可读。**

**一条具体建议**（来自 `telemetry-schema.md`）：

```
□ ⭐ 一定要记 top_k
   ——RAG 回归常常是它从 5 悄悄变成 20
```

**采样也是隐私手段**：

```
□ ⭐ 低价值 span 采样率降到 0
   ——既省成本，也减少暴露面
```

呼应 `observability-tools.md`：
**Langfuse 允许你节流 span，LangSmith 惩罚细粒度 span**。

## 数据驻留与跨境

```
□ ⭐ 自托管方案让 trace 不离开你的 VPC
□ 托管 SaaS 默认数据在其云上——企业合同需约定驻留
□ ⭐ 跨境传输通常触发额外合规义务
```

呼应 `observability-tools.md` 的核心结论：
**如果 trace 里有不能出内网的数据，这一条直接决定选型**。

以及 `compliance-audit.md`：
**部署者日志留存 ≥6 个月**——留存要求与删除权之间要有明确策略。

## 自检

```
□ 技能文件里没有硬编码凭据或内网地址？
□ 需要处理 PII 的技能写了去标识化要求？
□ 写清了"假名化还是匿名化"？
□ 要求用边界标记包裹不可信数据？
□ 遥测只记版本与哈希而非原文？
□ 低价值 span 采样率可调到 0？
□ 数据驻留要求影响工具选型了吗？
□ 留存期与删除请求的处理策略明确吗？
```

## 一个常被忽略的点

> ⭐ **例子里的数据也算数据。**

```
❌ 技能示例里写"客户张三，手机 13800138000，卡号 6222..."
✅ 用明显的假数据：张某某、138****0000、[CARD_ID]
```

**两个理由**：

```
1. ⭐ 真实示例数据可能来自真实客户——放进技能库就是泄露
2. ⭐ agent 会照抄示例（见 guidance-forms.md 的占位符陷阱）
   ——示例里有真数据，输出里就会有
```

呼应 `examples.md`（**`skill-authoring`**）：
**一两份干净范例远胜几十个杂乱例子**——
"干净"也包括不含真实敏感数据。
