## 1. ⭐⭐⭐⭐⭐ 三层配置结构

```
① ⭐⭐⭐ hook event    —— 生命周期点（PreToolUse / Stop / SessionStart …）
② ⭐⭐⭐⭐ matcher group —— 过滤器（"仅 Bash 工具"）
③ ⭐⭐⭐⭐⭐ hook handler —— 实际运行的 shell 命令 / HTTP 端点 / MCP 工具 / prompt / agent
```

```json
{ "hooks": { "PreToolUse": [
    { "matcher": "Edit|Write",
      "hooks": [ { "type": "command", "command": "./protect-files.sh" } ] } ] } }
```

**一个容易忽略的性能设计**：

> ⭐⭐⭐⭐ **matcher 之外还有一层可选的 `if` 条件**——
> `if: "Bash(rm *)"` 先做一次廉价匹配，⭐ 不匹配就根本不 spawn 进程。

```
❌ 只有 matcher "Bash" → ⭐⭐⭐ 每一条 shell 命令都要 spawn 一次脚本进程
✅ 再加 if "Bash(rm *)" → ⭐⭐⭐⭐⭐ ⭐ 只有 rm 开头才 spawn，⭐⭐⭐⭐ 省掉进程开销
```

> ⭐⭐⭐⭐⭐ 这条⭐ 值得⭐ 单独⭐ 记住，⭐⭐⭐⭐⭐ ⭐ 因为⭐ 它⭐ 是⭐ "⭐⭐⭐⭐⭐ **把廉价判断⭐ 放在⭐ 昂贵动作⭐ 之前**"
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 的⭐ 又一个⭐ 实例——⭐⭐⭐⭐ ⭐⭐⭐ 与 `skill-security/references/hook-risk.md` 的⭐ 思路一致，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 也⭐ 与⭐ 第 5 节⭐ 那条⭐ "⭐ 便宜检查先做"⭐ 同源。

## 2. ⭐⭐⭐⭐⭐ 12 个生命周期事件

| 事件 | 何时触发 | 能否阻断 |
|---|---|---|
| `SessionStart` | 会话开始或恢复 | — |
| `UserPromptSubmit` | 提交提示后、Claude 处理前 | ✅ |
| `PreToolUse` | 工具调用执行前 | ✅ |
| `PermissionRequest` | 权限对话框出现时 | ✅ |
| `PostToolUse` | 工具调用成功后 | ❌ |
| `PostToolUseFailure` | 工具调用失败后 | ❌ |
| `Notification` | 发送通知时 | — |
| `SubagentStart` | 子代理被派生时 | — |
| `SubagentStop` | 子代理结束时 | ⭐ 可续接 |
| `Stop` | Claude 结束回复时 | ⭐ 可续接 |
| `PreCompact` | 上下文压缩前 | — |
| `SessionEnd` | 会话终止时 | — |

> ⭐⭐⭐⭐⭐ 其中⭐ `Stop` 与⭐ `SubagentStop` ⭐ 有一个⭐ 2026 年的⭐ 升级，⭐⭐⭐⭐ ⭐ 很值得记：
> ⭐⭐⭐⭐ **它们可以返回 `hookSpecificOutput.additionalContext`，
> ⭐⭐⭐⭐⭐ ⭐ 把新内容⭐ 喂回⭐ 这一轮，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不会⭐ 被当作错误。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 且⭐ 输入载荷⭐ 现在⭐ 包含 `background_tasks` 与 `session_crons`——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **Hook 能看见⭐ "还有什么在排队"，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 再决定⭐ 这一轮⭐ 是不是⭐ 真的该停。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 补上了⭐ 我们⭐ 此前⭐ 一条⭐ 只提了⭐ 一半的⭐ 建议：
> ⭐⭐⭐⭐⭐ `skill-execution/references/seven-contracts.md` 说⭐ "⭐ 别把完成任务⭐ 当成⭐ 终止条件"，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 没说⭐ 怎么⭐ 让 agent ⭐ 在⭐ "看起来完成了"⭐ 时
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 还能⭐ 看见⭐ 未完成的⭐ 后台任务——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ **这就是⭐ 那个⭐ 机制。**

## 3. ⭐⭐⭐⭐⭐ 退出码契约

```
⭐⭐⭐⭐⭐ exit 0        → 放行。
    ⭐⭐⭐⭐⭐ ⭐⭐⭐ 对 UserPromptSubmit / SessionStart：⭐⭐⭐⭐⭐ ⭐⭐⭐ stdout 的任何内容
                    ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 都会被加进 Claude 的上下文

⭐⭐⭐⭐⭐ exit 2        → ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 硬阻断。动作被取消，
                    ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ stderr 的内容⭐ 作为原因⭐ 反馈给 Claude

⭐⭐⭐⭐⭐ 其他非 0     → ⭐⭐⭐⭐ ⭐⭐⭐⭐ 错误。工具调用失败，⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型看到失败，
                    ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 动作⭐ 不被⭐ 特定地阻断
                    ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ stderr 只写日志，⭐⭐⭐⭐⭐ ⭐⭐⭐ 不给 Claude 看
```

> ⭐⭐⭐⭐⭐ 这个⭐ 三档⭐ 设计⭐ 比⭐ "成功/失败"⭐ 两档⭐ 精细⭐ 得多，⭐⭐⭐⭐⭐ ⭐ 而且⭐ 每一档⭐ 都有⭐ 明确后果。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 对照⭐ 我们⭐ 已有的⭐ 一条⭐ 原则：
> ⭐⭐⭐⭐⭐ **"`FAIL 阻断 / WARN 不阻断` 必须有不同后果，否则分级没意义"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 这里⭐ 是⭐ 它的⭐ 一次⭐ 教科书式实现：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **0 / 2 / 其他 ⭐ 三档，⭐⭐⭐⭐⭐ ⭐⭐⭐ 分别对应
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 放行+可注入 / ⭐ 阻断+原因反馈 / ⭐ 失败但不可见原因。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 也⭐ 与 `skill-scripting/references/script-cli-contract.md` 那份⭐ 完全同构
> （⭐ 脚本⭐ 用⭐ 退出码⭐ 跟模型说话）——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 两个⭐ 不同⭐ 载体⭐ 收敛到⭐ 同一个⭐ 契约，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 说明⭐ 这⭐ 确实⭐ 是⭐ "⭐⭐⭐⭐⭐ 跟模型通信"⭐ 的⭐ 正确方式。

## 4. ⭐⭐⭐⭐⭐ 沉默不等于批准

> ⭐⭐⭐⭐⭐ **"⭐ exit 0 且⭐ 无输出 ⭐ 意味着⭐ 这个 hook ⭐ 没有⭐ 决策要报告，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 于是⭐ 工具调用⭐ 继续走⭐ 正常的⭐ 权限流程。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐ **Hook 可以拒绝这次调用，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 保持沉默⭐ 并不等于⭐ 批准它。"**

```
⭐⭐⭐⭐⭐ 关键区分：
   "Hook 没反对"  ≠  "Hook 同意了"
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 沉默只是⭐ 把决策权⭐ 交还给⭐ 正常的权限流程
```

> ⭐⭐⭐⭐⭐ 这条⭐ 看似⭐ 只是⭐ 一句⭐ 澄清，⭐⭐⭐⭐⭐ ⭐ 实则⭐ 极重要——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 它⭐ 澄清了⭐ 一个⭐ 极易⭐ 搞错的⭐ 安全假设：
> ⭐⭐⭐⭐⭐ **"⭐ 我加了 hook，⭐⭐⭐⭐⭐ ⭐⭐⭐ 所以危险命令⭐ 被挡住了"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ 不一定。⭐⭐⭐⭐⭐ ⭐⭐⭐ 如果你的脚本⭐ 走了
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ `exit 0`（比如⭐ 某个分支⭐ 没覆盖到），
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 它⭐ 并没有⭐ 批准，⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 它⭐ 也没拦——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 决策⭐ 回到了⭐ 权限流程，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 那⭐ 是⭐ 另一套规则。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 这⭐ 与⭐ 我们已有的⭐ 一条⭐ 完美咬合：
> ⭐⭐⭐⭐⭐ **"⭐ 声明摄入 → ⭐ 权限强制 → ⭐ 运行时隔离"⭐ 三层纵深**
> （`skill-security/references/allowed-tools-least-privilege.md`）——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **Hook 沉默 ⭐ 意味着 ⭐ 第二层⭐ 交还给⭐ 第二层的默认规则，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而不是⭐ 跳过了⭐ 第二层。**

## 5. ⭐⭐⭐⭐⭐ 阻断消息必须可行动

官方文档那句⭐ 理由⭐ 已经⭐ 很好，⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 实践者的⭐ 版本⭐ 更锋利：

> ⭐⭐⭐⭐⭐ **"⭐ 写进 stderr 的⭐ 原因字符串⭐ 就是⭐ 模型⭐ 看到的⭐ 全部，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 所以⭐ 要⭐ 让它⭐ 可执行：⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 告诉模型⭐ 下一步该做什么，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不只是⭐ 哪里错了。"**
>
> ⭐⭐⭐⭐⭐⭐ **"⭐ 我们⭐ 是⭐ 吃了苦头⭐ 才学到⭐ 这一点的——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ Claude ⭐ 把⭐ 同一条⭐ 被阻断的命令⭐ 试了 ⭐ 九次，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ 因为⭐ 那条⭐ 拒绝消息⭐ 没有⭐ 给出⭐ 替代方案。"**

```
❌ "Blocked: command matches destructive pattern."
✅ "Blocked by guard rail: … ⭐ Reword the request, or ask a human to run this manually."
```

> ⭐⭐⭐⭐⭐⭐ **这是"⭐ 禁令必须⭐ 带⭐ 正面对应物 / 替代方案"⭐ 这条⭐ 结论的
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 又一次⭐ 独立出现**（此前⭐ 我们⭐ 已记录⭐ 四次：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 禁令反噬、⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ "不要简化→写明保留哪些步骤"、
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ "别猜→说出不确定+给最佳判断+必要时问"、
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ "Don't include→只报告 bug"）。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 但⭐ 这一次⭐ 是⭐ 最有说服力的⭐ 一次，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **因为它⭐ 给出了⭐ 一个⭐ 可观测的⭐ 代价：⭐⭐⭐⭐⭐ ⭐⭐⭐ 九次重试。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 也⭐ 与⭐ 我们⭐ 那条⭐ "⭐⭐⭐⭐⭐ **通过⭐ 给循环模式⭐ 命名、
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 告诉模型'重复是有意义的'，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ 你把⭐ 无限循环⭐ 转换成⭐ 一条⭐ 有用的⭐ 错误信息**"

## 速查

```
□ ⭐⭐⭐⭐⭐ 三层：hook event · matcher group · hook handler
□ ⭐⭐⭐⭐⭐ 12 事件：SessionStart · UserPromptSubmit · PreToolUse(阻断) · PermissionRequest(阻断)
   PostToolUse(不阻断) · PostToolUseFailure · Notification · SubagentStart/Stop · Stop · PreCompact · SessionEnd
□ ⭐⭐⭐⭐⭐ 退出码三档：0=放行（UserPromptSubmit/SessionStart 的 stdout 进上下文）
   2=硬阻断（stderr 作为原因反馈给 Claude）· 其他非0=错误（模型看到失败，stderr 只写日志不给 Claude）
□ ⭐⭐⭐⭐⭐ 沉默 ≠ 批准："Hook 没反对"不等于"Hook 同意了"——exit 0 无输出只是把决策交还权限流程
□ ⭐⭐⭐⭐⭐ 阻断消息必须可行动：写明下一步该做什么，而不只是哪里错了
   ⭐⭐⭐⭐⭐⭐ 实测代价：Claude 把同一条被阻断命令试了九次，因为拒绝消息没给替代方案
```
