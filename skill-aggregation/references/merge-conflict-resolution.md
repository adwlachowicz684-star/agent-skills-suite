## 1. 一个真实的输出

```
来源 A（埋点）：新增用户 1,204
来源 B（订单库）：新增用户 1,187
最终输出：新增用户 1,187
```

> ⭐⭐⭐⭐⭐ 两个数字都进了上下文，输出里只剩一个——
> 而"选了一个"这件事，在任何地方都没有写着。

输出是完整的、格式是对的、数字是真的。⭐⭐⭐⭐⭐ **它只是不是全部的事实。**

更难发现的一点：**取哪个，通常是最后一个被读到的、或最详细的那个**——
也就是说，它取决于读取顺序，而读取顺序通常取决于并行完成的先后。

> ⭐⭐⭐⭐⭐ 于是同一个输入可能得到不同的答案，而没有任何一方报错。
> 这正好是"不稳定"那类失败，但它长得完全像确定性输出。

## 2. 为什么默认动作是消掉矛盾

汇总指令的形状通常是：

```
"汇总各来源的结果，输出一份统一的报告"
```

> ⭐⭐⭐⭐⭐ **"统一"这个词本身就要求消除分歧**，
> 而消除分歧最省事的实现就是只留一个。

三个推力：

| 推力 | 说明 |
|---|---|
| 指令里的"统一/一致" | 分歧被当成待清理的瑕疵 |
| ⭐⭐⭐⭐ 输出模板只有一个字段 | 模板装不下两个值，于是必须选 |
| ⭐⭐⭐⭐⭐ 模型有完成倾向 | 报冲突 = 承认没做完；取一个 = 完成 |

第三条最根本：**报冲突意味着"我没能给出一个答案"，而模型的默认目标是给出答案。**

## 3. 矛盾是信息，不是噪声

```
A 与 B 差 17
→ 两个来源口径不同（一个是注册数、一个是首单数）
→ ⭐⭐⭐⭐⭐ 这个差异告诉你：这两个数本来就不该被当成同一个指标
```

> ⭐⭐⭐⭐⭐ **矛盾是唯一能暴露"口径不一致"的信号，
> 而汇总的默认动作恰恰把这个信号删掉了。**

对比一下：

| | 谁发现问题 |
|---|---|
| 缺失（某路没返回） | 覆盖率能发现 |
| ⭐⭐⭐⭐⭐ 口径不一致（都返回了但不是一个东西） | ⭐⭐⭐⭐⭐ 只有矛盾能发现 |

所以矛盾和缺失是两类不同的病，而多数汇总只处理了后者。

## 4. 三条规则

```
① ⭐⭐⭐⭐⭐ 差值超阈值 → 报冲突，不得静默取一个
② ⭐⭐⭐⭐⭐ 取一个时必须标注来源与口径（"按 A 口径：1,204"）
③ ⭐⭐⭐⭐ 口径不同 → 并列呈现，不做平均
```

第②条最便宜也最常被省：**"按 A 口径"四个字**，把"一个数字"变成"一个可追溯的数字"。

第①条的报冲突格式建议写死：

```
⚠️ 来源不一致：A=1,204 / B=1,187（差 17，阈值 1%）
   未采用任一值；口径待确认
```

> ⭐⭐⭐⭐⭐ 关键是"未采用任一值"——它把决策交回给人，而不是替人做完。

## 5. 平均是最危险的一种"解决"

```
(1,204 + 1,187) / 2 = 1,195.5
```

> ⭐⭐⭐⭐⭐ **平均产生一个两个来源都不支持的数字，
> 而它看起来最像"客观地处理了分歧"。**

它同时犯三个错：

```
① 制造了一个不存在的精度（1,195.5 个用户）
② ⭐⭐⭐⭐⭐ 掩盖了口径差异（本来该报的 bug 变成了数字）
③ 不可追溯（无法回答"这个数是怎么来的"）
```

判据：⭐⭐⭐⭐⭐ **如果这个值在任何一个来源里都找不到，它就不该出现在输出里**——
除非它是明确标注为"估算"的派生量。

同理适用于：取最大值、取最小值、取中位数——**它们都是"选了一个"，只是伪装成计算。**

## 6. 阈值从哪来

"差值超阈值就报冲突"里的阈值，是最容易出现无出处数字的地方。

| 来源 | 可用性 |
|---|---|
| ⭐⭐⭐⭐⭐ 业务容忍度倒推（对账差异 >0.1% 就要查） | 可用，需注明出处 |
| ⭐⭐⭐⭐ 历史观测（这两路平时差 0–20） | 可用，需注明是经验值 |
| ⭐ 拍一个数（1%） | ⭐⭐⭐⭐⭐ 会导致两种错：天天报警 / 永不报警 |

> ⭐⭐⭐⭐⭐ 阈值缺失比阈值不准更危险：
> 没有阈值时，模型用"看起来差得多"来判断，而这个判断每次都可能不同。

写法：`阈值：相对差 > 1%（经验值，未实测，来源：2026-08 对账记录）`
——参见 `skill-precision/references/unjustified-numbers.md`。

## 7. 自检

| 检查 | 不通过的信号 |
|---|---|
| ⭐⭐⭐⭐⭐ 两路给不同值时，输出是报冲突还是只剩一个？ | 只剩一个 |
| ⭐⭐⭐⭐⭐ 取的值有没有标注来源与口径？ | 只有一个裸数字 |
| ⭐⭐⭐⭐⭐ 输出里有没有出现任何来源都不支持的值？ | 出现（平均数、估值） |
| ⭐⭐⭐⭐ 阈值是否写了出处？ | 只有一个百分数 |
| ⭐⭐⭐⭐ 并列呈现是不是被输出模板挡住了？ | 模板该字段只有一格 |
| ⭐⭐⭐⭐⭐ 把 A 的结果改成 1,500 跑一次，输出变了吗？ | ⭐⭐⭐ 没变 = 它一直在取 B，从未比较 |
