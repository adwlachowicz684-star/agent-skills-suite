## 1. 官方比喻

> ⭐ **两侧悬崖的窄桥 → 给精确护栏**
> **无危险的开阔地 → 给大方向**

这个比喻把"该写多细"变成了一个可判断的问题：
**这条路径错了会不会摔死？**

## 2. 三档自由度

| 档 | 适用 | 写法 |
|---|---|---|
| **低** | 脆弱操作、不可逆、多种做法都错 | 精确步骤、具体命令、无替代 |
| **中** | 有推荐做法但可变化 | 带默认值的模板、可调整参数 |
| **高** | 无危险、多种正确做法 | 目标 + 判据，不指定路径 |

典型对照（cherry-pick 的例子）：

```
低自由度（不适合）      高自由度（适合）
Step 1: git log ...     把 commit cherry-pick 到干净分支。
Step 2: cherry-pick     解决冲突时保留意图。
Step 3: git status      无法干净落地就说明原因。
...
```

> ⭐ cherry-pick 属于"中等偏高"——有多条路径能达成，
> 写死按键顺序反而会在上下文变化时失效。

## 3. 匹配原则

```
任务越脆弱 → 自由度越低
环境越不确定 → 自由度越高
```

判断问题：

```
① 做错了代价多大？（不可逆 → 低自由度）
② 有多少种正确做法？（只有一种 → 低自由度）
③ 环境会不会变？（会 → 高自由度）
```

---

## 4. ⭐ 一句该贴在墙上的话

> **"这一段配得上它的 token 成本吗？"**

每一条约束都在消耗常驻预算。
**加约束之前先问它是否真的改变了模型行为**
（这与 `pruning.md` 的 no-op 测试同源）。

---

## 5. 过度约束的代价

技能会被复用到你没预想的场景。写死到"某个确切用例"：

```
❌ 上下文一变技能就失效
❌ 模型被卡在错误路径上还要硬走
❌ 无法利用模型自己的判断
```

> ⭐ **给模型它需要的信息，但别替它决定怎么做。**

## 速查

| 任务 | 自由度 |
|---|---|
| 生产数据库变更 | 低（精确护栏） |
| 删除/覆盖操作 | 低 |
| 有团队约定的流程 | 中 |
| 代码重构 | 高（给目标与判据） |
| 探索/调研 | 高 |
