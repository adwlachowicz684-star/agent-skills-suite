## 必填字段

```yaml
---
name: skill-name
description: 做什么 + 什么时候用
---
```

**只有这两个是必需的。** 其余全部可选。

## 可选字段

| 字段 | 约束 | 用途 |
|---|---|---|
| `license` | 短名称或指向 LICENSE 文件 | 许可 |
| `compatibility` | ≤500 字符 | 环境要求（**多数技能不需要**） |
| `metadata` | 键值映射 | 自定义元数据（author、version…） |
| `allowed-tools` | 空格分隔字符串 | **预批准**的工具（实验性，支持度不一） |

```yaml
compatibility: Requires Python 3.14+ and uv
metadata:
  author: example-org
  version: "1.0"
allowed-tools: Bash(git:*) Read
```

## name 的三条铁律

| # | 规则 |
|---|---|
| 1 | **1–64 字符**，仅 `a-z` `0-9` `-` |
| 2 | 不能以 `-` 开头或结尾，不能有连续 `--` |
| 3 | **必须与父目录名完全一致** |

```
✅ pdf-processing   data-analysis   code-review
❌ PDF-Processing   -pdf   pdf--processing
```

> 🚨 **第 3 条最容易踩**：name 与目录名不匹配时是**静默失败**——
> 技能被扫到但不加载，`/` 菜单里看不到，**也不报错**。
> 调不出来时先查这个。

## description 的写法纪律

**约束**：1–1024 字符，非空，不含 XML 标签。应同时说清**做什么**和**何时用**。

**四条纪律**：

| # | 纪律 | 说明 |
|---|---|---|
| 1 | **第三人称** | 不写"我可以帮你"，写"用于……" |
| 2 | **肯定式** | 模型**会忽略否定词**，别靠"不做 X"来表达正向用途 |
| 3 | **字面触发词** | 写用户真正会说的词，别写同义词 |
| 4 | **覆盖隐含意图** | 用户不明说也要能触发 |

**差的写法**：

```yaml
description: 帮助整理会议内容。
```

太短、太虚、无触发词。

**好的写法**：

```yaml
description: 用于把会议录音转写、草稿笔记、截图或聊天记录整理成正式中文
  会议纪要。只要用户提到会议纪要、会议记录、行动项、待办事项、讨论结论，
  就使用本 skill。
  Do NOT use for 代码评审、PR 描述、或询问会议最佳实践。
```

**"NOT for X → 用 Y 代替" 是最强的路由提示**——一条同时治欠触发和过触发。

### 中文场景（额外两条）

1. **中文触发词比英文精确**——"写 commit" 无歧义，英文 "write a commit" 有
2. **但中文表达太丰富**——同一件事至少五种说法

> 铁律：**把所有你和你同事会说的说法都写进 description。**
> 漏掉一个常用说法，用户就觉得"技能不灵"。

**中英双语触发词覆盖最全**：`name: 英文名 中文说明（4-6 字）`。

### 两个自测方法

**反向测试法**：把 description 读出来，如果听起来像营销文案，重写。

**意图匹配测试**：想 20 个问题（10 该触发 / 10 不该触发），看命中率。不够高就回来改。

## 常见错误速查

| 症状 | 原因 |
|---|---|
| 技能在菜单里看不到 | name ≠ 目录名（静默失败） |
| 从不自动触发 | description 太模糊、缺触发词 |
| 总在不该触发时触发 | description 太宽、缺 Do NOT |
| 改了 description 没生效 | name/description **在启动时读取**，需重启客户端 |
| YAML 报解析错 | `---` 没顶格，或文件不是 UTF-8 |

## 客户端扩展字段

这些**不是开放标准**，属客户端专属。移植时可能被静默剥离：

| 字段 | 作用 |
|---|---|
| `disable-model-invocation: true` | 禁止模型自动调用（**部署类技能必设**） |
| `user-invocable: false` | 从 `/` 菜单隐藏 |
| `context: fork` | 在子代理中隔离运行 |
| `agent` / `model` / `effort` | 指定执行者、模型、推理强度 |
| `allowed-tools` / `disallowed-tools` | 工具白/黑名单 |
| `paths` | 限制触发的文件范围 |
| `hooks` | 技能生命周期内的自动化 |

> ⚠️ `allowed-tools` 是**免确认**，不是**限制**。要移除工具用 `disallowed-tools`。
> 只有部分 runtime 解析这些字段——**不要把安全逻辑放在可能被静默剥离的字段里**。

**权限控制矩阵**：

| 配置 | 你能调 | 模型能调 | 描述何时在上下文 |
|---|---|---|---|
| 默认 | ✅ | ✅ | 始终 |
| `disable-model-invocation: true` | ✅ | ❌ | 仅手动调用时 |
| `user-invocable: false` | ❌ | ✅ | 始终 |
