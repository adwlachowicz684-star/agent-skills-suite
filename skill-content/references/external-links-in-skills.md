## 1. ⭐⭐⭐⭐⭐ 链接的三种命运

技能正文里放一个 URL，实际发生什么是不确定的：

```
① ⭐⭐⭐⭐⭐ 模型去抓取 → 消耗 token、引入不可控内容、可能失败
② ⭐⭐⭐⭐⭐ 模型不抓，按 URL 字面理解 → 它"知道"这个站点，于是用训练记忆填
③ ⭐⭐⭐⭐⭐ 模型不抓，标记为"需要查看" → 任务卡住或跳过
```

> ⭐⭐⭐⭐⭐ 三种命运由模型当时的判断决定，
> ⭐⭐⭐⭐⭐ **而技能作者写这个链接时，心里想的是其中特定的一种。**

这是本份最核心的一点：

> ⭐⭐⭐⭐⭐ **URL 在技能里不是"引用"，是一次没有写明的指令，
> 而这条指令的三种解释会导致完全不同的行为。**

## 2. ⭐⭐⭐⭐⭐ 它同时是依赖，而你没声明它

与另两份依赖文档对齐：

| 依赖类型 | 缺失时 |
|---|---|
| 脚本依赖（包） | ⭐⭐⭐⭐ 报错 |
| 数据依赖（文件/服务） | ⭐⭐⭐⭐ 报错或静默造数据 |
| ⭐⭐⭐⭐⭐ **知识依赖（URL）** | ⭐⭐⭐⭐⭐ **不报错，内容过时或用记忆填充** |

> ⭐⭐⭐⭐⭐ 第三行是最安静的一种：
> ⭐⭐⭐⭐ 没有 import 失败、没有 file not found，
> ⭐⭐⭐⭐⭐ **只有一段悄悄变得不可靠的内容。**

而它未被声明的原因和另两份一样：

> ⭐⭐⭐⭐⭐ frontmatter 没有 `knowledge_dependencies` 字段，
> 即使作者想声明也只能写进正文——**而正文是触发之后才加载的。**

## 3. ⭐⭐⭐⭐⭐ 抓与不抓，都可能是错的

两种失败方向相反，所以"让它自己决定"是最差选项：

**抓的代价：**

```
· ⭐⭐⭐⭐⭐ 抓取内容进入上下文，长度不可控（一个文档页可以上万 token）
· ⭐⭐⭐⭐⭐ 抓到的是最新内容，可能与技能其余部分不一致
· ⭐⭐⭐⭐ 失败时模型会换 URL 或放弃，行为不确定
```

**不抓的代价：**

```
· ⭐⭐⭐⭐⭐ 模型用训练记忆填充 → 可能是旧版本、可能是幻觉
· ⭐⭐⭐⭐⭐ 而这恰好是"错得自信"的高发区：
  它不知道自己不知道，因为 URL 看起来给了它信息
```

> ⭐⭐⭐⭐⭐ 所以规则不是"抓"或"不抓"，
> ⭐⭐⭐⭐⭐ **是在技能里写明"这个链接该怎么处理"。**

## 4. ⭐⭐⭐⭐⭐ 判据：这段内容会不会过期

一句话判断该内联还是链接：

> ⭐⭐⭐⭐⭐ **这段内容过期了，技能会错吗？**
> 会 → 必须内联（或至少内联关键值）
> 不会 → 可以链接

具体分档：

**必须内联 ⭐⭐⭐⭐⭐**

```
· 字段名、端点、参数值（错了就调不通）
· 阈值与判据（错了结果就错）
· Gotchas（它的价值就在于具体）
```

**可以链接 ⭐⭐⭐⭐**

```
· 背景知识、教程、规范全文
· 会更新但当前版本已够用的说明
```

> ⭐⭐⭐⭐⭐ 注意第二类：⭐⭐⭐⭐ **可以链接的前提是"当前已够用"**。
> 如果技能的正确性依赖"最新版本"，那它就不是背景知识，是硬依赖。

## 5. ⭐⭐⭐⭐⭐ 写法：内联、摘要、还是链接

三种写法，各有用处：

**① ⭐⭐⭐⭐⭐ 内联关键值（最常用，也最该用）**

```markdown
- 端点：`POST /rest/api/3/issue`（依据：官方 v3 文档，2026-06 核对）
```

> ⭐⭐⭐⭐⭐ 括号内那句同时完成了三件事：
> 给出来源、给出核对时间、⭐⭐⭐⭐⭐ **让后来者知道该什么时候重验**。
> 这与 `unjustified-numbers.md` 的"数字 + 出处"是同一手法。

**② ⭐⭐⭐⭐⭐ 链接 + 摘要（reference 里推荐的形式）**

```markdown
- 官方规范：<URL>
  摘要：仅定义 6 个字段（name/description/license/compatibility/
        metadata/allowed-tools），其余为平台扩展。
```

> ⭐⭐⭐⭐⭐ **摘要是关键**——它让模型不抓也能用，
> ⭐⭐⭐⭐⭐ 而且⭐⭐⭐⭐⭐ 摘要过期时是可发现的（有人会读到并与链接比对），
> 而"纯链接"过期时不可发现。

**③ ⭐⭐⭐⭐ 纯链接（仅当内容不影响正确性）**

```markdown
- 延伸阅读：<URL>
```

> ⭐⭐⭐⭐ 这条要显式标注"延伸阅读"——
> ⭐⭐⭐⭐⭐ 不标注的话，模型可能把它当成必须获取的依赖。

## 6. ⭐⭐⭐⭐⭐ 链接失效是静默的

四种失效，全部无声：

```
① 404                      → 抓取失败，模型可能跳过
② 页面改版，内容变了        → ⭐⭐⭐⭐⭐ 抓到了，但是错的内容
③ 重定向到新版本            → ⭐⭐⭐⭐⭐ 同上，且看起来完全成功
④ ⭐⭐⭐⭐⭐ 内容变成登录可见  → 抓到一个登录页，被当成内容
```

> ⭐⭐⭐⭐⭐ 第 ④ 种最典型：**抓取"成功"了，
> 模型拿到一段"请登录后查看"，然后基于它继续。**

检测（成本很低）：

```bash
# 批量检查链接可达性
grep -rhoE "https?://[^ )\"]+" skill-*/references/*.md | sort -u | \
  while read u; do echo "$(curl -s -o /dev/null -w '%{http_code}' -L "$u") $u"; done
```

> ⭐⭐⭐⭐⭐ 但注意：⭐⭐⭐⭐ **200 不代表内容没变**——
> 这正是"别把 HTTP 200 当成功"在文档维护上的版本。
> ⭐⭐⭐⭐ 所以年检不能只看状态码，⭐⭐⭐⭐⭐ **要看摘要是否仍与页面一致**。

## 7. ⭐⭐⭐⭐ 自检

```
① ⭐⭐⭐⭐⭐ 每个 URL，模型该抓还是不该抓？写明了没有？
② ⭐⭐⭐⭐⭐ 内容过期会让技能出错吗？会 → 内联关键值了吗？
③ ⭐⭐⭐⭐⭐ 有摘要吗？（让模型不抓也能用）
④ ⭐⭐⭐⭐ 标了核对时间吗？
⑤ ⭐⭐⭐⭐ 这是"延伸阅读"还是"硬依赖"？标注了吗？
```

> ⭐⭐⭐⭐⭐ 第 ① 条最常被违反，而它⭐⭐⭐⭐⭐ 唯一决定了行为的确定性。
> 不写明的链接等于⭐⭐⭐⭐⭐ **把一次网络请求交给模型自行决定**——
> 而它有三种同样合理的做法。

一个十秒判断：

> ⭐⭐⭐⭐⭐ **把这个链接删掉，技能还能正确工作吗？
> 不能 → 它是硬依赖，必须内联关键部分。**

---

## 一句可贴在墙上

> ⭐⭐⭐ **URL 在技能里不是引用，是一条没写明的指令——
> 抓、不抓、标记为待查，三种解释导致完全不同的行为。
> 所以要么内联关键值，要么写明该怎么处理它。**
