## 1. ⭐⭐⭐⭐⭐ 三个来源逼出同一个结论

三个独立来源，同一件事：

| 来源 | 结论 |
|---|---|
| `prompt-layering-positional-bias.md` | ⭐ 首因效应与近因效应可测量；中间是黑洞 |
| `three-stages-...md` | ⭐⭐⭐ 压缩带回的是"开头 5000"，**不是"最重要的 5000"** |
| `reference-file-practices.md` | 超 100 行会被 `head -100` 预览 |

> ⭐⭐⭐⭐⭐ **第二条最关键：系统没有能力判断哪 5000 重要，
> 它只能取开头。**
> 所以"把重要的放前面"不是建议，是**顺应机制**。

推论：**中间段落的可靠性最低**——它既不在首因区，
也不在近因区，还在压缩时最先被丢。

## 2. ⭐⭐⭐⭐ 五段式骨架

按可靠性从高到低排布内容，把最重要的塞进首尾：

```
① ⭐⭐⭐ 一句话契约      ← 最高可靠区
② ⭐⭐ 关键约束 / 红线    ← 最高可靠区
③ ⭐ 术语与前置           ← 中
④ ⭐ 详细流程与示例       ← 低（但可读时被完整读）
⑤ ⭐⭐ 验证与失败处理     ← 次高（近因区）
```

关键设计：**第 ② 和第 ⑤ 是同一批约束的两端重复**——
这正是 `prompt-layering-positional-bias.md` 的建议
（"关键规则在两端都写一遍"）在章节层面的落地。

各段的作用：

| 段 | 内容 | ⭐ 为什么在这 |
|---|---|---|
| ① 契约 | "本技能做 X，不处理 Y" | ⭐ 一句话决定后面所有解释的走向 |
| ② 红线 | 必须/绝不（3–5 条） | ⭐⭐ 最不能违反的，放最前面 |
| ③ 术语 | 一个概念一个词 | 中频段，丢了也能推断 |
| ④ 流程 | 步骤、示例、模板 | ⭐ 最长，但被读时通常是完整读 |
| ⑤ 验证 | 怎么证明完成、失败怎么办 | ⭐⭐ 近因区，且是收尾动作 |

## 3. ⭐⭐⭐⭐ 为什么验证不能放最后

按"做事顺序"，验证自然应该在流程之后。但**按可靠性，它应该靠后但不最后**：

```
流程 → 验证 → （不要再加"补充说明"）
```

> ⭐⭐⭐ **验证之后不要再放任何东西**——
> 否则近因效应会把注意力抢走，
> 而验证恰恰是"执行完立刻要做"的动作。

三个具体的排布错误：

| 错误 | 后果 |
|---|---|
| ⭐ 验证之后还有"注意事项" | ⭐⭐ 近因区被无关内容占据 |
| 附录/背景放在验证前 | 验证被挤出近因区 |
| ⭐ 流程超长且验证埋在中间 | ⭐⭐⭐ 既不在首因也不在近因——最差位置 |

## 4. ⭐⭐⭐⭐ 长文件：目录即黄金位

超过 100 行的 reference 会被 `head -100` 预览，所以：

```
第 1 行：一句话说明这个文件是什么
第 2–N 行：⭐ 目录（TOC）
```

> ⭐⭐⭐ **目录不是导航便利，是信息本身**——
> 当只有前 100 行被看到时，目录就是模型对这个文件的全部认知。

所以目录要写成**摘要式**，不是纯锚点：

```
❌ - 配置
✅ - 配置：必填 3 项，缺失时快速失败
```

⭐ 一行目录附带一个"这里有坑"的提示，
能让模型在没读全文的情况下知道该不该读。

## 5. ⭐⭐⭐ 反例：常见的错误排布

| 常见排布 | 问题 |
|---|---|
| 背景 → 目标 → 原则 → 流程 → 验证 | ⭐ 真正的红线被埋在"原则"里 |
| 流程 → 示例（很长）→ 验证 | ⭐⭐ 验证被长示例挤出近因区 |
| 全部平铺，无分层 | ⭐⭐ 没有首因区，模型自己挑——而你不知道它挑了哪条 |
| ⭐ 红线散落在各步骤里 | ⭐⭐⭐ "只在第 3 步不要做 X"= 其他步骤可以做 X |

> ⭐⭐⭐⭐ **最后一行最危险**：把约束写在具体步骤旁边，
> 等于默认它只在那一步生效。
> ⭐ **约束要么全局声明，要么写明作用域。**

## 6. ⭐⭐⭐ 一条自检

假装只能看到前 500 字和后 200 字，问：

```
1. 只看这两段，模型知道这个技能是干什么的吗？
2. ⭐⭐ 只看这两段，模型知道什么绝对不能做吗？
3. ⭐⭐ 只看这两段，模型知道做完之后要验证什么吗？
```

三个都要能答"是"。答不上来 → 中间埋了本该前置的内容。

> ⭐⭐⭐ 这个自检直接对应最坏情况（压缩后只剩这些），
> 所以它测的不是"读起来顺不顺"，是**最坏情况下还能不能用**。
