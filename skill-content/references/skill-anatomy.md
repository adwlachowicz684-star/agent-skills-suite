## 核心原则：程序优于声明

> ⭐ **技能应该教 agent 如何对待一类问题，
> 而不是为某个具体实例产出什么。**

对照看最清楚：

```
❌ 声明式（把答案写死）
   把 orders 表 join customers 表，按 customer_id 关联，
   筛选 region = 'EMEA'，对 amount 列求和。

✅ 程序式（教方法）
   1. 从 references/schema.yaml 读 schema，找到相关表
   2. 按 _id 外键约定做 join
   3. 把用户请求里的筛选条件作为 WHERE 子句
   4. 聚合数值列，格式化为 markdown 表格
```

这不是说技能不能有具体细节——
**输出格式模板、"绝不输出 PII"这类约束、工具专属指令都很有价值**。
要点是：**方法要能泛化，即使个别细节是具体的**。

## Gotchas：信号最高的内容

> ⭐ **许多技能里最有价值的内容就是 Gotchas 部分
> ——环境特有的、违反合理假设的事实。**

它们不是泛泛建议（"妥善处理错误"），
而是**对 agent 不被告知就一定会犯的错误的纠正**：

```markdown
## Gotchas
- `users` 表用软删除。查询必须带 `WHERE deleted_at IS NULL`，
  否则结果会包含已停用账号。
- 用户 ID 在数据库里叫 `user_id`，在认证服务里叫 `uid`，
  在计费 API 里叫 `accountId`——三个名字指同一个值。
- `/health` 端点只要 web server 在跑就返回 200，
  即使数据库连接已经断了。要检查完整健康状态请用 `/ready`。
```

**三条放置规则**：

```
1. ⭐ Gotchas 放在 SKILL.md 里——让 agent 在遇到之前就读到
2. 单独文件也行，但必须写明何时加载；
   ⭐ 对非显然的问题，agent 可能认不出触发条件
3. ⭐ 每次你纠正了 agent 的一个错误，就把纠正加进 Gotchas
   ——这是迭代改进技能最直接的途径之一
```

> 呼应 `pruning.md`（**`skill-refining`**）：
> **Gotchas 是唯一几乎不可能通过 no-op 测试的部分**，修剪时永远别动它。

## 输出格式模板

> ⭐ **需要 agent 按特定格式产出时，给模板。
> 这比用散文描述格式可靠得多——agent 对具体结构模式匹配得很好。**

```
□ 短模板：直接内联在 SKILL.md
□ 长模板 / 只在特定情况需要的模板：放 assets/，
  从 SKILL.md 引用，让它只在需要时才加载
```

## 约束与工具专属指令

三类允许"具体"的内容：

| 类型 | 例子 |
|---|---|
| 输出格式模板 | 报告骨架、JSON schema |
| 硬约束 | "绝不输出 PII"、"不许改 main 分支" |
| 工具专属指令 | `npm run deploy:staging`，等 `/healthz` 返回 200 |

## 引用成熟的既有原则

> ⭐ **命名既有方法的来源（TDD、DDD、red-green-refactor），
> 让 agent 和用户都能验证你指的是哪一种做法。**

这是极低成本、高收益的一条——
一个词（"按 TDD 的红-绿-重构循环"）能激活模型训练里的一整块共识，
比你自己写三段描述准确得多。

## 什么时候不该写这么多

官方明确提醒的克制点：

```
□ ⭐ 简洁、分步骤、带一个可运行示例的指导，
   往往胜过穷尽式文档
□ 当你发现自己在覆盖每一个边缘情况时，
   想想其中多数是否交给 agent 自己的判断更好
□ 不要重复教模型已经会的东西
   ——提供的是模型缺的上下文，不是 Python 或 Git 教程
```

## 与自由度的关系

呼应 `guidance-forms.md`（**`skill-crafting`**）与自由度校准：

```
多种做法都可行、任务容忍变化 → 给自由，只写启发式
有偏好模式但可接受变化       → 伪代码或模板
流程脆弱、易错、一致性关键   → 精确脚本和严格步骤清单
```

**判断依据始终是"错的代价"**：

```
code review      → 多种做法都成立 → 松散的自然语言启发式
报告格式          → 有偏好模式     → 模板
迁移 / 文档修补   → 脆弱且一致性关键 → 精确脚本 + 严格步骤
```

- [ ] 每次纠正 agent 的错误后，有没有把它加进 Gotchas？
- [ ] 需要固定输出格式的地方，给的是模板还是散文描述？
- [ ] 有没有引用成熟的既有原则（TDD / DDD 等）来省篇幅？
- [ ] 有没有哪段是在教模型已知的东西？
