## 1. ⭐⭐⭐⭐⭐ 一个每次都会发生的复制

```markdown
## 示例
输入：分析 2024-03-15 的销售数据
输出：2024-03-15 销售额 ¥128,400，环比 +12%
```

用户下一次输入："分析上周的数据"。

> ⭐⭐⭐⭐⭐ 输出里出现 `2024-03-15` 和 `¥128,400` 的概率，远高于随机。

这不是模型"理解错了"：

> ⭐⭐⭐⭐⭐ **少样本示例是最强的上下文信号。模型会复制其中的表面特征，
> 包括那些你只打算当作占位符的部分。**
> ⭐⭐⭐⭐ 它对示例的信任度高于对指令的信任度——
> 示例是"具体发生过的事"，指令是"一般性的说法"。

后果的严重性在于外形：

```
⭐⭐⭐⭐⭐ 输出格式完全正确、字段齐全、语气专业
⭐⭐⭐⭐⭐ 只有数字是复制来的
```

> ⭐⭐⭐⭐⭐ 这就是"结构正确的废话"的第九个来源，
> 而且是⭐⭐⭐⭐⭐ 唯一一个由你亲手写进去的。

## 2. ⭐⭐⭐⭐⭐ 三类高危值

按被复制的概率排：

**① ⭐⭐⭐⭐⭐ 日期与时间**

```
示例写 "2024-03-15" → 输出里出现这个日期
```

> ⭐⭐⭐⭐⭐ 最危险的一类：日期错一天，整份结论的时间基准就错了，
> 而且⭐⭐⭐⭐⭐ **读起来完全合理**（没人会怀疑一个格式正确的日期）。

**② ⭐⭐⭐⭐⭐ 金额、数量、百分比**

```
示例写 "¥128,400" / "+12%" → 输出倾向于给出同量级的数字
```

> ⭐⭐⭐⭐⭐ 比复制更隐蔽的是**锚定**：不一定一模一样，
> 但会被拉向示例的数量级。数据本该是 2,000，输出是 120,000。

**③ ⭐⭐⭐⭐ 人名、项目名、ID**

```
示例写 "客户：张伟" → 其他输入下也出现"张伟"
```

> ⭐⭐⭐⭐ 这一类相对容易发现（用户会看到不认识的名字），
> ⭐⭐⭐⭐⭐ 但它在"批量生成"场景下会系统性地污染一整批输出。

## 3. ⭐⭐⭐⭐⭐ 写法：显著假值

原则一句话：

> ⭐⭐⭐⭐⭐ **示例里的占位值必须"一看就是假的"。**

| ❌ 危险 | ⭐⭐⭐⭐⭐ 安全 |
|---|---|
| `2024-03-15` | `<YYYY-MM-DD>` 或 `2099-01-01` |
| `¥128,400` | `<金额>` 或 `¥1` |
| `+12%` | `<百分比>` 或 `+99%` |
| 客户：张伟 | 客户：`<姓名>` 或 `示例客户A` |
| `project-alpha` | `<项目名>` 或 `EXAMPLE-PROJECT` |

> ⭐⭐⭐⭐⭐ 为什么"一看就是假的"有效：
> ⭐⭐⭐⭐⭐ **模型复制表面特征的倾向不会消失，但复制到明显是占位符的值时，
> 结果是荒谬的——而荒谬是可见的，错误的值是不可见的。**
>
> 换句话说：你没法阻止复制，⭐⭐⭐⭐⭐ **那就让它复制到会暴露自己的东西。**

配套的显式声明（写在示例区块前）：

```markdown
> ⭐⭐⭐⭐ 以下示例中的 `<...>` 是占位符，实际输出必须使用真实数据，
> 不得复制示例中的任何具体数值。
```

> ⭐⭐⭐⭐⭐ 这句必须写。不写的话，
> 占位符`<金额>`有可能被当成字面文本输出——
> 那至少是可见的，但仍是缺陷。

## 4. ⭐⭐⭐⭐ 与"示例是采集的"的张力

`example-mining-from-traces.md` 说：教判断的示例必须采集，带杂讯。

> ⭐⭐⭐⭐⭐ 而采集来的示例里，**值全是真的**。

这不是矛盾，是分工：

| | 定格式的示例 | ⭐⭐⭐⭐⭐ 教判断的示例 |
|---|---|---|
| 来源 | 可以编 | 必须采集 |
| ⭐ 值 | ⭐⭐⭐⭐⭐ **必须显著假** | ⭐⭐⭐⭐⭐ **保留真值** |
| 理由 | 会被复制 | ⭐⭐⭐⭐⭐ 真值是判断的一部分 |

> ⭐⭐⭐⭐⭐ 关键判据：**这个值是"格式的示范"还是"判断的依据"？**
>
> - 教"输出长什么样" → 值只是填充物 → ⭐⭐⭐⭐⭐ 换成显著假值
> - 教"这种情况下该怎么判断" → 值本身就是判断的输入（比如"缺失率 8% 属于中等"）→ 保留

实操做法（成本极低）：

> ⭐⭐⭐⭐⭐ **采集真实示例后，只把"格式示范"部分的值替换成占位符，
> 保留"判断依据"部分的值，并在 Rationale 里写明依据。**

这同时满足两份文档的要求，且比全假或全真都好。

## 5. ⭐⭐⭐⭐⭐ 自检与 grep

一个能立刻跑的检查：

```bash
# 找示例区块里可能被当真的具体值
grep -nE "20[0-9]{2}-[0-9]{2}-[0-9]{2}|¥[0-9,]+|[0-9]+\.[0-9]%" SKILL.md
```

> ⭐⭐⭐⭐⭐ 命中不等于错误——但每一条都要能回答：
> **这个值是"格式的示范"还是"判断的依据"？**
> 答"示范"却用了真值 → 改成显著假值。

判据与上一条一致（含糊词黑名单那份）：

> ⭐⭐⭐⭐⭐ 说了很多次的规则，只有变成一条 grep 才会真的被执行。

另一个更快的自检：

> ⭐⭐⭐⭐⭐ **把示例的输入换成完全不同的内容，读一遍输出示例——
> 里面有没有任何值仍然成立？有，那就是会被复制的值。**

## 6. ⭐⭐⭐⭐ 例外：什么时候该用真值

三种情况不该替换：

**① ⭐⭐⭐⭐⭐ 阈值与分档边界**

```
"缺失率 > 5% 视为较差" ← 5% 是真值，必须保留
```

> ⭐⭐⭐⭐⭐ 这是规则本身，不是示例填充物。换成 `<阈值>` 会让规则失效。

**② ⭐⭐⭐⭐⭐ 格式/编码的真实样例**

```
"ID 形如 USR-2024-0042"
```

> ⭐⭐⭐⭐ 这里的数字是格式的一部分（位数、补零），替换会破坏示范作用。
> ⭐⭐⭐⭐⭐ 但必须配合一句"实际 ID 取自输入，不得复制此示例"。

**③ ⭐⭐⭐⭐⭐ Gotchas 里的具体反例**

```
"该接口在月结期间会静默返回上月数据"
```

> ⭐⭐⭐⭐⭐ 具体性是 Gotchas 的价值来源，绝不能抽象化。

判据收口：

> ⭐⭐⭐⭐⭐ **会被"复制"的值要假，会被"参照"的值要真。**
> 格式示范是复制，判断依据是参照。
