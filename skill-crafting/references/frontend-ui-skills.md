## 安装顺序：层层叠加

> ⭐ **这些技能不是随便推荐的，是按顺序排的——每个建立在前一个之上**：

```
#1 设计系统（给方向：风格、配色、字体）
#2 官方前端模式（按规范落地：布局、响应式）
#3 组件库（直接用现成的高质量组件）
#4 无障碍 / 设计规范 / 动画（在这些基础上叠加）
```

> ⭐ **一前一后的配合关系**：
> `#1` 负责给方向（如"玻璃拟态 + 柔和渐变"），
> `#2` 负责把这些想法按规范落地（CSS Grid、可靠的响应式断点、移动端不崩的结构）。

**这类技能的目录结构**（值得抄）：

```
skills/ui-ux-pro-max/
├── SKILL.md
├── scripts/search.py          ⭐ 确定性检索，不占上下文
├── references/                风格库、配色库、字体库、UX 规则
└── design-system/
    ├── MASTER.md              ⭐ 全局规则
    └── pages/checkout.md      页面级覆盖
```

> ⭐ **把知识库查询做成脚本**是这里的关键设计：
> 风格库可能几万行，但每次只需要检索出相关的几条——
> 这正是 `scripts/` 该干的事（呼应 `skill-crafting` 的 `script-engineering.md`）。

## 三步工作流：方向 → 细节 → 技术栈

```bash
# 步骤 1：先跑出设计系统（新项目都从这开始）
python3 scripts/search.py "beauty spa wellness elegant" \
    --design-system -p "Serenity Spa"

# 步骤 2：按领域补细节
python3 scripts/search.py "animation accessibility" --domain ux
python3 scripts/search.py "luxury serif elegant" --domain typography

# 步骤 3：按技术栈落地
python3 scripts/search.py "layout responsive" --stack html-tailwind
```

**步骤 1 会拿到什么**（这是好的技能输出的样子）：

```
□ 一整套设计方向——玻璃拟态 + 柔和渐变、宁静优雅
□ 配色——粉彩 + 鼠尾草绿 + 玫瑰金点缀
□ ⭐ 字体组合 + 为什么这样搭
□ ⭐ 一份"别这么做"的清单
   （别用生硬阴影、霓虹色、过于激进的 CTA）
```

> ⭐ **"别这么做"清单是 Gotchas 的对应物**——
> 呼应 `skill-authoring` 的 `skill-types.md`：这类内容来自实际踩过的坑，
> 是技能里信号最高的部分。

## 设计系统持久化

> ⭐ **多页面项目不要每页重新生成一遍**：

```bash
# 先建一套主设计系统
search.py "SaaS fintech" --design-system --persist -p "FinDash"
# 给结账页加一层覆盖
search.py "payment checkout secure" --design-system --persist \
    -p "FinDash" --page "checkout"
```

```
生成：
  design-system/MASTER.md          全局规则
  design-system/pages/checkout.md  页面级覆盖

用法：
  "用 checkout.md 做页面，没写到的地方就按 MASTER.md 来"
```

> ⭐ **这是指令与数据分离的一个绝佳实例**——
> 呼应 `skill-distribution` 的 `team-workflow.md` 的"SKILL.md 与数据文件分离"：
> **how 在技能里，what 在数据文件里**，技能里不再出现死数字。

## 可直接抄的具体数值

> ⭐ **这些数字是这类技能的核心价值——把"好看"变成可检查的谓词**：

**动画**：

```
□ ⭐ 微交互控制在 150–300ms
□ 多用 spring（弹簧）做动画，看起来更自然
□ ⭐ 优先用 transform 和 opacity
   ——别动 width/height，性能会很差
□ ⭐ 记得处理 prefers-reduced-motion（无障碍）
```

**布局与响应式**：

```
□ 用 CSS Grid（比 flex 更适合二维布局）
□ 设定可靠的响应式断点
□ ⭐ 结构在手机上不能崩
```

**设计判断的经验数据**：

```
□ 不同行业配色不同（健康、金融各有惯例）
□ 骨架屏 vs 加载圈的取舍
□ ⭐ 页面是"高端感"还是"偏大众"——这是要先定的方向
```

**组件库用法**（技能的作用不是"用上组件"）：

```
□ ⭐ 让 agent 能把组件调到符合品牌风格，而不是停在默认样式
□ 覆盖：主题、表单、数据表、命令面板
```

**无障碍**（另见 `a11y-skills.md`）：

```
□ WCAG 2.1 检查：颜色对比、键盘操作、屏幕阅读器、ARIA 属性
□ 很多企业项目默认要 WCAG AA，政府/医疗甚至要 AAA
□ ⭐ 抛开合规，无障碍本身就是更好的设计
```

## 上线前一句话检查

> ⭐ **这类技能最实用的形态——一句话触发一整套检查**：

```
"帮我检查这个页面的 WCAG AA 合规性，并把问题修一下。"
"按 Web 设计规范帮我检查这些文件。"
```

**会过一遍的常见项**：

```
□ 对比度够不够
□ 有没有 alt 文本
□ 表单标签是否正确
□ ⭐ 键盘能不能正常操作
□ 焦点是否清晰
□ ⭐ prefers-reduced-motion 这类细节
```

> ⭐ **"上线前一句话"是可自动检查验收清单的典型**（呼应 `design-system-skills.md`）：
> 全是**可判定的谓词**，而不是"看起来协调"。

## 自查

```
□ 是否先定设计方向（风格/配色/字体）再谈实现？
□ ⭐ 是否为"给方向"和"按规范落地"分了层（而非一个技能全包）？
□ 知识库查询是否做成了脚本（而非塞进正文）？
□ ⭐ 是否有三步工作流（方向 → 细节 → 技术栈）？
□ 设计系统是否持久化（MASTER.md + 页面级覆盖）？
□ ⭐ 是否做到了指令与数据分离（技能里无死数字）？
□ ⭐ 是否给了具体数值（150–300ms、transform/opacity）？
□ 是否含"别这么做"清单？
□ 是否处理了 prefers-reduced-motion？
□ ⭐ 组件库用法是否强调"调到品牌风格"而非默认样式？
□ 是否有一句话触发的上线前检查？
□ 检查项是否都是可判定谓词（而非"看起来协调"）？
□ 是否覆盖了键盘操作与焦点（不只是视觉）？
```
