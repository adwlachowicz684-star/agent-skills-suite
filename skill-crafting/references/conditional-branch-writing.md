## 1. ⭐⭐⭐⭐⭐ 没有 else 的 if

最常见的形态：

```markdown
- 如果配置文件存在，读取其中的端口设置
```

> ⭐⭐⭐⭐⭐ **这句话包含了 if，没有 else。**
> 于是"配置文件不存在"这个分支，由模型自己定义。

而它定义的版本通常是：

```
⭐⭐⭐⭐⭐ "继续，用默认值" 或 "跳过这一步"
```

> ⭐⭐⭐⭐⭐ 两个都不是你想要的，而⭐⭐⭐⭐⭐ **两者都不会报错**。

这跟默认动作那份是同一个机制，但更难发现：

```
默认动作那份：你根本没写 → 你知道自己没写
⭐⭐⭐⭐⭐ 这份：你写了一半 → ⭐⭐⭐⭐⭐ 你以为自己写了
```

> ⭐⭐⭐⭐⭐ **半写的约束比不写更危险**——
> 它给了模型一个信号"作者考虑过这里"，
> 于是它更自信地自行适配剩下的部分。

修法只有一句：

```markdown
- 如果配置文件存在，读取其中的端口设置
- ⭐⭐⭐⭐⭐ 如果不存在：停止并报告"未找到配置文件，无法继续"，不要使用默认端口
```

第二行 20 个 token，覆盖的是⭐⭐⭐⭐⭐ **一个必然会发生的情况**。

## 2. ⭐⭐⭐⭐⭐ 判据必须可判定

分支写了、else 也写了，但判据本身不可判定：

```markdown
- 如果数据质量较差，先做清洗
```

> ⭐⭐⭐⭐⭐ **"较差"是不可判定的**——
> 模型会用它的先验去定义"较差"，而那不是你的标准。

三个层次的写法：

| 层次 | 例子 | ⭐ 可判定吗 |
|---|---|---|
| ❌ 形容词 | "如果数据质量较差" | ❌ |
| ⭐⭐⭐⭐ 阈值 | "如果缺失率 > 5%" | ⭐⭐⭐⭐ 可判定 |
| ⭐⭐⭐⭐⭐ 探测 | "先统计缺失率，再按上表分档" | ⭐⭐⭐⭐⭐ 可判定且不过期 |

> ⭐⭐⭐⭐⭐ 第三层最优，理由是同一条老原则的又一次出现：
> **不要写"世界长什么样"，写"怎么查出它长什么样"。**
> （已是第六个同构场景：环境、端口、规模、字段、上游产物、判据。）

判据自检（一句话）：

> ⭐⭐⭐⭐⭐ **让两个人看同一份输入，他们会对走哪个分支达成一致吗？**
> 不会 → 判据不可判定。

## 3. ⭐⭐⭐⭐ 分支穷尽：三选一不是二选一

一个高频的漏分支：

```markdown
- 如果用户提供了日期，用它
- 否则用今天
```

漏掉的是：

```
⭐⭐⭐⭐⭐ 用户提供了日期，但格式无法解析
```

> ⭐⭐⭐⭐⭐ **"提供了"和"可用"是两件事。**
> 二选一的分支结构，默认把"提供了但不可用"归进了"提供了"。

通用形态——**任何"有/无"分支都应该写成三档**：

| 分支 | ⭐ 处理 |
|---|---|
| 有且可用 | 用它 |
| ⭐⭐⭐⭐⭐ 有但不可用 | ⭐⭐⭐⭐⭐ **报告，不要猜**（这是最常被漏的一档） |
| 无 | 走默认路径 |

> ⭐⭐⭐⭐⭐ 中间那档最危险，因为它⭐⭐⭐⭐⭐ **看起来属于"有"**——
> 模型会尝试解析、失败、然后编一个合理的值继续。

这与"错误被改写成功"是同一机制的入口：
⭐⭐⭐⭐ **那份讲的是最终结果被改写，这份讲的是改写发生在分支判定的那一刻。**

## 4. ⭐⭐⭐⭐ 嵌套深度与嵌套的替代

嵌套超过两层后，可读性崩塌，而且**命中率骤降**：

```markdown
- 如果是 A：
  - 如果是 B：
    - 如果是 C：…      ← ⭐⭐⭐⭐ 第三层几乎不会被正确走到
```

> ⭐⭐⭐⭐⭐ 原因不是"模型看不懂"，是⭐⭐⭐⭐⭐ **长分支链里每一层都有概率走错，
> 而走错之后它不会报错，只会安静地走一条邻近路径。**

两种替代：

**① ⭐⭐⭐⭐⭐ 改写成判定表（最推荐）**

| 条件 A | 条件 B | ⭐ 动作 |
|---|---|---|
| 有 | 有 | X |
| 有 | 无 | Y |
| 无 | — | Z |

> ⭐⭐⭐⭐⭐ 表格的优势不是好看，是⭐⭐⭐⭐⭐ **穷尽性可见**——
> 缺一格一眼能看出来，而嵌套缺一层看不出来。

**② ⭐⭐⭐⭐ 拆成顺序的前置门禁**

```
第一步：判定 A，不成立就停
第二步：判定 B，不成立就停
```

> ⭐⭐⭐⭐ 这与 `preflight-gate.md` 的"快速失败"同构：
> ⭐⭐⭐⭐⭐ **把嵌套的判定摊平成线性的门禁，每一道门禁的失败原因都是明确的。**

## 5. ⭐⭐⭐⭐⭐ 分支里的动作要具体到可执行

分支判据写对了，动作写空了：

```markdown
- 如果文件超过 1000 行：适当拆分
```

> ⭐⭐⭐⭐⭐ **"适当拆分"不是动作**——
> 它没有说按什么维度拆、拆成几个、命名怎么定。

判据（复用 `vague-word-blacklist.md` 那条）：

> ⭐⭐⭐⭐⭐ **这句含糊，是你授权它决定，还是你懒得写清楚？**

分支里的动作尤其不能含糊，原因是⭐⭐⭐⭐⭐ **非对称性**：

```
主流程含糊 → 模型按先验走，大概率接近你的意图
⭐⭐⭐⭐⭐ 分支含糊 → 模型按先验走，而这条路径你之所以单独写出来，
                    恰恰说明⭐⭐⭐⭐⭐ 默认路径在这里是错的
```

> ⭐⭐⭐⭐⭐ 这一条是本份最值得记住的：
> **分支的存在本身就证明"默认做法不适用"，
> 所以在分支里含糊，等于把模型推回那个已知不行的默认。**

## 6. ⭐⭐⭐⭐ 四个自检

写完后逐条问：

```
① ⭐⭐⭐⭐⭐ 每个 if 都有 else 吗？
② ⭐⭐⭐⭐⭐ 每个判据都能被两个人独立判定成同一结果吗？
③ ⭐⭐⭐⭐⭐ 每个"有/无"都补上了"有但不可用"吗？
④ ⭐⭐⭐⭐ 嵌套超过两层了吗？→ 改判定表
```

> ⭐⭐⭐⭐ 这四问可以直接 grep 前两问：
> ```bash
> grep -n "如果\|若\|when if" SKILL.md    # 逐个确认有没有配对分支
> ```
> ⭐⭐⭐⭐⭐ 与含糊词黑名单那条同构：**说了很多次的规则，
> 只有变成一条 grep 才会真的被执行。**
