## 1. 两个方向的迁移

规则不是放上去就固定了——**它会随着使用暴露出放错了地方**。

```
技能 → CLAUDE.md    （提升）
CLAUDE.md → 技能    （降级）
```

---

## 2. 向上：技能 → CLAUDE.md

触发条件：

```
⭐ 正文比 description 还短        → 它只是伪装成段落
⭐ 没有明确触发条件              → 它属于 CLAUDE.md
⭐ 对每个会话都适用（只有三句话）  → 提升为 CLAUDE.md
```

**收益**：省下路由开销，且更可靠（常驻，不需要触发）。

---

## 3. 向下：CLAUDE.md → 技能

触发条件：

```
⭐ CLAUDE.md 里一条只在特定情境适用的规则
⭐ CLAUDE.md 超过 500 词（ETH Zurich 研究：过度详细的上下文文件会降低表现）
```

**收益**：让它不再挤占常驻的加载面。

> ⭐ **若 CLAUDE.md 超过 500 词，把任务相关的部分抽成技能。**

---

## 4. ⭐ 头号反模式：三处各粘一份

> ⭐ **把同一份安全清单同时粘进 AGENTS.md、Cursor rule 和技能里——
> 三处必然漂移，而漂移的规则比没有规则更糟。**

正确做法：**单一事实源 + 引用**。

```
CLAUDE.md / AGENTS.md  → 常驻的硬规则（跨项目/跨工具）
技能                    → 引用它，不复制它
```

---

## 5. 判据表

| 问题 | 归属 |
|---|---|
| 这条规则每轮都为真？ | ⭐ CLAUDE.md / AGENTS.md |
| 只在"当做 X 时"为真？ | ⭐ 技能 |
| 需要在推理前强制执行？ | ⭐ Hook（不是记忆文件） |
| 该读但不该当约束守？ | docs（不是 CLAUDE.md） |
| 跨多个 AI CLI 工具？ | ⭐ AGENTS.md（被 Codex/Copilot 等识别） |

> ⚠️ **要强制阻止某个行为，用 `PreToolUse` hook，
> 别靠记忆文件**——记忆只是上下文，不是强制配置。

## 速查

| 信号 | 动作 |
|---|---|
| 技能正文极短、无明确触发 | ⭐ 提升为 CLAUDE.md |
| CLAUDE.md 里某条只偶尔适用 | ⭐ 降级为技能 |
| CLAUDE.md > 500 词 | 抽任务规则成技能 |
| 同一规则出现在多处 | ⭐ 合并为单一事实源 + 引用 |
| 要强制阻止某行为 | Hook，不是记忆文件 |
