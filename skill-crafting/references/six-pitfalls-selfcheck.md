## 1. ⭐⭐⭐⭐ 六个坑

```
① ⭐⭐⭐ 触发方式选错（model-invoked 还是 user-invoked）
② ⭐⭐⭐ description 没写好
③ ⭐⭐⭐⭐ 完成标准含糊
④ ⭐⭐⭐⭐ 信息层级没分（该推到指针后面的留在了正文）
⑤ ⭐⭐⭐⭐⭐ 没剪枝（空转 / 重复 / 沉积 / 膨胀）
⑥ ⭐⭐⭐⭐ 靠禁令引导（否定式）
```

> ⭐⭐⭐⭐ 第 ① 条⭐ 值得展开，因为它⭐ 常被当成⭐ 一个纯粹的权限设置：
> ```
> ⭐⭐⭐⭐ 这个技能⭐ 该被 agent ⭐ 自己发现（model-invoked，⭐⭐⭐⭐⭐ ⭐ 付上下文负担），
> ⭐⭐⭐⭐ ⭐⭐⭐ 还是⭐ 只靠我手动触发（user-invoked，⭐⭐⭐⭐⭐ ⭐ 零负担）？
> ⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 手动的多到⭐ 记不住了吗 → ⭐⭐⭐⭐⭐ ⭐ 该上⭐ 路由技能了吗？
> ```
>
> ⭐⭐⭐⭐⭐ 最后那个问句⭐ 很妙：⭐ **"手动技能多到记不住"⭐ 是一个⭐ 可观察的信号**，
> ⭐⭐⭐⭐ 它⭐ 提示你⭐ 该引入⭐ 路由层了——
> ⭐⭐⭐⭐ 与 `routing-tiers-and-arbitration.md` 的"10–50 个上向量召回"
> ⭐⭐⭐ ⭐ 是⭐ 同一件事的⭐ 另一种触发条件（一个看数量，⭐⭐⭐⭐ 一个看⭐ 你的记性）。

## 2. ⭐⭐⭐⭐ 二维自检清单

**触发**：

```
□ ⭐⭐⭐ model-invoked 还是 user-invoked？（前者付上下文负担）
□ ⭐⭐⭐⭐ 手动技能多到记不住了吗 → 该上路由技能吗？
□ ⭐⭐⭐⭐⭐ 核心词在⭐ 最前面吗？（会被截断）
□ ⭐⭐⭐ 有没有⭐ 把同一个分支⭐ 用同义词写了好几遍？（冗余）
□ ⭐⭐⭐⭐⭐ ⭐ 正文里已经有的身份，⭐ description 里⭐ 删干净了吗？
```

> ⭐⭐⭐⭐⭐ 第三条和第五条⭐ 最常被忽略。
> ⭐⭐⭐⭐⭐ 第五条尤其好——⭐ **description 与正文⭐ 重复声明身份，
> ⭐⭐⭐⭐ ⭐ 是在⭐ 同一个上下文里⭐ 为同一件事付两次钱。**

**完成标准**：

```
□ ⭐⭐⭐⭐⭐ 每一步的"做完了"⭐ 都可勾选吗？
□ ⭐⭐⭐⭐⭐ ⭐ 该穷尽的地方，⭐ 写成了"⭐ 每一个都要交代到"吗？
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 还是留了⭐ "产出一份清单"⭐ 这种⭐ 含糊话？
```

> ⭐⭐⭐⭐⭐ "产出一份清单"⭐ 这个反例⭐ 精准得刺人——
> ⭐⭐⭐⭐⭐ ⭐ 它看起来⭐ 有要求，⭐ 实际上⭐ 没有终止条件也没有覆盖定义。
> ⭐⭐⭐⭐ 这与 `trace-debugging.md` 的"循环根因是⭐ 没有明确的成功判据"
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 是同一条，⭐⭐⭐ 只是⭐ 落在⭐ 单步的粒度上。

**信息层级**：

```
□ ⭐⭐⭐⭐ ⭐ 每个分支都要用的 → 留在正文了吗？
□ ⭐⭐⭐⭐⭐ ⭐ 只有部分分支够到的 → ⭐⭐⭐ 推到⭐ 指针后面了吗？
□ ⭐⭐⭐⭐⭐ ⭐ 指针的措辞，⭐ 够不够稳地把 agent ⭐ 引过去？
```

> ⭐⭐⭐⭐⭐ **"只有部分分支够到的就推到指针后面"**——
> ⭐⭐⭐⭐⭐ 这是⭐ 渐进式披露的⭐ 一条⭐ 精细化判据：
> ⭐⭐⭐⭐ ⭐ 不仅⭐ 按"重不重要"分，⭐ 还要⭐ **按"⭐ 命中率"分**。
> ⭐⭐⭐⭐⭐ ⭐ 一条只有 10% 情况用得到的指令，⭐⭐⭐⭐ ⭐ 却 100% 地占用上下文。
>
> ⭐⭐⭐⭐⭐ 而第三条⭐ 此前完全没人提过：⭐⭐⭐ **指针本身也要写得好**。
> 与 `reference-file-practices.md` 的"⭐ 引用措辞决定⭐ 会不会被正确打开"
> ⭐⭐⭐⭐ ⭐ 是同一条的两个说法。

## 3. ⭐⭐⭐⭐⭐ 剪枝：空转 / 重复 / 沉积

```
□ ⭐⭐⭐⭐⭐ 逐句做过⭐ 空转测试吗？
□ ⭐⭐⭐ 有没有⭐ 同一个意思散在好几处（⭐⭐ 重复）？
□ ⭐⭐⭐⭐⭐ 有没有⭐ 和别处打架的旧值（⭐⭐⭐ 沉积）？
```

> ⭐⭐⭐⭐⭐ 这三个词⭐ 命名得非常好，值得⭐ 直接采用：
>
> | 词 | ⭐ 含义 | ⭐⭐ 检测 |
> |---|---|---|
> | ⭐⭐⭐⭐ **空转** | 一句话⭐ 读完等于没读（不产生任何行动） | ⭐⭐⭐ 逐句问"⭐ 没有它，agent 会做错吗？" |
> | ⭐⭐⭐ **重复** | 同一个意思⭐ 散在多处 | ⭐⭐⭐⭐ 检索⭐ 语义相近的段落 |
> | ⭐⭐⭐⭐⭐ **沉积** | ⭐⭐⭐⭐ 与别处⭐ 打架的⭐ 旧值 | ⭐⭐⭐⭐⭐ ⭐ 最难——⭐ 新旧两处各自读着都合理，⭐⭐⭐⭐ ⭐ 只有⭐ 放在一起⭐ 才矛盾 |
>
> ⭐⭐⭐⭐⭐ **"沉积"是本轮最值钱的一个概念**——
> ⭐⭐⭐⭐⭐ 它指的不是"过期"（过期只是旧），
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 而是⭐ **新加的内容和旧内容⭐ 互相矛盾，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 但⭐ 分别读⭐ 都看不出来**。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 我们已有的 `version-hygiene.md` 讲"⭐ 数值漂移"、
> `skill-rot-rollback-discipline.md` 讲"漂移"，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ ⭐ 而⭐ "沉积"给了⭐ 一个⭐ 更准确的⭐ 检测角度：
> ⭐⭐⭐⭐ **不要⭐ 单独审一句，要⭐⭐⭐⭐⭐ ⭐ 把⭐ 所有提到同一件事的地方⭐ 放在一起看。**
>
> ⭐⭐⭐⭐⭐ 空转测试与⭐ 已有判据的关系：
> ```
> 反转测试（反过来说得通吗？）  ┐
> 失败场景对应（没有它会出什么事？）├─ ⭐⭐⭐⭐⭐ ⭐ 都是⭐ 同一个问题：
> ⭐⭐⭐⭐⭐ 空转测试（读完等于没读吗？）┘   ⭐⭐⭐⭐⭐ ⭐ 这句话⭐ 有⭐ 信息量吗？
> ```
> ⭐⭐⭐⭐ ⭐ 这是⭐ 该判据的⭐ 第四种问法，⭐⭐⭐⭐⭐ ⭐ 且⭐ 操作最轻（逐句过一遍）。

## 4. ⭐⭐⭐ 措辞：否定式能不能正着说

```
□ ⭐⭐⭐⭐ 有没有⭐ 靠禁令引导（否定式）？
□ ⭐⭐⭐⭐⭐ ⭐ 能不能⭐ 改成⭐ 正着说⭐ 目标行为？
□ ⭐⭐⭐⭐ ⭐ 只有当⭐ 一条禁令⭐ 实在没法正着说，⭐⭐⭐⭐⭐ ⭐ 才留着它当硬护栏——
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 而且⭐ 即便如此⭐ 也要⭐ 配上"那该怎么做"
```

> ⭐⭐⭐⭐⭐ 这段⭐ 给出的⭐ 决策顺序⭐ 是⭐ 该判据⭐ 目前⭐ 最完整的表述：
> ```
> ① ⭐⭐⭐⭐⭐ 先尝试⭐ 改写成⭐ 正面的目标行为（首选）
> ② ⭐⭐⭐⭐⭐ ⭐ 实在没法正着说 → ⭐⭐⭐ 才保留禁令
> ③ ⭐⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 保留了也⭐ 必须⭐ 配替代品
> ```
> ⭐⭐⭐⭐⭐ 而⭐ 它的⭐ 理由⭐ 与 `write-reasons-not-rules.md` 一致：
> ⭐⭐⭐⭐ **正面表述⭐ 给的是⭐ 可迁移的判断依据，⭐⭐⭐ 禁令⭐ 只堵了⭐ 一条路。**
>
> ⭐⭐⭐⭐⭐ 这已是⭐ "禁令必须带替代方案"的⭐⭐⭐⭐⭐ **第八个来源**，
> ⭐⭐⭐⭐ ⭐ 且⭐ 第一次⭐ 明确了⭐ 优先级顺序（⭐ 能正着说就别用禁令）。

**长度**（最后一个维度）：

```
□ ⭐⭐⭐⭐ 整体是不是⭐ 就是⭐ 太长了（膨胀）？
□ ⭐⭐⭐⭐⭐ ⭐ 能不能靠⭐ 披露和拆分，⭐⭐⭐⭐⭐ ⭐ 让⭐ 每条路径⭐ 只扛⭐ 自己那份？
```

> ⭐⭐⭐⭐⭐ "让每条路径只扛自己那份"⭐ 是⭐ 渐进式披露⭐ 最精炼的一句话——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ **不是"总量要少"，而是⭐ "单次要少"**：
> ⭐⭐⭐⭐⭐ 总量可以很大（L3 无上限），⭐⭐⭐⭐ ⭐⭐⭐ 只要⭐ 任何一条路径⭐ 不走完全部。

## 5. ⭐⭐⭐⭐ 一句方法论

> ⭐⭐⭐⭐⭐ **"⭐ 像对待代码那样对待你的 skill。
> ⭐⭐⭐⭐ ⭐ 先证明问题真实存在，⭐⭐ 再写最小的解，
> ⭐⭐⭐ ⭐ 然后⭐ 逼自己⭐ 逐句、逐值地剪。"**

> ⭐⭐⭐⭐⭐ 这句⭐ 与我们已有的⭐ 多条原则⭐ 完全同构：
> ```
> "先证明问题真实存在"  ←→ 先手跑一遍再写断言 / ⭐ 反转测试
> "再写最小的解"        ←→ 最小可行三原则 / ⭐ 从 Tool Wrapper 起步
> "逐句、逐值地剪"      ←→ ⭐ 空转测试 / 沉积检测
> ```
>
> ⭐⭐⭐⭐⭐ 而⭐ "像对待代码那样"⭐ 这个⭐ 总体比喻
> ⭐⭐⭐⭐ 与 `solid-for-skills.md`（软件设计原则迁移）⭐ 是⭐ 同一立场，
> ⭐⭐⭐⭐⭐ ⭐ 但⭐ 这里⭐ 强调的是⭐ 工程纪律（剪枝、测试、评审），
> ⭐⭐⭐⭐ ⭐ 那份⭐ 强调的是⭐ 结构设计。
>
> ⭐⭐⭐⭐ 还有一句⭐ 诚实的提醒值得记：
> ⭐⭐⭐⭐⭐ **"哪怕是你⭐ 天天在用、⭐ 以为写得挺干净的 skill，
> ⭐⭐⭐⭐⭐ ⭐ 六个坑也⭐ 照样条条能踩。"**
> ⭐⭐⭐⭐ ⭐ 这解释了为什么⭐ 需要⭐ 定期审计（而非"写的时候注意"）——
> ⭐⭐⭐⭐ ⭐⭐⭐ 与 `skill-decay-governance.md` 的 `review_after` ⭐ 同源。

## 速查

```
□ ⭐⭐⭐⭐ 六个坑：触发方式选错 · description 差 · ⭐ 完成标准含糊
   ⭐ 信息层级没分 · ⭐⭐⭐⭐⭐ 没剪枝 · ⭐ 靠禁令引导
□ ⭐⭐⭐⭐⭐ 触发：⭐⭐⭐⭐⭐ 手动技能"多到记不住"= ⭐ 该上路由技能的信号
   ⭐⭐⭐⭐⭐ ⭐ 正文里已有的身份，description 里要删（否则同一件事付两次钱）
□ ⭐⭐⭐⭐⭐ 完成标准：⭐ 每步的"做完了"可勾选吗？⭐⭐⭐⭐⭐ ⚠️ "产出一份清单"= 含糊
□ ⭐⭐⭐⭐⭐ 信息层级：⭐⭐⭐⭐⭐ 按命中率分——⭐ 只有部分分支够到的 → 推到指针后面
   ⭐⭐⭐⭐⭐ ⚠️ 指针的措辞本身也要写得好
□ ⭐⭐⭐⭐⭐ 剪枝三词：⭐⭐⭐⭐ 空转（读完等于没读）· ⭐⭐⭐ 重复（同义散多处）
   ⭐⭐⭐⭐⭐ 沉积（⭐ 与别处打架的旧值，⭐⭐⭐⭐⭐ ⭐ 分别读都合理，⭐ 放在一起才矛盾）
   ⭐⭐⭐⭐⭐ 检测沉积：⭐⭐⭐⭐⭐ 别单独审一句，⭐ 把所有提到同一件事的地方放一起看
□ ⭐⭐⭐⭐⭐ 措辞顺序：① ⭐ 先改成正面目标行为 → ② ⭐ 实在没法才留禁令 → ③ ⭐⭐⭐⭐⭐ 必配替代品
□ ⭐⭐⭐⭐⭐ 长度：⭐ 让每条路径只扛自己那份（⭐⭐⭐⭐⭐ 不是总量要少，是⭐ 单次要少）
□ ⭐⭐⭐⭐⭐ 方法论：⭐ 像对待代码那样对待 skill——先证明问题存在，再写最小解，再逐句逐值地剪
```

**一句话**：

> ⭐⭐⭐⭐ **"沉积"是本轮最值钱的概念——它指的不是过期，而是新内容和旧内容互相矛盾、分别读都合理、只有放在一起才看得出来，所以检测它不能逐句审、要把所有提到同一件事的地方放在一起看；而剪枝的顺序是空转（读完等于没读）、重复（同义散多处）、沉积（打架的旧值）。**
