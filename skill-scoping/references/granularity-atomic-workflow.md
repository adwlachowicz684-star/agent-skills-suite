## 1. ⭐ 粒度是设计决策

```
太小 → ⭐ LLM 必须编排太多碎片
太大 → ⭐ 技能变得难以测试、复用或调试
```

> ⭐ 这句话把"拆多细"从审美问题变成了**两个可识别的失败模式**。

---

## 2. 原子技能

**一个原子技能完成一个连贯的工作单元。**

**用原子技能当**：

```
· ⭐ 中间产物本身有意义
· 该步骤可跨工作流复用
· ⭐ 失败可以在不重启整个分析的前提下修复
· ⭐ 步骤之间预期有人工评审
· 技能有清晰的输入与输出契约
```

---

## 3. 工作流技能

**工作流技能编排多个原子技能，并定义连接它们的逻辑。**

**用工作流技能当**：

```
· 顺序固定或遵循文档化的分支
· ⭐ 后面的决策依赖前面的输出
· 最终结果是主要产物
· ⭐ 早期步骤失败时，从头重跑是可接受的
· 工作流有明确的决策门
```

---

## 4. ⭐ 重启测试

> ⭐ **问：如果它跑到一半失败了，人类会从哪里重启？**
>
> ```
> 人类会从某个中间产物重启 → ⭐ 在那里拆开
> 人类会重跑整个序列       → 保持在一起
> ```

> ⭐ 这是我见过最实用的拆分判据——
> 它不依赖抽象原则，**直接问一个可观察的事实**。

> 与 `split-three-options.md` 那条"两个角色各用一半 → 拆成角色技能"
> 互补：一个看**故障恢复点**，一个看**使用者**。

---

## 5. 六维对照

| 维度 | 原子技能 | 工作流技能 |
|---|---|---|
| 耦合 | 低 | 高 |
| 可复用性 | 高 | 较低 |
| 决策点 | 少 | 多 |
| ⭐ 失败恢复 | 从某一步重启 | ⭐ 常从头重启 |
| ⭐ 人工检查点 | 步骤之间 | 在工作流边界 |
| 产物意义 | ⭐ 每个产物都有用 | 只有最终产物最重要 |

---

## 组合方式

> ⭐ **可组合性意味着技能"建议"下游技能（在正文里用文字），
> ⭐ 而不是直接调用它们。**

```
✅ hd:learn —— 单一职责：回答问题，只读
❌ 一个技能同时做：捕获教训、毕业它们、审计 harness、评判工作项
```

> ⭐ 后者的诊断：**"一件事陈述"写不出来 → 该拆**。
> 正文顶部的 **"one job statement" 就是契约**——
> **如果你没法用一句话写出来，这个技能需要拆。**

## 速查

```
原子技能（用当）：
□ ⭐ 中间产物本身有意义
□ 可跨工作流复用
□ ⭐ 失败能局部修复
□ ⭐ 步骤间预期有人工评审
□ 有清晰输入输出契约

工作流技能（用当）：
□ 顺序固定或有分支
□ ⭐ 后面依赖前面的输出
□ 最终结果是主产物
□ ⭐ 早步失败时从头重跑可接受
□ 有明确决策门

⭐ 重启测试：人类从哪里重启？
  从中间产物 → 拆；从头 → 合一

□ 正文顶部能用一句话写出"一件事陈述"
□ ⭐ 建议下游技能，而不是直接调用
□ 六维：耦合/复用/决策点/恢复/检查点/产物意义
```

**一句话**：

> ⭐ **问"人类会从哪里重启"，答案就是拆分点。**
