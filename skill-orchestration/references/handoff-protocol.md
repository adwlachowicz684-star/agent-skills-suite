## 为什么需要交接

> ⭐ **技能切换时上下文里的内容会被丢弃，
> 但前一阶段的发现是后一阶段的输入。**

呼应 `skill-activation.md`：
切换时要做的三件事之一就是**保存产物到文件**。

**三种会丢上下文的情况**：

```
1. ⭐ 技能停用/激活切换（上下文被替换）
2. ⭐ 子代理返回（子代理的上下文不回到父级）
3. ⭐ 会话结束 / 上下文压缩（中间过程丢失）
```

## 交接包的五个字段

```
□ ⭐ 已完成什么（带产物路径）
□ ⭐ 关键发现（结论 + 支撑锚点）
□ ⭐ 未解决什么（明确列出，不静默丢弃）
□ ⭐ 下一步的前提条件
□ ⭐ 约束与已获批准
```

> ⭐ **第三和第五条最常被漏**：
> 未解决的事会被下一阶段当成"不存在"；
> 已获的批准会被重新询问。

呼应 `idempotency-resume.md`（**`skill-crafting`**）：
**批准状态要写进状态文件，避免重跑时反复询问**。

## 三种交接场景

**① 技能切换**

```
进入阶段 2：
  1. 把阶段 1 的发现写到文件
  2. 停用阶段 1 技能
  3. 激活阶段 2 技能，在上下文里引用步骤 1 的路径
```

**② 子代理返回**

```
□ ⭐ 子代理共享父会话的文件，但上下文独立
□ ⭐ 所以产物必须走文件，不能靠"它记住了"
□ ⭐ 返回前先摘要——不要把整个上下文倒回来
```

呼应 `parallel-subagents.md`：
**在子代理之间传递结果前先摘要；大数据用基于文件的通信**。

**③ 长任务续接 / 压缩后**

```
□ ⭐ 带 paths: 的规则在压缩后会丢失
□ ⭐ 嵌套 CLAUDE.md 会丢失
□ ⭐ 技能清单不重新注入——只有真正调用过的存活
□ ⭐ 已调用技能的正文会重新注入，但有 5,000 tokens/技能、
    总 25,000 的上限，最旧的先丢
```

呼应 `runtime-controls.md`（**`skill-governance`**）的运行时真相表。

**推论**（也是这条最实用的部分）：

```
□ ⭐ 承重指令必须放在顶部（截断保头不保尾）
□ ⭐ 关键产物要写盘，不能只留在上下文里
```

## 摘要 vs 原文

**原则**：

```
□ 结论与锚点 → 摘要进上下文
□ ⭐ 完整证据  → 留在文件里，按路径引用
```

**为什么**：

```
□ 上下文是最贵的资源
□ ⭐ 但"摘要丢了关键细节"比"占点空间"更糟
□ 折中：摘要里必须带锚点（file:line、ID、路径），
        让下一阶段能按需取回原文
```

呼应 `grounding-verification.md`（**`skill-crafting`**）：
**结论必须挂在一个可独立验证的锚点上**——
交接时的锚点就是这个用途。

## 常见失败

| 失败 | 症状 | 修法 |
|---|---|---|
| **未解决项静默丢失** | 下一阶段以为都处理完了 | ⭐ 交接包显式列"未解决" |
| **批准重新询问** | 自主流程卡住 | ⭐ 批准状态持久化 |
| **子代理上下文倒回** | 父上下文被撑爆 | ⭐ 返回前摘要，大数据走文件 |
| **压缩后承重指令丢失** | 后半段跑偏 | ⭐ 关键指令放顶部 + 写盘 |
| **锚点丢失** | 结论无法验证 | ⭐ 摘要必须带 file:line / 路径 |
| **产物被覆盖** | 两个子代理写同一文件 | ⭐ 文件所有权排他 |

最后一条呼应 `multi-agent-review.md` 与
`parallel-subagents.md`：**给每个子代理排他的文件所有权**。
