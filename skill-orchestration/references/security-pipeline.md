# 多 Agent 并行流水线：以代码安全审计为例

> 一个 7 阶段、22+ 漏洞类别、多 agent 并行扫描的生产实例。
> 重点是它的**反幻觉验证**设计。

## 七阶段流水线

```
1. 范围界定       确定审计目标、语言栈、排除项
2. 资产梳理       入口点、依赖、数据流
3. ⭐ 并行扫描    多个 agent 按漏洞类别分头扫描
4. 结果汇聚       去重、按严重度排序
5. ⭐ 反幻觉验证  每条发现都要有可复现证据
6. 报告生成       CVSS + PoC + 修复建议
7. 复测           修完再扫一遍
```

**22+ 漏洞类别**按 OWASP 与语言特性划分，每类交给一个 agent。

## 多 Agent 并行扫描

**分工维度**：按漏洞类别切（注入、认证、XSS、SSRF、反序列化…），
而不是按文件切。

> ⭐ **按类别切比按文件切好**：
> 一个类别的 agent 需要的是同一套心智模型；
> 按文件切会让每个 agent 都要加载 22 类规则，token 直接爆掉。

呼应 `multi-agent-review.md` 的角色配置原则：
**每个专家只带自己领域的规则**。

**并行前提**（呼应 `composition.md`）：

```
□ 各 agent 输出互不依赖
□ 有统一的输出契约（否则汇聚时无法合并）
□ ⭐ 超时 90 秒
```

## 反幻觉验证

> ⭐ **这是整套设计里最值得抄的部分。**

安全审计的失败模式极其明确：**编造不存在的漏洞**。
一个看起来很专业的假阳性报告，比漏报更糟——它消耗团队的信任。

**规则**：

```
□ ⭐ 每条发现必须附可复现证据
   ——具体文件:行号 + 触发路径
□ ⭐ 无法给出证据的发现一律降级为"需人工确认"
   ——不能写成确定结论
□ ⭐ 反编译支持（JAR/WAR）让证据链能落到字节码
```

呼应 `grounding-verification.md`（**`skill-crafting`**）：
**落地 = 把输出锚定到现实**。这条规则把它编码成了领域硬约束。

**映射到通用场景**：

```
安全审计：每条漏洞要 file:line + 触发路径
代码评审：每条意见要 file:line + 为什么这样更好
数据分析：每个结论要能指出是哪行数据支撑的
合同审查：每条依据要来源级别 + 标题 + 生效日期
```

> ⭐ **这四句话其实是同一条规则**：
> **结论必须挂在一个可独立验证的锚点上。**

## 自演化知识库

```
□ 每轮审计的发现与验证结果回流到知识库
□ ⭐ 新的漏洞模式被记住，下次不用重新发现
□ ⭐ 被证伪的假阳性也记住，避免重复误报
```

> 呼应 `memory-state.md` 的跨会话记忆，与
> `library-ops.md`（**`skill-evaluating`**）的技能自我进化。

**关键设计**：**被证伪的也要记**。

```
只记成功的发现 → 知识库会越来越"自信"，假阳性率上升
⭐ 正负样本都记 → 下次能同时降低漏报和误报
```

呼应 `skill-lift-eval.md`（**`skill-evaluating`**）的 Rejected-Edit Buffer：
**被拒的编辑不丢弃，供未来反思**——零成本的负反馈。

## 可迁移的四条设计原则

**① 阶段化 + 可判定的转换条件**

```
❌ "扫描完就进入报告阶段"
✅ "所有 agent 返回结果且去重完成 → 进入报告阶段"
```

**② 并行分工按"心智模型"切，不按"数据块"切**

```
✅ 按漏洞类别（每类一套规则）
❌ 按文件（每个 agent 都要全部规则）
```

**③ 反幻觉验证是独立阶段，不是散在步骤里**

```
独立成阶段 → 不会被跳过
散在步骤里 → 赶工时就省了
```

呼应 `guidance-forms.md`（**`skill-crafting`**）：
**漏掉必需元素 → 用模板里的 REQUIRED 槽位**，而不是散文提醒。

**④ 正负样本都回流**

```
□ 成功的发现
□ ⭐ 被证伪的假阳性
□ ⭐ 人工确认时改判的（原本降级后升级，或反之）
```

## 配套的提交前验证技能

另一个值得抄的技能形态：**提交前自动验证**。

```
□ 静态安全扫描
□ ⭐ 基线感知的质量门禁
      ——只对新引入的问题失败，不因历史债务卡住
□ ⭐ 独立审查子 agent
      ——建造者不能当审计员
□ 自动修复循环
```

> ⭐ **"基线感知"是关键**。
> 不考虑基线的门禁会立刻被团队绕过——
> 因为它会让每个 PR 都红。
>
> 这对应 `grounding-verification.md` 里
> "建造者不能当审计员"与 `ci-cd-integration.md`（**`skill-governance`**）
> 的"Lint/Validate 阻断合并，Security Scan 只警告"。
