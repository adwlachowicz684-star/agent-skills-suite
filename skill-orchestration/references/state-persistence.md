## 1. ⭐ 会话间不保留状态是设计使然

> ⭐ **Claude 在会话之间不保留内存中的状态。这不是 bug，这是它的工作方式。**

所以：

```
任务清单 · 用户偏好 · 累积的数据
→ ⭐ 必须存到外部：本地文件、数据库、持久化 MCP memory server
```

指望"它应该记得"是错误预期。

---

## 2. 必须外部存储的三类状态

| 状态 | 例子 |
|---|---|
| **任务清单** | 多步任务的进度、已完成/待办 |
| **用户偏好** | 格式约定、命名习惯、输出风格 |
| **累积数据** | 历史运行结果、处理过的 ID、错误计数 |

一个典型结构（见 `official-lessons.md`）：

```json
{
  "lastRun": "2026-03-18T09:00:00Z",
  "processedIds": ["abc123", "def456"],
  "errorCount": 2
}
```

## 3. 存储位置选择

| 位置 | 特点 |
|---|---|
| ⭐ **`${CLAUDE_PLUGIN_DATA}`** | ⭐ **稳定存储，技能升级后仍存活** |
| 技能目录内 | ⭐ **升级时可能被覆盖**——不适合长期状态 |
| 追加写入的文本日志 | 最简单，适合历史事件（如站会日志） |
| JSON 文件 | 结构化状态 |
| SQLite | 复杂查询需求 |
| MCP memory server | 跨会话持久化 |

> ⭐ **需要长期保留的状态一律用 `${CLAUDE_PLUGIN_DATA}`，
> 不要放技能目录里。**

---

## 4. 读写时机

```
会话开始 → 读外部存储（恢复状态）
会话结束 → 写外部存储（保存状态）
```

> 技能在开始和结束时读写这个外部存储。

追加式日志的例子（历史事件记忆）：

```markdown
## ~/.claude/standups.log
2024-03-11
- shipped the cache invalidation fix
- started on the onboarding redesign
2024-03-12
- reviewed Sarah's auth PR
```

> 这让 Claude "记得"上次评审过 Sarah 的 auth PR 这类事件。

## 5. 与"外部状态"这一上下文手段的关系

`infinite-loop-timeout.md` 里"上下文溢出的四个预防手段"中，
第三条是**外部状态**：

> 不要把任务状态全放在会话里，
> **把中间结果写到文件或数据库，按路径引用**。

> ⭐ **同一个做法有两个收益**：
> ① 防止上下文溢出（成本）
> ② 跨会话持久化（能力）
>
> 所以"状态外置"不只是省 token，它是**让长任务可跨会话继续的前提**。

## 速查

| 需求 | 位置 |
|---|---|

| 复杂查询 | SQLite |
| 跨会话共享 | MCP memory server |
| ❌ 不要 | 技能目录内（升级会丢） |
