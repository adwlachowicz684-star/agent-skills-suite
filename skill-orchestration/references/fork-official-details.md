## 1. 它不 fork 当前会话

名字有误导性：

> ⭐ **`context: fork` 并不是"fork 当前会话"**——
> 那会把你们目前为止讨论的一切都交给子代理。

实际行为是**启动一个全新的子代理**，把技能内容作为它的 prompt。

**直接推论**：

```
⭐ 子代理看不到你的会话历史
→ 技能的指令必须自包含，能独立成立
```

> 如果任务**依赖会话历史**，正确做法是**fork 会话本身**，
> 而不是用 `context: fork`。

## 2. background：前台还是后台

```yaml
context: fork
background: false     # ⭐ 在调用这一轮里等结果
```

默认行为（v2.1.218 之后）：**fork 在后台跑，你继续干活，完成后结果回来。**

但以下情况**即使不设 `background: false` 也会等待**：

| 情况 | 说明 |
|---|---|
| 非交互模式 | 带 `-p` 标志，或用 Agent SDK |
| 环境变量 | `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`（同时关掉所有后台任务功能） |
| 同一技能已在运行 | 你再次调用它时 |
| 定时任务 | 计划任务以该技能为 prompt 触发 |

## 3. ⭐ 后台 fork 不受 /rewind 保护

这是最容易吃亏的一条：

> ⭐ **后台运行的 fork 所做的编辑，发生在你会话的检查点之外。**
> **`/rewind` 撤销不了它们——只能用 git 回退。**

如果技能会改文件，要么设 `background: false`，要么**确认工作区是干净的 git 仓库**。

---

## 4. 后台 fork 的工具集会变窄

后台子代理适用的是**更窄的工具集**：

> 适用于后台子代理的豁免规则**不覆盖** fork 出来的技能子代理
> ——它是普通的 agent 类型。

⭐ **如果你的技能步骤依赖这个集合之外的工具，设 `background: false` 以保留完整工具集。**

## 5. ⭐ 只有指导原则的技能会返回空

最常见的错误，官方明确点名：

> **`context: fork` 只对"有明确指令"的技能有意义。**
>
> 如果技能里只有"使用这些 API 约定"这类**指导原则而没有任务**，
> 子代理收到的是一堆原则、**没有可执行的 prompt**，
> 于是**返回空，没有任何有意义的输出**。

对照：

```
❌ "遵循以下编码规范：……"          → 子代理无事可做，返回空
✅ "读取 src/auth/ 下的文件，检查 SQL 注入，返回发现列表"  → 有任务
```

配套故障（见 `fork-context-skill.md`）：
**`agent: Explore` 是只读的**，写不了文件。要改文件就用 `general-purpose` 或自定义 agent。

## 6. agent 类型决定它看到什么

| agent | 能力 | 是否加载 CLAUDE.md |
|---|---|---|
| `Explore` | 只读，快速文件搜索 | ⭐ **跳过** |
| `Plan` | 架构分析、计划，可读不可改 | ⭐ **跳过** |
| `general-purpose` | 完整读写执行 | 加载 |
| 自定义（`.claude/agents/`） | 按定义 | 加载 |

> ⭐ **Explore 和 Plan 是仅有的两个跳过 CLAUDE.md 和 git status 的子代理**
> ——目的是保持上下文小。
> **没有 frontmatter 字段或 per-agent 设置能改这个行为。**

所以：

```
用 agent: Explore 的 fork 技能
→ 子代理只看到 SKILL.md 内容 + 自己的系统提示
→ ⭐ 项目规则一概不知
```

**如果某条规则必须传达给子代理**（比如"忽略 vendor/ 目录"），
⭐ **只能在委派时把规则写进 prompt 里明说**，指望 CLAUDE.md 是没用的。

另外：**主会话读取 Explore/Plan 的结果时是带完整 CLAUDE.md 上下文的**，
所以大多数规则**不需要**传到子代理本身。

## 7. Token 经济对照

| 模式 | 主上下文成本 | 压缩后 |
|---|---|---|
| 内联技能 | 正文全进主上下文 | 5,000 tokens |
| Fork 子代理 | ⭐ **零**（隔离执行） | 仅摘要 |
| 组合（技能+子代理） | 主上下文零 + fork 内完整 | 仅摘要 |
| 多个 fork | 每个 fork 都零 | 每个一份摘要 |

四类省上下文的手段是叠加关系：

```
渐进式披露     启动时只加载 frontmatter（~20 tokens/技能）
按需加载       触发后才加载正文
脚本执行       确定性操作跑在上下文外
⭐ context fork LLM 驱动的操作跑在隔离子代理里
```

## 8. 两个方向：技能 ↔ 子代理

官方明确了**两个方向**，别搞混：

| 方向 | 系统提示 | 任务 | 预加载 |
|---|---|---|---|
| **技能带 `context: fork`** | 来自 `agent` 字段指定的类型 | **写在技能里** | 按该 agent 的启动上下文（CLAUDE.md 等） |
| **子代理带 `skills` 字段** | 子代理自己的 markdown 正文 | Claude 的委派消息 | ⭐ **技能正文 + CLAUDE.md** |

第二种是"自定义子代理把技能当参考资料用"——
正好对应 `subagents.md` 那条：**子代理不从父对话继承技能，必须在 `skills:` 里显式声明。**

## 速查

| 场景 | 处置 |
|---|---|
| 任务依赖会话历史 | ❌ 用 `context: fork`；✅ fork 会话本身 |
| 需要改文件且要能回退 | 设 `background: false`，或用 git |
| 依赖窄工具集外的工具 | 设 `background: false` |
| fork 返回空 | ⭐ 技能只有原则没有任务 → 补明确指令 |
| `Explore` 写不了文件 | 换 `general-purpose` |
| 子代理不遵守项目规则 | ⭐ 规则写进委派 prompt（Explore/Plan 不看 CLAUDE.md） |
| 需要子代理会用某技能 | 在子代理的 `skills:` 字段声明 |
