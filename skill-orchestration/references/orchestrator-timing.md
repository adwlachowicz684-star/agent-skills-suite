## 1. ⭐⭐⭐ 过早编排 = 过早抽象

> ⭐⭐⭐ **"过早编排是新的过早抽象。"**
> （Premature orchestration is the new premature abstraction.）

```
❌ 不要从这里起步
✅ 先做第一个技能
   再做第二个
   ⭐ 当你发现自己把其中一个的输出复制粘贴到另一个里超过三次
   → 那时才写编排器
```

> ⭐⭐⭐ 这个类比非常锋利——**"过早抽象"是软件工程里公认的反模式，
> 而编排器就是技能领域的过早抽象**。
>
> 共同的错误根源：**在只有一个实例时就去设计通用结构**。

---

## 2. ⭐⭐ 三复制规则

```
⭐⭐ 手动搬运次数 > 3 → 该写编排器了
```

> ⭐ 这条与 `three-conditions-rule-of-three.md` 的三次法则、
> `five-layer-choice.md` 的"同一段指令复制两次以上就该升级为技能"
> 是同一个信号在⭐ 不同层级上的应用：
>
> ```
> 提示词复制 2 次以上 → 升为技能
> ⭐ 技能输出手动搬运 3 次以上 → 升为编排器
> ```
>
> ⭐ 注意两次的阈值不同（2 vs 3）——**层级越高，升级成本越大，
> 所以要求的证据越多**。这个梯度是合理的，不是矛盾。

## 3. ⭐ 编排器的真实代价：仪式感

作者的原话很诚实（这段值得原样记住）：

```
⭐ "编排器模式更强大，但也⭐ 更多仪式感。"
```

**具体的代价**：

```
· 需要一个编排脚本 / 主技能
· 需要状态文件（谁做完了、谁没做完）
· 需要错误处理（某个环节失败了怎么办）
· ⭐ 调试变难：你得同时看主技能和每个子技能
```

> ⭐ "仪式感"（ceremony）这个词选得很准——
> **它不是"复杂度"，是⭐ 你为了维持结构而必须做的、与任务本身无关的动作**。

**对应的收益**（也别因噎废食）：

```
⭐ 从"这里有个选题想法"到"文章发布 + 推文发出" = ⭐ 一条命令
```

## 4. ⭐ 状态文件：一个 Notion 队列就够了

一个真实配置（六技能一编排器）：

```
6 个技能 + 1 个编排器 + ⭐ 一个 Notion 队列当状态文件
```

> ⭐⭐ **"状态文件可以朴素到只是一个队列"** ——
> 这与 `state-persistence.md` 的"append-only 文本日志就够了"、
> `official-lessons.md` 的 standups.log 完全一致：
>
> **别一上来就设计状态机，一个能追加的文件就能解决 80% 的问题。**

**比喻**（很贴切，也解释了三者的关系）：

```
⭐ 技能是乐高积木
  编排器是拼装说明书
  Claude 是干活的那个小孩
```

> ⭐ 这个比喻里最有价值的是"Claude 是干活的那个"——
> **编排器不干活，它只说明顺序**；干活的是 agent 和技能。
> 所以编排器里不该写"怎么做"，那是技能的事
> （呼应 `skill-vs-workflow` 的"流转 vs 怎么做"）。

## 5. ⭐ 自然长成 vs 事先规划

作者的成长路径（值得抄的是它的"无意图"）：

```
① 先写一个技能
② 写第二个
③ ⭐ 到你有五个的时候，你会开始看到"这个该调用那个"的地方
④ ⭐⭐ 于是你不知不觉就搭出了一条流水线——⭐ 而不是刻意设计的
```

> ⭐⭐ **"That's the moment skills click."**
> （技能真正"通了"的那一刻，是你发现它们之间该互相调用的时候。）

**起步建议**（很具体）：

```
⭐ 从一个你⭐ 每天都做的事开始
   → 它五分钟就能写完
   → ⭐ 明天就能回本
```

## 速查

```
□ ⭐⭐⭐ 过早编排 = 过早抽象（新的过早抽象）
□ ⭐⭐ 三复制规则：⭐ 手动搬运输出 >3 次 → 才写编排器
□ ⭐ 阈值梯度：提示词复制 2 次 → 技能；⭐ 技能输出搬运 3 次 → 编排器
   （层级越高成本越大，要的证据越多）

□ ⭐ 代价是"仪式感"：编排脚本 + 状态文件 + 错误处理 + ⭐ 调试变难
□ 收益：多步骤 → ⭐ 一条命令

□ ⭐⭐ 状态文件可以朴素到只是一个队列（append-only 文件足够）
□ ⭐ 技能=积木，编排器=说明书，Claude=干活的人
   → ⭐ 编排器只说明顺序，不写"怎么做"

□ ⭐⭐ 路径：先 1 个 → 第 2 个 → ⭐ 到 5 个时自然看到调用点
   ⭐⭐ 流水线是长出来的，不是设计出来的
□ ⭐ 起步选"每天都做的事"，5 分钟写完，明天回本
```

**一句话**：

> ⭐⭐⭐ **过早编排是新的过早抽象——先做第一个技能、再做第二个，
> 当你手动搬运输出超过三次时，才轮到编排器。**
