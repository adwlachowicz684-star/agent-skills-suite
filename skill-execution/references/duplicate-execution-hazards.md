## 1. 幂等让第二次"成功"，这件事本身就是问题

```
post_comment(id=123, body="已处理")  第 1 次 → 成功
post_comment(id=123, body="已处理")  第 2 次 → 成功（幂等键命中）
结果：两条评论
```

> ⭐⭐⭐⭐⭐ 幂等键让第二次"成功"——
> **而它恰恰掩盖了"已经发生过一次"这个事实。**

幂等的设计目标是"重复调用不产生额外状态变化"，
但它的返回值通常是 `200 OK`，⭐⭐⭐⭐ 于是调用方（和模型）无法区分：

```
① 这次真的创建了
② 这次什么都没做，因为已经创建过
```

> ⭐⭐⭐⭐⭐ **两者在输出里长得一模一样，而它们的语义相反。**

## 2. 三个幂等解决不了的场景

| 场景 | 为什么幂等无效 |
|---|---|
| 追加型写入 | ⭐⭐⭐⭐⭐ 每次都是"新的一行"，不是"同一个键" |
| 有外部可见后果的动作 | 邮件/通知/评论，收件人看到两次 |
| ⭐⭐⭐⭐⭐ 计数与统计 | 计数器 +1 两次，而"当前值"看起来正常 |

追加型最典型，也最容易被当成幂等处理：

```
report.md  ← 生成报告（追加模式）
跑两次 → 报告里出现两段一模一样的"结论与建议"
```

> ⭐⭐⭐⭐ **它不是"多做了"，它是"把正确的内容写了两遍"——
> 于是没人会怀疑它，因为每一段单独看都对。**

这与 `skill-composition/references/composition.md` 里"中间产物落文件"那条要合起来看：
用固定文件名 + 追加模式，是最容易在重跑时中招的组合。

## 3. "重跑是安全的浪费"只在只读场景成立

一条流传很广的经验：

> "重跑一遍比排查状态不一致更便宜。"

它在只读场景下是对的——重跑不产生任何外部变化。
但⭐⭐⭐⭐⭐ **一旦技能里有写入动作，"重跑一遍"就是产生副作用的第二遍**。

| | 只读技能 | ⭐ 写入技能 |
|---|---|---|
| 重跑代价 | 时间 + token | ⭐⭐⭐⭐⭐ 时间 + token + **一次不可撤销的外部变化** |
| 典型 | 分析、检索、摘要 | 提交、发送、创建、迁移 |

判据一句话：**这次重跑会不会产生一个"上一次已经产生过"的外部痕迹？**
会 → 它不是重跑，是重复执行。

## 4. 可见副作用 vs 不可见副作用

```
可撤销 + 可发现   → 容忍重试（创建文件、写本地草稿）
不可撤销 + 可发现 → 重试后必须告知（提交了 commit，用户能看到）
⭐⭐⭐⭐⭐ 不可撤销 + 不可发现 → 必须先查状态再决定（发出邮件、触发 webhook）
```

第三格是唯一需要硬门禁的一格，理由不是"它更危险"这种空话：

> ⭐⭐⭐⭐⭐ **不可发现的重复执行，其"成功"记录和正确执行毫无区别——
> 事后无法从输出或日志里判断它发生过几次。**

于是排查时的第一句话永远是"看起来只发了一次"，
而这正是它不能被排查的原因。

## 5. 四类动作的处理表

| 动作 | 重复执行的后果 | 该怎么写 |
|---|---|---|
| 本地写文件（覆盖） | 无 | 无需特殊处理 |
| 本地写文件（追加） | ⭐⭐⭐⭐ 内容重复 | ⭐⭐⭐ 显式写"先清空再写"，不用追加 |
| 远程创建资源 | 多一个资源 | ⭐⭐⭐⭐ 幂等键 + **区分 created / already_exists** |
| ⭐⭐⭐⭐⭐ 对外发送 | 收件方收到两次 | ⭐⭐⭐⭐⭐ **执行前先查"是否已发送"，已发送则停止并报告** |

最后一行是唯一一条"必须查状态"的，其余三条靠幂等或写法就能兜住。

配套一条输出纪律：

```
已发送，共 1 次。
```

> ⭐⭐⭐⭐⭐ "共 1 次"三个字，把"我执行了"变成"我执行了且只执行了一次"——
> 它是唯一能让重复执行在事后可见的东西。

反向也要写：**不确定有没有发过 → 报告不确定，不得再发一次**。
`skill-recovery/references/failure-definition-missing.md` 里"空结果最贵"，
在这里的对应是：⭐⭐⭐⭐ 重发一次的代价，永远高于"我没确认它发没发"。

## 6. 自检

| 检查 | 不通过的信号 |
|---|---|
| ⭐⭐⭐⭐⭐ 这个技能有没有对外可见的后果？ | 正文没提，只写了"完成任务" |
| ⭐⭐⭐⭐⭐ 重复执行后，输出能看出来发生了几次吗？ | 两次的输出完全一样 |
| ⭐⭐⭐⭐ 写入是追加还是覆盖？ | 没写（默认由实现决定） |
| ⭐⭐⭐⭐ 幂等键命中时返回值与真实创建一致吗？ | 都是 200 OK |
| ⭐⭐⭐⭐⭐ 有没有"执行前先查是否已做"这一步？ | 直接进入执行 |
| ⭐⭐⭐ 跑两次，文件系统/外部系统里出现了几份？ | ⭐⭐⭐⭐⭐ 两份，而日志里只有一条"成功" |
