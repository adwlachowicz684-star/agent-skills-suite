## 1. ⭐⭐⭐⭐⭐ 三种漂移

```
① ⭐⭐⭐⭐ 范围扩大：用户中途加要求
   "顺便也把 B 模块一起看了"

② ⭐⭐⭐⭐⭐ 目标变更：用户要的是别的东西
   "算了，我其实想知道为什么上次没报警"

③ ⭐⭐⭐⭐ 目标已达成但任务未结束
   做到一半发现真正的问题在别处
```

> ⭐⭐⭐⭐⭐ **第 ② 种最危险**——
> 它意味着**前面所有工作都是错的**，而没有任何东西会报错。

第 ③ 种也常被误判为"继续执行"：
模型会坚持跑完原计划，交付一个用户已经不需要的东西。

## 2. ⭐⭐⭐⭐⭐ 为什么它会静默

```
技能定义的是：输入 → 输出
技能没定义的是：⭐ 输入在过程中变了怎么办
```

于是模型的默认动作接管（见 `default-actions.md`）：
⭐⭐⭐⭐⭐ **遇到阻碍的默认动作不是停下报告，而是想办法绕过去**——
"目标变了"被当成一种阻碍，于是它想办法继续。

三种具体的静默表现：

| 表现 | ⭐ 后果 |
|---|---|
| ⭐⭐⭐⭐⭐ 折中：一半按旧目标、一半按新目标 | ⭐⭐⭐⭐⭐ 输出同时满足两个目标，且都不完整 |
| ⭐⭐⭐⭐ 堆砌：把新要求附加在末尾 | 结构混乱，前面的结论已失效但还在 |
| ⭐⭐⭐⭐ 静默切换：直接做新的，不说明旧的作废 | ⭐⭐⭐⭐ 用户以为两个都做了 |

> ⭐⭐⭐⭐⭐ 第一行正是 `parallel-and-concurrency.md` 里
> "N 个半成品"的另一个成因——
> ⭐⭐⭐ **那一份的成因是并行，这一份的成因是目标变了，但结果同构。**

## 3. ⭐⭐⭐⭐ 判别：这是同一个任务还是新任务

> ⭐⭐⭐⭐⭐ **判据不是"用户是不是还在说这件事"，
> 是"前面已经产出的东西还有没有用"。**

| 前面产出的 | 判定 | ⭐ 动作 |
|---|---|---|
| ⭐⭐⭐⭐⭐ 仍然有效（新目标是其延伸） | 同一任务，范围扩大 | 继续，但⭐ 明确说明范围变了 |
| ⭐⭐⭐⭐⭐ 部分失效 | ⭐⭐⭐⭐ 折中风险最高区 | ⭐⭐⭐⭐⭐ **停，问清哪些保留** |
| ⭐⭐⭐⭐⭐ 完全失效 | 新任务 | ⭐⭐⭐⭐⭐ 中止并重新开始 |

> ⭐⭐⭐⭐⭐ **中间那一档是最容易出错的地方**——
> 因为它看起来"大部分还能用"，于是模型倾向于继续跑。
> 而⭐⭐⭐⭐⭐ **"大部分能用"意味着有一部分不能用，
> 而没人知道是哪一部分。**

一个便宜的判别动作：⭐⭐⭐⭐ **先列出"已经产出了什么"**
——列不出来就说明前面的工作不值得保留，直接重新开始更干净。

## 4. ⭐⭐⭐⭐⭐ 处理规则：四选一

技能里应该把这四条写成硬规则，让模型查表而不是判断：

| 情形 | ⭐ 动作 |
|---|---|
| 范围扩大，已有产物有效 | ⭐⭐⭐⭐ 继续；⭐ 输出里标注"范围已扩大，新增 X" |
| ⭐⭐⭐⭐⭐ 部分失效 | ⭐⭐⭐⭐⭐ **停止并列出哪些保留、哪些作废，请用户确认** |
| ⭐⭐⭐⭐⭐ 完全失效 | ⭐⭐⭐⭐⭐ **中止，明确声明前面作废，重新开始** |
| ⭐⭐⭐⭐ 无法判断 | ⭐⭐⭐⭐⭐ **问**——不猜 |

> ⭐⭐⭐⭐⭐ 最后一行呼应编排里那条仲裁原则：
> **无法判断就提问，而不是硬选一个。**
> 这里也一样：⭐⭐⭐ 猜错的代价是"交付一个混合体"，远高于问一句。

一个硬性输出要求：**任何一次目标变更，都必须在输出里可见**。

```
❌ 直接给新结果
✅ "注：按你新的要求（查上次为什么没报警）重新开始，
    前面的代码分析已作废。"
```

> ⭐⭐⭐⭐⭐ **不做这句声明，用户会以为两个都做了**——
> 这是"静默切换"那一行的直接对策。

## 5. ⭐⭐⭐⭐ 部分产物的处置

三种处置方式，按保守程度：

```
① ⭐⭐⭐⭐ 保留并标注（"以下基于原目标，可能已不适用"）
② ⭐⭐⭐⭐⭐ 移入附录，正文只给新目标的结果
③ ⭐⭐⭐⭐ 完全丢弃并声明
```

> ⭐⭐⭐⭐⭐ **第 ② 种在多数情况下最合适**：
> 既不浪费已完成的工作，又不会让失效结论混在正文里被当成有效。

处置原则一句：

> ⭐⭐⭐⭐⭐ **失效的产物不能出现在正文的结论位置。**
> 用户扫的是结论，标注再清楚也常被略过——
> ⭐⭐⭐⭐ 所以位置比措辞重要。

另外一条关于已完成动作的：
⭐⭐⭐⭐ **如果前半程有写入动作（改了文件、发了通知），
目标变更后必须报告这些已发生的副作用**——
它们不会因为"目标变了"而自动撤销。

## 6. ⭐⭐⭐⭐ 写法：漂移章节

不到 100 token，放在正文靠后（验证之前）：

```markdown
## 中途变更

如果任务目标在执行中发生变化：
- ⭐ 已有产物仍有效 → 继续，并在输出开头标注范围变化
- ⭐⭐ 部分失效     → 停止，列出保留/作废清单，请用户确认
- ⭐⭐ 完全失效     → 中止，声明前面作废，重新开始
- ⭐⭐ 无法判断     → 问，不猜

⭐ 任何变更都必须在输出里显式声明"前面的 X 已作废"。
⭐ 前半程的写入动作必须报告，不因目标变更而省略。
```

> ⭐⭐⭐⭐ 最后两行是这份文档里最容易被省、
> 也最该留的两句——
> ⭐⭐⭐⭐⭐ 因为它们对抗的正是"静默"这个核心问题。

与停止条件那份的分工：

```
停止条件：跑不动 / 跑不完 时怎么停
⭐⭐⭐⭐⭐ 意图漂移：跑得动，但目的地变了 时怎么停
```

> ⭐⭐⭐⭐ 两者都是"出口"，但触发条件不同——
> 一个是能力问题，一个是方向问题。
> ⭐⭐⭐⭐⭐ **而方向问题更危险，因为能力问题通常会报错。**
