## 1. ⭐ 声明输出格式让消费者可机械解析

```
✅ hd-review 的审计有一个模板：
   assets/audit-report.md.template，带显式占位符

❌ "输出一份摘要" —— 没有声明形状，每次运行长得都不一样
```

> ⭐ 没有声明形状的输出，**下游无法被解析、无法被引擎消费、
> 无法跨运行做趋势对比**。

---

## 2. ⭐ assets/ 里的模板是最强的声明形式

```
⭐ 模板文件钉在 assets/ 里 —— agent 是"复制 + 填写"，而不是"重新发明"
```

为什么最强：

```
· 纯文字描述格式 → 模型每次重新理解 → 漂移
· ⭐ 模板文件     → 模型复制骨架填空 → 稳定
```

> ⭐ 这正是"规则升级为代码"在输出层的对应物：
> **与其用一段话描述格式，不如给一个文件让它填。**

## 3. 三种目录语义

```
references/  ⭐ READ      —— 读进上下文（付 token）
assets/      ⭐ COPY+FILL —— 复制并填写（零成本引用）
scripts/     ⭐ EXECUTE   —— 执行，不进上下文
```

> ⭐ 这三个词的区分比"目录里放什么"更本质——
> **它决定了 agent 对该文件做什么动作，以及是否消耗上下文**。

**链接规则**：

```
⭐ 相对链接只保持一层深 —— 让解析模型保持简单
⭐ 脚本按路径调用（而不是 markdown 链接进上下文）
   —— 让它们的字节不进入模型的工作记忆
```

## 4. 同类输入 → 同形输出

> ⭐ **同样的输入产生同样形状的输出，
> 下游工具（审计、仪表盘）才能跨运行做趋势指标。**

这条常被忽略，但它是**可观测性的前提**：

```
输出形状稳定 → 可以自动统计 → 可以看到趋势 → 可以发现回归
输出形状随机 → 只能人肉看   → 无法比较     → 回归静默发生
```

> 与 `assert-on-environment.md` 的"确定性断言能两秒筛掉一半失败样本"同源——
> **形状稳定是自动化的前提**。

## 5. 规模上限

```
⭐ 200 行路由是软目标
⭐ ⭐ 500 行是硬上限（ship-blocker）
⭐ description：180 字符软目标，1024 字符硬上限
```

对照组：

```
✅ SKILL.md 150 行；每个 reference 只在路由中提到该主题时才加载
❌ SKILL.md 800 行，所有 reference 都内联了
```

## 速查

```
□ ⭐ 输出格式已声明（不是"输出一份摘要"）
□ ⭐ 模板钉在 assets/ 里（复制+填写，不是重新发明）
□ references=READ / assets=COPY+FILL / scripts=EXECUTE
□ ⭐ 相对链接只一层深
□ ⭐ 脚本按路径调用，不链接进上下文
□ ⭐ 同类输入 → 同形输出（可趋势化）
□ 200 行软目标 / ⭐ 500 行硬上限
□ description 180 软 / 1024 硬
□ ⭐ 失败处理：畸形输入要"清晰错误 + 恢复路径"
   ⭐ 静默崩溃是 ship-blocker
```

**补充：失败处理两条**

```
① ⭐ 明确"本技能不做什么" —— 防止在相邻提示上过触发
② ⭐ 优雅回退 —— 超出范围的输入不崩溃，而是把控制权交回默认模型行为
```

示例对比：

```
✅ hd:maintain apply 中止并提示
   "缺少 --plan-hash。请先运行 rule-propose。" 并指向恢复命令
❌ 技能在畸形输入上静默崩溃
```

**一句话**：

> ⭐ **模板文件是输出契约最强的声明形式——
> agent 复制+填写，而不是每次重新发明。**
