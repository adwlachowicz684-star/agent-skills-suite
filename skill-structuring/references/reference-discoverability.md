> 前置：那份讲⭐ **文件放进去之后怎么组织**（切分、深度、目录），
> 这份讲⭐⭐⭐⭐⭐ **它到底会不会被读到**——
> 一个从未被读取的 reference 文件，在运行时等于不存在，
> ⭐⭐⭐⭐⭐ 但它仍然被算进技能的体积、仍然出现在目录里、仍然让人以为"已经写过了"。

## 1. ⭐⭐⭐⭐⭐ 三个阶段，只有第三个是可选的

```
发现    只读 frontmatter（name + description）
激活    加载 SKILL.md 全文
需要时  才加载**特定**的 reference 文件   ← ⭐ 这一步是模型自己决定的
```

前两步由机制保证发生。**第三步不是。**

> ⭐⭐⭐⭐⭐ **前两步没有"会不会发生"的问题，第三步有。
> 而几乎所有关于 reference 的建议都默认第三步会自动发生。**

代价结构也和其他两层相反：

| 层 | 未使用时的成本 | 失效后果 |
|---|---|---|
| L1 元数据 | 常驻收费 | 技能不存在 |
| L2 正文 | 触发时整份加载 | 执行走偏 |
| ⭐ L3 参考 | ⭐⭐⭐ **零** | ⭐⭐⭐⭐⭐ **静默——没人知道少读了什么** |

> ⭐⭐⭐⭐⭐ **"未读取前成本为零"是 L3 最大的优点，也是它最大的问题：
> 它使漏读在经济上完全不可见。**

## 2. 一个 reference 文件存在，需要同时满足三件事

```
① 文件在磁盘上的路径是对的
② SKILL.md 里有一行指向它
③ ⭐⭐⭐⭐⭐ 模型在运行时判断"这次需要它"
```

第 ① 条有现成工具能查（路径、YAML、大小写），第 ② 条肉眼能查，
**第 ③ 条没有任何工具能查，而它恰恰是唯一真正决定结果的。**

> ⭐⭐⭐⭐⭐ **于是最常见的排查结果是：①② 都对，于是认定"没问题"——
> 而技能照样在缺少那份文档的情况下跑。**

一个可直接用的验证（成本一句话）：

```
问模型："这个技能下有哪些参考文件？你在什么情况下会去读 `references/authentication.md`？"

答不上第二种 → ⭐⭐⭐⭐ 它知道文件存在，但不知道什么时候该读
              → 于是它的实际行为是：永远不读，或者每次都读
```

## 3. ⭐⭐⭐⭐⭐ 模型判断"要不要读"用的是触发条件，而目录项提供的是主题

这是本份最核心的一条。对比两种写法：

```markdown
❌ 目录项式
- references/authentication.md
- references/error-handling.md
- references/pagination.md

✅ 触发条件式
| `references/authentication.md` | 涉及登录 / token / 鉴权失败时读 |
| `references/error-handling.md` | 接口返回非 2xx、或要分类错误时读 |
```

两者提供的信息量差别不在字数，在**可被匹配的东西**：

> ⭐⭐⭐⭐⭐ **模型手上有的，是"当前这次任务的情形"；
> 它能做匹配的前提是，文档那一侧写的是"情形"而不是"主题"。**

"authentication" 是一个主题。要判断这次要不要读，模型得先自己回答
"这次算不算 authentication 的情形"——⭐⭐⭐⭐ **它答得出来，但那次回答的依据是它的先验，不是你的分类。**

而这一条最容易被忽略的后果：

> ⭐⭐⭐⭐⭐ **主题式描述的命中率高度依赖"这个主题名是否恰好出现在用户的话里"。**
> 用户说"登录不上"而你的文件名是 authentication——
> 于是该读的时候没读，而没有任何报错。

## 4. 与"按内容命名"那条规则的仲裁

`reference-file-practices.md` 有一条明确规则：

> ⭐ 文件按内容命名，不按使用时机命名
> ✅ react-hooks.md ❌ advanced.md · part2.md

本份看似在说相反的（按触发条件写）。**不冲突，因为两者作用的对象不同**：

| 规则 | 作用对象 | 反的是什么 |
|---|---|---|
| ⭐ 按内容命名 | **文件名** | ❌ part2 / advanced / misc（名字不表意） |
| ⭐⭐⭐⭐⭐ 按触发条件描述 | **SKILL.md 里指向它的那一行** | ❌ 只写文件名当目录项 |

> ⭐⭐⭐⭐⭐ **文件名回答"这是什么"，路由行回答"什么时候读"。
> 两个问题都要答，只是在两个不同的地方答。**

三者齐全的样子：

```
文件名：error-handling.md          ← 内容（模型记住"有这么个东西"）
路由行：非 2xx / 超时 / 要分类错误时读  ← 触发条件（模型决定"这次读不读"）
文件首行：Parent skill: xxx        ← 归属（被单独读到时知道上下文）
```

⚠️ **不要为了"触发条件"把文件名写成 when-error**——
使用时机是易变的（今天只在报错时读，明天可能要预检），
⭐⭐⭐ **文件名一改，所有引用它的地方都要改；而路由行改一处即可。**

## 5. 四种失效形态

| 形态 | 表现 | 为什么查不出来 |
|---|---|---|
| ⭐⭐⭐⭐⭐ **死文件** | 文件在目录里，SKILL.md 从没提过它 | 目录看起来很全，没人逐条核对 |
| ⭐⭐⭐⭐⭐ **目录项描述** | 只写了文件名 | ①② 都对，只有 ③ 不成立 |
| ⭐⭐⭐⭐ **主题 ≠ 用词** | 写的是主题词，用户说的是症状 | 症状词和主题词不同时出现在任何一处 |
| ⭐⭐⭐ **路由表过长** | 20+ 行路由，后半部分被略读 | 每一行单独看都没问题 |

第三条最值得展开，因为它有个便宜的解法：

> ⭐⭐⭐⭐ **路由行要写症状词，不只是术语词。**
> 就像 description 要收"这次上线又出问题了"这种说法，
> reference 的路由行同样要收"登录不上""token 过期"这类说法。

第四条的机制与我们已有的结论一致：
⭐⭐⭐ **文件越多，路由表越长；越长，越靠后的行越不被读——
而"靠后"是排版决定的，不是重要性决定的。**

## 6. ⭐⭐⭐⭐ 僵尸 reference：它从来没被读过，而没人知道

与"僵尸技能"完全同构，但更隐蔽，因为：

```
僵尸技能：  至少还有触发日志可以看
⭐⭐⭐⭐⭐ 僵尸 reference：读取发生在模型内部，⭐⭐⭐⭐ 没有任何地方记录"它读过哪些文件"
```

两种发现方法：

**有遥测时**：记录每次运行读取了哪些 reference，按引用次数排序。
⭐⭐⭐ **零引用的文件不是"还没被用到"，是"永远不会被用到"**——
因为它的触发条件从未在任何一次真实任务里成立过。

**没有遥测时**（多数情况）：让模型复述。

```
"列出你会去读的参考文件，以及各自的触发条件"

⭐⭐⭐⭐⭐ 它复述不出来的那些，就是运行时不存在的文件
```

修法不是删，是先判断属于哪一类：

| 情况 | 处理 |
|---|---|
| 内容其实正文里已有 | 删（重复） |
| 内容正确但触发条件没写 | ⭐ 补路由行（这是绝大多数） |
| 内容正确但确实极低频 | 保留，⭐ 但要在文件首行写清"什么情况下才需要它" |

## 7. ⭐⭐⭐ 路由表本身也会成为瓶颈

一个 reference 集合超过 10 个文件之后，路由表就从"索引"变成"又一份正文"：

```
10 个文件 × 一行 ≈ 15 行 ≈ 200 token（可接受）
25 个文件 × 一行 ≈ 38 行 ≈ 500 token（⭐ 开始挤占正文预算）
```

> ⭐⭐⭐⭐ **L3 的意义是"不读时不占上下文"，但路由表是常驻的——
> 你为了省正文把内容拆出去，结果省下的 token 又被目录吃回去了。**

分档处理：

```
≤10 个   直接平铺在 SKILL.md 路由表里
10–25 个 ⭐ 按主题分组，组内再写触发条件（两级结构）
>25 个   ⭐⭐⭐ 单独一个 references/index.md，SKILL.md 只留一句"先读 index"
```

⚠️ 最后一种有个坑：**多了一跳，而那一跳同样可能不发生**——
SKILL.md 里那句话必须写成触发条件（"开始处理前先读 `references/index.md` 定位相关文件"），
⭐⭐⭐⭐ **写成"详见 index"等于没写**，这与"只给链接 = 可能不发生的跳转"是同一条。

## 8. 检查清单

- [ ] 目录里每个 reference 文件，都在 SKILL.md 里有一行指向它（无死文件）
- [ ] 每一行写的都是**触发条件**，不是文件名（无目录项式描述）
- [ ] 路由行里同时有**术语词**和**症状词**
- [ ] 文件名按内容命名，不是 `part2/advanced/misc/old`
- [ ] 每个文件首行有 `Parent skill: xxx`
- [ ] 文件数 >10 时已分组；>25 时已有 index 且 SKILL.md 里写的是动作
- [ ] ⭐ 让模型复述"什么情况下读哪个文件"，复述不出来的已处理
- [ ] ⭐ 路由表总行数 < 25（否则它正在挤占正文预算）

## 一句话

> ⭐⭐⭐⭐⭐ **reference 文件在被读取之前成本为零，在被读取之前价值也是零。
> 决定它有没有被读的，是 SKILL.md 里那一行的写法——
> 而那一行通常是作者唯一没有回头看过的地方。**
