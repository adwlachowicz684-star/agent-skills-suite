## 1. ⭐ 五问决策流

> 每段知识都问一遍，第一个"是"就定位置：

```
这段知识是否每次激活技能都需要？
  ├─ 是 → ⭐ 放 SKILL.md（入口文件，每次必读）
  └─ 否 ↓

是否每次进入该模块时都需要？
  ├─ 是 → ⭐ 放模块主文件（如 creator.md）
  └─ 否 ↓

是否仅在某个特定 Step 才需要？
  ├─ 是 → ⭐ 放对应的 phase 文件（如 collect-phase.md）
  └─ 否 ↓

是否只在特定条件下查阅？
  ├─ 是 → ⭐ 放参考文件（tools.md / safety.md）
  └─ 否 ↓

⭐ 考虑是否需要保留。
```

---

## 2. 为什么这五问有效

```
① ⭐ 它把"该放哪"从审美变成可判定——
   每一问都是关于"何时被需要"的事实，不是关于"看起来该在哪"
② ⭐ 最后一问是"是否需要保留"——
   ⭐ 大多数技能都漏了这一步
   这跟 challenge principle（每段都要证明配得上 token）同源
③ 它天然产出分层——不用额外设计目录结构
```

> ⭐ 与 `granularity-atomic-workflow.md` 的"重启测试"互补：
> 那份决定**拆分边界**（技能之间），这份决定**放置层级**（文件之间）。

## 3. 与三级加载的对应

```
L1 元数据    name + description        —— 始终加载
L2 正文      SKILL.md body            —— 触发时加载
L3 资源      references/scripts/assets —— ⭐ 按需
```

五问的落点：

```
第 1 问"是" → L2（正文）
第 2–4 问   → L3 的不同细分
第 5 问     → ⭐ 删除
```

**L3 内部还有三种语义**（见 `output-contract-templates.md`）：

```
references/  READ      —— 读进上下文（付 token）
assets/      COPY+FILL —— 复制并填写（零成本）
scripts/     EXECUTE   —— 执行，不进上下文
```

## 4. 参数传递：快照机制

跨阶段传参数要满足三条：

```
① ⭐ 显式   参数来源和去向清晰可追溯
② ⭐ 可校验 ⭐ 每个阶段有门卡检查参数完整性
③ ⭐ 防丢失 ⭐ 关键参数在快照中持久化
```

**载体**：

```
⭐ 快照（Snapshot）机制：
   每个阶段把产出写入快照，下一阶段从快照读取
   ⭐ 阶段门卡确保参数完整性
```

> ⭐ 这与 `assert-on-environment.md` 的"断言打在环境状态上"同源——
> 快照就是那个可被断言的环境状态。

## 速查

```
□ 每次激活都需要？        → SKILL.md
□ 每次进该模块都需要？    → 模块主文件
□ 只在某个 Step 需要？    → phase 文件
□ 只在特定条件下查阅？    → 参考文件
□ ⭐ 都不是 → 考虑是否保留

□ ⭐ 最后一问最常漏（challenge principle）
□ L3 三语义：READ / COPY+FILL / EXECUTE
□ 参数：显式 · 可校验（阶段门卡）· 防丢失（快照）
```

**一句话**：

> ⭐ **每段知识都要回答"它何时被需要"——
> 答不上来的，要么下沉，要么删除。**
