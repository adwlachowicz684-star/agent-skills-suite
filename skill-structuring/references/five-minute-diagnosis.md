## 1. 八步，每步不超过一分钟

按**常见失效概率从高到低**排序，前面的步骤先抓最常见的失败。

```
① 确认文件在它该在的地方
   ls -la ~/.claude/skills/<name>/SKILL.md      # 全局
   ls -la ./.claude/skills/<name>/SKILL.md      # 项目
   ⭐ 项目级存在的话，加载的就是它（项目级优先）

② 确认 frontmatter 能解析
   head -20 看第一行是不是 ---、name/description 非空、结尾 --- 在
   用 file 查有没有 BOM

③ 确认 Claude 看得见它
   ⭐ 让 Claude 枚举它当前能用的所有技能（含描述）
   你的不在列表里 → 加载器拒绝了 → 回到第 ② 步

④ 测匹配层
   提一个本该触发的请求，⭐ 在它行动之前先问「你会选哪个技能、为什么」
   它没提你的 → 就是 description 的问题 → 写得更具体

⑤ 测「选错技能」的情况
   同样请求，看是不是有竞争技能赢了
   → 收窄两个描述，或给赢的那个加 anti-trigger 子句

⑥ 查 allowed-tools
   技能调用了但中途失败 → 问 Claude 这个技能有哪些工具，和正文需要的比对

⑦ ⭐ 查 model 固定
   grep model: 看是不是 pin 了一个当前用户没有的模型

⑧ 查正文长度
   wc -w SKILL.md
   ⭐ 超过 3,000 词 → 长会话里会被截断 → 拆到 references/
```

> 第 ④ 步那个"在它行动之前先问"的技巧很关键——
> **一旦它开始干活，你就看不到它的路由决策了。**

## 2. 八步全过还是不对

> ⭐ **问题几乎肯定在正文逻辑，而不是接线。**

此时按调试普通 prompt 的方式处理：

```
① 缩到最小失败用例
② 一次只改一个地方
③ 看什么动了
```

这与 `claude-ab-loop.md` 的"每次只改 1–2 个变量，否则无法归因"是同一条纪律。

## 3. 两台机器行为不一致

先做五秒检查：

```bash
claude --version   # 两台都跑
```

> 版本不一致，问题就找到了。

版本一致但行为仍不同 → 怀疑**缓存状态**：

```
~/.claude/state/ 有时会残留过期条目
→ 重启 Claude Code 可清
```

分发纪律（与 `enterprise-registry.md` 一致）：

```
✅ 通过 catalog 发布，或提交到共享仓库并在 README 写清安装步骤
❌ 在 Slack 里说"把这个 SKILL.md 复制到你的 skills 目录"
   ——⭐ drift 就是这么开始的
```

## 4. 四个高频 FAQ

**Q：文件位置对、frontmatter 也对，为什么还是被忽略？**

> 几乎总是 description。Claude 用它作为触发信号；
> 如果它含糊、通用、或没用与请求匹配的用户侧措辞，
> **模型没有理由调用它**。

**Q：怎么确认技能真的加载了？**

> 直接让 Claude 枚举它当前可访问的所有技能及描述。
> 在列表里 → 发现层正常。
> 不在 → 加载器拒绝了文件（通常是 YAML 错误、缺必填字段、或 BOM）。

**Q：两个技能做类似的事，总选错怎么办？**

> 收窄两个描述，**不要共享通用的前缀**；
> 在两个正文靠上都加一小节 "When NOT to use this skill"。
> 如果逻辑 80% 相同 → **合并成一个内部再分支**。

**Q：全新会话能用，会话中途就失败？**

> ⭐ 几乎肯定是**正文长度截断**。
> 会话变长后，加载长 SKILL.md 会把当前轮推过上下文上限。
> 把正文压到 1,500 词以内，或把参考材料拆成按需加载的兄弟文件。

## 速查

| 现象 | 步 |
|---|---|
| 列表里没有 | ② ③ |
| 有但从不触发 | ④ |
| 触发了别的技能 | ⑤ |
| 触发了中途失败 | ⑥ |
| 换机器就坏 | ⑦（model pin）+ 版本/缓存 |
| 会话中途才失败 | ⑧（正文太长） |
| 全过还不对 | 正文逻辑，缩最小用例 |
