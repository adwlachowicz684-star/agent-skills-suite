## 1. ⭐⭐⭐⭐⭐ 半可用比失败更糟

> ⭐⭐⭐⭐⭐ **"⭐ 格式错误的 frontmatter 会让 Claude Code ⭐ 带着空元数据加载正文——
> ⭐⭐⭐⭐⭐ ⭐ 斜杠命令⭐ 仍然能用，⭐⭐⭐⭐⭐ ⭐ 但没有 description 可供匹配，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ ⭐ 于是⭐ 自动调用⭐ 静默地⭐ 永远不发生。"**

```
症状：/skill-name 手动调用 ✅ 正常
     自动触发              ❌ 从不发生
```

> ⭐⭐⭐⭐⭐ 这是⭐ 本轮最值钱的一条诊断，因为它⭐ 给出了一个⭐ 零成本的分诊：
> ⭐⭐⭐⭐⭐ **"显式调用能跑、自动触发不能"**——
> ⭐⭐⭐⭐ 我们已有的 `nine-checks-not-working.md` 第 8 项也提到过这一点，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但这里⭐ 给出了⭐ 它的⭐ 机制原因（元数据为空，不是描述写得差）。
>
> ⭐⭐⭐⭐⭐ 而且它⭐ 与 `official-spec-and-style.md` 那条⭐ 需要合起来看：
> ⭐⭐⭐⭐⭐ 那份说"⭐ 无效 YAML = ⭐ 加载失败（硬）"，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 这份说⭐ 还有⭐ 一种⭐ "⭐ 解析出空值但没报错" 的⭐ 中间态。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ **两者症状不同**：
> ```
> 硬失败  → 技能⭐ 完全不出现（/skills 里看不到）
> 半可用  → ⭐⭐⭐⭐⭐ 技能⭐ 在列表里、手动能调、⭐⭐⭐⭐⭐ ⭐⭐⭐ 只是⭐ 永远不自动触发
> ```

另一个描述同样准确：

> ⭐⭐⭐⭐ **"⭐ 无效 YAML 会导致⭐ 整个技能被⭐ 静默跳过，⭐⭐⭐ 没有任何报错，
> ⭐⭐⭐⭐ ⭐ Agent 启动时⭐ 完全不知道这个技能存在。"**

## 2. ⭐⭐⭐⭐ 六个具体错误形态

**① ⭐⭐⭐⭐⭐ 中文冒号**（中文写作时极易踩）

```yaml
❌ description: "当用户问：如何配置 Nginx 时使用。"
   ⭐⭐⭐⭐⭐ 中文全角冒号"：" ⭐⭐⭐ 不会触发 YAML 的键值分隔
   ⭐⭐⭐⭐ 但⭐⭐⭐⭐⭐ 半角冒号后不带空格 ⭐ 会不会报错取决于解析器

✅ 冒号后必须空格
```

> ⭐⭐⭐⭐⭐ 这条⭐ 此前完全没覆盖过，⭐⭐⭐⭐⭐ 而且⭐ 对中文技能库⭐ 是⭐ 高频坑——
> ⭐⭐⭐⭐ 中文正文里⭐ 到处都是全角冒号，⭐⭐⭐ description 里⭐ 自然也会写。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 判据：⭐ **description 里出现冒号，⭐ 一律加引号。**

**② ⭐⭐⭐⭐⭐ 未转义的半角冒号**

```yaml
❌ description: Fix errors: retry logic included
✅ description: "Fix errors: retry logic included"
```

**③ ⭐⭐⭐⭐ 井号被当成注释**

```yaml
❌ description: Handles retries # up to 3 attempts   ⭐ # 之后全被吃掉
✅ description: "Handles retries # up to 3 attempts"
```

**④ ⭐⭐⭐⭐ tab 缩进**

```
⭐⭐⭐⭐⭐ 缩进统一用 2 或 4 个空格，⭐⭐⭐⭐⭐ 永远不用 tab
理由：⭐⭐⭐ Python/PyYAML 解析器⭐ 对 tab 的行为⭐ 不一致
```

**⑤ ⭐⭐⭐⭐ 裸换行的多行字符串**

```yaml
❌ description: This skill handles retries
     and backoff                    ⭐ 第二行不在标量里

✅ description: >
     This skill handles retries
     and backoff                    ⭐ 用 > 折叠块标量
```

**⑥ ⭐⭐⭐⭐⭐ 开头有空行 / 缺少结束分隔符**

```
❌ ⭐⭐⭐⭐⭐ ⭐ --- 必须是⭐ 文件的第一个字符（⭐⭐⭐ 无前导空行或空格）
   否则⭐ frontmatter 会被⭐ 当成正文

❌ ⭐⭐⭐⭐ 缺少第二个 --- → ⭐⭐⭐⭐⭐ ⭐ YAML 块⭐ 永不终止，
   ⭐⭐⭐ 解析器⭐ 要么报错，⭐⭐⭐⭐ ⭐ 要么⭐ 把整个文件⭐ 当 frontmatter 吃掉
```

## 3. ⭐⭐⭐⭐⭐ 三条可直接跑的验证命令

这三条命令值得直接抄进你的检查脚本：

```bash
# ⭐⭐⭐⭐⭐ ① 重复键检测（有任何输出 = 该键出现了多次）
awk '/^---/{count++; if(count==2) exit} count==1' SKILL.md \
  | grep "^[a-z]" | sort | uniq -d

# ⭐⭐⭐⭐⭐ ② 分隔符检测（应恰好输出两行：开头 + 结束）
grep -n "^---" SKILL.md

# ⭐⭐⭐⭐ ③ name 是否在顶层（无输出 = 缺失或缩进错误 → 静默注册失败）
grep -m1 "^name:" SKILL.md
```

> ⭐⭐⭐⭐⭐ 第 ① 条⭐ 特别值得记：⭐ **重复键时，多数 YAML 解析器取⭐ 最后一个值，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 但 Claude Code 的加载器⭐ 可能⭐ 直接拒绝整个文件**——
> ⭐⭐⭐⭐⭐ ⭐ 取决于它用哪个解析器。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ **"可能"这个词是本条的重点**：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ **你没法从结果反推它到底做了哪一种**，
> ⭐⭐⭐⭐ ⭐ 所以⭐ 只能⭐ 预防（不放重复键）。
>
> ⭐⭐⭐⭐⭐ 第 ③ 条⭐ 给出的诊断很干净：
> ⭐⭐⭐⭐⭐ **`grep -m1 "^name:"` 无输出 = ⭐ 缺失 ⭐ 或⭐ 缩进错误**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 两者⭐ 都导致⭐ 静默注册失败，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 症状完全一样。
>
> ⭐⭐⭐ 另外一条⭐ 通用预防：`python3 -c "import yaml; yaml.safe_load(...)"`——
> ⭐⭐⭐⭐ ⭐ 部署前⭐ 先验证。

## 4. ⭐⭐⭐⭐ 布尔与 null 碰撞

> ⭐⭐⭐⭐⭐ **YAML 1.1（⭐ 很多解析器仍在用）把裸写的
> ⭐ `yes` `no` `true` `false` `on` `off` `null` `~`
> ⭐⭐⭐⭐⭐ ⭐ 当成⭐ 有类型的值，⭐ 而不是⭐ 字符串。**

```yaml
❌ name: null-safety-checker   ⭐⭐⭐ "null" 被解析成 YAML null
✅ name: "null-safety-checker"
```

> ⭐⭐⭐⭐⭐ 这个坑⭐ 极其隐蔽，因为它⭐ 只在⭐ 特定名字上发作：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ **你写 `onboarding` 没事，写 `on-call` 就出事。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而且⭐ 症状是⭐ "技能不出现"——⭐ 没有任何提示指向⭐ 这个字符问题。
>
> ⭐⭐⭐⭐ 顺带一条⭐ 同类：⭐⭐⭐⭐⭐ **数组必须写成 YAML 列表或用 `[a, b, c]`**，
> ⭐⭐⭐ 写成 `tags: a, b, c` ⭐ 会被当成⭐ 一个标量字符串。
> ⭐⭐⭐⭐ 这与 `allowed-tools` 那条"⭐ 写成逗号分隔字符串而非 YAML 列表"
> ⭐⭐⭐⭐ ⭐ 是⭐ 同一个错误。

**另外三个特殊字符**（会破坏解析，除非转义）：

```
: 冒号后跟空格   → 加引号
# 行首           → 加空格才是注释
% 百分号         → 加引号
& 和 *           → ⭐⭐⭐⭐ YAML 用它们做锚点（anchor）
```

## 5. ⭐⭐⭐ 其余三类

```
① ⭐⭐⭐⭐ 隐藏字符：从 PDF / 文字处理器 / 网页复制
   → ⭐⭐⭐ 智能引号、⭐⭐⭐⭐ 不换行空格
   ⭐⭐⭐⭐⭐ 症状：⭐⭐⭐⭐⭐ ⭐ 看起来完全正确，⭐⭐⭐⭐⭐ ⭐ 但解析不过
   ⭐⭐⭐⭐ ⭐⭐⭐ 与 `unicode-injection-defense.md` 是⭐ 同一类问题的⭐ 非恶意版本
   ⭐⭐⭐⭐ ⭐ 解法：⭐⭐⭐ 用纯文本编辑器确认⭐ 只有标准 ASCII

② ⭐⭐⭐⭐⭐ 常见的报错信息及其真实含义
   "could not find expected ':'"  → ⭐ 键后忘了冒号
   "mapping values are not allowed here" → ⭐ 缩进问题 或 ⭐ 冒号位置不对
   "unexpected end of stream"     → ⭐ 引号或括号没闭合

③ ⭐⭐⭐⭐ 排查手法：注释掉一半来二分定位
   ⭐⭐⭐⭐⭐ ⭐ frontmatter 长的时候，⭐⭐⭐⭐⭐ ⭐ 临时注释掉一部分
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 看⭐ 错误是否消失 → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 逐步缩小范围
```

## 速查

```
□ ⭐⭐⭐⭐⭐ "半可用"是⭐ 最糟的失败态：手动 /skill-name ✅、自动触发 ❌
   ⭐⭐⭐⭐⭐ ⭐ 机制：⭐⭐⭐⭐⭐ ⭐ 空元数据加载正文 → 斜杠命令能用，但⭐ 没有 description 可匹配
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 对照：硬失败 = 技能⭐ 完全不出现在列表里
□ ⭐⭐⭐⭐⭐ 中文技能库特有坑：⭐⭐⭐⭐⭐ ⭐ 中文全角冒号 → ⭐ 一律给 description 加引号
□ ⭐⭐⭐⭐⭐ 六个形态：全角冒号 · 未转义半角冒号 · # 被当注释 · tab 缩进
   ⭐ 裸换行多行 · ⭐⭐⭐⭐⭐ 开头有空行/缺结束 ---
□ ⭐⭐⭐⭐⭐ 三条命令：重复键(awk|sort|uniq -d) · 分隔符(应恰好2行) · name 顶层(grep -m1)
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 重复键：多数解析器取最后一个，但加载器⭐可能⭐直接拒绝整个文件 → ⭐ 只能预防
□ ⭐⭐⭐⭐⭐ 布尔/null 碰撞：null / no / on / off / yes / true / false / ~ 裸写会被转型
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 只在特定名字上发作（onboarding 没事，on-call 出事）
□ ⭐⭐⭐ 隐藏字符（智能引号、不换行空格）= 看起来完全正确但解析不过
□ ⭐⭐⭐⭐⭐ 报错对照：expected ':' = 忘冒号 · mapping values = 缩进/冒号位置
   unexpected end of stream = 引号或括号没闭合
□ ⭐⭐⭐⭐ 排查：注释掉一半二分定位
```

**一句话**：

> ⭐⭐⭐⭐ **"手动能调、自动触发不能"是半可用状态的零成本分诊——机制是 frontmatter 解析失败后带着空元数据加载正文，斜杠命令仍可用但没有 description 可供匹配；而它比硬失败更糟，因为技能还在列表里、看起来是好的，只是永远不会被自动选中。**
