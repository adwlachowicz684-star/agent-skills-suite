## 1. ⭐⭐⭐ 四步与停机规则

**按这个顺序从上往下走，⭐⭐ 找到问题就停。**

```
第一步：验证加载状态（文件层）
   · 目录路径和文件名完全正确吗
   · YAML 头格式——⭐⭐ 找一个能跑的技能逐行对比
   · 重启客户端 / 重新加载技能
   · 去技能列表里看，有没有显示出来
   ⭐⭐⭐ 这一步过不了 → 问题在第一层，⭐ 不要往下看了

第二步：手动强制调用（触发层）
   ⭐⭐ 直接说："使用 XXX 技能来处理这个问题"
   能正常执行 → ⭐ 触发层问题，回去改 description
   还是没反应 → ⭐ 回到第一步，根本没加载成功

第三步：对比输出差异（优先级层）
   手动调用成功但输出不对：
   · 和全局 Rule 冲突吗
   · 用户 Prompt 里有覆盖性指令吗
   · ⭐ 关掉其他技能单独测试，排除互相干扰

第四步：检查运行环境（环境层）
   前三步都没问题但还是报错：
   · 运行模式对吗
   · 依赖工具装了吗
   · 日志/控制台有报错吗
   · ⭐ 换个平台测试，确认是不是平台兼容性问题
```

> ⭐⭐⭐ 与 `troubleshooting-manual.md` 那个判据完全一致：
> **"指名调用能跑 = description 问题；不能跑 = 文件加载问题"**——
> 这里是同样分诊的四层展开版。
> ⭐⭐ 新增的是**第三步优先级层**和**第四步环境层**，
> 以及⭐⭐⭐ **"找到问题就停"这条停机规则**——
> 很多人四层全跑一遍，反而引入新变量。

## 2. ⭐⭐⭐ 80 / 15 / 5 的分布

```
⭐⭐⭐ 80%  → 第一步（文件层）就能解决
⭐⭐  15%  → 第二步（触发层）
⭐   5%   → 后两层（优先级 / 环境）
```

> ⭐⭐⭐ 这个分布对排查顺序有直接指导意义：
> **遇到"技能不生效"，先花 2 分钟把文件层查完，
> 比直接去调 description 的期望收益高 5 倍。**
>
> ⭐⭐ 它也修正了一个常见倾向：**多数人一上来就改 description**
> （因为"触发不准"是最直观的猜测），
> 但⭐⭐ 真正的问题八成在文件名、目录、YAML 这些"低级错误"上。

## 3. 四层各自的检查清单

**文件层**

```
□ 目录名是 skill 还是 skills？和平台要求一致吗
□ 文件名是 SKILL.md 吗？⭐ 大小写完全正确吗
□ 文件编码是 UTF-8 吗（⭐ 无 BOM）
□ YAML 头的 --- 顶格写了吗？前面没有空行吗
□ name 和 description 字段拼写正确吗
```

**触发层**

```
□ description 第一句写了"当用户……时使用"吗
□ ⭐ 埋了 3–5 个用户常用关键词吗
□ 写明了适用边界和不适用场景吗
□ ⭐⭐ 手动指名道姓调用能生效吗（这一步是分诊关键）
```

**优先级层**

```
□ 和全局 rules.md 有冲突吗
□ 用户的临时指令会不会覆盖技能规则
□ ⭐ 和其他技能的职责有重叠吗
```

**环境层**

```
□ 是在支持技能的运行模式下吗
□ 技能依赖的工具/脚本都安装了吗
□ 换个项目/平台能复现问题吗
```

**常见错误与解法**（可直接对照）：

```
YAML 解析错
   ✗ name:my-skill（冒号后没空格）
   ✗ description: "desc text'（引号不匹配）
   ✓ name: my-skill / description: "desc text"

编码问题 → ⭐ 重新存为 UTF-8（无 BOM）

scripts/ 不执行
   ⭐  chmod +x scripts/*.sh
   或  ⭐⭐ 提供不依赖脚本的回退路径
```

> ⭐⭐ "提供不依赖脚本的回退路径"这条容易被忽略，
> 但它与 `cross-agent-portability.md` 的
> "Cursor 不解析 allowed-tools"是同一类问题——
> ⭐ **环境不支持时，技能应该降级而不是完全失效。**

## 4. ⭐⭐ 一个常被忽略的经验判断

> ⭐⭐⭐ **"很多人觉得技能不稳定、容易出 bug，是 AI 技术不成熟。
> ⭐⭐⭐ 但真实情况是：90% 的问题，都是⭐ 低级错误 + 认知偏差。"**

> ⭐⭐⭐ 这句话值得单独记，因为它⭐ 直接指向排查的心态问题：
> **把问题归给"技术不成熟"，是一种⭐ 让自己不用去查低级错误的解释。**
>
> ⭐⭐ 与 `model-migration-audit.md` 那条完全同构：
> 那边的误诊是"模型变笨了"，这边是"技术不成熟"——
> ⭐ 两者都是⭐ **把不可控因素当解释，从而关掉自己能查的那部分**。

## 速查

```
□ ⭐⭐⭐ 四步：加载状态 → 强制调用 → 输出差异 → 运行环境
   ⭐⭐⭐ ⭐ 找到问题就停，别四层全跑（会引入新变量）
□ ⭐⭐⭐ ⭐ 80% 在文件层 / 15% 触发层 / 5% 后两层
   → ⭐⭐ 先花 2 分钟查完文件层，比直接改 description 收益高 5 倍

□ 文件层：目录名 skill or skills · ⭐ SKILL.md 大小写 · UTF-8 无 BOM
   --- 顶格无空行 · name/description 拼写
□ 触发层：⭐⭐ 指名调用能跑 = description 问题（分诊关键）
□ 优先级层：全局 Rule 冲突 · 临时指令覆盖 · ⭐ 职责重叠
□ 环境层：运行模式 · 依赖 · 换平台复现

□ YAML：冒号后空格 · 引号匹配
□ scripts/ 不执行：chmod +x · ⭐⭐ 提供无脚本回退路径
□ ⭐⭐⭐ 90% 问题是"低级错误 + 认知偏差"，不是技术不成熟
```

**一句话**：

> ⭐⭐⭐ **遇到技能不生效，按"加载 → 强制调用 → 输出差异 → 环境"四步从上往下走，
> 找到就停——因为 80% 的问题在第一步（文件名、目录、YAML 这些低级错误），
> 而多数人却一上来就去改 description。**
