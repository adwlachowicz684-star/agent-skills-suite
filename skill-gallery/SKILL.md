# 技能样本库

## 边界

- 用于：**看完整实例** · 逐句写法分析 · 找一份能改造的底稿 · 理解"好技能长什么样"
- 不用于：抽象原则 · 措辞技法 · 评估打分 · 原样照搬

## 核心原则

> ⭐⭐ **抽象原则看完还是不会写，看完一份完整源码就会了。**
> 样本的价值不在"能抄"，而在**它把取舍摊开了**——
> 哪里下死命令、哪里留自由度、为什么这条规则长这样。

| 你想知道 | ✅ 看样本 | ❌ 只看原则 |
|---|---|---|
| 规则该写到多细 | 样本里的实际措辞 | "要具体"（等于没说） |
| 什么时候下死命令 | 样本里那几处 MUST | "关键处要强制" |
| 边界怎么划 | 样本的 Out of scope | "要写边界" |
| 10 行能不能用 | 最小可行样本 | "要精简" |

> ⭐⭐⭐ **读样本的正确姿势是"它为什么这么写"，不是"它写了什么"。**
> 原样照搬而不改领域细节 = 制造伪技能。

> ⭐⭐⭐ 三个 S 级样本（skill-creator / systematic-debugging / file-search）的评语
> **全都在说"它改变了 agent 的行为方式"**——建立规范、强制顺序、避免过载，
> ⭐ **没有一个说"功能很全"**。

## 路由表（按需深读）
| `first-skill-minimal.md` | ⭐⭐ 第一个技能可以只有 10 行 + 四条黄金法则 |
| `five-starter-skills.md` | ⭐ 五个起步技能完整源码（含各自行数） |
| `code-review-skill-instance.md` | ⭐⭐ 八步、三档判词逻辑、三条硬规则；生成者≠校验者 |
| `systematic-debugging-skill.md` | ⭐⭐⭐ 四阶段、三次修复规则、⭐ 六条写法分析 |
| `unity-refactor-skill.md` | ⭐ 默认范围=最近改动、八条规则、"不确定就跳过" |
| `frontend-ui-skills.md` | ⭐ 三 agent 前置、反 AI 味表（禁令+替代的完美实证） |

## Critical Rules

1. ⭐⭐⭐ **照搬前先替换领域细节**——领域还是原样 = 伪技能（只有壳没有增量）
2. ⭐⭐ **读样本要读取舍**：哪些地方下死命令、哪些留自由度、为什么
3. ⭐⭐ **最该抄的是结构，不是内容**——步骤切分、判词分档、边界写法
4. ⭐ **最小可行样本优先**——先跑通 10 行版本，再照着复杂样本加东西
5. ⭐⭐ **看"它没写什么"同样重要**——省略处往往说明了粒度取舍
6. ⭐ 样本里的 gotchas 段落最值钱：**来自真实踩坑，无法靠推理得出**

## 何时不用（边界）

- 抽象原则与"这类技能该怎么设计" → 《skill-patterns》
- 措辞、形态、示例写法 → 《skill-crafting》
- 评估与打分 → 《skill-evaluating》
- 从零创建的完整流程 → 《skill-authoring》
- ⭐ 只想找一份能直接用的技能 → 先确认它解决的是不是你的问题，否则是伪技能
