>
> 本文是《skill-gallery》里唯一一份**产物型**样本。
> 另外两份分别是判定型（`judgment-skill-instance.md`）与变更+状态型（`stateful-skill-instance.md`）。
> 产物型的独特难点是：
> ⭐⭐⭐⭐⭐ **它的输出是一份"读起来完整的文档"，
> 于是所有缺陷——少了一路来源、结论没有动作、数字没拿到——
> 都不会表现为"缺了一块"，而表现为"这份报告挺全面的"。**

## 1. 它做什么

从 3 个已配置的数据源抓取本周数据，合成一份 Markdown 周报。

```
输入：周报日期范围（可省略，默认"上一自然周"）
输出：一份 Markdown 文件 + 一行摘要
副作用：写一个文件（因此 disable-model-invocation 保持 false，但写入路径受约束）
```

## 2. 完整源码

````markdown
---
name: weekly-digest
description: 从已配置的数据源抓取上一自然周的数据，生成一份 Markdown 周报文件，包含趋势摘要、异常项与建议动作。用于「生成本周周报」「把这周的数据汇总一下」「周报里的数据不对需要重跑」。
  Do NOT use for 单个数据源的临时查询（直接查）、实时数据看板（无缓存不适用）、跨月或跨季度汇总（用 monthly-review）。

# 周报生成

## 输出契约

生成一份 Markdown 文件，写入 `./reports/week-YYYY-MM-DD.md`（目录不存在则创建）。

文件必须包含且仅包含以下五节，顺序固定：

1. `## 统计区间`（一行，写明起止日期与解析依据）
2. `## 覆盖情况`（三行：成功源数/总源数、失败源清单及原因、覆盖百分比）
3. `## 趋势摘要`（3–5 条，每条 ≤ 2 行，每条必须带数字与来源）
4. `## 异常项`（逐条列出；若无，写"已检查 N 项，0 项异常，分母为 N"）
5. `## 建议动作`（逐条列出；每条格式为「动作 + 对象 + 阈值」，不得出现"建议关注"式措辞）

生成完成后，在对话中只回复一行：
`已生成 reports/week-YYYY-MM-DD.md：覆盖 2/3 源（67%），3 条趋势，2 条异常，1 条动作。`

## 步骤

1. 解析统计区间。未指定时取上一自然周。
   把解析结果写进输出第 1 节，格式如 `2026-09-21 ~ 2026-09-27（上一自然周，相对今天 2026-09-29）`。
   数据源里最后一条记录早于区间结束日时，在覆盖情况里注明"数据截至 X"，不得用区间结束日替代。

2. 逐个抓取 `sources.yaml` 里的数据源，结果写入 `./reports/_raw/<源名>-<run-id>.json`。
   run-id 为本次运行的 UTC 时间戳，每次运行不同。

3. 合成。三个源都成功才写"覆盖 3/3"；任一源失败则保留其余源并如实报覆盖率。

4. 生成文件，然后按输出契约第 5 节的格式校验一次。
   校验不通过则修正文件，不得直接回复"已生成"。

## 硬规则

- 未获取到的数据写"未获取（源：<源名>，原因：<原因>）"，不得写 0、不得写"无"、不得省略该行。
- 多个源对同一指标给出不同数值时，全部列出并注明口径差异；不得取其中一个、不得取平均。
- 每个数字必须带来源标签（如 `[源A]`）。没有来源的数字不得出现在文件里。
- 不得写入 `./reports/` 之外的路径。

## 失败处理

以下情况判定为失败，停止并报告（不生成文件）：
- 三个源全部失败
- 解析出的区间内没有任何一条数据（写"未获取到任何数据"，不写"本周无数据"）

以下情况不判定为失败，但必须在覆盖情况里写明：
- 部分源失败
- 源返回 200 但内容为空
- 源返回的最后一条记录早于区间开始日

## Gotchas

（首次创建，留空。每纠正一次补一条。）
````

## 3. 逐处点评：每一处在堵什么

| 位置 | 堵住什么 |
|---|---|
| description 里的三个 `Do NOT use` | ⭐⭐⭐⭐ 把"临时查询/看板/跨月"排除掉——这三类是误触发的主要来源 |
| ⭐⭐⭐⭐⭐ "输出契约"排在最前 | `skill-authoring/references/output-contract-first-order.md`：先定契约再写流程，否则流程会把输出反向决定 |
| ⭐⭐⭐⭐⭐ "包含且仅包含以下五节" | 防止模型"贴心地"多加一节"补充说明"——那一节通常在稀释 |
| 第 1 节要求写"相对今天 X" | `skill-input/references/relative-time-resolution.md`：时间窗口错了查询会成功，只是查的是另一周 |
| 第 2 节要求报覆盖百分比 | `skill-aggregation/references/partial-aggregation.md`：不报分母的"共 N 条"是真实但误导的 |
| ⭐⭐⭐⭐⭐ 第 4 节"若无，写已检查 N 项，0 项异常，分母为 N" | `skill-output/references/empty-output-silent-success.md`：空结果 ≠ 空输出；没有分母的"无"和"没查到"是同一个字符串 |
| ⭐⭐⭐⭐⭐ 第 5 节格式强制 + 禁止"建议关注" | 本轮 `skill-output/references/actionable-output.md`：可行动三要素 + "建议"是免责词 |
| 回话里报 `2/3 源（67%）` | ⭐⭐⭐⭐⭐ **摘要里也报覆盖率**——用户常常只读这一行 |
| run-id 进中间产物路径 | `skill-execution/references/intermediate-artifacts.md`：固定名会让第二次运行读到上一次的数据 |
| 硬规则第 1 条 | ⭐⭐⭐⭐⭐ 0 与"未获取"的区分；它同时是模板里最危险的默认值 |
| ⭐⭐⭐⭐⭐ 硬规则第 2 条"不得取平均" | `skill-aggregation/references/merge-conflict-resolution.md`：平均产生一个两个源都不支持的数字，而它最像"客观处理了分歧" |
| 硬规则第 3 条"没有来源的数字不得出现" | `decision-rationale-output.md` 的输出侧版本：不可复核的数字不能进文档 |
| ⭐⭐⭐⭐⭐ "校验一次，不通过则修正文件，不得直接回复已生成" | 防止"已完成"这个最廉价的转义 |
| 失败处理分两档列出 | `skill-recovery/references/failure-definition-missing.md`：只定义失败不定义成功，边界画在沙滩上 |
| ⭐⭐⭐⭐⭐ "不写本周无数据" | ⭐⭐⭐⭐⭐ 与硬规则第 1 条呼应：**"无数据"是一个答案，"没查到"不是** |
| Gotchas 留空并注明 | `skill-content/references/gotchas-mining.md`：Gotchas 是采集的，坐下来写产不出——填满它才是缺陷 |

## 4. ⭐⭐⭐⭐⭐ 产物型独有的四处设计

**① 契约里规定"仅包含五节"**

产物型最容易被"多加一节"破坏。多出来的内容不违反任何一条要求，
但⭐⭐⭐⭐⭐ 它出现在最后（近因区），于是把用户最后读到的东西换掉了。

**② 覆盖率在两处出现（文件里 + 回话里）**

因为⭐⭐⭐⭐⭐ 用户很可能只回话，不打开文件。
只写在文件里的覆盖率，等于没有覆盖率。

**③ 数字必须带来源标签**

判定型可以要求写依据（一段话），产物型不行——它是文档，塞满依据就没法读了。
所以产物型用⭐⭐⭐⭐⭐ **来源标签**替代依据：代价是几个字符，收益是每个数字都可回溯。

**④ 模板里预填了"会暴露自己的值"**

第 1 节的示例 `2026-09-21 ~ 2026-09-27` 是一个具体的历史日期。
按 `skill-examples/references/example-values-become-defaults.md`，它会被复制——
⭐⭐⭐⭐⭐ **而它复制到输出里时是明显过期的，于是会被发现。**
如果这里写的是"本周"或者直接留空，复制后就无从判断。

## 5. 这份样本刻意没做的事

- **没有状态**。每周独立生成，不读上周的周报——因此不需要 `skill-state` 那套版本与新鲜度判断。
- **没有判定等级**。它不产出"高/中/低风险"，因此不需要类别封闭与均衡测试集。
- **没有并发**。三个源串行抓取——并发会把失败从"少一路"变成"N 个半成品"，
  而这个技能恰恰需要清楚知道**哪一路**没抓到。
- **Gotchas 为空**。这是它刚建好时的正确状态。
