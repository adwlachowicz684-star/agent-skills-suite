## 5. ⭐⭐⭐⭐⭐ Grader 也评审 eval 本身

> ⭐⭐⭐⭐⭐ **"⭐ Grader ⭐ 同时⭐ 也⭐ 评审⭐ 这些 eval ⭐ 本身——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 标记出⭐ 弱断言，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 并⭐ 建议⭐ 缺失的⭐ 测试覆盖。"**

> ⭐⭐⭐⭐⭐⭐ **这是⭐ 本份⭐ 最值钱的⭐ 一条，⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 它⭐ 与⭐ 我们⭐ 已有的
> ⭐⭐⭐⭐ ⭐⭐⭐ 一条⭐ 结论⭐ 精确⭐ 对上，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而且⭐ 给出了⭐ 实现方式：**
> ```
> 我们的结论（assert-on-environment.md）：
>   ⭐⭐⭐⭐⭐ "同步校验断言本身——剔除恒过/恒失败的无效断言"
>   ⭐⭐⭐⭐⭐ ⭐⭐⭐ "恒过的断言比没有断言更危险"
>
> ⭐⭐⭐⭐⭐ 它的实现：
>   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 让 grader 子代理 ⭐ 在打分的同时 ⭐ 输出一份"对 eval 的批评"
>   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 包括：⭐ 哪些断言太弱 · ⭐⭐⭐⭐⭐ ⭐⭐⭐ 还缺什么覆盖
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **差别⭐ 在于：⭐⭐⭐⭐⭐ ⭐⭐⭐ 我们⭐ 那条⭐ 是⭐ 一句提醒
> （⭐ 靠人⭐ 记得⭐ 去做），⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 它⭐ 这条⭐ 是⭐ 流程里的⭐ 一个角色
> （⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 每次⭐ 都必然发生）。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 正是⭐ "⭐⭐⭐⭐⭐⭐ **规则升级为代码**"⭐ 那条的⭐ 又一个⭐ 样板。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 顺带⭐ 一个⭐ 反身性⭐ 观察：
> ⭐⭐⭐⭐ **一个只会被执行、从不会被评审的测试集，⭐⭐⭐⭐⭐ ⭐⭐⭐ 会随着时间
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 越来越⭐ 偏离⭐ 它⭐ 原本⭐ 要测的⭐ 东西**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与 `skill-decay-governance.md` 的
> "⭐ 技能库里⭐ 最差的⭐ 是你⭐ 最早写的"⭐ 是⭐ 同一个⭐ 现象，⭐⭐⭐⭐⭐ ⭐⭐⭐ 只是⭐ 发生在⭐ 测试集上。

## 6. ⭐⭐⭐⭐ 三个子代理的分工

```
⭐⭐⭐⭐ grader.md     ⭐ 判：⭐⭐⭐⭐⭐ ⭐⭐⭐ 对断言逐条打分（binary + evidence）
⭐⭐⭐⭐⭐ comparator.md ⭐⭐⭐⭐⭐ ⭐⭐⭐ 比：⭐⭐⭐⭐⭐ ⭐⭐⭐ 盲 A/B（no bias）
⭐⭐⭐⭐⭐ analyzer.md   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 析：⭐⭐⭐⭐⭐ ⭐⭐⭐ 事后分析 ⭐⭐⭐⭐⭐ ⭐⭐⭐ 为什么赢家会赢
```

> ⭐⭐⭐⭐⭐ 第三个⭐ 角色⭐ 是⭐ 我们⭐ 此前⭐ 没有的⭐ 一档：
> ```
> 我们已有：⭐⭐⭐⭐⭐ "生成者 ≠ 校验者"（frontend-ui-skills）
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 它更进一层：⭐⭐⭐⭐⭐ ⭐⭐⭐ **校验者 ≠ 解释者**
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 为什么⭐ 要⭐ 分出⭐ 第三个？⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 两者⭐ 产出⭐ 不同：
> ```
> comparator → ⭐⭐⭐⭐⭐ ⭐⭐⭐ "哪个更好"（一个判断，用于选）
> ⭐⭐⭐⭐⭐ analyzer   → ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ "为什么更好"（一组因果，用于改）
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **只做盲比，⭐⭐⭐⭐⭐ ⭐⭐⭐ 你⭐ 知道⭐ 该用⭐ 哪一版，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 但⭐ 不知道⭐ 下一版⭐ 该往哪改——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 于是⭐ 迭代⭐ 只能靠⭐ 猜。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 这⭐ 与 `skill-evolution-loop.md` 那句
> "⭐ 没有⭐ 反馈信号，⭐⭐⭐⭐⭐ ⭐⭐⭐ 自进化⭐ 就只是⭐ 用同样的错误方法⭐ 生成新版本"
> ⭐ 是⭐ 同一件事的⭐ 正面解法。

## 7. ⭐⭐⭐⭐ Optimize 与 Benchmark

```
⭐⭐⭐⭐⭐ Optimize  ：⭐⭐⭐⭐⭐ ⭐⭐⭐ description 触发优化，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 带 train/test 切分
⭐⭐⭐⭐⭐ Benchmark ：⭐⭐⭐⭐⭐ ⭐⭐⭐ 统计分析 —— ⭐⭐⭐⭐⭐ ⭐⭐⭐ mean / stddev / delta 跨配置
```

> ⭐⭐⭐⭐⭐ 前者⭐ 与⭐ 我们⭐ 记的⭐ `description-tuning-official-loop.md`
> （"⭐ 按测试集分数选，⭐⭐⭐⭐⭐ ⭐⭐⭐ 不按训练集"）⭐ 完全同源——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 两个⭐ 独立来源⭐ 都⭐ 用⭐ train/test 切分⭐ 来⭐ 防⭐ 过拟合。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 后者⭐ 补上了⭐ 一个⭐ 我们⭐ 缺失的⭐ 维度：
> ⭐⭐⭐⭐⭐ **stddev（标准差）。**
> ```
> 我们已有：⭐⭐⭐⭐⭐ mean（平均分）· ⭐⭐⭐⭐⭐ delta（差值）· ⭐⭐⭐⭐⭐ pass^5（稳定性）
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 它多出：⭐⭐⭐⭐⭐ ⭐⭐⭐ stddev —— ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 方差
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 为什么⭐ 方差⭐ 重要：⭐⭐⭐⭐⭐ ⭐⭐⭐ 两个版本
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 平均分⭐ 相同、⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 一个⭐ 稳定⭐ 一个⭐ 忽高忽低——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **在生产里⭐ 这⭐ 两个⭐ 完全不是⭐ 一回事。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 这⭐ 与 `capability-offset-net-gain.md` 那份
> "⭐ 相同平均分，⭐⭐⭐⭐⭐ ⭐⭐⭐ 两种实质（扩大能力边界 vs 换血）"⭐ 是⭐ 同一族：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ **平均分⭐ 是⭐ 一个⭐ 有损的⭐ 压缩，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 必须⭐ 配⭐ 至少一个⭐ 分布量。**

## 8. ⭐⭐⭐⭐ 与我们自己的元技能对照

```
⭐⭐⭐⭐⭐ 共同点：⭐⭐⭐⭐⭐ ⭐⭐⭐ 都把"规范本身 + ⭐⭐⭐⭐⭐ ⭐⭐⭐ 一份可运行范例"作为 references
           （我们记过：⭐⭐⭐⭐⭐ 不是让模型凭记忆写 SKILL.md，⭐⭐⭐⭐⭐ ⭐⭐⭐ 而是生成前先读这两份）
⭐⭐⭐⭐⭐ 差别  ：⭐⭐⭐⭐⭐ ⭐⭐⭐ 它是"一个工具"（五项能力在一个技能里，带脚本与界面）
           ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 我们是"一套资料"（十几个技能各自深入，靠人读）
```

> ⭐⭐⭐⭐⭐ 三条⭐ 可以⭐ 立刻⭐ 借过来的⭐ 设计：
> ```
> ① ⭐⭐⭐⭐⭐⭐ 让"成对对比"成为流程的默认形状（每个用例天然产生 with/baseline 一对）
>    ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不是靠人记得去做 A/B
> ② ⭐⭐⭐⭐⭐ 让"评审 eval 本身"成为一个角色（grader 顺带输出批评）
>    ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不是一句提醒
> ③ ⭐⭐⭐⭐⭐ 让 evidence 成为 schema 的必填字段
>    ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而不是一条写作建议
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 三条⭐ 的⭐ 共同点⭐ 也很清楚：
> ⭐⭐⭐⭐⭐ **都⭐ 是⭐ 把⭐ 我们⭐ 已有的⭐ "建议"，⭐⭐⭐⭐⭐ ⭐⭐⭐ 变成⭐ 它的⭐ "结构"。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 恰恰⭐ 是⭐ 整套库⭐ 反复⭐ 出现的⭐ 那一条：
> ⭐⭐⭐⭐⭐⭐ **需要⭐ 被保证的⭐ 事，⭐⭐⭐⭐⭐ ⭐⭐⭐ 要交给⭐ 有强制力的⭐ 机制——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ 不是⭐ 写得⭐ 更严厉，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而是⭐ 写成⭐ 结构。**

## 速查

```
□ ⭐⭐⭐⭐ 定位：把"写 prompt→测试→评估→迭代"从 ad-hoc 变成可重复工程流程
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 五项：Create / Eval / Improve / Benchmark / Optimize
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 它是"一个工具"，我们这套是"一套资料"——两种组织形态
□ ⭐⭐⭐⭐ 目录：SKILL.md + ⭐⭐⭐⭐⭐ agents/（grader·comparator·analyzer）+ scripts/ + eval-viewer/
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ agents/ 独立于 references/：⭐⭐⭐⭐⭐ ⭐⭐⭐ references=被读的知识，agents=被变成的角色
   ⭐⭐⭐⭐ ⭐⭐⭐⭐ eval-viewer/ 把"让人看结果"也做成产物——光说"要看"不够，得把"怎么看"也做出来
□ ⭐⭐⭐⭐⭐ 核心循环：⭐⭐⭐⭐⭐ ⭐⭐⭐ 每个用例同时跑两个子代理（with-skill + baseline）
   ⭐⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 关键在"结构上成对"而非"记得去做 A/B"——⭐⭐⭐⭐⭐ ⭐⭐⭐ 它是流程的默认形状
□ ⭐⭐⭐⭐⭐ 断言：binary pass/fail + ⭐⭐⭐⭐⭐⭐ evidence 必填
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ binary 而非打分：⭐⭐⭐⭐⭐ ⭐⭐⭐ "什么是3分"的标准本身又要主观判断，循环回去了
□ ⭐⭐⭐⭐⭐ grader 也评审 eval 本身：⭐⭐⭐⭐⭐ ⭐⭐⭐ 标记弱断言 + 建议缺失覆盖
   ⭐⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 对照我们"恒过的断言比没有断言更危险"——⭐⭐⭐⭐⭐ ⭐⭐⭐ 那条是提醒，这条是角色
□ ⭐⭐⭐⭐ 三子代理：grader(判) · comparator(盲A/B) · analyzer(为什么赢)
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 校验者≠解释者：⭐⭐⭐⭐⭐ ⭐⭐⭐ 只盲比知道用哪版，不知道下一版往哪改
□ ⭐⭐⭐⭐⭐ Optimize 用 train/test 切分防过拟合（与官方调优循环同源）
   ⭐⭐⭐⭐⭐ Benchmark 报 mean/stddev/delta —— ⭐⭐⭐⭐⭐ ⭐⭐⭐ stddev 是我们缺失的维度
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 平均分相同但一个稳定一个忽高忽低，在生产里完全不是一回事
□ ⭐⭐⭐⭐⭐ 可借三条：成对对比成为默认形状 · 评审 eval 成为角色 · evidence 成为必填字段
   ⭐⭐⭐⭐⭐⭐ 共同点：⭐⭐⭐⭐⭐ ⭐⭐⭐ 把"建议"变成"结构"
```

**一句话**：

> ⭐⭐⭐⭐ **skill-creator 把"每个用例同时跑 with-skill 与 baseline 两个子代理"做成流程的默认形状，把"评审 eval 本身"做成一个专门角色，把 evidence 做成 schema 的必填字段——三者的共同点是把我们反复强调的建议变成结构；而它多出的 stddev 提醒我们，平均分是一种有损压缩，必须配至少一个分布量。**
