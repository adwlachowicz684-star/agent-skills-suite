## 1. ⭐⭐⭐⭐⭐ 坏样本全文

下面这份是真实技能的常见形态，不是夸张：

```markdown
---
name: data-analysis
description: 一个专业的数据分析助手，可以帮助你分析各种数据，
  包括但不限于销售数据、用户数据、运营数据等。支持多种分析方法和图表，
  能够生成详尽的分析报告。适用于需要进行数据分析的各种场景。
---

# 数据分析助手

## 背景
在当今数据驱动的时代，数据分析能力至关重要。本技能旨在帮助用户
高效地完成数据分析工作，提升决策质量。

## 能力
1. 数据读取与清洗
2. 统计分析
3. 可视化
4. 报告生成

## 工作流程
1. 首先，仔细阅读用户提供的数据
2. 然后，进行必要的数据清洗，注意处理异常值
3. 接着，根据数据特点选择合适的分析方法
4. 进行深入分析，挖掘数据背后的洞察
5. 最后，生成一份详尽的分析报告

## 注意事项
- 请确保数据质量
- 分析要客观准确
- 报告要清晰易懂
- 注意保护数据隐私

## 输出
输出一份分析报告。
```

## 2. ⭐⭐⭐⭐⭐ 它为什么难辨

> ⭐⭐⭐⭐ **它没有一个错别字，格式完全规范，读起来非常专业。**

这正是它的危险性：

| 检查 | 结果 |
|---|---|
| YAML 合法 | ✅ |
| name 格式 | ✅ |
| 描述长度 | ✅ |
| 有章节结构 | ✅ |
| ⭐ **任何一条能起作用的指令** | ⭐⭐⭐ **❌ 一条也没有** |

> ⭐⭐⭐⭐⭐ **它能通过所有结构性检查，
> 而在行为层面它等于一个空技能。**
> 这就是"结构正确的废话"在技能库里的完整形态。

更糟的是：⭐ **它会触发，然后给出一个平庸但看起来完整的分析**——
于是你以为它有用。这是最难被发现的一类坏技能。

## 3. ⭐⭐⭐⭐ 逐条诊断（14 处）

| # | 原文 | ⭐ 病名 |
|---|---|---|
| 1 | `data-analysis` | ⭐ 通用名，必然与别的技能碰撞 |
| 2 | "一个专业的数据分析助手" | ⭐⭐⭐ 自夸，零信息（WHAT 缺失） |
| 3 | "包括但不限于…等" | ⭐⭐⭐⭐ 边界无限宽 → 必然误触发 |
| 4 | "支持多种分析方法和图表" | ⭐⭐ 罗列能力而非说明何时用 |
| 5 | "适用于需要进行数据分析的各种场景" | ⭐⭐⭐⭐ 同义反复，等于没写 WHEN |
| 6 | 无 NOT | ⭐⭐⭐⭐⭐ 无反触发 → 见 §5 |
| 7 | "## 背景" | ⭐⭐⭐ 黄金位置被叙事占据 |
| 8 | "仔细阅读" | 含糊词 |
| 9 | "必要的…清洗" | ⭐⭐⭐ 含糊词 + 无判据（什么算必要） |
| 10 | "注意处理异常值" | ⭐⭐⭐⭐ 没说怎么定义异常、怎么处理 |
| 11 | "选择合适的分析方法" | ⭐⭐⭐⭐⭐ 把核心判断整个交给模型 |
| 12 | "挖掘数据背后的洞察" | ⭐⭐⭐ 不可执行、不可验证 |
| 13 | "请确保/要客观/要清晰" | ⭐⭐⭐⭐ 三个含糊词连击 |
| 14 | "输出一份分析报告" | ⭐⭐⭐⭐⭐ 无结构、无必需要素、无验收 |

> ⭐⭐⭐⭐⭐ **第 11 条是致命伤**：
> 这个技能唯一真正有价值的东西就是"选哪种分析方法"，
> ⭐⭐⭐ 而它恰恰把这一条留给了模型——
> **模型本来就默认会选，所以这个技能没有改变任何行为。**
> 这就是"伪技能陷阱"的教科书案例。

第 6 条的后果特别值得单说：没有 NOT，意味着
**用户让 agent 修一个 typo，它也可能被这个技能接走**，
然后"好心"附送一段无关的数据分析。

## 4. ⭐⭐⭐⭐ 改写后的版本

```markdown
---
name: sales-cohort-analysis
description: 按 cohorts 分析销售数据的复购与留存——读入订单表，
  按首次购买月份分组，输出留存矩阵与环比变化。
  Use when 用户问"老客户还买不买""复购率多少""哪批客户流失了"。
  NOT for 单次营销活动效果评估（用 campaign-roi）、
  用户行为路径分析（用 funnel-analysis）、预测建模。
---

# 销售 cohort 分析

## 契约
读入订单表 → 按首购月份分群 → 输出留存矩阵。只读，不写入任何文件。

## 红线
- ⭐ 数据不足 3 个完整 cohort 时**停止并说明**，不输出不完整矩阵
- ⭐ 缺失值不得填 0（会伪造留存）——标记为 null 并在报告里说明
- 所有比率必须同时给出分子分母

## 输入
`--orders <csv>`：需含 `order_id, user_id, order_date, amount`

## 流程
1. `python scripts/cohort.py --orders <csv>` → `cohort.json`
2. 若退出码 10（字段缺失）→ 报告缺失字段并停止，不猜测映射
3. 读 `cohort.json`，生成矩阵（行=cohort 月，列=第 N 月留存率）
4. 标注环比变化 >10pp 的格子

## 输出（REQUIRED 四项，缺一即未完成）
| 项 | 内容 |
|---|---|
| 矩阵 | 留存率，每格含 分子/分母 |
| 变化 | 环比 >10pp 的格子 + 可能原因（标注为推测） |
| 数据说明 | 时间范围、样本量、**被排除的行及原因** |
| 存疑 | ⭐ 不确定的地方，或明确写"无" |

## 验证
`python scripts/validate_cohort.py cohort.json` 输出 0 errors；
⭐ 校验"各行留存率单调不增"——违反说明分组逻辑有错。

## 失败处理
脚本非 0 退出时，**报告失败并停止**；不得手动估算或跳过任一项。
```

**改了什么**：

| 维度 | 前 | ⭐ 后 |
|---|---|---|
| name | 通用 | ⭐⭐⭐ 特异（`sales-cohort-analysis`） |
| description | 自夸 + 无限边界 | ⭐⭐⭐⭐⭐ 具体动作 + 真实触发词 + 三条 NOT |
| 开头 | 背景叙事 | ⭐⭐⭐⭐ 一句话契约 |
| 核心判断 | "选择合适方法" | ⭐⭐⭐⭐⭐ 固化为确定流程 |
| 输出 | "一份报告" | ⭐⭐⭐⭐⭐ 四项 REQUIRED + 验收命令 |
| 失败 | 无 | ⭐⭐⭐⭐ 明确停止 + 禁止估算 |

## 5. ⭐⭐⭐⭐⭐ 通用识别法

三个问题，能问出 90% 的空技能：

**Q1 ⭐⭐⭐⭐⭐ 删掉 description 里的形容词和专业术语，还剩什么？**

```
"专业的数据分析助手…适用于各种场景" → 什么都不剩 → 空的
"按 cohorts 分析复购…Use when…NOT for…" → 剩很多 → 实的
```

**Q2 ⭐⭐⭐⭐⭐ 这个技能有没有改变模型的默认行为？**

```
⚠️ 如果模型"不用这个技能"也会做同样的事
   → ⭐⭐⭐⭐ 它没有价值（伪技能陷阱）
```

> ⭐⭐⭐⭐⭐ **这条是最强的判据**，也是唯一能抓出"第 11 条"那种
> 表面完整、实质空白的技能的方法。

**Q3 ⭐⭐⭐⭐ 不看正文，只看它能跑什么命令、输出什么字段？**

```
无脚本、无输出契约 → ⭐⭐⭐ 它的产出不可复现
```

配一条来自 `skill-quality/references/quality-rubric-nine-dims.md` 的提醒：
**实测表现占 23 分权重最高**——
⭐⭐⭐ **而这三条问法，就是不需要跑 eval 也能预判实测分数的快速筛。**
