## 1. ⭐⭐⭐⭐ 六条准则

**① ⭐⭐⭐ 选一小而强的一组**

```
⭐⭐⭐ 三到五个通常就够
⭐⭐⭐⭐⭐ ⭐ 每一个都要覆盖⭐ 空间中⭐ 不同的一片：
   ⭐ 一个简单的 · ⭐ 一个更难的 · ⭐ 一个模糊的 · ⭐⭐⭐⭐⭐ ⭐ 至少一个⭐ 边界情形
```

> ⭐⭐⭐⭐⭐ 这里⭐ 给了一个⭐ 比"覆盖主要分支"⭐ 更具体的⭐ 分配方式——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ **必须包含"一个模糊的"**。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 我们已有的 `examples-three-branches.md` 只说了
> "⭐ happy path / 边界 / 失败"，⭐⭐⭐⭐⭐ ⭐⭐⭐ 缺的⭐ 恰恰是⭐ 这一档：
> ⭐⭐⭐⭐⭐ **模糊输入的示例⭐ 教的是⭐ 判断，⭐ 而其余三档⭐ 教的都是⭐ 流程。**

**② ⭐⭐⭐⭐⭐ 贴近生产现实**

> ⭐⭐⭐⭐ **"⭐ 尽可能⭐ 从真实日志里⭐ 取例子。
> ⭐⭐⭐⭐⭐ ⭐ 合成示例⭐ 用于冷启动⭐ 没问题，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 它们⭐ 不应该⭐ 是模型⭐ 唯一⭐ 看到的⭐ 东西。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 例子⭐ 越接近⭐ 真实流量，⭐⭐⭐⭐⭐ ⭐⭐⭐ 就越有用。"**

> ⭐⭐⭐⭐⭐ 这⭐ 与 `eval-case-design.md` 的
> "⭐ 用反映你真实使用的⭐ 脏输入，⭐ 不是干净样例"⭐ 是⭐ 同一条原则，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 发生在⭐ 两个不同的载体上：
> ```
> 评测集：⭐ 脏输入（否则测不出真实水平）
> ⭐⭐⭐⭐⭐ 示例  ：⭐ 真实日志（否则教不会真实判断）
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ **一份技能⭐ 如果⭐ 评测集是脏的⭐ 而示例是干净的，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 它⭐ 会在评测上⭐ 暴露出 ⭐ 示例没能教会的⭐ 东西——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 这⭐ 其实是⭐ 一个⭐ 有用的⭐ 诊断信号。**

**③ ⭐⭐⭐⭐ 刻意制造多样性**

> ⭐⭐⭐⭐ **"⭐ 如果所有例子⭐ 长得都一样，⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型⭐ 遇到任何⭐ 不一样的东西⭐ 都可能⭐ 卡住。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 在⭐ 长度、措辞、难度⭐ 上⭐ 加入变化，⭐⭐⭐⭐⭐ ⭐⭐⭐ 使这个模式⭐ 不过于狭窄。"**

> ⭐⭐⭐⭐⭐ 关键在⭐ 后半句的理由：⭐ **"使这个模式不过于狭窄"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 也就是说，⭐⭐⭐⭐⭐ ⭐⭐⭐ 示例的作用⭐ 是⭐ 划定一个⭐ 模式的⭐ 边界，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 全同的示例⭐ 会把⭐ 这个模式⭐ 划得⭐ 过窄。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与 `few-shot-examples.md` 的"⭐ >5 收益递减"
> ⭐⭐⭐⭐ ⭐ 并不矛盾：⭐ **数量⭐ 有上限，⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 多样性⭐ 没有——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 五个⭐ 高度相似的示例 ⭐ 不如 ⭐ 三个⭐ 差异明显的。**

**④ ⭐⭐⭐⭐⭐ 结构必须一致**（见第 4 节，最重要）

**⑤ ⭐⭐⭐⭐ 推理只在"有价值"时才写**

> ⭐⭐⭐⭐⭐ **"⭐ 如果你⭐ 在意 ⭐ 某一步⭐ 怎么推理，⭐⭐⭐⭐⭐ ⭐⭐⭐ 就在示例里⭐ 写⭐ 简洁的推理，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 用来⭐ 教 ⭐ 思维链，⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而⭐ 不把提示⭐ 撑大。"**

> ⭐⭐⭐⭐⭐ 注意⭐ 这个⭐ 限定条件⭐ 很重要：⭐ **"只在有价值时"**。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 我们此前⭐ 记的是⭐ `examples-three-branches.md` 那条
> "⭐ 只给输入输出，⭐ 模型学到的是格式；⭐⭐⭐⭐⭐ ⭐⭐⭐ 加上思考过程⭐ 才学到判断"——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 那条⭐ 是⭐ 无条件推荐，⭐⭐⭐⭐⭐ ⭐⭐⭐ 这条⭐ 加了⭐ 前提。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ **仲裁：⭐ 对"判断类"示例（分类、分级、路由）⭐ 必写推理；
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 对"格式类"示例（模板、结构）⭐ 不必——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 那里⭐ 推理⭐ 只是⭐ 重复的噪音。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 另有一条⭐ 相关发现：⭐ 示例⭐ 与思维链提示⭐ 搭配时，
> ⭐⭐⭐⭐ ⭐⭐⭐ 少量精心挑选的示例⭐ 能演示⭐ 你想要的⭐ 分步推理，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ CoT 指引⭐ 把它⭐ 应用到⭐ 新的复杂输入上——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ **两者是⭐ 分工关系，⭐⭐⭐⭐⭐ ⭐⭐⭐ 不是⭐ 替代关系。**

**⑥ ⭐⭐⭐⭐ 尊重上下文预算**

```
⭐⭐⭐⭐ 删掉⭐ 客套话和样板文字
⭐⭐⭐⭐ 把输入⭐ 缩短到⭐  essentials
⭐⭐⭐⭐ 砍掉⭐ 冗余的解释
⭐⭐⭐⭐⭐ ⭐ 一个强的例子 ⭐ 优于 ⭐ 三个相似的
```

> ⭐⭐⭐⭐⭐ 最后一句⭐ 与 `few-shot-examples.md` 的
> "⭐ 3 个高质量 = 5 个普通，⭐ 且省 40% token"⭐ 是⭐ 同一结论的⭐ 定性版本。
> ⭐⭐⭐⭐ ⭐⭐⭐⭐ 而⭐ 那句⭐ 总原则⭐ 值得⭐ 单独记：
> ⭐⭐⭐⭐⭐ **"⭐ 删掉任何⭐ 不能实质性改变⭐ 模型行为的⭐ 东西。"**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与 `skill-reducer-study.md` 的
> "⭐ 压缩后质量反升 2.8%，⭐⭐⭐⭐ ⭐ 因为减少了干扰"⭐ 是⭐ 同一机制。

## 2. ⭐⭐⭐⭐⭐ 负例要"省着用"

> ⭐⭐⭐⭐⭐ **"⭐ 几条⭐ 现实的 ⭐ '别这么做，这样做' ⭐ 例子⭐ 可以⭐ 澄清边界，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 比如⭐ 何时该拒绝、⭐ 何时该升级。⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ **但要⭐ 省着用。**"**

```
⭐⭐⭐⭐⭐ 原文用词：use negative examples ⭐ sparingly（节省地、克制地）
```

> ⭐⭐⭐⭐⭐ 这条⭐ 与⭐ 我们已有的⭐ 一条⭐ 看似冲突，⭐⭐⭐⭐⭐ ⭐⭐⭐ 需要仲裁：
> ```
> 已有：`eval-case-design.md` 说 ⭐ 负向用例⭐ 比正向⭐ 更值钱
>       （因为"编造指标、泄露密钥"这类失败，⭐ 只看"该有的有没有"⭐ 永远测不出）
> 本条：负例要 sparingly
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐⭐ **两者⭐ 不矛盾——⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 说的⭐ 不是同一件事**：
> ```
> 评测集里的负向用例 → ⭐⭐⭐⭐⭐ ⭐ 越充分越好（⭐ 它检查"它没做什么"）
> ⭐⭐⭐⭐⭐ 正文里的负向示例 → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 要克制（⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 它占用上下文，
>                        ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 且⭐ 禁令型示例⭐ 有⭐ 反噬风险）
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ "反噬风险"⭐ 正是⭐ 我们⭐ 反复验证过⭐ 的那条：
> ⭐⭐⭐⭐⭐ **禁令⭐ 必须⭐ 带⭐ 正面对应物。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 所以⭐ 负例的⭐ 正确写法⭐ 是
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 原文给的⭐ 那个形式：
> ```
> ❌ 单独展示"错误做法"
> ✅ ⭐⭐⭐⭐⭐ "别这么做，这样做"——⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 两个都给，且⭐ 成对出现
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与 `six-pitfalls-selfcheck.md` 里
> "⭐ 正面原则改成反模式时⭐ 必须写 ⭐ 不要 X，改为 Y"⭐ 是⭐ 完全同一条要求。

**"省着用"的具体量**：⭐⭐⭐ a couple（一两条）现实的反例，**用来澄清边界**——
尤其适用于 ⭐ 何时拒绝 ⭐ 和 ⭐ 何时升级 ⭐ 这两类判断。

## 3. ⭐⭐⭐⭐⭐ 成本不是均匀的

> ⭐⭐⭐⭐⭐ **"⭐ 你不需要⭐ 每一步 ⭐ 都一样'重'。⭐⭐⭐⭐⭐ ⭐⭐⭐ 一个⭐ 合理的模式是：
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 在⭐ 出错代价高的步骤上 ⭐ 慷慨投入
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐（合规检查、财务决策、安全关键路由）；
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 在⭐ 简单低风险的转换上 ⭐ 用更轻的提示 ⭐ 甚至零样本。"**

```
⭐⭐⭐⭐⭐ 配套动作：⭐⭐⭐⭐⭐ 定期复查 ⭐ 每一步的 token 消耗，
              ⭐⭐⭐⭐⭐ ⭐⭐⭐ 以及 ⭐ 这些示例⭐ 是否⭐ 配得上⭐ 这个成本。
```

> ⭐⭐⭐⭐⭐ 最后那句⭐ 问句⭐ 是⭐ 本轮⭐ 最值得⭐ 记住的⭐ 一句：
> ⭐⭐⭐⭐⭐ **"⭐ 这个示例⭐ 还在⭐ 发挥它的作用吗？⭐⭐⭐⭐⭐ ⭐⭐⭐ （is this example still pulling its weight）"**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 它⭐ 给出了⭐ 一个⭐ 可周期性执行的⭐ 剪枝动作：
> ⭐⭐⭐⭐⭐ **逐个示例问"它还在发挥作用吗"，⭐⭐⭐⭐⭐ ⭐⭐⭐ 答不上来就删。**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与 `skill-portfolio-audit.md` 的
> "⭐ 按命中率分层——⭐⭐⭐⭐ ⭐ 只有部分分支够到的指令⭐ 100% 占着上下文"
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 是⭐ 同一个动作⭐ 在⭐ 示例粒度上的⭐ 版本。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而且⭐ 它⭐ 与⭐ 我们已有的⭐ 一条⭐ 精确对上：
> ⭐⭐⭐⭐⭐ **"每一处模糊⭐ 都是⭐ 一次⭐ 授权模型⭐ 替你决定"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 反过来：⭐ **每一个⭐ 没有⭐ 改变行为的示例，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 都是⭐ 一次⭐ 纯粹的⭐ 成本支出。**

**成本—质量权衡的基本事实**：

```
⭐⭐⭐ 更多更丰富的示例 → ⭐ 通常提升质量，⭐ 但花更多（延迟 + 花费）
⭐⭐⭐ 更少更小的示例   → ⭐ 更便宜，⭐ 但可能不够稳健
⭐⭐⭐⭐⭐ ⭐ 正确的平衡 ⭐ 对 ⭐ 低流量内部工具 ⭐ 和 ⭐ 高流量产品管线 ⭐ 是不同的
```

> ⭐⭐⭐⭐⭐ "⭐ 对不同场景⭐ 平衡点不同"⭐ 这句⭐ 看似平淡，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 但它⭐ 否定了⭐ 一个常见做法：⭐ **照抄别人的示例数量。**

## 4. ⭐⭐⭐⭐ 结构一致

> ⭐⭐⭐⭐⭐ **"⭐ 选一个模板⭐ 然后⭐ 坚持它——⭐ 同样的⭐ 章节、字段、顺序。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 如果⭐ 一个例子⭐ 是 ⭐ 输入 → 推理 → 输出，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 那么⭐ 全部⭐ 都应该是。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 一致性⭐ 帮助模型⭐ 锁定 ⭐ 什么才是重要的。"**

```
标准模板（推荐直接用）：
  ### Example N: [场景名]
  **Input**:     [样本]
  **Output**:    [期望结果]
  **Reasoning**: [为什么这是对的]
```

> ⭐⭐⭐⭐⭐ 这条⭐ 看似⭐ 是排版建议，⭐⭐⭐⭐⭐ ⭐⭐⭐ 但⭐ 理由⭐ 很硬：
> ⭐⭐⭐⭐⭐ **"⭐ 一致性⭐ 帮助模型⭐ 锁定⭐ 什么才是重要的"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 换句话说：⭐⭐⭐⭐⭐ ⭐⭐⭐ **结构不一致时，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型⭐ 会误把⭐ 格式的差异⭐ 当成⭐ 有意义的信号。**
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与我们已有的⭐ 一条⭐ 完全同构：
> ⭐⭐⭐⭐⭐ **`golden-rules-failure-modes.md` 说 ⭐ "把每个形容词⭐ 换成一条规格"**，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 因为⭐ 形容词⭐ 会被模型⭐ 当成噪音；
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而这里⭐ 是说 ⭐ 不一致的格式⭐ 也会变成噪音。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 一个⭐ 具体的⭐ 反面例子⭐ 值得记：
> ⭐⭐⭐⭐⭐ **三个示例⭐ 里两个有 Reasoning、一个没有 →
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 模型⭐ 会学到"⭐ 推理⭐ 是⭐ 可选的"，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而⭐ 你本意⭐ 是⭐ 它必须推理。**

## 速查

```
□ ⭐⭐⭐⭐ 六条准则：小而强(3–5，⭐⭐⭐⭐⭐ 必含一个"模糊"示例) · ⭐⭐⭐⭐⭐ 取自真实日志
   ⭐⭐⭐⭐ 刻意制造多样性(长度/措辞/难度) · ⭐⭐⭐⭐⭐ 结构一致 · 推理只在有价值时写
   ⭐⭐⭐⭐ 尊重上下文预算(一个强的 > 三个相似的)
□ ⭐⭐⭐⭐⭐ "删掉任何不能实质性改变模型行为的东西" ←→ 压缩后质量反升 2.8%，同一机制
□ ⭐⭐⭐⭐⭐ 六条里的分配：⭐ 示例划定模式边界；全同示例把模式划得过窄
   ⭐⭐⭐⭐⭐ ⭐ 数量有上限(>5 递减)，⭐⭐⭐⭐⭐ ⭐⭐⭐ 但多样性没有 → 3 个差异明显的 > 5 个相似的
□ ⭐⭐⭐⭐⭐ 负例 sparingly（正文里）——仲裁：⭐⭐⭐⭐⭐ ⭐ 评测集的负向用例越充分越好，
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 正文的负向示例要克制（占上下文 + 禁令反噬风险）
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ 写法必须成对："别这么做，这样做"——⭐⭐⭐⭐ ⭐⭐⭐ 禁令必须带正面对应物
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 最佳用途：澄清"何时拒绝"与"何时升级"
□ ⭐⭐⭐⭐⭐ 成本不均匀：出错代价高的步骤(合规/财务/安全路由)慷慨投入；
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 简单低风险转换用轻提示甚至零样本
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 周期性问："这个示例还在发挥作用吗？"答不上来就删
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 没有改变行为的示例 = 一次纯粹的成本支出
□ ⭐⭐⭐⭐⭐ 结构一致：⭐ 选定模板并坚持（同章节、同字段、同顺序）
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 不一致的格式会被当成有意义的信号
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⚠️ 三个示例两个有 Reasoning 一个没有 = 教它"推理是可选的"
```

**一句话**：

> ⭐⭐⭐⭐ **示例要"小而强、取自真实日志、结构严格一致"，且必须包含至少一个模糊输入的例子——因为其余几档教的是流程，只有模糊档教的是判断；而正文里的负例要 sparingly 且必须成对写成"别这么做，这样做"，因为禁令不带正面对应物就会反噬。**
