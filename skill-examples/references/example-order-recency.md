## 1. ⭐⭐⭐⭐⭐ 最后一条示例权重最高

首因/近因效应在章节层已经被反复说过：**开头是黄金位置、压缩只保留开头**。
同一机制在示例集内部同样成立，但几乎没人把它当成一个需要设计的属性。

```
示例 A（典型场景）
示例 B（边界场景）
示例 C（上周临时补的一条）   ← ⭐⭐⭐⭐⭐ 权重最高
```

> ⭐⭐⭐⭐⭐ **作者以为三条例等价，模型按位置给它们不同权重。**
> 而这本该是最容易控制的一个变量——排个序而已，零成本。

机制上和正文一样：示例是"已经发生过的事实"，模型对它的信任度高于指令。
当三条示例给出的信号不完全一致时，⭐⭐⭐⭐⭐ **它不是取平均，它取最近的那条**——
因为最近的那条在注意力上最活跃，而不是因为它更正确。

一个能立刻验证的现象：

```
把示例集顺序倒过来跑一次，输出风格会跟着变
```

变了 → 说明示例之间并不等价，而"哪条生效"由位置决定，不由内容决定。

## 2. ⭐⭐⭐⭐⭐ 而最后一条通常是最晚随手加的

这是本节真正值钱的地方——**权重最高的位置，和最不被审的位置，是同一个位置。**

示例集的演化方式非常稳定：

| 时点 | 动作 | 这条示例的质量 |
|---|---|---|
| 写第一版 | 挑最好的一条真实输出 | ⭐⭐⭐⭐⭐ 最高（精心选的） |
| 发现边界没覆盖 | 补一条边界示例 | ⭐⭐⭐⭐ 高（有明确目的） |
| ⭐ 线上出了个怪case | **追加一条** | ⭐⭐ **最低**（为了平息那一次，不是教规律） |

> ⭐⭐⭐⭐⭐ **补示例这个动作，恰恰发生在"作者最不关心教学、只想让这次过去"的时候。**
> 于是它权重最高，也最不具代表性。

更糟的是第三条的典型内容：它是为了处理**一次具体事故**写的，因此它往往
⭐⭐⭐⭐⭐ **携带了那次事故的全部特殊性**（某个具体文件、某个具体阈值、某个具体措辞），
而这些特殊性会被当成通用规律学走。

这与《`skill-examples/references/example-mining-from-traces.md`》并不矛盾，
但边界要划清：

```
✅ 采集来的：真实、被采纳、有 Rationale  → 可以放任何位置
❌ 应急追加的：只代表那一次、没有 Rationale → ⭐⭐⭐⭐⭐ 它不该在最后
```

判据一句话：**这条示例能回答"为什么在这个场景该这么做"吗？** 答不上来 ⇒ 它是平的，
把它挪到中间（中间是黑洞，权重最低——这一次"黑洞"反而是合适的归宿）。

## 3. 三条示例不是"三选一"，是"三选三"

常见误解：三条示例是三个候选，模型挑一个用。实际不是。

> ⭐⭐⭐⭐⭐ **三条示例同时在起作用，只是分工不同：
> 第一条定义"这件事长什么样"，最后一条定义"边界在哪"。**

于是两套信号必须彼此一致，而没有任何环节检查这件事：

| 位置 | 承载的信号 | 不一致时的后果 |
|---|---|---|
| 第一条 | ⭐⭐⭐⭐ 典型形态（格式、粒度、语气） | — |
| 中间 | ⭐⭐ 几乎不承载（黑洞） | — |
| 最后一条 | ⭐⭐⭐⭐⭐ **边界与尺度**（多细、多长、多保守） | 边界被最后一条改写 |

典型事故：

```
示例1：输出 3 行，简洁        ← 定义了形态
示例3：为了解释一个复杂case，写了 20 行  ← ⭐⭐⭐⭐⭐ 定义了尺度
实际输出：20 行
```

作者的本意是"示例3 只是那个复杂case 才这么长"，而⭐⭐⭐⭐⭐ **模型没有"这条只适用于该case"
这个信息——它只知道最后看到的是 20 行**。

修法不是删掉示例3（它确实覆盖了必要的边界），是**让它不承载尺度信号**：

```
❌ 示例3 完整展开 20 行
✅ 示例3 只给判断（"此输入属于 X 类 → 走 B 分支"），输出用"同示例1格式"指代
```

即：⭐⭐⭐⭐⭐ **边界示例只示范判断，不示范长度。** 长度由第一条锚定，
而第一条是唯一一条你精心挑选过的。

## 4. ⭐⭐⭐⭐ 反例的位置：不能放最后

已有规则说"正文里的负例要 sparingly"（《`skill-examples/references/few-shot-example-quality.md`》）。
位置这一维此前没写过：

```
正例 A · 正例 B · 反例 C（放最后）
```

> ⭐⭐⭐⭐⭐ **反例放最后，等于让"错误的样子"占据注意力最活跃的位置。**

模型不会因此就去照着反例做——它不会那么笨。真正发生的是更微妙的一件事：

> ⭐⭐⭐⭐⭐ 反例在最后，会让模型在生成时**优先检查"我是不是正在犯这个错"**，
> 而把"我该做什么"挤到次要位置。输出因此变得保守、变短、倾向于省略。

表现为"加了反例之后输出变保守了"，而作者通常的解释是"反例写得还不够清楚"。

正确排布：

```
① 正例（典型）→ ② 反例 + 理由 → ③ 正例（边界）
⭐⭐⭐⭐⭐ 用一条正例收尾，让最近的那条是"对的"
```

中间夹反例是安全的，因为中间是黑洞；⭐⭐⭐⭐⭐ **收尾必须是正例**——
这与《`skill-content/references/instruction-ordering.md`》"验证之后不要再放任何东西"
是同一条原则：**近因区放什么，就放大什么。**

## 5. 排序规则

| 位置 | 放什么 | ⭐ 理由 |
|---|---|---|
| 第 1 条 | ⭐⭐⭐⭐⭐ 最典型、最干净、格式最规范的正例 | 它锚定形态与尺度，且是两条精心挑选的之一 |
| 中间 | 反例（带理由）、罕见分支 | ⭐⭐⭐⭐⭐ 黑洞位置，权重最低，适合"必须有但不该被模仿"的内容 |
| 最后 1 条 | ⭐⭐⭐⭐⭐ 边界正例（只示范判断，不示范长度） | 它锚定边界，必须是你认可的边界 |
| ⭐ 绝不放最后 | 应急追加的、没有 Rationale 的、为了平息某次事故写的 | ⭐⭐⭐⭐⭐ 权重最高 + 质量最低 = 最差组合 |

三条附带纪律：

- ⭐⭐⭐⭐ **顺序是变更，不是排版**——改示例顺序要走行为对比
  （《`skill-versioning/references/version-diff-behavior-compare.md`》），
  因为它改变的是输出形态，而 diff 只显示"移动了几行"
- ⭐⭐⭐⭐⭐ **追加示例时，明确它要插在哪**——默认是中间，不是末尾
- ⭐⭐⭐⭐ 示例集超过 3 条后，位置效应会被稀释（每条权重都下降），
  但**最后一条仍然最高**，所以规则不变

## 6. 自检

```
□ ⭐⭐⭐⭐⭐ 最后一条示例，是不是"最晚随手加的"那条？
     是 → 把它挪到中间，或补上 Rationale
□ ⭐⭐⭐⭐⭐ 把示例集顺序倒过来跑一次，输出形态变了吗？
     变了 → 示例之间不等价，而"哪条生效"由位置决定
□ ⭐⭐⭐⭐ 最后一条是不是反例？是 → 用一条正例收尾
□ ⭐⭐⭐⭐ 最后一条的长度，是不是明显超过第一条？
     是 → ⭐⭐⭐⭐⭐ 它正在锚定输出长度，改成只示范判断
□ ⭐⭐⭐ 中间的示例是不是"必须有但不该被模仿"的（反例、罕见分支）？
     不是 → 把这类内容挪到中间
□ ⭐⭐⭐⭐ 每条示例都能回答"为什么在这个场景该这么做"吗？
     不能的那条，应该在中间（黑洞），不该在两端
```
