## 1. ⭐⭐⭐⭐⭐ 模型从反例里学到的是字面形式，不是规则

写反例时的默认心态：

> "我给它看一个错的样子，它就知道不能这么做了。"

实际学到的东西要具体得多：

```
❌ 错误示例：直接给出结论"这个方案不行"，没有说明依据
```

> ⭐⭐⭐⭐⭐ **模型带走的不是"要有依据"，
> 而是"'这个方案不行'这句话不该出现"。**

于是它改成"从几个维度看，该方案存在一定风险"——字面形式避开了，
⭐⭐⭐⭐⭐ **而"没有依据"这个真正的问题原封不动地留着。**

这就是"示例值会被当成默认值"
（《`skill-examples/references/example-values-become-defaults.md`》）在反例上的版本：
那份讲**值**被复制，本份讲⭐⭐⭐⭐⭐ **形式被规避**。
两者都是同一个机制的后果：模型处理的是**字面层**，而作者以为它在处理**语义层**。

唯一有效的对抗手段是把语义显式写出来：

```
❌ 错误示例：……（违反规则 3：结论必须带依据）
```

> ⭐⭐⭐⭐⭐ **标注"违反哪条规则"这半句，才是反例真正的载荷。**
> 没有它，整条反例只是在教模型换一种说法。

## 2. 三个常见失败形态

| # | 形态 | 模型实际学到什么 | ⭐ 危险度 |
|---|---|---|---|
| ① | 反例比正例更详细 | ⭐⭐⭐⭐⭐ "详细的那个是标准"，因为示例的详尽度本身就是尺度信号 | 最高 |
| ② | 只有 ❌ 没有 ✅ | "避开这个形式"——禁令反噬 | ⭐⭐⭐⭐ |
| ③ | 反例与正例差异过大 | ⭐⭐⭐⭐ "这是另一件事"，不是"这件事做错了" | ⭐⭐⭐⭐ |

**① 最危险也最常犯**，因为写反例的人天然想把它写清楚：

```
❌ 错误示例（展开 15 行，逐条说明错在哪）
✅ 正确示例（3 行）
```

作者的本意是"充分说明为什么错"，而⭐⭐⭐⭐⭐ **在示例集里，长度就是权重**——
最详细的那条会同时锚定形态和尺度。于是"最不该被模仿的那条"成了最被模仿的那条。

修法很硬：**反例的长度必须 ≤ 正例**。说明放在标注里（一句话），不放在展开里。

**③ 常被误认为是"覆盖更全面"**：反例用一个完全不同的场景，看起来覆盖面更大，
而⭐⭐⭐⭐⭐ 差异太大的两条示例之间建立不起"对错"关系——模型只会把它们当成两个分支。

## 3. ⭐⭐⭐⭐⭐ 最小差异对：只差一处

反例要有效，必须与对应的正例构成**最小差异对**：

```
输入相同 → 处理相同 → ⭐ 只有一处不同
```

```
✅ 正例：输入未提供时区 → 标注"按 UTC（规则5）"，并在输出首行回显
❌ 反例：输入未提供时区 → 直接按本地时区处理，未回显
        （违反规则 5；其余与正例完全相同）
```

> ⭐⭐⭐⭐⭐ **差异只有一处时，"错在哪"是模型唯一能推断出的答案；
> 差异有五处时，它得自己挑——而它挑的通常是最表面的那一处。**

判据一句话：**遮住 ❌ 和 ✅ 的标记，还能一眼看出哪条是错的吗？**
看不出 ⇒ 差异要么太多，要么在无关的地方（格式、语气、长度），
⭐⭐⭐⭐ 于是模型学到的是"风格上别这样"，不是"逻辑上别这样"。

## 4. ⭐⭐⭐⭐⭐ 反例必须带正面对应物

这一条在库里已经出现过多次（禁令要带正面对应物、禁止解释错误要给 safe_reply、
"不要 X" 要写成 "不要 X，做 Y"）。在反例上它的具体形态是：

```
❌ 反例：……（违反规则 3）
⭐⭐⭐⭐⭐ ✅ 应为：……（同一输入的正确输出）
```

为什么这里尤其不能省——

> ⭐⭐⭐⭐⭐ **只有 ❌ 的反例，给模型留了一个空位：**"那该长什么样？"
> 而空位由模型填，填的依据是它自己的先验，不是你的规则。
> 于是反例把"遵循规则"换成了"避开一个形式 + 自行发挥"。

这正好是禁令反噬的机制：⭐⭐⭐⭐⭐ **禁令消除的是一个具体形式，不是一类行为。**
正面对应物的作用是**把消除换成替换**。

附带一条：正面对应物必须与反例**同一输入**（否则又不构成最小差异对），
且⭐⭐⭐ 不要写成"正确做法见上文"——示例是"已发生的事实"，
指回正文会让模型在两个信任等级之间跳，而它跟的是示例。

## 5. ⭐⭐⭐⭐ 反例会变成"曾经的错误"

这是反例特有的一种腐烂，此前没写过：

```
v1 反例：❌ 不要把所有数据一次性加载进内存
v2 修复：引入流式处理，框架已强制
现在：   这条反例描述的错误在结构上不可能发生了
```

> ⭐⭐⭐⭐⭐ **反例腐烂的方式不是"变错"，是"变得不可达"——
> 它描述的那个错误已经不存在了，而它仍然占着上下文、仍然被当作边界信号。**

比正文腐烂更难发现的地方在于：⭐⭐⭐⭐ **正文过时会被人发现（照着做会失败），
反例过时不会（没人会去"照着反例做一遍"来检验它）。**

所以它需要一个正文不需要的东西：**时效标记**。
最低成本的形式是在标注里带上出处：

```
❌ 反例：……（违反规则 3；来源：2026-08 线上事故 #142）
```

有了来源就有两个用处：⭐⭐⭐⭐ 三年后能判断它是否还成立；
⭐⭐⭐⭐⭐ 以及它能回答"这条规则为什么存在"——这恰恰是
《`skill-content/references/gotchas-mining.md`》里最难采集的那一类素材。

## 6. 反例的结构

```markdown
**输入**：<与对应正例完全相同的输入>

❌ 反例（违反规则 N：<一句话>；来源：<事故/日期，可选>）
<输出，长度 ≤ 正例>

⭐⭐⭐⭐⭐ ✅ 应为（同一输入）
<输出>
```

五条硬约束：

| # | 约束 | ⭐ |
|---|---|---|
| ① | 必须标注违反的是哪条规则（编号或规则原文） | ⭐⭐⭐⭐⭐ |
| ② | 必须与正例只差一处 | ⭐⭐⭐⭐⭐ |
| ③ | 必须带 ✅ 正面对应物，且同一输入 | ⭐⭐⭐⭐⭐ |
| ④ | 长度 ≤ 正例 | ⭐⭐⭐⭐⭐ |
| ⑤ | 位置放中间，不放最后 | ⭐⭐⭐⭐（《`skill-examples/references/example-order-recency.md`》） |

以及数量：正文 sparingly 指的是**正文里**；评测集里的负例要充分
（《`skill-evaluating/references/eval-case-design.md`》）。
两处不矛盾，因为⭐⭐⭐⭐⭐ **正文的反例是"教学"，评测集的负例是"检查"**——
教学要最小（占上下文、且有反噬风险），检查要最全（它测的是"它没做什么"）。

## 7. 自检

```
□ ⭐⭐⭐⭐⭐ 每条反例都标了"违反规则 N"吗？
     没标 → 它在教换一种说法，不是在教规则
□ ⭐⭐⭐⭐⭐ 反例比正例长吗？长 → 它同时锚定了形态与尺度，最危险
□ ⭐⭐⭐⭐⭐ 遮住 ❌/✅ 标记，还能看出哪条错吗？看不出 → 差异不在关键处
□ ⭐⭐⭐⭐⭐ 每条反例都带 ✅ 同一输入的正面对应物吗？
□ ⭐⭐⭐⭐ 反例描述的那个错误，现在还可能发生吗？（结构已封堵 → 删）
□ ⭐⭐⭐ 反例在最后吗？在 → 挪到中间
□ ⭐⭐⭐⭐ 反例里出现的字面形式，换个说法就能绕过吗？
     能 → 它只消除了形式，没消除行为
```
