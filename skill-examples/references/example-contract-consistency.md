## 1. ⭐⭐⭐⭐⭐ 一个几乎没人做的检查

```
拿技能的 schema / 输出契约，去校验它自己示例里的每一段输出。
```

这个检查几乎从没被执行过，原因很实在：

> ⭐⭐⭐⭐⭐ **schema 被理解成"用来校验模型输出的东西"，
> 而示例是"写文档的人自己写的"——没人会觉得需要校验自己写的东西。**

而它恰恰是最便宜、命中率最高的一个检查。首次执行时，
⭐⭐⭐⭐ **命中率通常在 50% 以上**：少了字段、多了字段、枚举值写成了自然语言、
时间没带时区、数字没带单位。每一处都在示例里，于是每一处都会出现在输出里。

```
❌ 契约：status ∈ {ok, warn, fail}
   示例：status: 看起来正常       ← ⭐⭐⭐⭐⭐ 不可解析
```

## 2. 不一致时，示例赢

这一点由《`skill-examples/references/example-overrides-instruction.md`》确立：
示例的信任度高于指令。把它和契约放在一起，结论不变——

```
契约（正文 / schema / 模板）  = 指令层
示例                          = ⭐⭐⭐⭐⭐ "已发生的事实"

冲突时 → 模型跟示例
```

> ⭐⭐⭐⭐⭐ **所以契约和示例打架，输的一定是契约。**

而且它不报错：契约是"要求"，示例是"示范"，
模型没有任何机制会把"示范不符合要求"识别为一个问题——它只会照着示范做。

## 3. ⭐⭐⭐⭐⭐ schema 在校验示例的复制品

这是本节最反直觉的一层，也是这份文档存在的理由。

通常的理解链条是：

```
契约 → 模型遵守 → 输出 → schema 校验 → 通过/失败
```

实际的链条是：

```
⭐⭐⭐⭐⭐ 示例 → 模型复制 → 输出 → schema 校验 → 通过
```

> ⭐⭐⭐⭐⭐ **schema 校验的那个输出，是示例的复制品。**

于是产生一个此前没人说过的后果：

| | 后果 |
|---|---|
| 示例符合契约 | schema 通过 ✅（但通过的是复制品，不是遵守） |
| ⭐⭐⭐⭐⭐ 示例不符合契约 | ⭐⭐⭐⭐⭐ **schema 失败，而失败的原因是示例，排查方向却是"模型没遵守"** |

第二种的代价不是"校验没拦住"，是⭐⭐⭐⭐⭐ **它让排查方向完全错误**——
作者会去加强契约（写得更细、加更多约束），
而契约从来不是问题所在：⭐⭐⭐⭐ **契约写得清清楚楚，是示例在反向教。**

判据一句话：**schema 报错时，先拿它去校验示例。**
示例自己都过不了，输出必然过不了，而改输出侧的每一次尝试都在改症状。

## 4. 三种不一致

| # | 类型 | 示例 | ⭐ 后果 |
|---|---|---|---|
| ① | 字段缺失 | 契约 5 个字段，示例给 3 个 | ⭐⭐⭐ 输出少字段（至少可见） |
| ② | 字段多余 | 示例给了契约没有的 `备注` | ⭐⭐⭐⭐ 输出多字段，下游忽略但不报错 |
| ③ | ⭐⭐⭐⭐⭐ 值域/语义不同 | 枚举写成自然语言、单位缺失、布尔写成"是/否" | ⭐⭐⭐⭐⭐ **可解析性丢失，且完全静默** |

**③ 最严重**，因为它正是"结构化 ≠ 正确"的反面：
《`skill-output/references/structured-output-pipeline.md`》讲
"schema 合规不保证值对"；本份讲⭐⭐⭐⭐⭐ **更前置的一层——
值根本进不了 schema，因为示例教的是自然语言值。**

典型形态：

```
契约：confidence ∈ {high, medium, low}
示例：confidence: 比较有把握        ← 模型照抄，输出不是合法值
下游：if confidence == "high"  → 永远不成立 → 静默走默认分支
```

⭐⭐⭐⭐⭐ **而没有任何环节报错**：JSON 解析通过、字段存在、
只是它的值不在枚举里，而枚举校验如果没有真的跑，就什么都不会发生。

附带一条同类：**单位**。契约写 `duration_ms`，示例写 `duration: 3`（意思是 3 秒）。
这与《`skill-interfaces/references/contract-evolution.md`》"改语义必须改字段名"同源，
只不过这里是⭐⭐⭐⭐⭐ **从第一版起就错了，而示例是唯一把这个错误固定下来的地方。**

## 5. 没有 schema 时，示例就是契约

多数技能没有 schema，这时示例承担了契约的全部职责——
而它是在没有任何声明的情况下承担的。

> ⭐⭐⭐⭐⭐ **作者以为"没有 schema"＝"输出格式灵活"，
> 实际是"输出格式由示例决定，且没有人知道"。**

这带来两条硬要求，缺一条就等于没有契约：

```
① ⭐⭐⭐⭐⭐ 示例必须包含全部字段（不能"省略显而易见的"）
② ⭐⭐⭐⭐⭐ 示例的值必须可解析（枚举值、带单位、带时区、布尔用 true/false）
```

第①条最常被违反：作者省略"显然会有"的字段，于是模型在它认为显然的地方也省略——
而⭐⭐⭐⭐ **两者的"显然"不是同一个集合**（这正是交接包里 failures 字段被省的机制）。

第②条的一条速判：**示例里的每个值，能否直接被 `json.loads` 之后拿来做比较？**
不能 ⇒ 下游解析不了，而它看起来是一份完整的输出。

## 6. 契约改了，示例没改

《`skill-examples/references/example-placement-and-rot.md`》讲示例会烂（标识符改名）。
这里是另一种，且更贵：

```
v2 契约：新增 required 字段 coverage
示例：   仍是 v1 的形状，没有 coverage
```

> ⭐⭐⭐⭐⭐ **契约变更是显式动作（改 schema、写 changelog），
> 示例更新不是——它不在任何 checklist 上。**

于是 v2 上线后，⭐⭐⭐⭐⭐ **示例仍在教 v1 的形状，而 skill 的 changelog 写着"已支持 coverage"**。
两个事实都对，输出里没有 coverage，而 schema 校验（如果真跑了）会失败——
失败报告会指向"模型没遵守契约"。

修法只有一条，但必须制度化：**改契约的同一个 commit 必须改示例**。
判据不需要判断力：⭐⭐⭐⭐⭐ **契约 diff 里出现字段增删时，示例 diff 不能为空**——
这条可以进 CI。

## 7. 自检

```
□ ⭐⭐⭐⭐⭐ 拿 schema 校验每个示例的输出，都通过吗？（首次约 50% 不通过）
□ ⭐⭐⭐⭐⭐ schema 报错时，先校验示例了吗？
□ ⭐⭐⭐⭐⭐ 示例里的枚举字段，值是合法枚举值而不是自然语言吗？
□ ⭐⭐⭐⭐⭐ 示例里的数字带单位/时区吗？
□ ⭐⭐⭐⭐ 示例包含契约里的全部字段吗？（没有 schema 时这条是硬要求）
□ ⭐⭐⭐⭐ 示例有契约里没有的字段吗？有 → 输出会多字段，下游静默忽略
□ ⭐⭐⭐⭐ 上次改契约的 commit 里，示例 diff 是空的吗？是 → ⭐⭐⭐⭐⭐ 示例在教旧契约
□ ⭐⭐⭐ 示例的值能 json.loads 后直接比较吗？
```
