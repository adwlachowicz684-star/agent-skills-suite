## 1. ⭐⭐⭐⭐⭐ 你想不出来

写 description 时，触发词部分的典型做法是**坐着想**：

```
"用户可能会说……'分析数据''做个报表''看看趋势'"
```

> ⭐⭐⭐⭐⭐ **这批词的特征是：书面、完整、礼貌、使用领域正确术语。**
> 而真实用户的输入是：**口语、残缺、带错别字、用错术语。**

这个偏差和我们已有的那条完全一致：

> ⭐⭐⭐ **"手动测试用自己的措辞"是最大的测试错误**——
> 请同事用他的原话测。

触发词是同一个问题的另一面：**你用作者的词汇去预测用户的词汇。**

三个具体的失效：

| 你想的 | 用户实际说的 |
|---|---|
| "生成季度销售报表" | "上季度卖得咋样" |
| "分析用户留存" | "为啥人都不来了" |
| "检查代码规范" | "这写的能过吗" |

## 2. ⭐⭐⭐⭐ 五个矿脉

按信噪比排序：

| # | 矿脉 | ⭐ 信噪比 |
|---|---|---|
| 1 | ⭐⭐⭐⭐⭐ **真实对话记录**（你或同事真问过的） | 最高 |
| 2 | ⭐⭐⭐⭐ 工单 / issue / 群聊原话 | 高 |
| 3 | ⭐⭐⭐ 搜索框历史（内部工具、文档站） | 中高 |
| 4 | ⭐⭐⭐ 新同事的问法（还没被术语同化） | ⭐ 中高，且不可替代 |
| 5 | ⭐⭐ 竞品/同行的说法 | 中低（会引入外部习惯） |

> ⭐⭐⭐⭐ **第 4 条值得单独说**：
> 老同事已经被同化，会不自觉使用"正确术语"。
> **新同事的问法里，藏着你已经听不见的那批词。**

而第 1 条的采集方式很简单：

```
回头翻你和 agent 的真实对话，把所有"第一次提出这个请求"的那句话抄下来。
```

## 3. ⭐⭐⭐⭐ 采矿的具体做法

**第一步：抄原话，不要改写**

```
✅ "上季度卖得咋样"
❌ "查询季度销售情况"（你改写了就失去了价值）
```

**第二步：按意图分组，不按字面**

```
"卖得咋样" / "业绩如何" / "这个月完成没" → 同一组
```

> ⭐⭐⭐ 分组的目的是看**哪一组原话最多**——
> 那组就是你 description 里必须出现的说法。

**第三步：挑代表性的一句进 description**

```
⭐ 每组最多挑一句，且挑⭐ 最有画面感、最不像文档的那句
```

## 4. ⭐⭐⭐⭐⭐ 用户的词 ≠ 你的词

三条必须记住的不对称：

**① ⭐⭐⭐⭐⭐ 用户不知道你的分类**

```
你说："数据异常检测"
用户说："这数不对吧"
```

**② ⭐⭐⭐⭐ 用户描述症状，不描述任务**

```
你说："生成复盘报告"
用户说："这次上线又出问题了"
```

> ⭐⭐⭐⭐ 这条最关键：**用户的第一句话常常是症状陈述，不是任务请求。**
> 所以触发词里应该有 ⭐ **症状类的说法**，而不只是任务类的。

**③ ⭐⭐⭐⭐ 用户用错术语，且不会纠正**

```
用户说"把这个表导出来"（其实他要的是转换格式）
```

> ⭐⭐⭐ 所以 ⭐ **错误的术语也要收**——
> 你收了它，才能在触发后把它纠正到正确的分支上。
> 不收它，用户就得到"没有相关技能"，然后自己去手工做。

## 5. ⭐⭐⭐⭐ 挑哪些：三个筛子

采集到的词不能直接全塞进去（会撑爆长度并扩大误触发），过三个筛子：

| 筛子 | 问题 |
|---|---|
| ⭐ 真实性 | 这句话真的有人说吗？（想出来的 → 淘汰） |
| ⭐⭐ 区分度 | 它会让别的技能也触发吗？（会 → 加限定或放弃） |
| ⭐⭐⭐ 覆盖率 | 加上它，能覆盖一类新情况吗？（不能 → 不值这个 token） |

> ⭐⭐⭐⭐ **第二个筛子直接连着我们已有的那条**：
> description 按碰撞风险分级——**你加的每个触发词都在改变碰撞风险。**
> 所以"加词"不是免费的，它同时提高召回和误触发。

配一条硬约束：**触发词占用 description 的比例不超过 1/3**，
其余留给 WHAT 和 NOT——否则它变成一个关键词袋，失去语义。

## 6. ⭐⭐⭐ 什么时候该停下来

采集是无底的，两个停止条件：

```
① ⭐ 连续 5 条新语料，没有产生新的关键词 → 饱和了
② ⭐⭐ 近命中负例的误触发率开始上升 → 已经加过头
```

> ⭐⭐⭐ 第二条是真正的停止信号：
> **误触发率上升说明你加的词已经开始侵入别人的地盘。**
> （这正是 `trigger-tuning-loop.md` 说的"加反触发"的时机。）

---

## 7. ⭐⭐ 常见错误

| 错误 | 后果 |
|---|---|
| ⭐⭐⭐ 只收"正确术语" | 覆盖不到真实输入 |
| ⭐⭐⭐ 把改写后的句子当原话 | ⭐ 采集失效，等于在想 |
| ⭐⭐ 触发词堆到占满 description | 变成关键词袋，语义丢失，误触发上升 |
| ⭐⭐ 只在建技能时采一次 | ⭐⭐⭐ 语言会漂移（新同事、新业务），要定期补 |
| 用英文语料推导中文触发词 | ⭐⭐⭐ 见 `localization-zh-adaptation.md`：本地化 ≠ 翻译 |

> ⭐⭐⭐ 第四条最容易被忽略：**触发词是有保质期的。**
> 建议每季度和"用户实际怎么问"对一次。
