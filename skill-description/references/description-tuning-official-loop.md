## 1. ⭐⭐⭐ 什么样的 query 才是好样本

**官方给出的正反例对比**（这组对照本身就很说明问题）：

```
❌ 坏："Format this data"
      "Create a chart"
   ⭐⭐ ⭐ 太泛，⭐⭐⭐ 测不出区分度

✅ 好："boss 发来 Q4 sales final FINAL v2.xlsx，
       利润 = 收入(C列) - 成本(D列)，加一列算出来"
   ⭐⭐⭐ ⭐ 带着⭐ 真实杂讯——文件名 · 列号 · 来龙去脉⭐ 全都有
      ⭐⭐⭐ ⭐⭐ 这才是⭐ 触发判断的试金石
```

> ⭐⭐⭐ **"带着真实杂讯"** 是本份最该记住的一条。
>
> 它与 `eval-case-design.md` 的"用反映你真实使用的脏输入，不是干净样例"、
> `outgrowth-regression-detection.md` 的"用你实际打出的半成品 message"
> ⭐⭐⭐ 是⭐ 第三个独立来源——
> **干净样例会让你高估触发率，而且高估多少你不知道。**

## 2. ⭐⭐⭐ 负例最有价值的是"近命中"

> ⭐⭐⭐ **不该触发的查询里，最有价值的是⭐ "近命中"样本：
> ⭐⭐ ⭐ 与技能共享关键词或概念，⭐⭐⭐ 但实际需要的是不同的东西。**

**官方特意提醒的一个反面做法**：

```
❌ 不要用"写个斐波那契函数"这种⭐ 明显无关的当负例
   ⭐⭐⭐ ⭐ 太简单，⭐⭐ 测不出误触发
```

> ⭐⭐⭐ 这条与我们已有的一条⭐ 强力互证：
> `examples-three-branches.md` 说 Pattern 类技能"⭐ 必须测 near-miss"，
> 因为"只测该识别的能识别不够，还要测不该识别的会被拒绝"。
>
> ⭐⭐ 两份独立来源，同一个词（near-miss / 近命中）。
> ⭐⭐⭐ 它们共同说明：**负例的难度才是评测的质量指标**——
> 一份全是"斐波那契"的负例集，等于没有负例集。

## 3. ⭐⭐⭐ 优化循环：60/40、跑 3 次、最多 5 轮

```
① ⭐⭐ 收集 ⭐ 20 个查询
② ⭐⭐⭐ ⭐ 按 60/40 切分为⭐ 训练集 / ⭐ 测试集
③ ⭐⭐ 评估当前描述
   ⭐⭐⭐ ⭐ 每个查询⭐ 跑 3 次拿⭐ 稳定触发率（单次有波动）
④ ⭐⭐ 让模型⭐ 基于失败样本提出改进
⑤ ⭐⭐ ⭐⭐⭐ 最多迭代 5 轮
```

**"跑 3 次"这条值得单独记**：

> ⭐⭐⭐ 触发是⭐ 概率性的，单次通过/不通过⭐ 不能作为判据。
>
> ⭐⭐ 与我们已有的 `assert-on-environment.md` 的 **pass^5** 同源——
> 只是这里更省（3 次），因为⭐ 触发判定的成本比完整执行低。
> ⭐⭐ 两者合起来是一套分级：**触发稳定性跑 3 次，执行正确性跑 5 次。**

**"最多 5 轮"是一条停止规则**：

> ⭐⭐ 这与"三次法则"、systematic-debugging 的三次修复规则同族——
> ⭐⭐⭐ **给迭代一个上限，否则它会变成撞墙**。

## 4. ⭐⭐⭐ 按测试集分数选，不按训练集

> ⭐⭐⭐ **"最终按⭐ 测试集分数而非训练集分数选最优描述——
> ⭐⭐⭐ ⭐ 防止过拟合到那 20 个查询上。"**

> ⭐⭐⭐ 这是本份最有价值的一条，也是⭐ 我们此前完全没覆盖的维度。
>
> 为什么这条容易被违反：⭐ 你会自然地在训练集上看到分数一路涨
> （因为每轮改进都是⭐ 针对训练集的失败样本提的），
> ⭐⭐ 但这个涨⭐ 很可能是记忆而非泛化。
>
> ⭐⭐⭐ 一个⏱ 低成本但高价值的检查：
> **如果你每一轮都在涨，要警惕——那正是过拟合的典型曲线。**

> ⭐⭐ 与我们已有的一条对照：
> `eval-loop-official.md` 说"两组都通过的断言没有区分度"——
> ⭐⭐ 两条都在说同一件事：**评测要能证伪。**
> 只不过一条针对断言，一条针对样本集。

## 5. ⭐⭐ 官方验证结果

```
Anthropic 在自己 ⭐ 6 个公开的文档类 skill 上验证
⭐⭐ ⭐ 5 个触发表现得到改善
```

> ⭐⭐⭐ 值得注意的分寸：**6 个里 5 个改善，不是 6 个。**
> ⭐⭐ 一个诚实的数字比"显著提升"更可信，
> 也说明⭐ **描述调优不是万能的——总有一个技能的瓶颈不在描述上。**

**配套的另一半**（触发之外的质量评测）：

```
⭐⭐ 带技能的运行与 baseline ⭐ 必须⭐ 同一轮同时启动，⭐⭐ 保证两边条件对等
⭐⭐ comparator agents 做⭐ 盲评 A/B：
   两个技能版本对打，或"有技能 vs 无技能"
   ⭐⭐⭐ 评审 agent ⭐ 不知道输出来自哪边，只判质量高低
```

> ⭐⭐ 这与 `comparator-ab-eval.md` 完全一致（第二个来源），
> ⭐⭐ 但补了一个⭐ 此前没写的具体约束：**同一轮同时启动**——
> 不能先用 baseline 跑一遍、再装技能跑一遍，因为⭐ 间隔里的环境变化会污染对比。

## 速查

```
□ ⭐⭐⭐ 正例要⭐ 带真实杂讯（文件名/列号/来龙去脉）；⭐⭐ 太泛的测不出区分度
□ ⭐⭐⭐ ⭐ 负例最有价值的是⭐ 近命中（共享关键词但需求不同）
   ⭐⭐⭐ ⭐ 别用"写个斐波那契"这种明显无关的——太简单，测不出误触发
□ ⭐⭐⭐ 循环：20 查询 → ⭐ 60/40 切分 → ⭐ 每查询跑 3 次 → ⭐ 最多 5 轮
□ ⭐⭐⭐⭐ ⭐ 按⭐ 测试集分数选，不按训练集（防过拟合到那 20 个）
   ⭐⭐ 一路在涨正是过拟合的典型曲线
□ ⭐⭐ 官方验证：6 个文档类 skill，⭐ 5 个改善（诚实数字）
□ ⭐⭐ A/B：⭐ 带技能与 baseline ⭐ 同一轮同时启动；评审盲评不知道来源
□ ⭐⭐ 分级：触发稳定性跑 3 次，执行正确性跑 5 次
```

**一句话**：

> ⭐⭐⭐ **官方调优循环是：20 个查询按 60/40 切分、每个查询跑 3 次拿稳定触发率、最多迭代 5 轮，且必须按测试集分数而非训练集分数选最优描述（否则只是把描述过拟合到那 20 个查询上）；样本的关键是——正例带真实杂讯，负例用"近命中"而不是明显无关的。**
