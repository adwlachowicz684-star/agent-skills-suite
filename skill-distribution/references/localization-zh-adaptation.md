## 1. ⭐⭐⭐⭐⭐ 本地化 ≠ 逐句翻译

> ⭐⭐⭐⭐⭐ **"⭐ 本项目⭐ 不以⭐ 逐句翻译 ⭐ 为目标，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而是⭐ 让 Skill ⭐ 更容易⭐ 被中文用户⭐ 自然触发，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 并在⭐ 中文开发、办公和内容场景⭐ 中⭐ 给出⭐ 可执行结果。"**

```
❌ 逐句翻译：把 description 从英文译为中文
✅ 本地化  ：让中文用户 ⭐ 用他们本来会说的话 ⭐ 就能触发它
```

> ⭐⭐⭐⭐⭐ 这个区分⭐ 极其重要，⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 它⭐ 直接命中了⭐ 我们⭐ 反复强调的⭐ 那条：
> ⭐⭐⭐⭐⭐ **"description ⭐ 必须含⭐ 用户⭐ 实际会说的⭐ 关键词"**——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 而⭐ "用户实际会说的话"⭐ 在⭐ 另一种语言里⭐ 不是⭐ 翻译出来的，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 是⭐ 重新采集的。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 一个⭐ 译得再准的 description，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 如果⭐ 用的⭐ 是⭐ 中文里⭐ 没人会说的⭐ 说法，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ 它⭐ 的⭐ 触发率⭐ 就是零。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 与 `trigger-tuning-loop.md` 那条
> "⭐ 漏触发的根因是⭐ 太具体 / ⭐⭐⭐⭐⭐ ⭐⭐⭐ 缺用户实际用词"⭐ 是⭐ 同一条，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 只不过⭐ 这里⭐ 缺的⭐ 是⭐ 一整个语言⭐ 的用词。

## 2. ⭐⭐⭐⭐⭐ 三层适配

```
① ⭐⭐⭐⭐⭐ 中文触发适配
   ⭐⭐⭐⭐⭐ ⭐ 覆盖：⭐ 正式表达 · ⭐ 口语 · ⭐ 中文文件名 · ⭐⭐⭐⭐⭐ ⭐⭐⭐ 隐含任务意图
② ⭐⭐⭐⭐⭐ 中文场景适配
   ⭐⭐⭐⭐⭐ ⭐ 典型场景：⭐ 周报 · ⭐ 方案评审 · ⭐ 中文合同 · ⭐ 数据台账 · ⭐ 技术汇报
③ ⭐⭐⭐⭐⭐ 中文 few-shot
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 提供：⭐ 真实中文输入 · ⭐ 可检查输出 · ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 容易误触发的相邻反例
```

> ⭐⭐⭐⭐⭐ 三层里⭐ 最值得⭐ 单独⭐ 拎出来的⭐ 是⭐ 第 ① 层里的⭐ 两项，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 它们⭐ 在⭐ 英文技能里⭐ 几乎⭐ 从不会出现：
>
> **「中文文件名」**
> ```
> 中文用户的请求里常带中文文件名：
>   "帮我整理一下 2026年第三季度财务报表.xlsx"
>   "看看 产品需求文档-v3.md 有没有问题"
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 技能的示例与触发词⭐ 必须⭐ 能容纳⭐ 中文文件名
> ```
>
> **「隐含任务意图」**
> ```
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 中文表达常不直接说出动作：
>   "这个月的数据有点乱"     → 隐含"整理/核对/清洗"
>   "领导明天要看"           → 隐含"生成汇报材料"
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ → ⭐⭐⭐⭐⭐ ⭐⭐⭐ 只写显式动作词的 description ⭐ 抓不到这些
> ```
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 而⭐ 第 ③ 层里的⭐ **"容易误触发的相邻反例"**
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 与⭐ 我们已有的⭐ `eval-case-design.md`
> "⭐ 负向用例⭐ 比正向⭐ 更值钱"⭐ 以及⭐ `description-tuning-official-loop.md`
> "⭐ 负例要用⭐ 近命中，⭐⭐⭐⭐⭐ ⭐⭐⭐ 别用明显无关的"⭐ 完全同源——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ **三个来源⭐ 都在强调⭐ 同一件事：⭐⭐⭐⭐⭐ ⭐⭐⭐ 负例必须"近"。**

## 4. ⭐⭐⭐⭐⭐ 一个通用推论：触发是语言相关的

> ⭐⭐⭐⭐⭐ **"⭐ 技能⭐ 的 ⭐ 触发能力 ⭐ 不是 ⭐ 跨语言的。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐ 一份⭐ 为英文语境⭐ 调好的 description，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 搬到中文语境⭐ 不会因为⭐ '语义相同' ⭐ 而 ⭐ 保持同样的触发率。"**

```
⭐⭐⭐⭐⭐ 推论一：⭐⭐⭐⭐⭐ ⭐⭐⭐ 换语言 = ⭐⭐⭐⭐⭐ ⭐⭐⭐ 必须重新采集触发词，不是翻译
⭐⭐⭐⭐⭐ 推论二：⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 混合语料（中英夹杂）是一种真实输入形态，要专门覆盖
⭐⭐⭐⭐⭐ 推论三：⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 评测集也必须本地化——
              ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 用英文 query 测出的触发率⭐ 不代表中文表现
```

> ⭐⭐⭐⭐⭐ 推论三⭐ 尤其⭐ 关键，⭐⭐⭐⭐⭐ ⭐⭐⭐ 因为⭐ 它⭐ 与⭐ 我们已有的⭐ 一条⭐ 直接咬合：
> ⭐⭐⭐⭐⭐ **"⭐ 用⭐ 反映你真实使用的⭐ 脏输入，⭐ 不是干净样例"**
> （`outgrowth-regression-detection.md`）——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 而⭐ "脏" ⭐ 在⭐ 中文场景里⭐ 首先就包括 ⭐ **中英夹杂**。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 我们此前⭐ 记过的⭐ "⭐ 覆盖口语/书面/带错别字/中英夹杂"
> （`description-tuning-official-loop.md`）⭐ 也⭐ 正是指⭐ 这一点。
>
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 而⭐ 一个⭐ 更进一步的⭐ 观察：
> ⭐⭐⭐⭐⭐ **本土化版本⭐ 会⭐ 新增⭐ 上游没有的⭐ 任务路由**
> （该项目⭐ 就新增了"旧客服 Prompt 清理"和"模型迁移后审计"两个⭐ 真实任务路由）——
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ 因为⭐ 有些需求⭐ 是⭐ 场景特有的，
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ ⭐⭐⭐⭐ 它⭐ 在上游语境里⭐ 根本不存在。
> ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 这⭐ 也⭐ 说明：⭐**本地化⭐ 不只是适配，⭐⭐⭐⭐⭐ ⭐⭐⭐ 也可能是⭐ 增量创造。**

该项目列出了⭐ 四类⭐ 持续验收项，⭐⭐⭐⭐⭐ ⭐⭐⭐ 其中⭐ 两项⭐ 是⭐ 我们⭐ 已有清单里⭐ 没有的：

## 速查

```
□ ⭐⭐⭐⭐⭐ 本地化 ≠ 逐句翻译：⭐ 目标是"用中文用户本来会说的话就能触发"
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ "用户实际会说的话"在另一种语言里是重新采集的，不是翻译的
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 译得准但用的是没人会说的说法 = 触发率为零
□ ⭐⭐⭐⭐⭐ 三层适配：⭐⭐⭐⭐⭐ ⭐⭐⭐ 触发（正式/口语/中文文件名/隐含意图）
   ⭐⭐⭐⭐⭐ ⭐⭐⭐ 场景（周报/方案评审/中文合同/数据台账/技术汇报）
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ few-shot（真实中文输入 + 可检查输出 + ⭐⭐⭐⭐⭐ ⭐⭐⭐ 容易误触发的相邻反例）
□ ⭐⭐⭐⭐⭐ 两项英文技能里几乎不出现的：中文文件名 · ⭐⭐⭐⭐⭐ ⭐⭐⭐ 隐含任务意图
   "这个月的数据有点乱"→整理/核对/清洗；"领导明天要看"→生成汇报材料
□ ⭐⭐⭐⭐⭐ 上游同步分层：⭐ 脚本/安全修复/许可证/事实性参考 → 忠于官方
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐ 触发词/场景示例/few-shot → 保持本地
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐ lockfile 管"取哪个版本"，这份清单管"哪些不跟着版本走"
□ ⭐⭐⭐⭐⭐ 触发是语言相关的：换语言必须重新采集触发词
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 评测集也必须本地化——⭐⭐⭐⭐⭐ ⭐⭐⭐ 英文 query 测出的触发率不代表中文表现
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐⭐ ⭐⭐⭐ 本土化可能新增上游没有的任务路由（场景特有需求 = 增量创造）
□ ⭐⭐⭐⭐ 持续验收四项：frontmatter · 插件清单 · ⭐⭐⭐⭐⭐ 同步基线 · ⭐⭐⭐⭐⭐ 中文触发评测集
   ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ 合起来 = 结构/来源/行为 三段，对应 L1/治理/L2
```

**一句话**：

> ⭐⭐⭐⭐ **本地化不是逐句翻译而是让中文用户用本来会说的话就能触发——"用户实际会说的关键词"在另一种语言里必须重新采集而非翻译，且评测集也要一并本地化，因为英文 query 测出的触发率不代表中文表现；上游同步时分清"脚本与安全修复忠于官方、触发词与示例保持本地"。**
