# 技能包：让技能集变成可寻址的产物

> 一个"包"就是一个有名字、可安装、可更新的技能集合。
> ⭐ **但"可安装"不等于"可固定、可复现、可评审"。**

## 什么时候才需要包

先泼一盆冷水：**单个团队在单个仓库里，几个 markdown 文件的版本管理、评审、回滚，git 已经全给了**。
这时候加一层包机制，只是多了一条分发渠道，**没有减少任何工作量**。

真正值得上包的信号：

```
□ 多个仓库 / 多个开发者需要同一套技能
□ ⭐ 而且各处的副本已经漂移开了
```

三个决定它是否回本的条件：

```
① 有唯一的所有者，决定包里有什么、什么时候变
② ⭐ 每次安装都能解析到一个 tag 或 commit
   ——更新是"某人做出的决定"，而不是"某天发生的事件"
③ 包保持小
   ——⭐ 装进去的技能数量本身会拉低 agent 表现
```

## 两条路线的能力对照

| 属性 | skills.sh CLI | Claude Code plugin marketplace |
|---|---|---|
| 版本身份 | **无**（锁里存来源 + 内容哈希） | **有**：plugin.json → marketplace 条目 → commit SHA |
| pin 方式 | 可选 `ref`（分支会漂，tag/SHA 不动） | `source.sha` |
| 更新检测 | 重算目录哈希，与存储值比对 | 解析版本命中缓存则跳过更新 |
| 从记录恢复 | ⚠️ 缺失（issue #549 仍开着） | 从 marketplace 条目重装 |
| 组织级白名单 | ⭐ **CLI 文档中没有** | `strictKnownMarketplaces`（受管设置） |

Vercel 于 **2026-08-04** 上线 packs：
一个包持有公开或私有技能，有自己的 registry URL，
`npx skills add https://skills.sh/p/` 安装，
可分享给"任何人，或你的 Vercel 组织，以便统一团队各项目使用的技能"。

⚠️ 但要清楚它的边界：**它把技能集变成了可寻址的产物，
但没有把它变成可以依赖、可固定、可评审的依赖项。**

## 版本身份才是关键

Claude Code 插件系统的因果链写得很直白：

```
插件的解析版本决定：
  ├─ 缓存路径
  └─ 更新检测（解析版本与已有的一致 → /plugin update 与自动更新跳过）

解析顺序回退链：
  plugin.json → marketplace 条目 → commit SHA
```

这条链的价值在于：

> ⭐ **身份不变 → 任何机器上都不产生变化；
> 身份变了 → 所有机器在发布者选定的同一时刻产生同一变化。**

这就是为什么 `source.sha` 值得 pin ——
它冻结的就是这个身份。

skills.sh 那条路线用较弱的部件追求了同样的效果：
`npx skills update` 在已存的 ref 上重新拉取、重算目录哈希、不一致才重装。
所以 **tag 或 SHA 能 pin，分支不能**。

> **没有这层身份，包就只是一次下载，
> 它的 update 命令就是"拉当下有的东西"。**

## 锁文件里有什么

`skills-lock.json` 的一个条目结构：

```json
{
  "source": "...",
  "sourceUrl": "...",
  "ref": "...",
  "sourceType": "...",
  "skillPath": "...",
  "computedHash": "SHA-256，覆盖技能目录下每一个文件",
  "subagents": "...",
  "wellKnownDigest": "..."
}
```

两点：

- ⭐ `computedHash` 是**整个目录**的 SHA-256，不只是 SKILL.md
  ——所以 `scripts/` 被偷换也能被发现
- ⚠️ **从锁文件恢复项目的命令仍缺失**（vercel-labs/skills#549 仍 open；
  把 restore 命令从 `experimental_install` 提升为 `install`/`ci` 的 PR #564 未合并）

也就是说：**锁能验，不能装**。这个缺口在 CI 里尤其难受。

## 三个会翻车的用法

**① 为了"统一团队标准"批量装一个大包**

```
包里每个技能都会进入选择池，不管有没有人调用它
→ 参见 `skill-selection` 的 `library-size-effect.md`
```

**② 把降级怪到上下文窗口头上**

```
⭐ 技能遮蔽最多占 68%，且是唯一置信区间排除零的成分
   上下文开销在任何库规模下都与零无显著差异
→ 裁剪包有用；换大窗口没用
```

**③ 把"进入 registry"当成"已经过审"**

```
上架 ≠ 审核
审核发生在上架那一刻，不是你安装的那一刻
→ 参见 `skill-governance` 的 `marketplace-security.md`
```

## 一条实操建议

如果你的工具链**既有 marketplace 又有锁文件**（ClawHub 是唯一同时具备的），
优先走那条路——版本身份 + 内容哈希 + 可复现安装，三者缺一都会在某天咬你。
