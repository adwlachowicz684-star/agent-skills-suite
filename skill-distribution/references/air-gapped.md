## 最关键的一行配置

```yaml
models:
  primary: ollama/llama4-scout
  fallback: ollama/qwen3:8b
  cloud_fallback: false      # ⭐ 最关键的一行
network:
  mode: "offline"
  dns_resolution: false
  gateway:
    bind: "loopback"
security:
  sandbox:
    mode: "all"
  tools:
    deny: ["group:web", "group:api"]
```

> ⭐ **`cloud_fallback: false` 是最重要的一行。**
> 没有它，本地模型返回低置信度响应时，系统会**尝试访问云端 API**——
> 产生连接超时错误污染日志，**并可能触发安全监控告警**。

> 这也呼应 `skill-crafting` 的 `error-handling.md`：
> **失败回退路径本身要显式声明，不能靠默认行为。**

## 模型选择是单向决策

> ⭐ **在 air-gapped 环境里，你无法按需拉取新模型来试。**
> **在烧掉传输份额之前就要选好。**

**生产环境的硬件下限**（实测参考）：

| 模型 | 内存 | CPU / GPU |
|---|---|---|
| Llama 4 Scout (Q4) | 32 GB RAM | 8 核，或 24GB VRAM（RTX 4090 / A5000） |
| Qwen3 8B | 16 GB RAM | 4 核（Apple M3 Pro 统一内存可跑） |
| DeepSeek Coder V2 16B | 24 GB RAM | 或 16 GB VRAM |

**速度预期**：

```
消费级硬件 15–60 tokens/秒（取决于模型大小与量化）
参考：RTX 4090 上跑 Llama 4 Scout，
      一封邮件草稿 3–5 秒
      ⭐ 交互式够用，但明显慢于云端 API
```

**分工建议**：

```
通用任务  → 广谱模型（Llama 4 Scout 级）
代码任务  → 专用代码模型（DeepSeek Coder 级）
⭐ 用模型路由配置把两类任务分开
```

> 呼应 `skill-governance` 的 `cost-control.md` 的模型路由：
> **分层路由在任何环境都成立，只是离线时"便宜档"变成了"本地小模型"。**

## 技能依赖必须打包时带上

> ⭐ **一条铁律：每个外部依赖都必须在传输时捆绑好。**
> **运行时不 `npm install`，不拉取任何包。**

```
□ 把技能的 node_modules 与技能代码一起打包
□ 放进 sneakernet 归档
□ ⭐ 离线环境里"稍后安装"等于"永远不可用"
```

> 呼应 `packaging.md` 的 provenance 与 `skill-scripting` 的 `script-engineering.md`
> 的 PEP 723 内联依赖——**自包含在离线场景从"推荐"升级为"必需"**。

## 改指向内部服务

> 生态里大量技能依赖互联网（网页抓取、API 集成、云存储连接器）。
> **在 air-gapped 环境里它们根本不会工作。**

**改写方式**：

```
邮件技能      → 指向内部 Exchange 服务器或本地 Postfix 中继
知识库技能    → 指向本地 ChromaDB 实例，
               嵌入由同机 Ollama 上的 nomic-embed-text 生成
```

**离线优先的技能自身该做的**（可作为技能模式抄）：

```
□ 启动时检测本地服务状态与网络连通性
□ 持续监控 GPU / CPU / 内存占用
□ 按任务动态选择本地模型（通用 vs 代码专用）
□ ⭐ 模型失败或服务挂起时自愈：
   重启服务 / 切到备用模型 / 高内存时清理缓存
□ 持续输出状态与健康指标
```

**监控频率参考**（一个成熟实现的数据 Schema）：

```
模型状态    每 30 秒
延迟指标    每 1 分钟
资源占用    每 5 分钟
错误日志    实时（含回退与自愈触发事件）
```

## 数据治理：air-gap 不等于可以粗心

> ⭐ **促使你做 air-gap 的那套数据治理，必须延伸到 agent 如何存储会话数据、日志与记忆。**

**会话记录**：

```
每次交互都记到 sessions/*.jsonl
⚠️ 在涉密环境里，这些记录包含的正是 air-gap 要保护的那些数据
→ ⭐ 会话存储的密级必须与源数据同级
→ 文件系统加密（LUKS / FileVault）
→ 内置 AES-256-GCM 静态加密是第二层，
  但它防的是文件级提取，⭐ 防不住整盘镜像
```

**记忆持久化**：

```
□ 跨会话记忆不能同步到任何云服务 → memory.sync: "local"
□ 记忆存储必须位于加密的本地存储
□ ⭐ 按保留策略定期审计记忆内容，清理该清除的
```

**数据主权核查清单**：

```
□ 无 API 调用离开本地网络（用网络监控验证）
□ 所有模型本地提供（无云端模型回退）
□ 嵌入生成在本地（不用云端 embedding API）
□ 向量库运行在本地基础设施
□ 审计日志存本地
□ 模型更新遵循审批流程（不自动下载）
```

## 自检清单

```
□ cloud_fallback 是否显式设为 false？
□ 网络模式、DNS、网关绑定是否已锁死？
□ 工具是否已 deny 掉 web / api 组？
□ 模型是否在断网前就拉取完毕（单向决策）？
□ 硬件是否满足所选模型的下限？
□ ⭐ 所有技能依赖是否已在传输时打包？
□ 依赖外部服务的技能是否已改指向内部服务？
□ 会话日志的密级是否与源数据同级？
□ 存储是否已加密（并知道内置加密防不住整盘镜像）？
□ 记忆同步是否设为 local？
□ 是否有按保留策略的记忆审计？
□ 模型更新是否有审批流程（不自动下载）？
□ 是否用网络监控验证过"确实没有外联"？
```
