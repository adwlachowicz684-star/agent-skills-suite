## 1. 三种粒度

| 粒度 | 下游拿到什么 | 占上下文 | ⭐ 失败形状 |
|---|---|---|---|
| ⭐ 内容内联 | 全部原始内容 | ⭐⭐⭐⭐⭐ 全部 | 挤掉别的指令 |
| ⭐⭐⭐⭐ 引用 | 路径 / ID / 游标 | ⭐ 几十 token | 取不到、取到旧的 |
| ⭐⭐⭐⭐⭐ 摘要 | 压缩后的结论 | ⭐⭐ 几百 token | ⭐⭐⭐⭐⭐ 丢了下游要的那一条，且下游不知道 |

> ⭐⭐⭐⭐ 三者不是"选一个"，是⭐⭐⭐⭐⭐ **引用 + 摘要** 的组合——
> 摘要让它知道值不值得取，引用让它能取到全量。
> 只有摘要没有引用，下游无法验证；只有引用没有摘要，下游不知道该不该取。

## 2. ⭐⭐⭐⭐⭐ 默认是内联，而默认是错的

不写粒度时，模型默认把上游输出整段带进下一步。原因很实在：

> ⭐⭐⭐⭐⭐ **"把结果传给下一个"这句话的默认实现，就是把结果放在上下文里**——
> 因为上下文是它唯一确定能传东西的地方。

代价不是线性的，因为压缩取的是开头：

> ⭐⭐⭐⭐⭐ 挤掉的不是"一些 token"，是⭐⭐⭐⭐⭐ **更早的指令**。
> 而压缩带回的是"开头 5000"，不是"最重要的 5000"——
> 被挤出去了，就真的回不来了。

那起最典型的事故：抓取脚本把原始网页全文直接返回，3 万字进上下文，模型中途丢掉关键任务指令，
转头问用户"你在等什么"。修复后 3 万字 → 不到 2000 字符，**而且回复质量反而更高**——
噪音本身就在损害质量。

> ⭐⭐⭐⭐ 正确的形态是：**脚本写文件，只回传路径 + 摘要**。
> 这也顺带解释了"脚本源码不进上下文、输出进"那个不对称——
> ⭐⭐⭐⭐⭐ 输出也不必全进，只有**需要被模型判断的那部分**该进。

## 3. ⭐⭐⭐⭐⭐ 摘要是最危险的一档

内联太大是可见的问题（慢、超窗口、回答变差），引用失效至少会报错。
⭐⭐⭐⭐⭐ **摘要是唯一一种"看起来完美、实际丢了东西、且不报错"的粒度。**

> ⭐⭐⭐⭐⭐ 根因：**摘要是被上游决定"什么重要"的结果，
> 而上游不知道下游要什么。**

这个错位是结构性的，不是写摘要的人不认真：

```
上游认为重要的：总体趋势、异常点、结论
下游实际需要的：某个特定字段的逐条原始值
```

于是下游拿到一份读起来很专业的摘要，缺的那一列它不知道缺了。
而它不会报错——**它的输入格式完全正确、内容完全自洽**。

三条必须随摘要一起传的东西：

```
① ⭐⭐⭐⭐⭐ coverage（这份摘要覆盖了多少原始内容：1200 条里的 1200 条？还是 200 条？）
② ⭐⭐⭐⭐⭐ retrieval（怎么取回全量：路径 / ID / 查询参数）
③ ⭐⭐⭐⭐⭐ dropped（摘要过程中明确丢弃了什么，而不是"没提的就是不重要"）
```

> ⭐⭐⭐⭐⭐ 第 ③ 条最容易被省，也最不可替代：
> 没有它，"没提到"会被下游读成"没有"——⭐⭐⭐⭐⭐ **而"无"和 0 是最危险的占位符。**

## 4. 引用的三种失效

引用便宜，但它会失效，而且三种失效方式完全不同：

| 失效 | 表现 | ⭐ 关键 |
|---|---|---|
| ⭐⭐⭐⭐ 取不到 | 404 / 权限不足 | ⭐⭐⭐⭐ 至少会报错 |
| ⭐⭐⭐⭐⭐ 取到旧的 | 路径存在但内容过期 | ⭐⭐⭐⭐ **不报错**（与"用文件存在判断做过"同构） |
| ⭐⭐⭐⭐⭐ 取到别的 | run-id 碰撞 / 路径被复用 | ⭐⭐⭐⭐⭐ 内容格式完全正确，是另一次运行的 |

> ⭐⭐⭐⭐⭐ 中间那一条最需要防：引用必须自带新鲜度判据，
> 读取方必须校验，而不是"能读就信"。

判据很省：**引用里带 run-id 或写入时间戳，读取方比对。**
这与 `skill-execution/references/intermediate-artifacts.md` 的两条规则是同一套——
那份管单个技能内的中间产物，这份管跨技能交接，**两边都要做，缺一边另一边就白做了**。

## 5. ⭐⭐⭐⭐⭐ 判据与检查

一个问题决定粒度：

> ⭐⭐⭐⭐⭐ **下游需要的是"全部细节"，还是"能自己取到全部细节"？**
> 是后者 → 引用 + 摘要就够了。绝大多数情况都是后者。

三条自检：

```
① 交接内容超过 ~500 token 且下游只会用到其中一部分 → 改引用 + 摘要
② ⭐⭐⭐⭐⭐ 摘要里没有 coverage / retrieval / dropped → 摘要不完整，下游无法验证
③ 引用里没有 run-id 或时间戳 → 取到旧数据的风险敞口是开的
```

> ⭐⭐⭐⭐⭐ 第 ② 条可以直接变成 lint 规则：
> 交接包里出现 `summary` 字段但没有 `coverage` 或 `retrieval`，就报错。
> 这与"禁令要带替代方案"是同一思路——**要求"传摘要"必须同时要求"传怎么验证摘要"。**

最后一句：

> ⭐⭐⭐⭐⭐ **粒度的本质是"下游能不能验证上游"。**
> 内联能验证但太贵，引用便宜但要防旧，摘要便宜且不可验证——
> 所以摘要必须被强行补上可验证性，否则它就是把静默失败打包成了一个漂亮的结论。
