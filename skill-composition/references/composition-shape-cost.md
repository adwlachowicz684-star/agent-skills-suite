## 1. 四种形态不是四种能力，是四条代价曲线

| 形态 | 结构 | 典型收益 |
|---|---|---|
| 顺序链 | A → B → C | 步骤清晰、易理解 |
| 扇出扇入 | A → {B,C,D} → 汇总 | ⭐ 快 |
| 条件分支 | 按输入选一条 | 省掉无关步骤 |
| 流水线 | 每级产出一个产物 | 产物可复用、可重放 |

常见误判是把这张表当成"能力递增"的阶梯——于是"用上扇出"被当成进阶。

> ⭐⭐⭐⭐⭐ **这四种形态的能力是一样的：都能完成同一件事。差别只在代价与失败的形状。**
> 所以选型问题不是"哪个更强大"，是 ⭐⭐⭐⭐ **"哪一条代价曲线我付得起、哪一种失败我看得见"**。

## 2. 五维代价表

| 形态 | 可靠性 | ⭐ 失败可见性 | 延迟 | 上下文 | 调试成本 |
|---|---|---|---|---|---|
| 顺序链 | pⁿ | ⭐⭐⭐⭐ **高**（会卡住） | Σ | ⭐⭐ 累积产物 | O(log n) |
| ⭐ 扇出扇入 | ⭐ **pⁿ⁺ᵏ**（最差） | ⭐ **低**（少一路） | max | ⭐⭐⭐⭐ 可控（只回传摘要） | ⭐ O(k) |
| 条件分支 | p（只走一条） | ⭐⭐ 低（走了默认分支） | 单条 | 最低 | ⭐⭐ 中（要先确定走的哪条） |
| 流水线 | pⁿ | ⭐ 最低（错误被逐级改写） | Σ | ⭐ 累积产物 + 每级文件 | O(n) |

三处需要解释：

- 条件分支的可靠性看起来最好（只走一条），代价是⭐⭐⭐⭐ **未覆盖的输入会静默落进默认分支**——它的失败不在"跑砸了"，在"跑错了分支且分支本身成功"。
- 流水线的可见性最低，因为⭐⭐⭐⭐⭐ **每一级都真的成功了**，只是成功在错误的输入上。
- ⭐⭐⭐⭐⭐ **可靠性最低的形态不是可见性最低的形态**——顺序链可靠性一般但失败会卡住，扇出扇入可靠性更差且失败不卡住。

## 3. ⭐⭐⭐⭐⭐ 可靠性：指数是"组件数"，不是"链长"

同样三个业务步骤：

```
顺序链    A → B → C          = 3 个组件  → p³
扇出扇入  A → {B,C,D} → 汇总  = 5 个组件  → p⁵
```

> ⭐⭐⭐⭐⭐ **汇总本身是一个组件，而它几乎从不出现在架构图上。**

p = 0.95 时：3 环 0.857，5 环 0.774。组件数从 3 到 5，**可靠性掉 8 个点，换来的只是延迟**。

而且汇总这个组件有个特殊性：

> ⭐⭐⭐⭐⭐ **它是唯一一个"把所有分支的结果放在一起"的组件——
> 前面每一路的失败都必须经过它才能被发现。它是单点。**

推论：扇出扇入不是"更先进"，是⭐⭐⭐⭐⭐ **用可靠性换延迟，而换掉的那一段恰恰是曲线最陡的部分**（指数增长区）。所以只有在延迟真的是瓶颈时才该升级。

## 4. ⭐⭐⭐⭐⭐ 可见性：与可靠性不一致的那一列

| 形态 | 失败时长什么样 | 有错误信号吗 |
|---|---|---|
| 顺序链 | 卡在某一步 | ✅ 有——下游拿不到输入，或报错 |
| ⭐ 扇出扇入 | 少了一路 | ❌ 没有——其余路都成功，汇总照常完成 |
| 条件分支 | 走了另一条 | ❌ 没有——那条分支本身是成功的 |
| 流水线 | 错误被逐级改写 | ❌ 没有——每级都真的完成了工作 |

> ⭐⭐⭐⭐⭐ **"会卡住"是一种被严重低估的优点。**

顺序链的失败是"停下来了"，于是有人看见、有人来问、有人去修。扇出扇入的失败是"完成了，只是少了一路"——⭐⭐⭐⭐⭐ **没有任何组件处于错误状态，于是没有任何机制会触发排查**。

这也是为什么升级形态前必须先有覆盖率字段：

> ⭐⭐⭐⭐⭐ **覆盖率是扇出扇入唯一的人工心跳。没有它，这个形态的失败在运行期完全不可观测。**

## 5. 延迟：把和变成 max

```
顺序链：t_A + t_B + t_C
扇出：  t_A + max(t_B, t_C, t_D)
```

收益是真的，但两个常被忽略的细节：

**① 收益取决于方差，不取决于路数。** 三路耗时接近时收益接近 3 倍；一路特别慢时，⭐⭐⭐⭐ **max 就是那一路，并行等于没并行**——而"有一路特别慢"恰恰是常态（它通常是数据最多的那一路）。

**② 扇入必须等最慢的一路。** 于是⭐⭐⭐⭐ **总延迟由最慢的分支决定，而最慢的分支通常是失败或重试的那一路**——也就是说，出问题时并行不省时间，只是把等待变得不可见。

## 6. 上下文：顺序链累积产物，扇出只回传摘要

顺序链里，每一级的输出都留在上下文里供下一级使用；累加下来，⭐⭐⭐⭐ **走完 n 级，上下文里有 n 份产物**。

扇出扇入可以只回传摘要或路径：

```
分支输出 → 写文件 → 回传 {path, 摘要, coverage}
```

> ⭐⭐⭐⭐⭐ **所以扇出扇入在上下文这一维反而更省——前提是分支真的只回传摘要。**
> 若分支把完整结果回传，你同时付了可靠性的代价和最差的上下文代价。

## 7. ⭐⭐⭐⭐⭐ 调试成本：二分定位只在顺序链上成立

`chain-failure-localization.md` 给的"从后往前二分"有个隐含前提：**失败沿一条线传播，存在一个断点**。

| 形态 | 定位复杂度 | 为什么 |
|---|---|---|
| 顺序链 | ⭐ O(log n) | 有一个断点，可二分 |
| ⭐ 扇出扇入 | ⭐⭐⭐⭐⭐ O(k) | ⭐⭐⭐⭐⭐ **失败可能同时在多路，没有"一个断点"** |
| 条件分支 | ⭐⭐⭐ 先定分支再加 O(log n) | 多一步：确定走的是哪条 |
| 流水线 | O(n) | 每级的产物都在，可以逐级比对 |

> ⭐⭐⭐⭐⭐ **二分在并行下失效，因为二分假设"错误是单点"；而并行的典型失败是多点各缺一块。**

所以扇出扇入的排障成本不只是更高，而是⭐⭐⭐⭐ **性质变了**：从"找断点"变成"逐路检查"。而逐路检查的前提是先知道路数（k）与每路的状态——这正是覆盖率字段。

## 8. ⭐⭐⭐⭐⭐ 迁移路径：升形态必须同时升可观测性

```
单技能 ──→ 顺序链      当：2 个技能且顺序必须强制
顺序链 ──→ 扇出扇入    当：各路真正独立 ⭐ 且已经能报覆盖率
扇出扇入 ──→ 流水线    当：中间产物需要被沉淀、被重放
```

> ⭐⭐⭐⭐⭐ **升形态而不升可观测性 = 把失败从"可见"搬到"不可见"。**

顺序链的失败会卡住（你能看见），扇出的失败不卡住（你看不见）——所以"升级形态"的实际含义是⭐⭐⭐⭐⭐ **用可见性换延迟**。这是一笔可以做的交易，但必须知道自己付了什么。

三条准出条件（升到扇出之前必须满足）：

```
① ⭐⭐⭐⭐⭐ 覆盖率字段已存在且被读取（不是写了没人读）
② ⭐⭐⭐⭐⭐ partial 能透传到最终输出，不被加工成"完整"
③ ⭐⭐⭐⭐ 顺序敏感性测试已跑过（A→B 与 B→A 结果一致）
```

**反向迁移同样重要**：当可观测性投入跟不上时，⭐⭐⭐⭐ **退回顺序链是正确选择**——它慢，但它的失败会卡住，而"卡住"是最便宜的告警。

## 9. 自检

**① 把其中一路改成失败，跑一次。**
输出有任何变化吗？没有 → 覆盖率字段不存在，或存在但没人读。这个测试 30 秒，能一次性验证扇出形态是否可观测。

**② 数一下架构图上的组件数，再数实际被调用的组件数。**
差的那些就是被忽略的——通常是：汇总节点、校验节点、重试包装。**每差一个，可靠性指数就多一位，而你算的是少的那个。**

**③ 把最慢的一路单独跑一次，记下耗时。**
它接近并行总耗时的多少？接近 → 你的并行没有省时间，只是把等待藏起来了。

**④ 关掉覆盖率字段跑一次，看有没有人发现。**
没人发现 → 这个字段是装饰；⭐⭐⭐⭐⭐ **契约写在文件里 ≠ 契约在运行**（与"删字段测试"同构）。
