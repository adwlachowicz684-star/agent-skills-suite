## 1. ⭐⭐⭐⭐⭐ 无界循环是最贵的 bug

> ⭐⭐ **每一个生产 agent 都需要预算与停止条件。**

这句话值得注意的是它的语气：**不是"建议加"，是"必须有"。**
而我们多数技能里只有一条"如果失败就重试"——
那等于给了模型一个没有出口的许可。

与我们已有内容的分工：

| 文档 | 管什么 |
|---|---|
| `infinite-loop-timeout.md` | ⭐ **循环**：在重复（同一个动作做两遍） |
| ⭐ 本份 | ⭐⭐⭐ **预算**：在推进，但没尽头 / 没变化 |

> ⭐⭐ **循环容易发现（日志里能看到重复），无进展发现不了
> （每一步看起来都是新的、合理的）。**

## 2. 五道上限

| 上限 | 参数 | 说明 |
|---|---|---|
| ⭐ 步数 | max-step（如 20） | ⭐ 硬上限，模型永远不该被问"要继续吗" |
| Token | 总 token | 跨整个循环累计 |
| ⭐ 挂钟时间 | 总耗时（含工具调用） | ⭐ **面向用户的 agent 尤其要设** |
| 无进展 | N 步无变化 | 见下节 |
| 置信度 | 自评分低于阈值 | 见下节 |

两个容易被漏的：

**① 挂钟时间。** 大家只设步数和 token，但用户感知的是**墙上的钟**。
一个 15 步、每步 20 秒的循环，步数没超、token 没超，
用户已经等了 5 分钟。

**② 硬上限的含义。**

> ⭐⭐ **模型永远没有机会回答"我应该永远继续下去吗？"这个问题。**

这句值得单独记——它把"加一个 max_iterations 参数"这件事
上升成了**责任归属**：**终止不该是模型的一个选项。**

对应到我们已有的三条：
`infinite-loop-timeout.md` 的"不要给重试指令却不给重试预算"、
`error-handling.md` 的"让终止显式化"——
**三个来源，同一条原则。**

## 3. ⭐⭐⭐⭐⭐ 无进展检测器

> ⭐⭐⭐ **如果 agent 的计划或摘要在 N 步之内没有变化，
> 停下来请求人类输入。**

它的检测对象很特别——**不是"有没有报错"，是"有没有变化"**：

```
第 3 步：计划 = 先查日志，再定位服务，最后改配置
第 6 步：计划 = 先查日志，再定位服务，最后改配置   ← 无进展
第 9 步：计划 = 先查日志，再定位服务，最后改配置   ← 停
```

每一步都在"做事"（读文件、调工具），日志完全正常，
**但它在绕同一个圈，而圈的外观看不出重复。**

> ⭐⭐⭐ 这解释了 `trace-debugging.md` 里那句
> "一个在第 12 轮才明显的循环，通常是从第 3 轮开始的"——
> **无进展检测器就是把它在第 6 轮而不是第 12 轮抓出来的机制。**

### 与循环检测的区别

| | 循环 | 无进展 |
|---|---|---|
| 现象 | 同一动作重复 | 动作不同，状态不变 |
| 检测 | ⭐ 比对输入 | ⭐ 比对计划/摘要的语义 |
| 常见度 | 较少 | ⭐⭐ **更多** |

## 4. ⭐⭐⭐ 置信度阈值

> **模型必须给自己的每一步打置信度分。**

单独看这条容易觉得多余——直到你把它和"逃生口"放在一起：

```
`prompt-altitude-three-laws.md`：盲区里要"说出不确定 → 给最佳判断 → 必要时问"
本份：                           ⭐ 把它变成了一个可比较的数字
```

> ⭐ **差别在于：定性版本依赖模型自己意识到不确定；
> 打分版本给了你一个可以设阈值的量。**

不过要诚实标注它的成本：**每步自评本身就是额外 token。**
所以合理的用法是**只在关键决策点上要求打分**，而不是每一步。

## 5. ⭐⭐⭐ 工具数量上限

> ⭐⭐ **工具数保持在 30 以下；超过之后，误路由率会急剧上升。
> 超过就拆成子代理。**

这是"数量阈值"这个家族的新成员，整理一下已有的：

| 对象 | 阈值 | 出处 |
|---|---|---|
| ⭐ 同时挂载技能 | ≤3 | `three-skill-ceiling.md` |
| 技能库存（质量） | 10–20 | `skill-portfolio-audit.md` |
| 技能库存（路由） | 50 → 两步路由 | `routing-tiers-and-arbitration.md` |
| ⭐ **工具** | **<30** | 本份 |
| 参考文件 | 一层深度 | `reference-file-practices.md` |

> ⭐ 注意前两条与第四条**不矛盾**：技能有 description 做语义路由，
> 工具只有名字和一行描述——**信息量更少，所以阈值更低**。

顺带一条与位置偏差互证的：

> ⭐ **前沿模型对开头和结尾的回忆好于中间（lost in the middle）。
> 把关键指令放在两端。**

这与我们已有的三条（压缩取开头 5000、`head -100` 预览、
位置偏差两端重复）是**第四个来源**。

## 6. ⭐⭐ 在技能里怎么写

```markdown
## 预算与停止

- 最多 20 步；第 15 步时汇报一次进度
- ⭐ 如果连续 3 步计划没有实质变化 → 停止，说明卡在哪，请求输入
- 面向用户的操作：总耗时超过 3 分钟先给一次中间反馈
- ⭐ 不要在指令里写"如果失败就重试"而不写重试几次
```

> ⭐⭐ **最后一条是最常见的漏洞**：给了重试的许可，没给重试的预算。

---

## 一条该贴墙上的话

> ⭐⭐⭐ **终止条件不是"出错时怎么办"，是"没出错时什么时候停"。**

多数技能只写了前者——所以它们在没有错误的情况下
会一直跑下去，直到 token 耗尽或用户不耐烦地打断。
