## 1. 一个写了但永不执行的章节

```markdown
## 失败处理
如遇错误，记录错误信息并中止，不要继续输出不完整的结果。
```

看起来很完整：**有动作（记录 + 中止）、有禁令（不要继续）、有理由（不完整）。**

> ⭐⭐⭐⭐⭐ 唯独没有写：什么算"遇错误"。

而"是否遇到了错误"这件事，⭐⭐⭐⭐⭐ **由模型自己判定**——
它判定的依据不是你的标准，是它自己的完成倾向。

---

## 2. 它有动作，没有触发条件

技能里几乎每个章节都有触发条件：

| 章节 | 触发条件 |
|---|---|
| 流程 | 被调用 |
| 条件分支 | `if X` |
| 输出契约 | 每次结束 |
| ⭐⭐⭐⭐⭐ 失败处理 | ⭐⭐⭐⭐⭐ **（空）** |

> ⭐⭐⭐⭐⭐ 失败处理是技能里唯一一个"定义了动作、却把触发条件留给读者"的章节。

后果不是"偶尔误判"，是⭐⭐⭐⭐⭐ **系统性不进入**：

```
模型倾向于完成 → 倾向于把当前状态判为"还在正常进行"
→ 失败处理永远不被触发
→ ⭐⭐⭐⭐⭐ 你写的那段话从未执行过一次
```

而且它不会报错——**因为"没有失败"本来就是它要报告的状态。**

## 3. 五类没被定义的"失败"

| 情况 | 算失败吗 | ⭐ 模型的默认判定 |
|---|---|---|
| 工具超时 | 通常是 | ✅ 会报 |
| ⭐⭐⭐⭐⭐ 工具返回 200 但内容为空 | 应该是 | ⭐⭐⭐⭐⭐ ❌ 判为成功 |
| ⭐⭐⭐⭐⭐ 结果集为空（0 条） | 取决于意图 | ⭐⭐⭐⭐⭐ ❌ 判为"确实没有" |
| ⭐⭐⭐⭐ 部分成功（3 个里 2 个） | 是（partial） | ❌ 判为成功 |
| ⭐⭐⭐⭐ 结果明显不合理（负数、超范围） | 是 | ❌ 判为成功 |

> ⭐⭐⭐⭐⭐ 只有第一类会被模型主动判为失败——因为它是唯一一个"系统说了失败"的。
> 其余四类都要靠**技能自己定义**，而技能几乎从不定义。

这正是"别把 HTTP 200 当成功"那条规则的延伸：⭐⭐⭐⭐⭐ **200 是系统判定的成功，
而技能需要的成功标准是业务判定的——两者之间没有任何自动映射。**

## 4. 空结果是最贵的那一类

```
查询返回 0 条
→ 可能是真的 0 条
→ 也可能是查错了条件 / 连错了库 / 时间窗口不对
```

> ⭐⭐⭐⭐⭐ **"0"同时是两种完全相反的状态的答案，而输出里看不出是哪一种。**

它比错误更贵，因为：

| | 会不会被发现 |
|---|---|
| 报错 | 会（有信号） |
| ⭐⭐⭐⭐⭐ 0 条 | ⭐⭐⭐⭐⭐ 不会（它看起来是一个答案） |

而且它会稳定地通过所有检查：
schema 通过、字段齐全、类型是数字、不是 null——⭐⭐⭐⭐⭐ **它在所有门禁上都是绿的。**

写法只有一句，但必须有：

```
⭐⭐⭐⭐⭐ "结果为空时，输出『未获取到（已尝试：X）』，不得输出 0 或『无』，
            除非能明确指出分母（共检查 N 项，0 项异常）"
```

> ⭐⭐⭐⭐⭐ 关键在后半句：**"0"只有在带分母时才是一个答案**，
> 没有分母的 0 是一个占位符（见 `placeholder-in-output.md`）。

## 5. 定义了失败，没定义成功

```
"如遇错误则中止"
→ 那什么情况下不中止？
```

> ⭐⭐⭐⭐⭐ **失败的边界是成功的边界画出来的。**
> 只写失败，等于把边界的另一半留给模型。

正确写法是同时给出成功判定的最小集：

```
完成需同时满足：
① 目标范围内所有对象都已处理（N 已知）
② 每个对象都有明确结论（不是"未获取"）
③ 输出字段无空值（允许显式"未获取"）
不满足任一 → 进入失败处理
```

⭐⭐⭐⭐ 第①条里的 N 不能省：**没有分母就判断不了"都处理完了"**
（见 `skill-output/references/enumeration-and-completeness.md`）。

## 6. 修法：把触发条件写成可枚举的判定

失败处理章节推荐形状：

```markdown
## 失败处理

进入本节的判定（任一成立即进入）：
- 工具调用报错或超时
- ⭐ 返回 200 但结果集为空且未声明分母
- ⭐ 覆盖率 < 100%
- ⭐ 任一必填字段无法取得真实值（不得以默认值填充）
- ⭐ 结果超出合理范围（负数 / 超过总量 / 与已知事实矛盾）

进入后：
1. 停止后续写入动作
2. 按结构化错误协议输出（含 safe_reply）
3. ⭐ 不得改用其他数据源或改变口径后继续
```

> ⭐⭐⭐⭐⭐ 最后一条最容易被省，也最常被违反——
> 它是"模型遇到阻碍时的默认动作是绕过去"的直接对策。

## 7. 自检

| 检查 | 不通过的信号 |
|---|---|
| ⭐⭐⭐⭐⭐ 失败处理章节有没有列出"什么算失败"？ | 只有"如遇错误" |
| ⭐⭐⭐⭐⭐ "返回空"是否算失败？ | 没提 |
| ⭐⭐⭐⭐⭐ "部分成功"是否算失败？ | 没提 |
| ⭐⭐⭐⭐ "200 但内容为空"是否算失败？ | 没提 |
| ⭐⭐⭐⭐⭐ 成功判定的最小集写了吗？ | 只写了失败侧 |
| ⭐⭐⭐⭐⭐ 造一个"查询返回 0 条"的输入跑一次，技能进失败处理了吗？ | ⭐⭐⭐ 没进 = 这一节从未执行过 |
