## 这类技能在解决什么问题

```
没有技能时：
  每次生成 PPT/Excel/PDF，agent 都自己"猜"配色和字号
  → 每次都不一样
  → ⭐ 而且它不知道你公司的品牌色是什么

有了技能：
  配色、字号、页边距、Logo 位置、日期格式全部一次定义
```

> ⭐ 这正是技能的典型适用场景：
> **模型具备"做出一份文档"的能力，
> 但缺的是"按你们公司的标准做"。**

## 它的结构

```
## Brand Identity
公司名 / 标语 / 行业

## Visual Standards
主色：Acme Blue #0066CC (RGB: 0,102,204) — 标题、主按钮
     Acme Navy  #003366 (RGB: 0,51,102)  — 正文、强调
辅助色：Success Green #28A745 / Warning Amber #FFC107
       Error Red #DC3545 / Neutral Gray #6C757D

字体层级：
  H1 32pt Bold Acme Blue
  H2 24pt Semibold Acme Navy
  Body 11pt Regular Acme Navy
  Caption 9pt Regular Neutral Gray

Logo 用法：
  位置：首页/首片左上角
  尺寸：宽 120px（保持比例）
  ⭐ 留白：四周至少 20px
  ⭐ 禁止：变形、旋转、加效果

## Document Standards
按 PPT / Excel / PDF 分别定义

## Content Guidelines
语气：专业但亲和、避免行话、主动语态
数字：千分位、$X,XXX.XX、百分比一位小数、Month DD, YYYY

## Quality Standards（发布前自查）
## Prohibited Elements（禁止项）

## Scripts
apply_brand.py     自动套用品牌格式
validate_brand.py  校验是否符合品牌
```

## 为什么数值可以直接写进正文

> ⭐ **因为这些数值就是"知识"，不是"逻辑"。**

```
#0066CC、11pt、20px 留白、120px 宽度
```

这些是**常量事实**，模型需要它们才能做对。
把它们移进 `references/` 反而更糟——
每次都要多一次读取，而它们**几乎每次都会被用到**。

判据回顾（`splitting.md`）：

```
□ 每次都会用到 → 留正文
□ 偶发才用到   → 移 references/
□ ⭐ 需要一致性 → 进 scripts/
```

## 为什么还要配脚本

注意最后有两个脚本：

```
apply_brand.py      自动套用
validate_brand.py   校验
```

> ⭐ **第二个脚本是这类技能的点睛之笔。**

理由：靠模型"照着规范做"是**概率性的**；
用一个脚本**检查**结果是**确定性的**。

```
模型生成文档 → validate_brand.py 检查
             → 颜色不对 / 字号不对 → 报错并指出位置
```

这是 `grounding-verification.md` 那套"落地与验证"的直接应用，
而且它把验证放对了地方：**不在模型内部，在技能边界**。

## 可迁移的三条

**① 禁止项要像它这样写**

```
Never use:
  - Clip art 或未经许可的图库照片
  - Comic Sans、Papyrus 或装饰性字体
  - 彩虹色或渐变
  - 动画或切换效果（除非特别指定）
  - 竞品的品牌或引用
```

> ⭐ 每一条都是**具体的、可判定的**。
> 对照"不要用太花哨的效果"——那不是约束。

**② 按产出类型分别定义**

```
PPT  → 版式模板、每片最多 6 条 bullet、图表只用品牌色
Excel → 表头样式、边框、交替行、图表默认色序
PDF   → 页眉页脚、页边距、行距、段落间距
```

> 一份规范覆盖多种产出时，**按产出类型分节**，
> 而不是混在一起让模型自己挑。

**③ 给"发布前自查"清单**

```
□ Logo 位置与尺寸正确
□ ⭐ 所有颜色与品牌色板完全一致
□ 全文字体一致
□ 无拼写语法错误
□ 数据呈现准确
□ 专业语气
```

这就是输出契约——**模型在交付前能自己过一遍**。

## 一个警告

> ⚠️ **品牌规范会变。**

配色调整、Logo 更新、字号规范修订——
这些都会发生，而写死在技能里的数值**不会自动更新**。

三条应对：

```
① ⭐ 标注版本号与生效日期
   "Brand guidelines v2.3，2026-03 生效"

② ⭐ 把规范放在单一来源，技能引用它
   而不是在多个技能里各写一份色值

③ 定期复查——写进技能的维护周期
   （见 lifecycle.md 的 MATURE 阶段）
```

第 ② 条尤其重要：**同一份色值出现在三个技能里时，
改一次要改三处，而漏改的那处会静默产生不合规的产出。**

## 一个延伸判断

这类技能说明了一件事：

> ⭐ **"公司特有的、模型不可能知道的常量"是最高价值的技能内容。**

模型知道怎么做一个好看的 PPT；
它不知道你们的主色是 #0066CC，
也不知道你们的 Logo 要留 20px 白边。

> **这部分内容，是任何通用模型都不会自带、且必须有人写下来的。**
