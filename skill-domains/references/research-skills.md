# 研究类技能

> ⭐ **研究技能需要比普通写作技能更强的护栏，
> 因为它能悄无声息地制造权威感。**
>
> **一段流畅但来源糟糕的摘要，看起来会很可信。**

## 五条硬护栏

> ⭐ **每条都该直接写进研究类技能**：

```
1. ⭐ 重要事实断言必须有出处链接
2. 优先一手来源——官方文档、数据集、原始论文
3. ⭐ 时效敏感的事实要标日期
4. ⭐ 区分"证据"与"解读"
5. ⭐ 不准编造引用、引文、研究细节或数字
   并要求 agent 说明"哪些它没有验证"
```

> 呼应 `skill-crafting` 的 `grounding-verification.md` 的
> **"证据先于声明"** 与 `skill-crafting` 的 `fact-boundary.md`。

**为什么研究技能特别需要这些**：

```
□ 编造的引用会传播很远
□ 过时的统计会塑造一个坏决策
□ ⭐ 好的研究技能让 agent 更谨慎，而不只是更快
```

## 六步研究法

```
1. 定义研究范围与目标
   明确研究问题、边界、预期交付物、重点领域

2. 初步探索性检索
   侦察信息版图，识别关键来源与初步发现，
   ⭐ 发现相关主题与信息缺口

3. 深入关键领域
   对每个子主题定向调查，收集技术细节与多方观点，
   系统记录发现

4. ⭐ 交叉验证
   多源核实关键事实，评估可信度，识别矛盾，
   建立经过验证的知识库

5. 综合与分析
   识别模式与关联，产生原创洞察，用证据回答研究问题

6. 生成结构化报告
   含执行摘要，按主题组织并附支撑证据
```

> ⭐ **第 4 步"交叉验证"是最容易被跳过的**，
> 也是研究技能与普通写作技能的分水岭。
> 呼应 `skill-crafting` 的 `guidance-forms.md`：**这一步需要禁令 + 借口反驳**。

**三个应用示例**（放进技能里当示例很好用）：

| 类型 | 范围定义 | 深入什么 | 验证什么 |
|---|---|---|---|
| 市场研究 | 市场规模、玩家、技术、趋势、挑战、展望 | 电池化学、份额、供应链、成本 | ⭐ 交叉核实规模估算、验证技术对比 |
| 技术调研 | 部署策略、工具、监控、扩展、安全 | CI/CD、模型版本、A/B、监控 | 多专家来源对比建议 |
| 竞品分析 | Top 5 工具、功能、定价、集成、体验 | 详细功能对比、定价档位、用户评价 | ⭐ 核对功能清单、核实定价、看评价模式 |

**明确的不适用场景**（Do NOT 该写这些）：

```
□ 快速事实核查       → 用简单搜索
□ 实时信息需求       → 此技能重深度而非速度
□ 高度专业化主题     → 需要人类专家
□ 需访问付费内容     → 仅限公开可得信息
```

## 按阶段拆分技能，而不是一个大技能

> ⭐ **学术研究类技能的最佳实践是拆成一条流水线**：

```
literature-search   多源检索与排序（Semantic Scholar / arXiv / OpenAlex / Crossref）
deep-research       前沿检索、综述、深挖、代码、综合、报告
literature-review   有依据的综述（多视角专家人格对话）
novelty-assessment  反复查新
citation-management BibTeX 采集、校验、去重
related-work-writing 按主题组织相关工作
survey-generation   综述写作 + 引用校验
```

**推荐顺序**（这本身就是编排设计）：

```
1. literature-search   收集候选论文
2. deep-research       把领域组织成主题
3. literature-review   比较方法与缺口
4. citation-management 校验引用
5. ⭐ related-work-writing —— 只在来源检视完成之后才做
```

> ⭐ **最后一步的顺序很关键**：
> **先让 AI 结构化证据，让你来判断结论——
> 而不是先让 AI 给出结论。**

> 呼应 `skill-orchestration` 的 `composition.md` 的串行编排与 I/O 契约。

## 文献综述不是"总结一篇论文"

> ⭐ **一个常见误用**：拿文献综述技能去总结单篇论文。
> **它是用来理解一个研究领域的。**

**应该用在**：

```
□ 想知道一个领域几年间如何发展
□ 需要按主题或方法给论文分组
□ 想识别开放问题
□ 需要 Related Work 章节
□ 在比较假设、数据集、指标或基线
```

**好输出应包含**：

```
□ 研究聚类
□ 方法族系
□ 关键数据集
□ 评估指标
□ ⭐ 时间线发展
□ ⭐ 竞争性观点
□ ⭐ 强证据与弱证据
□ ⭐ 未解决的缺口
□ 必须全文精读的论文
```

**一条必须写进技能的警告**：

> ⚠️ **不要不经核对原文就相信引用、年份或方法分类。**
> 文献综述技能能组织你的阅读，**但它不该是最终权威**。
>
> 正式的系统综述通常用 PRISMA 等框架
> 让检索、筛选与纳入决策透明化。
> **AI 技能可以支持这个过程，但不替代综述方案设计。**

> ⭐ 呼应 `skill-governance` 的 `compliance-audit.md` 与 `skill-crafting` 的 `fact-boundary.md`：
> **AI 提供组织，人类承担判断。**

## 报告的读者分层

> ⭐ **同一份研究发现，给不同读者的组织方式不同**：

```
决策层读者  → ⭐ 以"决策"开头
技术读者    → 保留方法与细节
研究读者    → ⭐ 让引用与注意事项紧贴论断
```

**通用要求**：

```
□ 论断链接到来源
□ ⭐ 区分"观察"与"建议"
□ ⭐ 解释推理路径
□ 保持不确定性可见
```

> ⭐ **一句总结值得记住**：
> **最好的研究报告不是更长，而是更易审计。**

## 自查

```
□ 是否有"重要断言必须有出处"的硬要求？
□ 是否要求区分证据与解读？
□ ⭐ 是否明令禁止编造引用与数字？
□ 是否要求 agent 说明"哪些没验证"？
□ 六步里是否包含"交叉验证"这一步？
□ 是否写清了不适用场景（快速核查 / 实时 / 付费内容）？
□ 研究流水线是否按阶段拆成多个技能？
□ ⭐ related-work 阶段是否排在"来源检视完成"之后？
□ 文献综述是否定位为"理解领域"而非"总结单篇"？
□ 是否含"不要不经核对就相信引用"的警告？
□ 报告是否按读者类型分层组织？
□ 是否让引用与注意事项紧贴论断（便于审计）？
```
