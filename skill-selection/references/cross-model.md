## 为什么同一个技能在不同模型上表现不同

> ⭐ **Prompt 本质上是一种自然语言程序，但每个模型是不同的"编译器"。**

同一段 C++ 用 GCC 和 Clang 编译，结果理论上应该一样。
但 Prompt **不是形式语言**，没有精确的语义规范——
**每个模型对它的"理解"和"执行"都有自己的方式**。

---

## 四种差异来源

| 差异 | 表现 |
|---|---|
| **指令微调方式不同** | 有的模型对**角色设定**非常敏感（写"你是一个严格的数据分析师"它会认真扮演）；有的不太在意，更倾向按自己的"理解"来 |
| **对格式约束的服从度不同** | 写"只输出 JSON，不要任何其他文字"——有的严格遵守，有的推理完会附一段解释，有的**受指令约束强、忽略角色倾向** |
| **上下文利用能力不同** | 同样长度的指令，不同模型**注意力分配**不同：有的容易忽略靠后的内容，有的对开头几句权重格外高，有的**工具调用时会"遗忘"指令里的约束** |
| **对歧义的处理方式不同** | 遇到模糊地带：有的**主动推断并扩展任务边界**，有的**谨慎确认甚至拒绝**，有的严格按指令执行、不做额外推断 |

> ⚠️ 第三、四条对技能尤其致命：
> **"工具调用时遗忘 System Prompt 里的约束"**
> ——这正好解释了为什么有些技能在长流程里会后半段跑偏。

**实测差异**（JSON 输出可靠性）：

| 模型 | 明确 schema 下有效率 |
|---|---|
| GPT（明确模式） | ~95% |
| Llama 3.3 70B | ~70% |

> **25 个百分点的可靠性差距。**

## 模型无关写法

> ⭐ **这是本章最可操作的部分。**

```
□ 使用明确的 JSON schema（不要只说"输出 JSON"）
□ system / user 分离
□ 提供少样本示例（few-shot）
□ 不使用特定于某个模型的措辞
```

**针对四种差异的对策**：

| 差异 | 对策 |
|---|---|
| 角色设定敏感度不同 | **不要依赖角色扮演**——把要求写成具体行为，而非"你是一个……" |
| 格式服从度不同 | 给**完整 schema**，并在示例里给一个真实样例 |
| 忽略靠后内容 | **承重指令放顶部**（呼应截断保头不保尾） |
| 歧义处理不同 | **消除歧义**——把模糊地带写成显式的 `if <可观察谓词> then` |

**其他实测约束**：

| 平台 | 指令长度上限 |
|---|---|
| ChatGPT GPTs | **~8,000 字符** system prompt |
| Gemini Gems | **~4,000 字符** system prompt |

> 超过这个数，你的技能在那些平台上根本放不下。

## 跨模型测试

> **对同一提示词并行发给多个模型，对比输出**——
> 这是在生产部署前发现兼容性缺陷的**最快方法**。

```
□ 同一份未修改的提示词
□ 并行跑 GPT / Claude / Gemini
□ 对比：JSON 失败 · 拒绝模式差异 · 成本权衡
□ 实测：4 个模型 × 20 个测试用例可在约 15 秒内返回
```

**要测三类东西**：

```
1. 触发是否一致（这个技能在该模型上会被调用吗）
2. 输出格式是否一致
3. 边界行为是否一致（拒绝 / 扩展 / 推断）
```

## 格式可移植性对比

| | 可移植性 | 指令深度 | 生态 |
|---|---|---|---|
| **Skills（SKILL.md）** | ✅ **开放标准**，32+ 工具读取 | **无实际限制**——可含 references、脚本、工具限制、子技能、hooks | 独立市场 |
| **ChatGPT GPTs** | ❌ 仅 ChatGPT | ~8K 字符 + 最多 20 个文件 + Actions（需自托管 API） | GPT Store（3M+） |
| **Gemini Gems** | ❌ 仅 Google | ~4K 字符 + 知识文件，**无 Actions 对等物** | 无公开商店 |

> ⭐ **如果你的 AI 策略涉及不止一个模型或平台，
> Skills 是唯一面向未来的选择。**

| 需求 | 选 |
|---|---|
| 要遵循复杂多步流程 + 严格护栏 | **Skills（三者中唯一可行）** |
| 要触达海量消费者 | GPT Store |
| 要深度绑定 Google Workspace | Gems |

## 一个反直觉结论

> **Skills 在分发上赢不了 GPT Store（3M+ GPTs，8 亿周活用户）。**
> 但它在**表达能力和可移植性**上碾压。

**具体取舍**：

```
要"让几百万人用一个小玩具"     → GPT
要"让一个流程在多个平台上可靠跑" → Skill
```

> 另外注意一个细节：ChatGPT 的 Skills 与 Claude 的 Skills
> **格式同源**（OpenAI 官方也用 SKILL.md + 开放标准），
> 但**加载机制各有差异**——写的时候按标准写，测的时候按平台测。

## 自查

```
□ 是否依赖了角色扮演（"你是一个……"）而非具体行为要求？
□ 是否给了完整 JSON schema（而非只说"输出 JSON"）？
□ 承重指令是否放在了顶部？
□ 是否消除了模糊地带（写成 if-then 而非"酌情"）？
□ 是否在不止一个模型上测过同一份未修改的技能？
□ 指令长度是否在最严格的平台上限内（Gems ~4K 字符）？
□ 长流程后半段是否重复了关键约束（防工具调用时遗忘）？
```
