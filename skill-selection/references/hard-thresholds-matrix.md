## 1. ⭐⭐⭐⭐⭐ 三条硬门槛

满足任意一条 → **不要做技能**（换载体）：

**① ⭐⭐⭐⭐⭐ 每次输入输出都不同，无法提炼稳定模式**

```
❌ "帮我回这封邮件"
✅ 这是对话，不是技能
```

> ⭐⭐⭐⭐⭐ 判据：**你能写出"输出必须包含 X"吗？**
> 写不出 → 没有可验证的契约 → 它不是技能。

**② ⭐⭐⭐⭐⭐ 需要实时数据，但没有任何工具能取到**

```
❌ "告诉我今天的股价"
   （没有联网工具时）
```

> ⭐⭐⭐⭐⭐ **这是三条里最危险的一条**——
> 因为技能不会因为没数据而停下，⭐⭐⭐⭐⭐ **它会编一个。**
>
> 这与"错误被改写成功"是同一机制的不同形态：
> 那份是技能返回了错误而模型改写，
> ⭐⭐⭐⭐⭐ **这份是根本没有错误可改——它以为自己知道。**

**③ ⭐⭐⭐⭐ 需要执行权限，但环境不允许**

```
❌ "帮我发邮件" （没有邮件工具/权限）
```

> ⭐⭐⭐⭐⭐ 表现不是失败，是⭐⭐⭐⭐⭐ **静默降级到别的路径**——
> 它可能会"贴一段邮件正文让你自己发"，
> 而这个降级对监控系统是完全不可见的。

## 2. ⭐⭐⭐⭐ 三条软门槛

不阻止做技能，但要调整预期：

| 软门槛 | ⭐ 调整 |
|---|---|
| ⭐⭐⭐⭐ 你没做过 ≥3 次 | ⭐⭐⭐⭐ 先手动做几次，模式才会稳定（三次法则） |
| ⭐⭐⭐⭐ 没有客观的对错 | ⭐⭐⭐⭐⭐ 验收标准会写不出来 → 先补标准，再写技能 |
| ⭐⭐⭐⭐ 只在一个项目用一次 | ⭐⭐⭐⭐ 用提示词即可（不值得占用常驻判断预算） |

> ⭐⭐⭐⭐ 第三条最常被违反，代价也最隐蔽：
> ⭐⭐⭐⭐⭐ **一次性技能从装上的那一刻起就在收费**——
> 它在每一次判断里都作为候选被读了一遍，
> 而它永远只会被用一次。

这与 `skill-portfolio-audit.md` 里那条
"一次性技能在写它的那一刻就能判断，应零延迟清除"
是同一条：**不需要积累数据，写的时候就知道。**

## 3. ⭐⭐⭐⭐⭐ 越过硬门槛会怎样

三种越界的失败形状，全都是静默的：

| 越界 | ⭐⭐⭐⭐⭐ 失败形状 |
|---|---|
| ① 无稳定模式 | ⭐⭐⭐⭐ 每次输出都"合理"但不达标，且无法说清差在哪 |
| ② ⭐⭐⭐⭐⭐ 无实时数据 | ⭐⭐⭐⭐⭐ **编造，且自信** |
| ③ ⭐⭐⭐⭐ 无执行权限 | ⭐⭐⭐⭐⭐ **静默降级到别的路径** |

> ⭐⭐⭐⭐⭐ **共同点：没有一个会报错。**
>
> 这是整套库里被反复验证最多的一条结论的又一次出现——
> 此前已有六个来源（结构正确的废话、自信的漂移、错得自信而正确、
> 错误被改写成功、N 个半成品、部分成功未报覆盖率），
> ⭐⭐⭐⭐⭐ **这是第七个场景，且是唯一一个"设计阶段就能预判"的。**

最后半句是关键：**其余六个都要跑起来才发现，
而越过硬门槛这件事，写之前就能看出来。**

## 4. ⭐⭐⭐⭐ 硬门槛 vs 五层选型

两者是串联关系，不是并列：

```
第 1 步：⭐⭐⭐⭐⭐ 过硬门槛吗？（本份）
         → 过 → 不做技能，换载体或放弃
第 2 步：⭐⭐⭐ 用五层选型定载体
         （提示词 / 技能 / 子代理 / MCP / 工作流）
第 3 步：⭐⭐⭐⭐ 选作用域（个人全局 / 项目级）
```

> ⭐⭐⭐⭐⭐ **顺序不能反。**
> 先做选型再查门槛，等于先把技能建起来再问"该不该建"——
> 而那时你已经投入了，会倾向于找一个理由留下它。

这正是"过早抽象"的另一种形态：
⭐⭐⭐⭐ 过早通用化、过早编排、过早分目录之外，
⭐⭐⭐⭐⭐ **第四种是"过早固化"——把还没成型的模式固化成技能。**

## 5. ⭐⭐⭐⭐⭐ 一句话判据

三个问题，全部答"是"才做：

```
① ⭐⭐⭐⭐⭐ 我能写出"输出必须包含 X"吗？
② ⭐⭐⭐⭐⭐ 它需要的数据/权限，我能拿到吗？
③ ⭐⭐⭐⭐⭐ 这件事我做过三次以上吗？
```

> ⭐⭐⭐⭐⭐ 三问的排序有意义：
> **第 ① 问最先，因为它最难补**——
> 数据可以想办法拿到，次数可以积累，
> ⭐⭐⭐⭐⭐ **但"输出该是什么"如果答不出，说明你不知道自己在要什么。**

一个自检（很便宜）：

> ⭐⭐⭐⭐⭐ **先写验收标准，再写技能。**
> 验收标准写不出来 → 别写技能。
>
> 这与 `minimum-viable-three-principles.md` 里
> "先定义 finished 的样子"是同一条，
> ⭐⭐⭐⭐ 而这里的额外价值是：**它还顺带回答了"该不该做"**。
