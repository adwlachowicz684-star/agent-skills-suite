# 技能 vs 微调 vs RAG

## 四者边界

| 机制 | 回答什么 | 比喻 |
|---|---|---|
| **Tools / MCP** | 能做什么动作 | 手 |
| **Skills** | 怎么把事情做好 | 脑 |
| **RAG** | 是什么（事实） | 记忆 |
| **Fine-tuning** | 模型本能层面的一致性 | 本能 |

> **RAG 管"是什么"（原料），Skills 管"怎么做"（厨艺）。**
> 只有 RAG 没 Skill，agent 拿到资料不会用；
> 只有 Skill 没 RAG，agent 有方法但没素材。

**RAG 与 Skills 的精确分界**：

```
RAG    "我们的政策对 X 是怎么说的？"   → 提供事实
Skills "用我们的政策框架分析这个情况"   → 提供判断
```

## 技能 vs 微调：完整对比

| 维度 | 微调 | 技能 |
|---|---|---|
| **改什么** | 模型权重（神经网络） | 外部指令文件（SKILL.md） |
| **持久性** | 永久，直到重训 | 动态，可即时增删改 |
| **成本** | 高（算力、数据、时间） | 可忽略（文本文件） |
| **更新耗时** | 数小时到数天 | **秒级** |
| **部署** | 替换整个模型 | 拷文件到技能目录 |
| **影响范围** | 影响模型所有行为 | 任务特定激活 |
| **所需专长** | ML 工程 + 训练数据整理 | 技术写作 |
| **版本管理** | 模型 checkpoint | **Git 兼容的文本文件** |
| **分享** | 模型分发（GB–TB） | 文件分享（KB–MB） |
| **回滚** | 重新部署旧模型 | **删文件 / 改名** |
| **测试** | 评估数据集、benchmark | **直接用 AI 测** |
| **平台依赖** | 模型特定 | **跨平台标准** |

> ⭐ **"回滚"那一行最能说明问题**：
> 微调出问题要重新部署模型；技能的回滚是删一个文件。

**微调的真正代价**（不只是算力）：

```
永久    改动固化在权重里
昂贵    需要算力与训练数据
静态    ⭐ 更新需要完全重训
```

## 什么时候才该微调

> ⭐ **默认从技能开始，只有技能走到底还不行才往下走。**

**适合微调的四种情况**：

```
1. 需要特定输出格式
   ——难以通过提示词稳定达成的 JSON 结构、领域专用记法
   ⚠️ 但：现代提示词（尤其配合工具）已能达成多数格式要求

2. 优化延迟
   ——微调后的小模型可能比"大模型 + 复杂提示词"更快
   ⚠️ 但：提示缓存 + 优化过的技能设计往往已够用

3. 确实有海量训练数据
   ——百万级高质量样本，且有基础设施用好它们
   ⚠️ 但：维护负担随模型复杂度增长；多数组织高估了自己的数据质量

4. 监管合规要求
   ——部分受管行业要求完全掌控模型权重、训练数据来源与推理基础设施
```

**不该微调的信号**：

```
□ 行为改变是任务特定的        → 用技能
□ 需要频繁更新                → 用技能
□ 预算/时间受限              → 用技能
□ 只是工作流引导              → 用技能
□ 没有训练数据，只有业务规则   → 用技能
□ 更简单的方法还没试过        → 先试更简单的
```

> ⭐ **一条来自实践的建议**：
> **即使要微调，也保持聚焦且最小——别试图编码领域知识，那是检索的事。**

## 成本对照：一个真实测算

> 客服自动化场景的对比（SaaS 产品）：

| 项 | 微调方案 | 技能方案 |
|---|---|---|
| 数据准备 / 开发 | $150,000 | $40,000 |
| 微调 / 知识库 | $75,000 | $10,000 |
| 集成 | $50,000 | $25,000 |
| **年度维护** | **$100,000** | **$20,000** |
| **5 年总计** | **$625,000** | **$155,000** |
| 首次上线周期 | **6 个月** | **6 周** |

**技能方案的优势**：

```
□ 成本低 75%
□ 上线快 4 倍
□ ⭐ 随基础模型升级自动变好
□ 更易调试与迭代
□ 提供可透明的推理过程
```

> ⚠️ 注意措辞：微调方案在**特定场景**提供边际质量提升，
> **但成本差异很难证明其合理性**。这不是说微调无用，
> 而是说**它不该是默认选项**。

## 决策路径

```
从技能开始 —— 永远是起点
  ↓
评估性能，识别差距
  ↓
诊断差距类型：
  推理质量不够    → 换更强的模型（不是微调）
  知识缺口        → 改进检索（不是微调）
  格式问题        → 更好的提示词，或轻量微调
  一致性太差      → 加示例与约束
  ↓
只有当：
  □ 技能已优化到极限仍不足
  □ 具体差距确实能通过训练解决
  □ 成本能被创造的价值证明
  □ 有资源做持续维护
才考虑微调
```

**成本阶梯**（往下走每一步都增加成本、复杂度与维护负担）：

```
领域推理      → 技能 + 好提示词        $
领域知识      → 技能 + 检索            $$
特定格式      → 轻量微调              $$$
完全定制      → 重度微调              $$$$
```

**一个四问速判**：

```
1. 需要 AI 知道特定事实，还是遵循特定流程？
   事实 → RAG        流程 → 技能
2. 是一次性任务还是重复发生？
   一次性 → 提示词    重复 → 技能
3. 需求多久变一次？
   频繁 → 技能（易更新）  很少 → 量大可考虑微调
4. 有什么资源？
   非技术 → 技能/提示词  有 ML 工程师 → 可考虑微调
```

## 最佳实践：分层协同

> ⭐ **企业最优解不是二选一，而是分层分工。**

```
感知层（意图识别、实体抽取）
  → 轻量化模型微调，固化识别逻辑，降低延迟

知识层（动态知识库、RAG 检索）
  → 由 Skill 挂载各类数据源，agent 动态选择检索方式

应用层（业务流程）
  → Skill 编码流程与规则
```

**选型矩阵**：

| 场景特征 | 优先微调 | 优先技能 |
|---|---|---|
| 输出一致性要求 | 极高（合规/医疗/金融强规范） | 中高（技能规则可约束） |
| 任务变更频率 | 极低（年度级） | 较高（周/日级） |
| 数据资源 | 充足高质量标注集 | 只有业务规则，无训练数据 |
| 团队构成 | 有算法工程师 | 业务/后端工程师为主 |
| 工具调用需求 | 低 | 高（需联动多 API 与系统） |
| 延迟要求 | 极低（端侧） | 可接受多步推理的轻微延迟 |

## 自查

```
□ 是否已用尽更简单的办法（提示词 → 技能 → 检索）？
□ 差距类型是否诊断清楚了（是推理/知识/格式/一致性中的哪一类）？
□ 是否误把"知识缺口"当成了"需要微调"？
□ 是否算过 5 年总成本（含年度维护，不只是首次开发）？
□ 是否知道"随基础模型升级自动变好"这一项的价值？
□ 若微调，是否保持聚焦最小（只做格式/风格/延迟，不做领域知识）？
□ 是否规划了分层协同（感知层微调 + 知识层检索 + 应用层技能）？
□ 团队是否真有 ML 工程与持续维护资源？
```
