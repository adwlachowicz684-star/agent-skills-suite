## 1. ⭐⭐⭐⭐⭐ 一个此前没说清的矛盾

两条我们已有的结论：

```
A ⭐⭐⭐⭐ 低频但高价值的专家型技能恰恰最该留
B ⭐⭐⭐⭐ 每个项目只留 2–3 个技能
```

看起来直接冲突。仲裁：

> ⭐⭐⭐⭐⭐ **两者管的容器不同。**
> ⭐⭐⭐⭐⭐ **低频高价值的应该"留在库里、不装进项目"。**

> ⭐⭐⭐⭐ **"留"和"装"是两个独立的选择**——
> 此前把它们当成了一个（要么装要么删），
> 于是 34% 僵尸里有一部分是被误杀的、
> 也有一部分是被误留的。

---

## 2. ⭐⭐⭐⭐⭐ 三层作用域

| 层 | ⭐ 装什么 | 数量 |
|---|---|---|
| ⭐⭐⭐⭐ **个人全局** `~/.claude/skills/` | 跨项目通用：提交规范、调试方法论、个人偏好 | 10–20 |
| ⭐⭐⭐⭐⭐ **项目级** `<repo>/.claude/skills/` | 只在这个代码库成立：架构约定、部署流程、本项目术语 | ⭐⭐⭐⭐⭐ **2–3 个为上限** |
| ⭐⭐⭐⭐ **备份 / 归档** 外部目录 | 低频高价值、暂时不用、等待重审 | 不限（不参与判断） |

> ⭐⭐⭐⭐⭐ 第三层是这份最重要的贡献：
> ⭐⭐⭐⭐⭐ **它让"删"变成"移"**——
> 而"移"的决策成本远低于"删"（因为可逆）。

这与 `skill-refining/references/skill-scope-tiering.md` 那条
"没有恢复路径的空壳，就是没人承认的删除"完全同源：
**可逆性是让治理真正发生的前提。**

## 3. ⭐⭐⭐⭐ 挂载 vs 存在

```
存在（在磁盘上）  → ⭐⭐⭐ 零判断成本
挂载（参与匹配）  → ⭐⭐⭐⭐⭐ 每次判断都要读一遍
```

> ⭐⭐⭐⭐⭐ **一个从没被触发过的技能，成本不是零——
> 但只有"挂载着的"才在收费。**

所以关键操作是：

```
⭐⭐⭐⭐⭐ 从项目级移到归档层 = ⭐⭐⭐⭐⭐ 成本归零，但知识不丢
```

具体数字（来自 47 个技能的实测）：

```
每次潜在激活的⭐⭐⭐⭐⭐ 认知切换成本 40–80 token
⭐⭐⭐⭐⭐ 装一半 → 认知切换省 24K / 月（远大于常驻的 $2–4）
```

> ⭐⭐⭐⭐⭐ **认知切换是主要成本，不是常驻。**
> 这补上了此前只算"常驻元数据"的缺口。

## 4. ⭐⭐⭐⭐⭐ 判断预算才是瓶颈

一个常被算错的对比：

```
100 个技能 × 每次判断 ≈ 10K tokens（常驻元数据）
一个技能真被触发一次，正文 2K–5K
```

> ⭐⭐⭐⭐⭐ **库存 100 个时，光是"考虑要不要用"
> 就比"真的用一次"还贵。**

所以：

```
⭐⭐⭐⭐⭐ 限制库存的理由不是"占空间"，是"占判断"
```

这也解释了为什么"低频高价值该留但要移走"——
⭐⭐⭐⭐ 它占的是低频的判断预算，而**高频判断发生在项目里**。

一个推论：

> ⭐⭐⭐⭐⭐ **同一个技能，装在项目级和装在全局，成本差一个数量级**
> ——不是因为大小，是因为项目级会话的判断次数远高于全局会话的。

## 5. ⭐⭐⭐⭐ 降级与提升

双向移动，都要有触发条件：

**降级（项目 → 归档 / 全局）**

```
⭐⭐⭐⭐⭐ 触发：连续 30 天 0 次调用
⭐⭐⭐⭐⭐ 或：命中率 < 20%
⭐⭐⭐⭐ 动作：移到归档层，README 记"为什么归档"
```

**提升（归档 / 全局 → 项目）**

```
⭐⭐⭐⭐⭐ 触发：连续两周每周 ≥3 次手动提到它
⭐⭐⭐⭐⭐ 判据：手动搬运 ≥3 次才升（与"过早编排"同阈值）
```

> ⭐⭐⭐⭐⭐ **"连续两周每周 ≥3 次"这个门槛的意义**：
> 它排除了"这周刚好在做这件事"——
> ⭐⭐⭐⭐ 单次高频往往是任务性质，不是长期模式。

还有一个方向常被忽略：

```
⭐⭐⭐⭐ 全局 → 项目：当它开始出现项目特有的内容时
⭐⭐⭐⭐⭐ 判据：技能里出现了这个项目才有的路径/术语/缩写
```

（与 `skill-content/references/portability-across-projects.md` 的"组织耦合"是同一信号——
**一旦出现，这个技能就已经是项目级的了，只是还没搬过去。**）

## 6. ⭐⭐⭐⭐ 常见错误配置

| 错误 | ⭐ 后果 |
|---|---|
| ⭐⭐⭐⭐⭐ 把所有技能都装在项目级 | ⭐⭐⭐⭐⭐ 高频会话 × 大库存 = 判断成本爆炸 |
| ⭐⭐⭐⭐⭐ 低频专家技能装在项目级 | ⭐⭐⭐⭐⭐ 它和高频的抢预算，然后被误判为"僵尸" |
| ⭐⭐⭐⭐ 归档层不存在 | ⭐⭐⭐⭐⭐ "删"是唯一选项 → 没人愿意治理 → 库存只增不减 |
| ⭐⭐⭐⭐ 同名技能同时装在项目级和全局 | ⭐⭐⭐⭐⭐ 全局覆盖项目 —— 与"离得近更强"的直觉相反 |

最后一条值得展开：

> ⭐⭐⭐⭐⭐ **对"生效范围"这个直觉（离工作目录近的更强）是对的，
> 但对"同名冲突"它完全相反**——越宽泛的越赢。
>
> 所以"我在项目里放了一个改进版"是无效的：
> ⭐⭐⭐⭐ **它会被全局的同名技能覆盖，而且不报错。**

这也给了上面那条"全局 → 项目"的迁移一个技术前提：
⭐⭐⭐⭐ **迁移前必须先确认没有同名冲突。**
