# 状态与记忆

## 边界

- 用于：**技能"记住什么"——进度持久化、跨会话接续、记忆分层、自带记忆文件**
- 不用于：跑砸了怎么办 → 《skill-recovery》
- 不用于：技能之间怎么传数据 → 《skill-interfaces》
- 不用于：上下文预算与压缩截断 → 《skill-context》

## 核心原则

> ⭐⭐⭐⭐⭐ **会话切换会重置"已完成"的记忆，但不会重置文件系统。**
> ⭐⭐⭐⭐⭐ **指令层无状态，数据层可以有状态——这两句话必须同时成立。**

## 速查

- ⭐⭐⭐⭐⭐ **"我在上下文里记着进度"不是接续方案**——上下文正是那个会消失的东西
- ⭐⭐⭐⭐⭐ **重跑常常比接续可靠**：重跑成本 < 排查状态不一致的成本时，重跑
- ⭐⭐⭐⭐ 技能里的**事实会腐烂**，因为程序记忆层没有时间维度 → 事实写进记忆，不写进正文
- ⭐⭐⭐⭐ **写"已完成"不够，要写可撤销的 undo 文件**（见《skill-recovery》）

## Critical Rules

- ⭐⭐⭐⭐⭐ **禁止把"我在上下文里记着进度"当作接续方案**——上下文正是会消失的那个东西
- ⭐⭐⭐⭐⭐ **禁止把事实写进正文**（会腐烂）；事实写进记忆层，方法写进技能
- ⭐⭐⭐⭐⭐ **持久化必须带 run-id 与时间戳**，否则"文件存在"被误读成"这一步做过了"
- ⭐⭐⭐⭐ **写入状态前先校验新鲜度**；读取旧状态比没有状态更危险（它看起来是对的）
- ⭐⭐⭐⭐ **失败时保留现场**，不得清理中间产物
- ⭐⭐⭐⭐ **重跑便宜就重跑**，不要为了"接续"引入状态
- ⭐⭐⭐ 会话内状态与跨会话状态必须分开写，混在一起会让"清会话重跑"失效
