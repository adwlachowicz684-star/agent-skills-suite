# 记忆分层：每层有自己的写入、检索与收缩规则

> ⭐ **记忆不是一个向量库。**
> 它是四个职责不同的部分，各有各的读写与压缩规则。

## 四层各自装什么

| 层 | 装什么 | 延迟 | 特点 |
|---|---|---|---|
| **对话层** | 最近若干轮 | 0（已在注意力里） | ⭐ 每写进一个 token 都付输入价 |
| **语义层** | 抽取出的**事实**与嵌入 | 20–80ms | 按相似度检索 |
| **情节层** | 带时间戳与 ID 的**过去交互** | — | agent 的"日记" |
| **程序层** | 学会的技能、例程、计划 | — | ⭐ **技能就在这一层** |

另一种常见切法把"会话层"单列（会话内持久、重启即失，
硬预算如 32k，溢出时激进摘要；延迟 1–5ms），
是提示缓存的最大受益者。

## 写入节奏：最容易搞错的一条

> ⭐ **每一层的写入节奏完全不同**：

```
对话层    每一轮
会话层    每几轮
情节层    会话结束时
语义层    每晚（离线整合，用小模型抽取持久事实）
程序层    ⭐ 仅在任务被验证之后
```

> ⭐ **最常见的性能退化与成本超支原因：
> 把每一次工具调用实时倒进向量库。**

这不是优化问题，是**架构错误**——
它把对话层的节奏强加给了语义层。

## 三个已知失败模式

**① 记忆投毒**

```
没有分层写入策略时
攻击者可控的内容会从对话层被"提升"到语义层甚至程序层
```

这是为什么**程序层必须要求"任务被验证"才写入**——
它是唯一会改变未来行为的层。

**② 上下文碎片化**

```
各层检索出互不相连的片段
重组后拼成一个不连贯的上下文
→ 症状：缺少跨层检索编排
```

**③ 备忘即来源混淆**

```
agent 在对话层写给自己的笔记
后来被当作"来源证据"检索出来
```

> ⭐ 清晰的层边界能防止这件事——
> **"我自己写的"和"外部提供的"必须可区分。**

## 检索要跨层编排

不是把所有东西交给一个向量索引，而是：

```
① 决定"哪一类召回请求由哪一层回答"
② 决定多层同时命中时如何合并与排序
```

两个实测有效的技巧（代码类记忆）：

```
⭐ BM25 + 稠密向量混合
   ——纯向量搜索在精确代码符号、文件路径、函数名上失败
   ——混合检索在代码符号检索上优于纯向量约 38%
   用 RRF（倒数排名融合）合并两路分数

⭐ 元数据前置过滤
   按 project / repo / 时间戳 / author 先筛，再做相似度检索
```

本地 SQLite + `sqlite-vec` 能做到 **<30ms** 召回延迟，且数据不出本机。

## 遗忘是特性

> ⭐ **遗忘要刻意设计，不是事故。**

每层都要有自己的收缩方式：

```
摘要 · 聚类 · 按新近度衰减 · 主动丢弃
```

一个具体机制：**艾宾浩斯遗忘曲线**——
对长期未被引用、低置信的记忆块衰减其检索权重。

以及：**矛盾消解**——
冲突的记忆陈述（如过时的 API 端点）要**标记出来交人工**，
而不是静默地让新的覆盖旧的。

⚠️ 两条诚实的局限：

```
· 嵌入模型升级后需要重建索引
· 多租户环境下的矛盾消解需要严格的权限边界
```

## 情节记忆：多数团队做错的地方

朴素做法（教程和默认模板里最常见的）：

```
把每条用户消息和助手回复都嵌入、原始存进向量库
每轮检索 top-k
```

它在规模上会崩，四个原因：

```
① ⭐ 原始转写有噪声
   问候、澄清、走错的路，都会污染检索质量

② 嵌入按主题聚类
   ——不是按细粒度相关性，导致近重复答案被反复检索

③ 缺乏语义元数据
   "部署失败" vs "部署成功" 这类关键区分丢失了

④ 向量检索没有内建的新近偏置
   需要显式的衰减策略
```

✅ 已验证的解法是**情节蒸馏**：
每次有意义的交互结束（任务完成、工单关闭、评审收尾）后，
用一个整合提示生成**为检索优化的结构化情节记录**。

> 关键差别：**存蒸馏后的记录，不是原始转写。**

一个量化参考：
两层式（情节轨迹 + 蒸馏语义）架构
**把用户提示的上文规模减少 90%，同时保持连续性**。

## 与技能的关系

**① 技能属于程序层**——
这解释了它的写入纪律：

```
⭐ 只在"被验证有效"之后才更新技能
而不是每次用完都改
```

没有 eval 兜底的自我修改，正是从这里看出了问题：
它把"一次通过"当成了"已验证"。

**② 技能的持久化产物**（见 `cross-session-artifacts.md`）
其实是在**情节层与语义层之间**架桥——
`CONTEXT.md` 偏情节（发生了什么），
ADR 偏语义（我们认定的事实）。

**③ 别用对话层的机制装别层的内容**

> 把所有东西塞进 CLAUDE.md 之所以必然失败，
> 就是因为那是拿对话层的机制去装语义层和程序层的内容。

## 什么时候不需要这套

```
❌ 单轮 agent 与无状态工具
❌ ⭐ 模型上下文窗口已经覆盖记忆需求，根本不需要检索
```

四条记忆层不是荣誉勋章——**用不上就是额外复杂度**。
